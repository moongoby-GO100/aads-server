## 5. "오늘 홈" 화면 설계

위에서 아래로 중요도 순.

1. **머리줄**: 사업자 스위처(전체/개별) · 날짜(오늘, KST) · 마지막 수집 시각과 상태 점(초록/주황/빨강).
2. **오늘 지표 5개 카드** (숫자 크게, 비교값 작은 글씨, 카드 전체가 클릭 영역)

| 카드 | 값 | 데이터 출처(기존 API) | 클릭 시 |
|---|---|---|---|
| 오늘 매출 | 오늘·어제 합계, 전주 같은 요일 대비 | `/sales`, `/settlements` | 돈 흐름 › 매출 (오늘 필터) |
| 통장 입출금 | 오늘 입금·출금, 잔액 합 | `/bank-summary`, `/accounts` | 돈 흐름 › 통장 |
| 검토 대기 | "최근 7일 N건 / 전체 M건" 2단 표기 | `/reviews` | 검토·마감 › 검토할 거래(미검토 필터) |
| 급여일 | 다음 급여일까지 D-n, 예상 지급액 | `/payroll` | 사람 › 급여 |
| 승인 대기 | 가입요청+서류검수+서명대기 합 | `/employees/join-requests`, `/onboarding/documents`, `/contracts/pending-signature` | 사람 › 승인함 |

3. **처리할 일 목록**(최대 7행, 우선순위순): 예 "가입 요청 2명 승인", "배민 정산 차이 확인", "신한 수집 14시간 멈춤 — 다시 연결". 각 행 오른쪽에 바로 실행 버튼.
4. **외식 지표 띠**: 배달 4사 정산 차이 · 식재료율 · 인건비율 · 이번 달 추정 손익(기존 월 KPI 재사용).
5. **수집 상태**: 채널별 마지막 성공 시각(`/collection-status`).

구현 원칙: 1차는 **프론트에서 기존 API 병렬 호출로 집계**한다(서버 변경 없음). 첫 화면 완료 시간 p95 가 1.5초를 넘으면 2차로 `/home-summary` 집계 API 를 별도 작업으로 낸다(측정 후 결정, 현재 [미측정]).

## 7. 디자인 시스템

기존 `:root` 변수(13~28행)를 확장한다. 기존 변수명은 유지(다른 화면 회귀 방지).

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | #f6f7f9 | 배경 |
| `--panel` | #ffffff | 카드 |
| `--ink` / `--muted` | #111827 / #6b7280 | 본문 / 보조 |
| `--accent` | #f26a2e (유지) | 브랜드·주요 버튼 |
| `--pos` / `--neg` / `--warn` | #15936b / #dc4c4c / #b7791f | 증가·감소·주의(기존 green/red/amber 별칭) |
| `--radius` | 14px 카드 · 10px 버튼 | |
| `--shadow` | 0 1px 2px rgba(17,24,39,.06), 0 4px 16px rgba(17,24,39,.04) | 카드 |
| 간격 | 4·8·12·16·24·32 | 8 배수 그리드 |

타이포: 시스템 폰트 스택(Pretendard 있으면 우선), 숫자는 `font-variant-numeric: tabular-nums`.
크기: 지표 숫자 28px/700, 카드 제목 13px/600 muted, 본문 14px, 표 13px. 금액은 천 단위 쉼표 + "원".

컴포넌트: 지표 카드(`.kpi-card`), 할 일 행(`.todo-row`), 상태 점(`.dot.ok|warn|err`), 공통 필터 바(`.filter-bar`), 표(머리 고정, 숫자 우측 정렬, 행 높이 44px), 상태 블록(`.state`), 하단 탭(`.bottom-tabs`).
색만으로 상태를 전달하지 않는다(아이콘·문구 병기). 본문 명도 대비 4.5:1 이상.
