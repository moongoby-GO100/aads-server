- 지시: 대표님 "진행해" (116 디스크 확보 PRD 4단계 3-4항 승인)
- 상위: `docs/design/20261105_AADS_116 디스크 확보와 42 보관 계층 PRD.md` (document_key `disk-116-offload-to-contabo42-prd`)

## 1. 배경

- 116 디스크는 2026-11-05 98% → 84% 로 낮췄지만 목표(75% 이하)에 못 미친다.
- 116 에서 이미지를 빌드할 때마다 빌드 캐시와 후보 이미지가 쌓인다(API 후보 이미지 회당 5.2GB, 빌드 직전 여유 8GB 요구). 이날 하루 API 후보 이미지 4개·대시보드 3개가 만들어졌다.
- 빌드 자체도 116 CPU 를 오래 쓴다(대시보드 빌드 약 3~5분, API deps 이미지 4GB). 채팅과 같은 서버다.
- contabo42: 같은 데이터센터(RTT 0.5ms), 12코어·47GB, 디스크 여유 750GB+, docker 29.1.3.

## 2. 목표 / 비목표

- 목표: API(`aads-server/deploy.sh`)·대시보드(`aads-dashboard/deploy.sh`) 이미지를 **42 에서 빌드**하고 116 은 **받기만** 한다. 116 빌드 캐시를 0 에 가깝게, 빌드 CPU 를 116 에서 제거한다.
- 비목표: 블루그린 계약 변경(한 릴리스 SHA 당 이미지 한 번 빌드, `--no-build` 슬롯 기동, 같은 digest 대기 슬롯 동기화, 롤백)은 그대로. 운영 컨테이너 실행 위치(116)도 그대로.

## 3. 설계

### 3.1 전달 경로 — 42 로컬 레지스트리 + SSH 터널 (116 docker 데몬 재시작 없음)
- 42 에 `registry:2` 를 `127.0.0.1:5000` 에만 연다(외부·메시 노출 없음).
- 116 은 `ssh -N -L 127.0.0.1:5000:127.0.0.1:5000 mesh-42` 터널(systemd 상시)로 접근한다. docker 는 `localhost` 레지스트리를 기본으로 insecure 허용하므로 **116 dockerd 설정 변경·재시작이 필요 없다**(116 은 live-restore 꺼짐 — 데몬 재시작 시 전 컨테이너 중단 위험).
- 레이어 단위로 받으므로 바뀐 레이어만 전송된다(deps 4GB 레이어는 재사용).

### 3.2 빌드 — 42 의 docker 로 원격 빌드
- `docker -H ssh://mesh-42 build`(또는 buildx 원격 빌더)로 116 의 깨끗한 릴리스 컨텍스트(기존 `RELEASE_CONTEXT_DIR`)를 42 로 보내 빌드한다.
- 빌드 결과를 42 레지스트리에 `localhost:5000/aads-server:<sha>`·`aads-dashboard:<sha>` 로 push, digest 를 기록한다.
- 116 에서 `docker pull localhost:5000/...@<digest>` → `docker tag aads-server:<sha>` 로 기존 이름을 그대로 만든다. 이후 단계(슬롯 기동·대기 동기화)는 변경 없음.

### 3.3 안전장치
- 스위치 `AADS_REMOTE_BUILD=42|off`. 처음엔 대시보드만 켜고, API 는 대시보드 3회 성공 뒤 켠다.
- 42 접속·빌드·push·pull 중 하나라도 실패하면 **기존 116 로컬 빌드로 자동 폴백**하고 deploy_runs 에 사유를 남긴다(배포가 42 에 볼모로 잡히지 않게).
- digest 고정: pull 한 이미지의 digest 가 42 가 기록한 digest 와 같아야 다음 단계로 간다.
- 42 레지스트리 정리: 릴리스별 최근 10개만 보존(주 1회 GC).

### 3.4 116 측 정리
- 원격 빌드가 기본이 되면 `disk_cleanup_v2.sh` 의 빌드 캐시 상한을 8GB → 2GB 로 낮춘다(폴백 빌드용 최소치).

## 4. 단계

| 단계 | 내용 | 영향 |
|---|---|---|
| A | 42 레지스트리(127.0.0.1:5000)·116 터널 유닛 설치, 수동 push/pull 시험 | 운영 영향 없음 |
| B | 대시보드 `deploy.sh` 원격 빌드 + 폴백 + 테스트, `AADS_REMOTE_BUILD=42` 로 3회 배포 | 대시보드만 |
| C | API `deploy.sh` 원격 빌드(deps 이미지 포함) + 폴백 + 테스트 | API 배포 |
| D | 116 빌드 캐시 상한 2GB, 효과 측정(디스크·배포 시간·116 CPU) | |

## 5. 완료 기준
- 대시보드·API 각 3회 이상 원격 빌드 배포 성공, 폴백 경로 테스트 통과.
- 배포 1회당 116 디스크 증가량 = 바뀐 레이어 크기 수준(빌드 캐시 증가 0).
- 116 `/` 75% 이하.
