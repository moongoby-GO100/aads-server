## 0. 한 줄 요약

두 화면은 모두 "목록이 아니라 설명·버튼·카드가 첫 화면을 차지한다". 소스 재현 기준으로 `/reports` 는 1440x820 에서 목록이 7행, 접힘(360x780)에서 5행이고 접힘 폭에서는 상세 영역이 80px 로 눌려 글자가 세로로 깨진다. `/changes` 는 접힘에서 고친 파일 행이 1행만 보인다. 목업은 **목록 우선, 필터 접기, 행당 2줄, 업무 용어 배지**로 바꿔 `/reports` 는 14행/8행, `/changes` 는 13행/7행(고친 파일 행 11행/5행)을 보이게 한다. 단, 이번 측정에는 두 가지 한계가 있다(§1.1, §2).

### 1.2 소스 재현 기준 실측표 (변경 전 → 목업)

"온전히 보이는 행"은 목록 영역 안에 행 전체가 들어온 개수다. `/changes` 의 "목록 줄"은 날짜 머리글 + 운영 반영 줄 + 고친 파일 행의 합이다.

| 화면 | 해상도 | 필터·버튼·설명이 차지하는 높이(헤더 아래~목록 시작) | 행 높이 | 온전히 보이는 행 (전 → 후) | 문제 |
|---|---|---|---|---|---|
| 보고서 열람 | 1440x820 | 100px → 112px | 81px → 44px | **7 → 14** | 행 3줄(제목·추천·날짜), 날짜가 "2026년 10월 14일 오전 6:07" 로 길다 |
| 보고서 열람 | 360x780 | 100px → 122px | 81px → 56px | **5 → 8** | 목록 279px + 상세 80px 로 고정 분할 — 상세 글자가 세로로 깨짐, 상세로 갈 방법이 없음 |
| 보고서 열람(산출물 탭, 상세 선택) | 1440x820 | 138px → 125px | 81px → 44px | **7 → 14** | 유형 드롭다운이 항상 보임, 상세는 이모지 + 원본 JSON 이 그대로 펼쳐짐 |
| 변경 이력 | 1440x820 | 378px → 115px (첫 고친 파일 행까지) | 48px → 44px | **13 → 13** (고친 파일 행 **8 → 11**) | 제목 + 설명 2줄 + 버튼 + 날짜 카드 머리글 3줄 + 운영 반영 5줄이 먼저 나온다 |

원시 측정값: `rowcount.json` (키 `before/…` = 변경 전 재현, `mock/…` = 목업).

관찰:

1. `/reports` 의 접힘 폭 문제가 가장 크다. 좌측 목록 `minWidth 280px` 와 우측 상세가 고정 분할이라 폰에서 상세를 읽을 수 없다.

3. `/changes` 는 PC 에서는 이미 촘촘해서 행 수 개선이 작다(13 → 13). 개선은 접힘 폭과 "고친 파일 행"에서 나온다. 완료 기준은 목록 12줄/6줄이므로 PC 는 유지, 접힘은 6 → 7 로 기준을 넘긴다.

## 2. 발견: 운영 `/reports` 는 구현 대상 페이지에 도달하지 못한다

- 서버 68 nginx(`/etc/nginx/conf.d/aads-reports.inc`)가 `location = /reports { return 301 /reports/; }`, `location = /reports/` 를 FastAPI `/static/reports/index.html`(공개 문서 포털)로 보낸다. 같은 포함 파일이 443 서버 블록에서 쓰인다.
- 그래서 `https://aads.newtalk.kr/reports` 에서는 `src/app/reports/page.tsx`("보고서 열람")가 보이지 않는다. 이 페이지는 nginx 규칙을 피하는 경로가 있는지, 아니면 사실상 도달 불가인지 이번 작업에서 확인하지 못했다(로그인 불가, nginx 수정 금지).
- 이 목업의 `/reports` 는 **dashboard 코드의 보고서 열람 페이지**를 뜻한다. 구현 러너를 내기 전에 CEO 가 정해야 한다: ① 문서 포털이 `/reports` 를 계속 쓰고 보고서 열람은 다른 주소로 노출 ② 보고서 열람이 `/reports` 를 가져가고 포털은 `/education/` 으로 이동. nginx 변경은 배포 승인 사항이며 이번 범위 밖이다.

### 3.1 보고서 열람 (`/reports`)

- 목록 머리: 검색 1줄(36px) → 탭 3개를 한 줄 분할 버튼으로(`시장조사 30 | 기획서 14 | 산출물 40`) → 건수·정렬 한 줄(산출물 탭에서는 `필터 · 전체 유형 ▾` 요약 버튼이 같은 줄에 들어간다). 하단 키보드 힌트 줄은 없애고 건수는 위 줄로 올린다.
- 행: 시장조사 = `제목` / `[시장조사] 추천: …  날짜`. 기획서 = `기획서 #140` / `[기획서][승인됨|검토 중] 선택 후보 …`. 산출물 = `산출물 이름 프로젝트` / `[설계서|조사 노트|명세서|분석 결과|검토 결과|보고서]`. 영문 코드(`design_doc` 등)는 업무 용어로 바꾼다. 날짜는 `10-14 18:07`.
- 상세: 제목 위에 유형·상태 배지, 제목, 작성일·프로젝트·분석 비용을 한 줄 메타로. 추천은 강조 상자, 근거와 원본 JSON 은 접기 버튼 뒤에 둔다.
- 접힘 폭: 목록이 전체 폭, 행을 누르면 상세가 전체 화면으로 열리고 `← 목록으로` 로 돌아온다(PC 의 좌우 분할은 600px 이상에서만).

### 3.2 변경 이력 (`/changes`)

- 도구줄: `무엇이 언제 바뀌었나` + 새로고침, 그 아래 기간 분할 버튼(3/7/14/30일), 그 아래 한 줄 요약(PC·태블릿만).
- 날짜 행(2줄): `10-14 (수) · 파일 312개 수정` / `[운영 4번 반영][배포 실패 1건][기록 안 됨 14] AADS 212 · KIS 60 · GO100 40`. 오른쪽에 `접기/펼치기`. 첫 날은 열려 있다(현재 동작 유지).
- 열린 날: 경고 한 줄 → 운영 반영 요약 1행(성공/실패 건수, 실패 사유 한 줄, 누르면 펼침) → 고친 파일 행(파일명 + 폴더 / 상태 배지 + 설명 + 시간). 상태 말(`운영 반영됨`, `올림 (배포 대기)` …)은 기존 `STATUS_LABEL` 을 그대로 쓴다.

## 5. 완료 기준 (구현 단계)

1. 보고서 열람: 1440x820 에서 목록 **12행 이상**, 360x780(공통 헤더 186px 아래)에서 **6행 이상**.
2. 변경 이력: 1440x820 에서 목록 줄 **12줄 이상**, 360x780 에서 **6줄 이상**, 고친 파일 행이 접힘에서 **3행 이상**.
3. **기존 검색·필터·정렬 동작 유지**: 검색어 3개 필드 일치, 산출물 유형 필터, 탭별 건수, ↑↓ 선택 이동, 기간 3/7/14/30일 전환, 날짜 펼침/접힘, 새로고침.
4. 로딩·빈 목록·오류 상태가 서로 다른 화면으로 보인다(오류가 "데이터 없음" 으로 보이지 않는다).
5. 구현 러너는 `/docs` 공통 컴포넌트를 재사용하고 새 컴포넌트를 만들지 않는다.
6. 구현 전에 §2 의 `/reports` 주소 결정이 끝나 있어야 한다.

## 7. 목업 검토 등록 결과

2026-10-14 에 `POST https://aads.newtalk.kr/api/v1/projects/AADS/mockup-reviews`(리뷰 생성)과 `POST …/projects/AADS/documents`(정본 초안 등록)를 인증 없이 각 1회 호출했고 둘 다 **HTTP 401** `인증이 필요합니다. Bearer 토큰을 제공하세요.` 를 받았다. 이 세션에는 테넌트 Bearer 토큰이 없고, 다른 서비스의 키를 가져오거나 토큰을 직접 발급하거나 DB 에 직접 쓰지 않았다. 지시에 따라 여기서 중단했다.

- 리뷰 생성·revision 등록·submit: **미완료** (review_id, revision_id, manifest_hash 없음)
- 이 문서의 정본 등록: **정본 미등록(미완료)**, 열람 링크 미제공
- 준비해 둔 것: `manifest.json` — revision 등록 본문의 `manifest` 부분(screens 2, assets, evidence)과 리뷰 생성 본문. 토큰이 있는 Runner/운영자가 그대로 보내면 된다.
- 등록 시 알아둘 점: (a) 서버는 `internal://docs/…` 아래 파일을 서버의 `docs/` 에서 읽어 해시를 다시 계산한다. 그래서 자료를 `docs/design/mockups/20261014_reports_changes/` 에도 두었고, 이 커밋이 서버에 반영된 뒤에 등록해야 한다. (b) 제출(submit) 시 `plan`/`prd`/`spec` 문서 참조 3개가 필요하다. 승인된 면제 정책 참조가 없어 이 작업에서는 채우지 못했다 — 등록할 plan/prd/spec 정본이 있으면 `doc_refs` 에 넣고, 없으면 면제 정책을 CEO 가 정해야 한다.
- 목업 승인(approve)은 호출하지 않았다. 승인은 CEO 전용이다.

## 8. 다음 구현 러너에 넣을 MOCKUP_* 3줄 (초안 — 값은 등록·CEO 승인 뒤에 채운다)

```
MOCKUP_REVIEW_ID: <등록 후 review_id>
MOCKUP_REVISION_ID: <CEO 가 승인한 revision_id>
MOCKUP_MANIFEST_HASH: <승인된 revision 의 manifest_hash>
```

세 값은 등록(§7)이 끝나고 CEO 가 승인해야 생긴다. 지금은 비어 있으며, 값을 추측해서 넣지 않는다.
