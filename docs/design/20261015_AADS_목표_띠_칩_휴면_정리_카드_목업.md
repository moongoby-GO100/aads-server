## 0. 한 줄 요약

새 화면을 만들지 않고 **현재 목표 띠(chat/page.tsx 12815행 부근)** 의 칩에 우선순위 배지·자동승인 칩을 얹고, 확정 정렬은 `P0 → P1·P2 → 💤 휴면` 으로 바꾼다. 휴면·차단 정리는 띠 오른쪽 `🧹 휴면·차단 정리 18건` 칩에서 열리는 **채팅 속 카드 1장**으로 하며, 카드는 **① 진행 P0 3개 고르기 → ② 휴면 후보(① 에서 고른 P0 제외) → ③ 차단 해소 또는 종료(blocked 는 휴면과 따로)** 3단이다. 🔄 작업중·⏳ 대표님 대기 그룹과 `🔗 목표 미연결` 칩은 PRD §6-1 미결(I-1~I-4)이라 기본 목업에서 뺐고, 별도 시안 `goal-strip_icons-option` 으로만 둔다.

## 1. 측정 방법과 한계 — 먼저 읽을 것

| 항목 | 내용 |
|---|---|
| 변경 전 | 운영 `/chat` 은 로그인이 필요해 **실캡처를 하지 못했다.** 현재 띠의 인라인 스타일을 정적 HTML 로 재현한 것이다(`source_reconstruction`). 칩은 `이름·진행률·막힘` 만 보인다. |

| 실측 숫자 | 목표관리자 15:40 KST: 열린 목표 49 · 열린 P0 30 · 정리 후보 18 = 휴면 active 14(그중 P0 7) + blocked 4 · 「오비스 진화」(P0-CRITICAL, blocked, 09-29 이후 무활동). 정지 대상 보류 목표(blocked·draft·일시정지)는 PRD §1 의 13개. |
| 가상 값 | 위 실측을 뺀 나머지 — 목표 이름·진행률·사용량·마지막 활동일·차단 사유·선택값·`+38`·(별도 시안의) 미연결 3건은 **목업용 가상 값**이다. 화면 하단 주석에 "가상" 을 적었다. |
| 숫자 불일치 | 재작업 지시문은 차단 목표를 5개로 적었으나 실측은 blocked 4 이다. 실측을 따라 ③ 은 4건으로 그렸다(KIS 시세 캐시 행 제외). 활성 14 와 차단 4 의 합이 18 이라 초안(draft) 행은 두지 않았다. |
| 띠의 범위 | 띠는 **이 세션이 맡은 목표(sessionGoals)** 를 보여준다. 49개 전부가 아니다. 목업은 대표님 통합 세션을 가정해 11개 + `+38` 로 그렸다. |

## 3. 화면 설계 (요구사항 번호)

### 3.1 목업 A — 상단 목표 띠

| 번호 | 설계 | 근거 |
|---|---|---|
| A1 | 칩 = `[P0·P1·P2 배지] 이름 진행률 [⚠️ N일] [자동승인 칩]`. 주도 목표는 기존대로 굵은 주황 테두리 유지. 상태 아이콘(🔄/⏳)은 기본 목업에 없고 별도 시안에만 있다. 💤 는 휴면 칩 앞에 붙는다 | PR-3, §6-1 |
| A2 | **확정 정렬: P0 → P1·P2 → 💤 휴면.** 각 그룹 앞에 작은 머리표(`P0 5`, `P1 · P2 4`, `💤 휴면 2`). 머리표는 펼친 상태에서만. 🔄 작업중·⏳ 대표님 대기 그룹은 PRD §6-1 이 정할 때까지 넣지 않는다 | PR-3, §6-1 |
| A3 | **P0 이면서 7일 이상 무활동이면 이름 뒤 `⚠️ 8일`.** 14일이 넘으면 💤 로 바뀌며 `⚠️ 16일` 도 유지. 「오비스 진화」가 `P0 CRITICAL ⚠️ 16일 💤` 로 표시된다 | PR-4, DO-1 |
| A4 | 자동승인 칩 8종 — 아래 표 | PRD §5 |
| A5 | 툴팁(마우스 올림 / 모바일은 칩을 누르면 아래 시트): 설정자·설정일·범위·`used/max`(막대)·만료일(D-n). 사용 80% 초과 또는 만료 7일 전이면 칩 안에 `⚠️`. blocked 목표는 "목표가 blocked 라 판정에서 제외됩니다. 차단을 해소해 재개하면 다시 켜집니다" 문구 | AA-6, AA-4, AA-3 |
| A6 | (별도 시안 전용) `🔗 목표 미연결 3건` 칩(점선, 띠 앞쪽 고정)과 🔄/⏳ 그룹. 기본 목업에는 없다 | §6-1 I-1~I-4 |
| A7 | 맨 앞 `열린 목표 49 · P0 30` 요약 칩, 오른쪽 고정 영역에 `🧹 휴면·차단 정리 18건`(보라 강조, 모바일 `정리 18`)·`접기/펼치기`. `+38` 은 기존 `+N` 패턴. 정리 후보가 0건이면 이 칩은 나타나지 않는다(empty 화면) | DO-3 진입점 |
| A8 | 칩 클릭 → 오른쪽 패널. 휴면·정지·한도 소진이면 패널 맨 위에 **행동줄**: 휴면은 `재개 / 일시정지 / 종료 / 병합 ▾`, blocked 는 `차단 해소(재개)` 로 문구가 바뀐다(한도 소진은 `한도 갱신`). 막다른 표시를 두지 않는다 | PRD §2 실패 복구 |
| A9 | 모바일(≤480px): 접힌 띠는 가로 스크롤 한 줄(기존). 펼치면 칩 대신 **행 목록**(행 35px, 그룹 머리 22px)으로 바뀌어 자동승인 칩이 오른쪽에 정렬 | — |
| A10 | 띠는 PRD DO-1 의 파생 휴면(14일 무활동)을 그대로 보여주므로 blocked 목표(오비스 진화·레거시 데이터 이관)도 💤 그룹에 들어간다. **blocked 를 휴면 후보와 따로 묻는 것(DO-2)은 정리 카드의 일**이고 띠 정렬은 건드리지 않는다 | DO-1, DO-2 |

|---|---|---|---|
| 수동 | `🔒 수동` | `🔒 수동` | 채팅 띠 개선·보고서 개편·문서 정리 |

### 3.2 목업 B — 휴면·차단 정리 카드

| 번호 | 설계 | 근거 |
|---|---|---|

## 5. 완료 기준 (구현 단계, M3)

1. 데스크톱·모바일에서 정렬이 `P0 → P1·P2 → 💤` 로 보이고, P0 7일 무활동 칩에 ⚠️, 14일 무활동은 💤 + 맨 뒤. (🔄/⏳ 는 §6-1 확정 후)
2. 자동승인 칩 8종이 서버 `auto_approval.state` 와 1:1 로 표시된다(서버 값이 없으면 칩을 그리지 않고 기존 띠 유지).
3. 툴팁·시트에 설정자·설정일·범위·used/max·만료일이 모두 나온다.
4. 정리 카드는 ① → ② → ③ 순서이고, ① 에서 고른 목표가 ②·③ 에 다시 나오지 않으며, blocked 는 ② 에 들어가지 않는다. 아무것도 고르지 않으면 서버에 변경을 보내지 않는다. 자동 종료·삭제 경로가 없다.
5. 브라우저 E2E 가 불가하면 "⚠️ 브라우저 E2E 미실행" 을 표기한다(PRD §9-3).

## 6. 대표님·구현 담당에게 확인할 것 (미결 — 목업은 아래 제안대로 그렸다)

1. **P0 이면서 휴면인 목표의 위치.** PRD 순서를 그대로 따르면 가장 높은 등급인 「오비스 진화」가 49개 칩 맨 뒤로 밀려 접힌 띠에서는 안 보인다(PRD §1 이 지적한 문제와 같다). 제안: 💤 그룹 안에서 P0 를 앞에 세우고, 접힌 상태 오른쪽 고정 영역에 `💤 휴면 N · ⚠️ P0 M` 요약 칩을 둔다. 목업은 그룹 안 정렬만 반영했다. 요약 칩은 승인 시 추가.
2. **자동승인 상태가 겹칠 때의 우선순위.** PRD §5 에 순서가 없다(예: blocked + 한도 소진). 제안: `정지 > 만료 > 한도 소진 > 해제됨 > 위임 > 전체/고위험까지/수동`. 실제 판정에서 인정되지 않는 상태가 위에 온다. M2 의 `auto_approval.state` 가 이 순서로 한 값만 내려야 화면과 판정이 어긋나지 않는다.
3. **재개 때 자동승인 복원 방식.** PRD AA-3 은 "재개·차단 해소 시에만 다시 켠다" 까지만 정했다. 만료일이 이미 지났거나 한도가 소진된 grant 를 재개로 되살리면 어떻게 되는가? 목업은 "기존 범위·한도·만료 그대로 복원(만료면 ⌛ 로 보이고 갱신 필요)" 로 그렸다. 30일 새로 부여하는 안은 한도·만료가 조용히 늘어나므로 권하지 않는다.
4. **정리 반영은 한 번에 전부 또는 전부 취소.** 목업의 오류 상태가 이를 전제로 한다(일부만 반영되는 상태를 화면이 설명해야 하는 부담이 크다). 서버가 한 트랜잭션으로 처리해야 한다.
5. **P0 슬롯은 ① 에서 고른 3개에만.** ② 휴면의 P0 를 재개하거나 ③ 의 P0 blocked 를 차단 해소해도 진행 P0 상한 3 을 넘길 수 없다. 목업은 이 경우 `P0→P1 하향` 칩을 달아 보였다(① 에서 슬롯이 다 찬 상태). ① 에서 고른 P0 를 종료·병합·일시정지하는 모순 선택을 막는 규칙은 M3 가 정한다.
6. 띠의 자동승인 칩 문구를 `🟢 고위험까지 9/10` 로 줄인 것(§3.1). PRD 문구 `🟢 자동(고위험까지) 9/10` 를 띠에 그대로 쓰면 데스크톱에서 한 줄에 칩이 2개씩만 들어간다.
7. 같은 `⚠️` 가 두 뜻이다 — 칩 이름 뒤는 "P0 무활동 N일"(PR-4), 자동승인 칩 안은 "사용 80% 초과·만료 임박"(AA-4). 위치와 툴팁으로 구분했다. 헷갈리면 AA-4 쪽을 `⏳` 등 다른 기호로 바꾼다.
8. 카드는 대표님 세션에만 전달하는 것을 가정했다(PRD PR-2 취지). 비대표님이 보는 읽기 전용 화면은 그리지 않았다.
9. **PRD §6-1 I-1~I-4 (🔄/⏳ 그룹·미연결 칩).** 결정 전이므로 기본 목업에서 뺐다. 결정되면 `goal-strip_icons-option` 을 기본으로 승격하거나 폐기한다.
10. 띠(DO-1 파생 휴면)에는 blocked 가 💤 로 보이고 카드(DO-2)에서는 따로 묻는 이중 표기가 헷갈릴 수 있다. 목업은 PRD 대로 그렸고, 불편하면 띠에서도 blocked 를 별도 표시하는 안을 PRD 에 올린다.

## 7. 목업 검토 등록 결과 — 미완료

이번 재작업에서는 목업 검토 API 와 정본 문서 API 를 **호출하지 않았다**(러너는 401 이고 등록은 CEO 세션이 한다). 승인(approve)도 하지 않았다. 앞선 작업(2026-10-15)에서는 인증 없이 각 1회 호출해 둘 다 HTTP 401 이었다.

- 리뷰 생성·revision 등록·submit: **미완료** (review_id, revision_id, manifest_hash 없음)
- 이 문서의 정본 등록: **정본 미등록(미완료)**, 열람 링크 미제공
- 준비해 둔 것: `manifest.json` rev2 — 리뷰 생성 본문과 revision `manifest`. 토큰이 있는 CEO 세션이 그대로 보내면 된다.
- 등록 시 알아둘 점: (a) 서버는 `internal://docs/…` 아래 파일을 서버 `docs/` 에서 읽어 해시를 다시 계산하므로 **이 변경이 서버에 반영된 뒤** 등록해야 한다. (b) submit 에는 `plan`/`prd`/`spec` 3개가 필요하고 항목마다 `document_key + revision_id + content_hash` 가 있어야 한다. prd 후보는 `goal-priority-dormancy-autoapproval-display-prd` rev4 이고 revision_id·content_hash 는 정본 조회로 받는다. plan/spec 정본은 없어 면제 정책 참조를 CEO 가 정해야 한다.
