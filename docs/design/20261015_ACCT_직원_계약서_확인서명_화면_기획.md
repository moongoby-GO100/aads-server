## 1. 지금 흐름 진단 (origin/main 3b6630b8, 운영 r37 동일)

| # | 문제 | 원인 (코드) | 영향 |
|---|---|---|---|
| 1 | 직원이 로그인하면 관리자 화면(V4.1)으로 이동 | `index.html` `shouldOpenV41App()` 이 로그인만 확인하고 직원 역할을 확인하지 않음 (`return hasServerAuth()`) | 직원에게 매출·매입·세무 등 관리자 메뉴가 보임 |
| 2 | V4.1 에는 직원 화면이 없음 | `mockup-v4-1.html` 에 `isEmployeeExperience` 같은 직원 판단이 0곳. 계약 모듈 `contract-editor-v41.js` 는 관리자용 작성기(작성·서명요청·PDF)뿐 | 직원은 본인 계약서 목록·내용·서명 버튼을 볼 수 없음 |
| 3 | 직원용 목록·서명 기능은 예전 화면에만 있음 | `index.html` 의 `renderContracts()`(직원은 '내용 확인·서명')와 `openContractSignModal()`(전문 미리보기 + 자필서명) | 서명 알림 링크(`yf_contract_token`)로 들어올 때만 예전 화면이 열려 서명 가능 |
| 4 | 예전 서명 창도 '읽고 서명'이 약함 | 전문과 서명칸이 한 창에 있고, 끝까지 읽었는지 확인하지 않음. 핵심 조건 요약이 없음 | 내용 확인 없이 서명 가능. 모바일에서 서명칸이 작음 |

결론: 이번 주 반영한 '직원 화면 보기', 임금 자동 나눔, 근무일정 선택은 모두 **관리자 쪽 기능**이었다. 직원이 계약서를 보고 서명하는 흐름은 처음부터 기획하지 않았다.

## 2. 대상 사용자와 경로

| 구분 | 내용 |
|---|---|
| 대상 | 매장 직원 (주로 휴대폰, 업무 앱 경험 적음) |
| 첫 진입 | 알림·링크 또는 직접 로그인 → **직원 홈**. 서명할 계약서가 있으면 맨 위 카드 |
| 반복 사용 | 하단 탭(모바일) / 상단 메뉴(PC): 홈 · 계약서 · 급여명세 · 근태 · 입사서류 |
| 실패 복구 | 로그인 만료 → 다시 로그인 후 보던 계약서로 복귀 / 계약서 없음 → 안내와 새로고침 / 링크 만료·이미 서명 → 상태 표시와 다시 요청 / 제출 실패 → 서명 유지, 다시 제출 |

## 3. 화면 구성 (목업 기준)

1. **직원 홈** — 인사, "근로계약서 서명이 필요합니다" 카드(요청일, 계약 종류, `읽고 서명하기`), 계약·급여·서류 요약.
2. **내 계약서 목록** — 본인 계약서만. 서명 대기 → 서명 완료 → 이전 계약 순서. 필터(전체/대기/완료/이전). 행마다 시작일·임금·근무 요약. 완료본은 `내용 보기`·`PDF 받기`.
3. **계약서 읽기** — PC: 왼쪽 전문, 오른쪽 핵심 조건 요약(시작일·근무지·근무·휴게·휴일·임금·지급일)과 읽은 정도. 모바일: 위에 요약 칩 4개, 아래 전문, 하단 고정 버튼. **끝까지 스크롤해야 `동의하고 서명하기`가 켜짐.** 내용이 다르면 `관리자에게 수정 요청`.
4. **동의·서명** — PC: 오른쪽 칸. 모바일: 아래에서 올라오는 창(서명칸 높이 150px 이상, 터치 44px 이상). 이름, 손글씨 서명, 동의 체크 2개(내용 동의 / 전자서명 효력), `서명 제출`.
5. **서명 완료** — 완료 시각, `서명본 PDF 받기`, 목록·홈 이동. 관리자에게 알림.

## 4. 구현 방향

| 순위 | 작업 | 파일 | 비고 |
|---|---|---|---|
| P0 | 직원 역할이면 V4.1 로 보내지 않음 | `index.html` `shouldOpenV41App()` | `isEmployeeExperience()` 가 참이면 false. 바로 서명 가능해짐 |
| P1 | 직원 홈·목록·읽기·서명 화면을 목업대로 교체 | `index.html` 직원 보기 또는 새 `modules/employee-portal.js` | 기존 API 재사용: 계약 목록, `contractPreviewHtml`, `POST /contracts/signing` |
| P1 | 끝까지 읽기 확인, 핵심 조건 요약, 모바일 서명 창 | 위와 같음 | 서버 저장 변경 없음 |
| P2 | 관리자 '직원 화면 보기'가 새 직원 화면을 그대로 보여 주게 맞춤 | `index.html` `employeePreview` | 읽기 전용 유지 |

DB 스키마 변경 없음. 서명 API·서명본 PDF 생성은 그대로 쓴다.

## 5. 완료 판정 기준

- 직원 테스트 계정으로 로그인 → 직원 홈이 열리고 관리자 메뉴 0개 (PC·모바일 캡처).
- 계약서 목록에 본인 계약서만 표시, 서명 대기 건 맨 위.
- 끝까지 읽기 전 서명 버튼 비활성 → 끝까지 읽으면 활성.
- 테스트 계약 1건 서명 → 상태 `signed`, 서명본 PDF 받기 성공.
- 관리자 계정은 지금처럼 V4.1 로 이동 (회귀 없음).
- 단위테스트: 역할별 진입 경로, 읽기 확인, 서명 제출 실패 시 서명 유지.
