### 1.1 87efafb 배포 전

서버 Playwright(chromium), 로그인 상태, 3회 반복. 로딩 시간은 페이지 이동 시작부터 첫 목록 행이 DOM 에 생길 때까지(중앙값, 초). "첫 화면 목록 행"은 탭 바 아래에서 목록 영역이 보이는 높이 안에 **행 전체가 들어온** 개수다.

1. 프로젝트 파일 탭은 필터가 차지하는 높이(767px)가 화면 높이(820px)에 가깝다. 유형·포맷 칩이 모두 펼쳐져 있고 전자계약 카드(5건 목록)가 항상 열려 있다.
2. 360 폭은 상단 공통 헤더가 186px(버튼이 두 줄로 접힘)이고 탭 바까지 합쳐 243px 가 목록 앞에 있다. 이 공통 헤더는 이번 범위가 아니므로 그대로 두고, 헤더 아래에서 6행을 확보하는 것을 기준으로 삼았다(§5 참고).

4. 884x1000 폭에서 파일을 고르면 화면 전체가 "📄 문서 보기" 로 바뀌고 목록 영역이 사라진다. 목록으로 돌아가는 버튼은 있다.

### 1.2 87efafb 배포 후 (현재 운영)

같은 방법(서버 Playwright, 로그인, 2회). 행은 이제 `button[title]` 2줄 행이고 행 높이 44px, 행 간격 포함 46px 이다. "목록 영역"은 목록이 스크롤되는 상자(위 `listTop`, 아래 `visBottom`)다.

| 화면 | 해상도 | 필터·버튼이 차지하는 높이(탭 바 아래~첫 행) | 목록 시작 | 목록 영역 아래 끝 | 첫 화면에 온전히 보이는 행 | 로딩(2회) |
|---|---|---|---|---|---|---|
| 프로젝트 파일 탭 | 1440x820 | 189px | 298px | 787px (화면 820 − 하단 상태줄 33px) | **10** (일부 걸친 행 11) | 3.6초 / 3.9초 |
| 프로젝트 파일 탭 | 884x1000 | 157px | 294px | 967px | **14** (걸친 행 15) | 4.8초 / 3.6초 |
| 프로젝트 파일 탭 | 360x780 | 189px | 426px | 747px | **6** (걸친 행 7) | 6.7초 / 4.6초 |

- 87efafb 로 1440x820 은 0행 → 10행, 360x780 은 0행 → 6행, 884x1000 은 3행 → 14행이 됐다. 작업자 추정 "약 11행"은 실측으로는 **10행**이다.
- 1440 에서 12행에 못 미치는 이유는 두 가지로 측정된다: ① 프로젝트 버튼이 두 줄로 접힘(NTV2 가 둘째 줄) → 첫 행이 목업보다 30px 아래(304px vs 274px), ② 목록 아래에 `6474개 문서 · 변경 없음 / 캐시: 오전 7:52` 상태줄 33px → 목록 영역이 787px 에서 끝남. 행 간격 2px(46px 간격)도 보탠다.
- 로딩 시간은 배포 전(6.4~10.5초)보다 짧게 나왔지만, 같은 날 서버 부하가 달랐고 2회뿐이라 87efafb 의 효과로 단정하지 않는다.
- 문서 정본 탭은 87efafb 가 건드리지 않았다. 배포 후에도 같은 화면을 다시 캡처했고(`before/canon-list-default_*`) 로딩은 6.1초 / 5.1초 / 6.5초(1440/360/884 순서)로 배포 전(3.3~3.8초)과 달랐다 — 서버 부하 차이로 보고 같은 화면으로 취급한다.
- 파일을 연 상태(360): 문서 머리말에 `목록` 버튼, 분류 칩(프로젝트·유형·포맷), 제목, **전체 경로**가 이미 있다. 라벨(서버 문서 등)과 경로 복사는 없다.

현황 캡처: `before/` (5개 화면 상태 × 3개 해상도), 원시 측정값 `before/measure_87efafb.json`.
