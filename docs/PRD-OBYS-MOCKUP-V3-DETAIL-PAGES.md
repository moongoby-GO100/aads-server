# 오비서 V3 상세페이지 업무별 전용화 PRD

- 문서 ID: `AADS-OBYS-MOCKUP-V3-DOMAIN-DETAIL-20260921`
- 대상: `/static/apps/obys/mockup-v3.html`
- 상태: 구현 기준 확정

## 1. 문제와 목표

61개 상세 경로가 서로 다른 제목과 요약을 갖고 있으나 조회 조건, 목록 컬럼, 건별 상세, 금액 표시와 실패 복구가 17개 공통 프로필에 묶여 있었다. 이 때문에 재고잔량·근무시간·감사 영향 건수처럼 통화가 아닌 값도 원화로 표시되고, 권한·연동 화면에서 거래용 조회 조건과 승인 CTA가 노출됐다.

목표는 각 상세 경로에 `조회 범위 / 업무 상태 / 검색 대상 / 목록 컬럼 / 값 단위 / 주 행동 / 실패 복구` 계약을 명시하여 실제 API 연결 시 화면별 DTO와 권한을 바로 매핑할 수 있게 하는 것이다.

## 2. 사용자 흐름

1. 첫 진입: 좌측 메뉴의 상세메뉴를 선택하면 해당 업무의 핵심 KPI와 전용 조회 조건이 즉시 보인다.
2. 반복 사용: 기간·업무 범위·업무 상태·검색어로 목록을 좁히고 행을 선택해 원문, 근거, 처리 이력을 확인한다.
3. 실패 복구: 수집형 화면은 재수집/연동 설정, 승인형 화면은 반려 사유/재상신, 문서형 화면은 원본 재업로드, 권한형 화면은 세션/권한 점검으로 연결한다.
4. 모바일: 같은 정보 구조를 카드 목록으로 바꾸되 전용 컬럼 라벨과 값 단위를 유지한다.

## 4. 구현 계약

- 모든 61개 `detailPageDefinitions` 경로는 같은 키의 `detailPageBlueprints`를 가져야 한다.
- 블루프린트는 `profile`, 전용 `scope/status`, `columns`, `valueType`, `cta`, `recovery`를 필수로 가진다.
- `valueType`은 `money/count/duration/quantity/percent/score` 중 하나이며 화면과 드로어에서 동일 포맷을 사용한다.
- 목록 필터와 건별 드로어는 블루프린트를 단일 근거로 렌더링한다.
- 정의 누락은 공통 화면으로 조용히 대체하지 않고 개발 검증에서 실패시킨다.

## 5. 완료 기준

- 61개 상세 경로와 61개 블루프린트가 1:1 일치한다.
- 업무 도메인마다 조회 라벨, 상태 옵션, 값 단위, CTA, 복구 문구가 다르게 렌더링된다.
- 날짜 역전, 빈 결과, 로딩, 오류·재시도 상태가 유지된다.
- 데스크톱 표와 모바일 카드 모두 전용 라벨과 값 포맷을 사용한다.
- 브라우저에서 대표 경로(매출, 계좌, 급여, 재고, 세무, 승인, 연동, 감사)를 열어 콘솔 오류와 잘못된 통화 표기를 확인한다.

## 6. 메뉴 소유권과 중복 정리

메뉴가 같은 자료를 보여도 목적이 다르면 화면을 복제하지 않고 소유권을 분리한다.

| 소유 메뉴 | 책임 | 다른 메뉴에서 허용하는 연결 |
|---|---|---|
| 매출관리 | 매출·주문·카드 승인/취소·정산 대사 | 외부연동의 판매 설정으로 이동 |
| 계좌·입출금 | 잔액·입출금·입금예정·미매칭 | 외부연동의 은행 설정으로 이동 |
| 재고·매입 | 매입처·발주·입고·매입자료 등록 | 외부연동의 매입 설정으로 이동 |
| 세무·회계 | 증빙대장·증빙등록·전표관리·신고납부 | 문서보관함의 원본 파일로 이동 |
| 외부연동 | 인증·수집주기·권한·오류 복구 | 각 업무 메뉴의 현황/등록 화면으로 이동 |
| 문서보관함 | 확정 문서와 원본의 보관·권한·이력 | 처리 업무 화면으로 이동 |

- `판매/은행/매입/세무 연동`은 자동수집 설정만 담당하고 거래 조회·등록을 중복 제공하지 않는다.
- 문서보관함의 `증빙`은 `증빙 원본보관`으로 명시해 세무 증빙대장과 구분한다.
- 공통 집계 카드를 모든 하위 메뉴에 복제하지 않고, 상세 경로별 사업자·거래처·계좌·지점·상태 축을 별도 정의한다.

## 7. 자동연동 실패 시 자료 등록

매출, 카드·주문, 입출금, 입금예정, 매입, 세무증빙 화면은 해당 업무에 필요한 경우에만 아래 복구 진입점을 제공한다.

1. 엑셀·CSV 일괄등록: 양식/원본 선택 → 컬럼 매핑 → 오류·중복·합계 검증 → 임시등록 → 승인.
2. 건별 직접입력: 사업자·일자·자료구분·거래처·원천번호·공급가·세액·합계·원본을 입력한다.
3. 감사 추적: 원본 파일 해시, 업로더, 등록시각, 검증 결과, 승인자를 보존한다.
4. 실패 복구: 오류 행만 내려받아 수정·재등록하고 정상 행은 중복 생성하지 않는다.

등록 화면은 시안 단계에서도 실제 API 연결 계약을 드러내야 한다. 운영 구현에서는 업로드 세션, 컬럼 매핑, 검증 결과, 임시 저장, 승인 API를 단계별로 분리한다.

## 8. 세무 증빙 계약

증빙대장은 사업자·기간·증빙 종류·처리 상태로 조회하며 다음 구분을 최소 지원한다.

- 전자세금계산서, 전자계산서, 현금영수증
- 카드매출전표, 카드매입전표
- 종이세금계산서, 간이영수증, 기타증빙
- 매출/매입 방향, 과세/면세/영세/불공제, 공급가·세액·합계
- 승인·발행번호 중복검사, 거래처 사업자번호, 원본 파일, 전표 연결 상태

건별 등록은 검증 전 임시 상태로 저장하고, `공급가 + 세액 = 합계`, 면세 세액 0원, 원천번호 중복, 사업자 귀속을 확인한 뒤 전표 후보를 생성한다.

## 9. 전표관리 계약

전표관리는 원천세 화면을 재사용하지 않는 독립 업무 화면이다.

| 기능 | 필수 항목 | 통제 |
|---|---|---|
| 조회 | 사업자·기간·발생원천·계정과목·상태 | 일자별 목록→건별 상세 |
| 입력 | 전표일자·적요·차변/대변 계정·금액·증빙 | 차변합계=대변합계 |
| 승인 | 임시·회계검토·대표승인·확정 | 권한·금액 정책 적용 |
| 수정 | 수정전표 또는 역분개 | 확정 원본 직접 덮어쓰기 금지 |
| 마감 | 월 잠금·잠금해제 요청 | 처리자·사유·승인자 감사로그 |

완료 기준은 새 전표 입력, 증빙 연결, 대차 균형 검사, 승인, 확정 전표 역분개가 각각 독립 화면과 복구 경로를 갖고 브라우저에서 동작하는 것이다.

## 10. 실제 페이지 전환 계약

- 목업의 상세 경로 키를 실제 프론트 라우트와 API 권한 키의 기준으로 사용한다.
- 시안 데이터 배열은 API DTO로 교체하되 빈 결과·로딩·오류·재시도·권한 부족 상태를 유지한다.
- 파일 등록은 원본 저장 완료 전 거래/전표를 확정하지 않는다.
- 모든 변경 API는 idempotency key와 감사 이벤트를 남기고, 마감월 자료는 수정 대신 역분개를 기본으로 한다.
- 데스크톱 표와 모바일 카드에서 같은 필터·상태·등록 결과를 확인할 수 있어야 한다.
