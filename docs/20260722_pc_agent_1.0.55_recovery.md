# PC Agent 1.0.55 연결·종료·설치 복구 기록

## 확인된 원인

- 운영 API 릴리스의 PC Agent 버전은 1.0.50이었지만 마지막 Windows 연결은 1.0.52였다.
- 두 updater가 버전을 단순 불일치(`!=`)로 비교해 서버가 낮은 경우에도 업데이트로 판단했다.
- 구형 self-update는 비동기 task 안의 `SystemExit`로 worker 재기동을 누락할 수 있었다.
- 트레이의 Tk 확인창은 pystray callback thread에서 실행되어 Windows에서 버튼 입력이 멈출 수 있었다.
- 배포 서버의 설치 EXE는 2026-05-11 빌드여서 최신 launcher/tray 수정이 포함되지 않았다.

## 조치

- 숫자 버전 비교로 `remote > local`만 자동 업데이트하며 역다운그레이드를 차단한다.
- 손상 복구 다운로드도 같은 버전 또는 상위 버전만 허용하고 VERSION을 0.0.0으로 훼손하지 않는다.
- Windows 완전 종료 확인은 topmost 네이티브 MessageBox를 사용하고 오류 시 종료하지 않는 fail-closed로 변경한다.
- 사용자가 완전 종료를 승인하면 Task Scheduler watchdog을 종료·삭제해 즉시 재기동되는 현상을 막는다.
- PC Agent 버전을 1.0.55로 올리고 Windows GitHub Actions 빌드를 feature/fix 브랜치에서도 실행한다.

## 완료 기준

- 관련 Python compile 및 PC Agent 회귀 테스트 통과.
- GitHub Actions가 Windows x64 EXE를 생성하고 release asset을 게시.
- active/standby 서버의 VERSION, ZIP, EXE가 모두 1.0.55로 일치.
- Windows PC가 1.0.55로 연결되고 heartbeat 및 `system_info` 명령이 성공.
- 트레이 완전 종료에서 아니오는 연결 유지, 예는 agent와 watchdog이 함께 종료.
