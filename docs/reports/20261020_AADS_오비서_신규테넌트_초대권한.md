# 오비서 신규 테넌트 대표의 직원 초대·가입요청 승인 권한

- document_key: `obys-tenant-owner-invite-gate`
- 작업: AADS-OBYS-TENANT-OWNER-INVITE-GATE-20261020-R2
- 정본 등록: **정본 미등록** (이 세션에는 정본 등록 도구가 없다. 열람 링크 미제공)

## 원인

신규 테넌트 대표(E2E-오비서시험A, tenant `1bbc4f60…`)가 '직원 초대·가입 승인' 화면에 들어가면 세 가지가 깨졌다.

1. `app/core/obys_tenant.py` 게이트가 `GET/POST /employees/invites`, `DELETE /employees/invites/{id}` 를 레거시 허용목록 테넌트에만 열어 403 이 났다.
2. `list_join_requests` 가 비레거시 테넌트에는 본인 이메일 요청만 돌려줘 대표의 승인 대기가 0건이었다.
3. `/employees/approved`·`/contracts` 의 403 은 이번 범위가 아니라 그대로 둔다.

## 변경 (STEP 0 분류)

| 대상 | 분류 | 내용 |
|---|---|---|
| `obys_tenant._INVITE_ADMIN_WHITELIST`, `_matches_whitelist` | 신규 | (메서드, fullmatch 경로) 3개: GET·POST `/employees/invites`, DELETE `/employees/invites/{8~64자 id}`. prefix 로 `/employees` 를 열지 않았다. |
| `obys_tenant._is_tenant_scoped_path` | 수정 | 기존 prefix·서명 화이트리스트 판정 뒤에 위 화이트리스트를 OR 로 추가. 기존 판정은 그대로. |
| `_is_legacy_caller` | 신규 | 서비스에서 레거시 여부를 판정하는 얇은 래퍼. |
| `_validated_invite_targets` | 수정 | 비레거시 호출자가 호출자 테넌트 소유가 아닌(또는 매핑 없는) 사업자를 지정하면 403. 대상 없는 payload 는 400. 레거시는 종전 400·빈 목록 유지. |
| `_invite_in_scope` | 수정 | `strict` 인자 추가. 비레거시는 소유 테넌트가 호출자로 확인되는 초대만 통과(귀속 불명 초대는 숨김). 레거시는 종전과 동일. |
| `list_invites`, `revoke_invite` | 수정 | 비레거시는 `strict=True` 로 판정. `create_invite` 는 `_validated_invite_targets` 로 막힌다. |
| `list_join_requests` | 수정 | 비레거시 owner/admin(`_is_admin`)은 `tenant_id == 호출자 테넌트` 인 요청 전체(삭제 제외) + 본인 이메일 요청. 그 밖에는 본인 이메일 요청만. 레거시는 불변. |
| 삭제 | 없음 | 삭제한 코드·테스트 없음. |

설계 판단: 신규 가입자는 직원이라도 자기 개인 테넌트의 owner 라 `_is_admin` 이 참이다. 그래서 대표용 목록에 **본인 이메일 요청을 항상 합쳤다**(고용주 테넌트에 귀속된 본인 가입요청이 사라지는 회귀 방지, `test_obys_employee_join_tenant_scope` 가 잡아냈다). 타인의 타 테넌트 요청은 섞이지 않는다.

DB 스키마·migration·프론트(`admin.html`) 변경 없음. 화면에서 대표가 본인이 다른 매장에 낸 대기 요청을 보면 승인 버튼이 403 으로 거절되는데(서비스가 레코드 테넌트 대조), 동작 오류는 아니라 화면은 건드리지 않았다.
