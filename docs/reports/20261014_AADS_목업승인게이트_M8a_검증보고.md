## 3. 판정 영속화 (할 일 1)

`mockup_gate_decisions` 컬럼: `decided_at`(timestamptz) + `decided_at_kst`(생성 컬럼, KST), `phase`(5종 CHECK), `mode`(off/shadow/enforce CHECK), `allowed`, `blocking`, `shadow`, `reasons`(jsonb), `ui_reasons`(jsonb), `bundle_declared`, `task_id`, `job_id`(`runner-` 로 시작할 때만), `project_key`, `tenant_id`, `review_id`, `revision_id`, `audit_event_id`, `actor`. FK 없음(검토·job·테넌트 행이 사라져도 증거는 남아야 한다).

- 적용 대상이 아닌 작업(번들 선언 없음 + UI 아님, 또는 mode=off)은 행을 만들지 않는다.
- 기록 실패(테이블 미적용, DB 장애)는 로그 한 줄이고 판정은 그대로다. INSERT 는 savepoint 안에서 돈다 — 호출자의 트랜잭션을 abort 시키지 않는다. 실측: 테이블이 없는 DB 에서 기존 통합 20건이 모두 통과했다(§6).
- fail-closed 유지: 선언된 번들 + DB 장애 → `gate_unavailable` 거절. enforce + DB 장애 → 거절. 이 경우 같은 연결은 오염됐을 수 있어 호출자가 새 연결로 재기록한다(`recorded=false` 로 표시).
- `blocking`: submit / pre_execution / checkpoint 의 거절은 기존대로 항상 작업을 멈춘다. chat_write / pre_push 의 거절은 enforce 일 때만 멈춘다(shadow 는 `allowed=false, blocking=false` 로 기록 + 경고).
- migration 은 운영에 적용하지 않았다. 확인: 운영 DB 에 `mockup_gate_decisions` 없음(스키마 덤프, 읽기 전용).

## 4. 채팅 직접 쓰기와 pre-push (할 일 2·3)

**채팅.** `tool_executor` 도 도구 함수를 직접 호출하므로 게이트는 도구 함수 안에 있다. 세션 id → 테넌트를 `resolve_bound_tenant_id` 로 구하고 `task_id=chat:<session>` 으로 `gate_check(phase="chat_write")`. 테넌트를 못 구하면 게이트 장애로 보고 선언 번들·enforce 는 닫힌다. `git_remote_commit` 은 스테이징된 파일 목록(`git diff --cached --name-only`)으로 판단한다. 승인된 번들은 도구의 선택 파라미터 3종으로 선언한다. `patch_remote_file` 은 게이트를 한 번만 타고 게이트 없는 쓰기 본체를 호출한다(이중 판정·이중 기록 방지).

**pre-push.** 훅은 push 되는 각 커밋(머지 커밋 제외)의 변경 파일과 커밋 메시지를 CLI 에 넘긴다. 메시지의 `MOCKUP_REVIEW_ID` / `MOCKUP_REVISION_ID` / `MOCKUP_MANIFEST_HASH` 가 번들 선언이다. 코드 10(거절)·20(판정 불능)은 enforce 에서만 나오고 push 를 막는다. shadow 에서는 노란 경고만 하고 push 를 막지 않는다. 훅은 `timeout 30` 아래에서 돈다.

**설치(이 세션은 `.git/hooks` 로 복사하지 않았다).** 정본은 `scripts/hooks/pre-push` 이고 운영 사본(`/root/aads/aads-server/.git/hooks/pre-push`)은 현재 정본과 다르다. 배포 후 Runner/운영자가 한 번 실행한다.

    cp scripts/hooks/pre-push .git/hooks/pre-push && chmod +x .git/hooks/pre-push

`tests/unit/test_dup_guard.py` 의 정본↔설치본 동기화 검사는 워크트리(`.git` 이 파일)에서는 skip 되고 본체 저장소에서 검사된다. 설치 전에는 그 검사가 실패할 수 있으니 복사 후에 돌린다.

**migration 적용(배포 승인 시).** `psql -f migrations/20261014_mockup_gate_decisions.sql` (멱등, BEGIN/COMMIT 포함). 롤백은 `migrations/rollback/20261014_mockup_gate_decisions.down.sql`.

### 신규 단위 테스트가 덮는 것

## 9. 미지원 경로 (게이트가 보지 못하는 쓰기)

| 경로 | 왜 막히지 않나 |

## 10. enforce 전환 제안 조건 (CEO 승인 사항 — 이 세션은 전환하지 않음)

1. migration 이 운영에 적용되고 `mockup_gate_decisions` 에 shadow 기록이 **연속 7일** 쌓일 것(`recorded=false` 가 0건에 가까울 것).
2. 그 7일 동안 **오차단 0건**: `mode='shadow' AND allowed=false` 인 행을 사람이 전부 검토해 "정당한 거절"임을 확인(오탐은 규칙을 고치고 7일을 다시 센다). 확인용 쿼리 예: `SELECT phase, reasons, count(*) FROM mockup_gate_decisions WHERE allowed=false AND decided_at > now()-interval '7 days' GROUP BY 1,2`.
3. **M6**(백엔드: 실제 목업 검토 생성→수정요청→승인 흐름)과 **M7**(UI 쪽 흐름)이 각각 **운영에서 1회 이상 실사용**되어, 승인된 번들을 선언한 작업이 `allowed=true` 로 기록된 행이 있을 것. M6 의 일회용 DB 증거는 운영 사용 증거가 아니다.
4. pre-push 훅이 운영 저장소에 설치됐고(§4 명령), 위 7일 동안 훅 경고가 최소 1회 이상 기록과 일치함을 확인.
5. 전환은 docker-compose 환경변수 변경이므로 R-DOCKER 에 따라 CEO 승인 후 점검 창구에서 `--no-deps` 단일 서비스로 한다. 롤백은 `MOCKUP_GATE_MODE=shadow` 로 되돌리는 것.
