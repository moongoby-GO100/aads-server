# Company Intelligence HTML 보고서 재사용 가이드 v1.0

## 목적

기업 조사 결과를 단순 요약문이 아니라 외부 공유 가능한 의사결정 문서로 일관되게 제작한다. 회사 홍보자료를 그대로 옮기지 않고 `독립 확인`, `회사 공개`, `미확인`을 분리해 독자가 사실의 강도를 즉시 판단하게 한다.

기준 구현체:

- `app/static/reports/20260909_recolumn_cogcom_company_analysis.html`
- 공개 경로: `https://fb.newtalk.kr/static/reports/{filename}`

## 필수 조사 순서

1. 정확한 법인 식별: 법인명, 대표, 설립일, 사업자번호, 주소, 공식 도메인을 최소 2개 근거로 대조한다.
2. 제품 분해: 기능명이 아니라 입력 → 처리 → 검증 → 출력 → 운영 흐름과 실제 사용자 업무를 기술한다.
3. 사업모델: 구독, 구축, 커스텀, 사용량, 파트너·마켓플레이스, 공공지원 매출을 분리한다.
4. 고객 증거: 로고보다 업무 전후, 사용기간, 처리량, 오류율, 실제 추천인을 우선한다.
5. 경쟁 지도: 직접 제품뿐 아니라 사내 수작업, Excel/VBA, SI, ERP 추가개발 같은 대체재도 포함한다.
6. 리스크: 재무, 보안, 법무, 제품, 운영, 인력, IP를 별도 게이트로 둔다.
7. 실행 권고: “좋다/나쁘다”가 아니라 PoC 범위, 측정법, 통과 기준, 실패 시 대안을 제시한다.

## 근거 등급

| 등급 | CSS class | 의미 | 사용 예 |
|---|---|---|---|
| 독립 확인 | `verified` | 공공기관, 규제기관, 특허, 공식 마켓플레이스, 계약 원문 등 외부 근거 | 법인 설립일, 판매 상태, 특허 출원 |
| 회사 공개 | `claimed` | 공식 홈페이지, 자사 뉴스룸, 고객사례, 대표 인터뷰 | 고객 수, 시간절감, 해외 MOU |
| 미확인 | `unknown` | 공개자료로 확인 불가하거나 계약·원자료가 필요 | ARR, 유지율, SLA, 보안 인증 |

숫자에는 기준일과 출처를 붙인다. 회사가 제시한 `90%`, `100%` 같은 값은 독립 측정처럼 표현하지 않는다. 비공개 재무를 직원 수나 기사 빈도로 역산하지 않는다.

## 권장 목차

1. Executive brief와 한 문장 판정
2. 법인 프로필과 성장 연혁
3. 시장 문제·구매자·사용자·대체재
4. 제품 아키텍처와 기능별 상세
5. 산업별 솔루션·사용자 여정
6. 수익 엔진과 단위경제 가설
7. 고객 증거의 질과 ROI
8. 차별점과 생태계
9. 직접·간접 경쟁사 비교
10. SWOT
11. 보안·법무·재무·운영 리스크
12. 분석가 점수표(주관 점수임을 명시)
13. PoC·제휴·투자 권고
14. 실사 질문 목록
15. 출처·방법론·제한

## 디자인 원칙

- 첫 화면에서 회사, 제품 정의, 기준일, 한 문장 판정을 모두 보이게 한다.
- 긴 보고서는 상단 고정 목차와 섹션 앵커를 제공한다.
- 모바일은 1열, 태블릿은 2열, 데스크톱은 최대 4열 카드로 반응형 구성한다.
- 외부 폰트·프레임워크 없이 단일 HTML로 동작하게 해 장기 보존성과 배포 안정성을 높인다.
- 표는 좁은 화면에서 가로 스크롤되며, 인쇄/PDF 시 상단 메뉴를 숨긴다.
- 색상은 브랜드 장식보다 증거 등급과 위험 우선순위를 구분하는 데 먼저 사용한다.

## 검증 체크리스트

- HTML 파서로 문법 검사
- 인라인 JavaScript 구문 검사
- `git diff --check`
- 시크릿·토큰·내부 비공개 URL 포함 여부 검사
- 모든 외부 출처 링크의 HTTP 응답 확인
- 공개 URL HTTP 200 및 로컬 파일과 공개 본문 핵심 문구 일치 확인
- 데스크톱(1440px)·모바일(390px) 스크린샷 확인
- 출력/PDF 미리보기에서 페이지 잘림 확인
- `HANDOVER.md`에 파일, 공개 URL, 검증, 커밋·푸시·배포 상태 기록

## 갱신 규칙

- 파일명은 `YYYYMMDD_company_product_company_analysis.html` 형식을 권장한다.
- 보고서 본문에 분석 기준 시각(KST)과 버전을 명시한다.
- 재무·가격·경영진·인증·특허 상태는 갱신 때마다 재조회한다.
- 기존 링크를 깨지 않도록 동일 파일을 개정할 때 버전을 본문에 남기고, 대규모 구조 변경은 새 파일로 발행한다.
- 공개자료와 실사자료가 충돌하면 실사자료의 문서명·기준일을 명시하고 정정 이력을 남긴다.
