# 오비서 M1 비레거시 테넌트 세션 직원 판정 수정

## 원인

비레거시 테넌트의 GET /session 은 `tenant_session_for_user` 만 반환했다. 이 함수는 멤버십 role 만 보고 직원 가입요청을 보지 않아, 승인 직원(membership=member)이 `permissions.role=member`, `employee_request_status` 없음으로 내려갔다. index.html 의 `isEmployeeAccount()` 가 false 가 되어 관리자 V4.1 로 이동했다.

## 변경

| 대상 | 분류 | 내용 |
|---|---|---|
| `app/services/yeoljeong_finance_service.py` `employee_request_permissions` | 신규 | 가입요청 1건 → permissions. 기존 `session_for_user` 안에 있던 approved/pending/rejected 규칙을 그대로 추출 |
| 같은 파일 `session_for_user` | 수정 | 추출한 함수를 호출. 응답은 동일 |
| `app/services/obys_upload_service.py` `session_for_current_user`, `_own_employee_request`, `OWN_EMPLOYEE_REQUEST_SQL` | 신규 | 비레거시 /session 전용. 현재 테넌트 + 본인 이메일 + 사업자-테넌트 매핑 조건으로 DB 만 조회(레거시 HR 파일 미접근) |
| 같은 파일 `tenant_session_for_user` | 유지 | `obys_workspaces` 가 권한 판정(role, can_manage_settings)에 쓰므로 건드리지 않음. 바꾸면 직원의 출퇴근 열람 권한이 달라진다 |
| `app/api/obys_finance.py` `get_session` | 수정 | 비레거시 분기를 `session_for_current_user` 로 교체 |

동작 규칙

- 특권 주체(`is_internal_admin`, user_role ceo/admin/system), 멤버십 owner/admin, 이메일 없음 → 조회하지 않고 기존 응답.
- 가입요청 없음 → 기존 응답과 바이트 단위로 동일.
- 가입요청 있음 → 기존 permissions 위에 `employee_request_status`, `employee_request_id`, role 등을 덮어쓴다. user/tenant 와 기존 키는 그대로.
- 조회 실패(DB 오류 등) → 경고 로그를 남기고 기존 멤버십 응답. 로그인 자체를 막지 않는다.
- 삭제한 것 없음.

알려진 한계

- `user.is_admin` 은 바꾸지 않았다. 레거시는 가입요청 role=admin 인 직원에게 true 를 주지만, 비레거시는 멤버십이 쓰기 권한의 원본이라 응답 permissions 만 맞췄다.
- 테스트 계정 m1-staff1 은 자기 테넌트 owner 라 직원 검증 계정으로 부적합하다(기록만).
