# 리뷰어 보존 하드게이트 — 정확한 되돌리기(REVERT_OF) 예외

document_key: aads-review-exact-revert-exemption

## 배경
GO100 runner-aeeaba38 의 순수 revert(1 추가 / 1,579 삭제)가 `_precheck_preservation_gate` 순삭제 비율 차단(FLAG 0.3)에 걸렸다.
지시된 삭제를 하는 revert 가 구조적으로 항상 막히면 우회가 습관이 되므로, 좁고 검증 가능한 예외만 둔다.

## 면제 흐름
1. **지시서 표식**: `REVERT_OF: <sha 7~40자>` 한 줄. 사용 예시 — `REVERT_OF: b4dda431f`
2. **러너 검증** (`scripts/pipeline-runner.sh::revert_of_verified_json`): sha 를 전체 sha 로 풀고,
   `git show <sha> | git patch-id --stable` 와 `git diff HEAD <base> -- <sha 가 건드린 파일들> | git patch-id --stable`
   (이번 작업 diff 의 역패치)를 비교한다. 정확히 같을 때만 `{"sha","patch_id","files"}` 를 낸다.
   sha 를 못 찾거나 한 줄이라도 다르면 빈 출력이다. 비교 대상은 sha 가 건드린 파일 집합뿐이라 결과 문서 등
   추가 파일이 섞여도 비교에 영향이 없다.
3. **요청 payload**: 러너가 `/api/v1/review/code-diff/requests` 본문에 `revert_of_verified` 를 추가한다(검증 성공 때만).
4. **리뷰어 면제** (`code_reviewer._precheck_preservation_gate`): 요청에 `revert_of_verified` 가 있고 지시서 REVERT_OF sha 와
   접두 일치할 때만, `files` 에 든 파일 구간을 순삭제 비율·삭제 심볼 판정에서 뺀다.
   - 메타: `preservation_exempt_reason="exact_revert"`, `preservation_exempt_sha`, `preservation_exempt_patch_id`,
     `preservation_exempt_files`, `preservation_exempt_lines` (code_reviews.feedback 에 저장)
   - LLM 검수·범위 게이트·임계치(`_PRESERVATION_NET_REMOVAL_*`)는 그대로다. 그 외 파일의 변경은 종전 게이트가 판정한다.

## 알려진 한계
- 검증 요청은 러너의 **최초 검수** 경로에만 실린다. `retry_review`·rebase 재검수 경로는 플래그를 싣지 않아 종전 게이트 그대로다(후속 필요 시 확장).
- `git patch-id --stable` 은 공백 차이를 무시한다. 공백만 다른 되돌리기도 일치로 본다.

## 재작업 1/2 — AI 리뷰 반려 지적 처리

1. **출처 보증(P1)**: `/api/v1/review` 는 JWT 면제라 요청 본문을 믿지 않는다. 러너가 검증 성공 시 `pipeline_jobs.revert_of_verified` 에 `{sha,patch_id,files}` 를 DB 로 직접 기록하고, `app/api/code_review.py::_attest_revert_of_verified` 가 요청의 sha·patch_id 가 그 기록과 같을 때만 **기록의 값(files 포함)** 을 리뷰어에 넘긴다. 기록이 없거나 다르면 종전 게이트(fail closed). 마이그레이션에 `pipeline_jobs.revert_of_verified` 컬럼 추가(적용은 기존 마이그레이션 경로).
2. **JOB_DIFF_EXCLUDE_SPECS(P1)**: `revert_of_verified_json` 이 원본 커밋의 파일 목록·patch-id 계산에 같은 제외 스펙을 적용한다. 테스트: 산출물을 복원·재작성해도 코드 revert 는 일치.
3. **LLM 프롬프트(P1)**: 면제가 적용되면 프롬프트에 `[정확한 되돌리기 면제]` 고지를 넣어 해당 파일 구간 삭제를 보존 FLAG 근거로 쓰지 않게 한다. 다른 구간은 종전 기준. 테스트가 프롬프트 전달을 확인한다.
4. **인용 경로(P2)**: `_diff_header_paths` 가 git 인용·8진수 이스케이프·공백 경로를 해석한다(모호한 rename 은 None=미면제). 한글·공백 경로가 실제 리뷰어 면제까지 가는지 테스트.

검증: `bash scripts/run_unit_tests.sh` — exact_revert_exemption 22, net_removal_gate 15, private_symbol_exemption 40, patch_file_false_positive 9, cross_file_move 17 모두 통과. `ruff --select F821,F811` 통과.
