## 7. 한계와 절충 (숨기지 않는다)

1. **shim 대기가 작업 하나의 일반 슬롯을 점유한다.** 무거운 명령이 대기하는 동안 그 작업은 진행하지 않는다. 대기 상한(`RUNNER_MARKET_HOURS_HOLD_MAX_WAIT_SEC`, 기본 1800초)을 넘으면 명령을 **실행하지 않고** `exit 75` 로 끝나며 stderr 에 `MARKET_HOURS_DEFERRED … 실행하지 않았습니다` 를 남긴다. 검증이 "통과"로 오인되지 않게 하려는 선택이다. 대안은 작업 단위 보류(claim 단계에서 막기)이며, 이번에는 일반 작업 상한(§3-2)이 그 역할을 일부 한다.

4. 대기 중이던 작업이 15:30 에 한꺼번에 풀리면 순간 부하가 몰릴 수 있다(추정). 기존 서버 상한과 heavy lane 슬롯이 그것을 받는다.


적용 순서(승인 후, 점검 창구 또는 장 마감 후 권장):

1. 코드가 contabo14 러너에 들어갔는지 확인한다(커밋·푸시 후 기존 러너 동기화 경로). 이 작업은 동기화를 하지 않았다.
2. 휴장일 파일을 두고(§5) 연도 날짜가 들어 있는지 확인한다.
3. drop-in 을 설치한다.
4. `systemctl daemon-reload` 후 러너 유닛에 환경을 반영한다. 러너는 실행 중 작업을 자식으로 가지므로 반영 방식(재시작 가능 여부, 기존 재적재 절차 유무)은 contabo14 에서 확인하고 승인받아 정한다. 이 작업에서는 확인하지 않았다. 실행 중 작업을 끊는 방식은 쓰지 않는다.
5. 로그에서 `MARKET_HOURS_ENTER`(장중) 또는 `MARKET_HOURS_EXIT` 와 `MARKET_HOURS_POLICY` 를 확인한다.

실행 중 작업이 보존되는지 확인하는 방법:

- 적용 직전 `running`/`claimed` 작업 id 목록을 저장하고, 적용 후 같은 id 가 `running` 으로 남아 있는지, 해당 프로세스 PID 가 그대로인지 본다.
- 이 변경은 claim 의 WHERE 조건과 새 shim 호출만 바꾸므로 기존 프로세스를 신호로 건드리는 코드는 없다(`test_nothing_is_killed_or_updated_by_the_gate`, `test_runner_apply_never_signals_processes`).

롤백(빠른 순):

1. drop-in 을 삭제하고 `daemon-reload` 후 다음 루프에서 반영 — 15초 안에 hold 가 지워진다.
2. 파일을 지우기 곤란하면 `RUNNER_MARKET_HOURS_GATE=0` 으로 바꾸고 같은 방식으로 반영.
3. 코드 자체를 되돌려야 하면 이 커밋을 revert 한다.

정책 행(`runner_host_policy`) 지원이 필요한가: 이번 구현은 환경변수 기반이라 **필요 없어 migration 초안을 만들지 않았다.** 호스트별로 DB 에서 장중 제한을 켜고 끄고 싶다는 요구가 생기면 그때 `migrations/drafts/` 에 초안만 두고 적용은 승인 후로 한다.

## 11. 파일 겹침과 정본 등록

- 같은 시기 러너 `runner-f0e2a7a5`, `runner-14b5eae4` 와 겹치는 파일은 `scripts/pipeline-runner.sh` 와 `.local` 쌍 하나뿐이라고 본다(이 작업의 변경 파일과 비교). 같은 파일을 동시에 고치면 rebase 충돌이 나므로 먼저 푸시되는 쪽 기준으로 나중 쪽이 다시 맞춘다. `HANDOVER.md` 는 수정하지 않았다.
- R-DOC: 이 문서는 `project_document_heads` 에 **등록하지 않았다.** 운영 DB 쓰기가 금지된 작업이라 `scripts/index_docs.py` 를 실행하지 않았고, 커밋·푸시 후 색인 경로에서 초안으로 올라가야 한다. 현재 상태는 **정본 미등록(미완료)**, **열람 링크 미제공**이다.

## 12. 교훈

- 새 동작을 기존 함수 안에 넣으면, 그 함수만 추출해 돌리는 테스트가 새 함수를 못 찾아 깨진다. 새 호출은 기능 플래그 뒤에 두면 꺼짐 상태가 이전 동작과 같다는 것을 구조로 보장한다.
- "main 에 0건"처럼 브랜치 이름만 믿으면 낡은 로컬 브랜치를 본다. 운영 SHA 와 `origin/main` 을 먼저 맞춰 봐야 한다.
- 기존 긴급 정의가 대부분을 포함하면 새 게이트는 열려 있는 것과 같다. 긴급 기준은 코드보다 먼저 통계로 확인한다.
