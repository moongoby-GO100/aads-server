## H2 급여 연결 지점 (설계만, H2 코드 미수정)

H2 근태 기반 급여 초안은 4대보험·원천세를 계산하지 않는다. 급여명세 `tax_withholding` 을 채울 때는
`compute_withholding(income_kind, base_amount)` 하나만 호출한다. 호출하는 쪽이 소득 구분을 명시해야 하고,
`WithholdingUnverified` 가 나면 해당 칸을 채우지 않고 "검증 필요"로 표시한다. 근로소득 간이세액표가 검증되기 전에는 급여명세에 원천세 숫자를 넣지 않는다.

## P-15 운영 읽기 점검

- 읽기 전용 SELECT 1회를 `acct` DB 에 시도했으나 `permission denied for database "acct" — User does not have CONNECT privilege` 로 거부됐다.
- 권한 부여(GRANT)는 운영 DB 쓰기이므로 하지 않았다. **행 수는 확인하지 못했다(미확인).**
- 운영 후속(운영 담당): ACCT 앱 계정에 `acct` DB CONNECT·SELECT 권한을 부여하거나, `acct` 접근 권한이 있는 계정의 DSN 을 `.env` 의 `ACCT_APP_DATABASE_URL` 에 주입한다. DB 이름이 `acct` 가 아니면 `ACCT_LEDGER_DB_NAME` 을 설정한다.
- 이 때문에 `acct_purchase` 전표 조회의 운영 동작은 **검증되지 않았다**. 단위 테스트는 라우팅(어느 DB 로 연결하는가)만 확인한다.

## 알려진 위험·제약

- `_scope_business` 는 레거시 테넌트가 `yeoljeong_businesses` 에서 기본 사업자(biz-mia)를 소유한다고 가정한다. 운영 데이터에서 확인하지 못했다.
- 원천세 신고 생성·계산은 이제 `income_kind` 가 필수다. 기존 호출자가 생략하면 계산 대신 "검증 필요"가 나간다.
- 접수 정보는 마이그레이션 없이 `details` JSONB 에 저장한다(운영 DB 쓰기 금지, 마이그레이션 자동 적용 안 됨). 전용 컬럼이 필요하면 별도 작업이다.
- 일용근로·근로소득 원천세는 막혀 있다. 조문 확인 후 `WITHHOLDING_RULES` 에 상수와 출처를 추가하면 열린다.
- 동결 기본값이 true 라 `OBYS_JOURNAL_WRITE_FROZEN=false` 로 바꾸기 전에는 세금신고·분류규칙 쓰기가 409 를 낸다(전표 쓰기와 같은 범위).
