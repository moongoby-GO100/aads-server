## 리뷰 지적 처리 (라운드 1/2)

1. [P1] 권한 오류 형식 불일치 — 수정. 수집기가 실제로 저장하는 `clobe:permission_denied`(`_run_kind`), `permission_denied`(`_preflight` 의 CollectionError), `permission_denied:<상세>`(연결 행)를 정규식 `^(?:clobe:)?permission_denied(?::|$)` 로 모두 받는다. `startswith("permission")` 은 없앴다. 테스트는 `ClobePermissionDenied` 를 실제로 만들어 `_run_kind` 와 같은 방식(`f"clobe:{str(exc)[:40]}"`)으로 코드를 만든 뒤 매핑을 확인한다(`test_permission_denied_is_mapped_from_the_code_the_collector_really_stores`).
2. [P1] 세션 열기·사전 점검 실패가 상태에 안 남는 문제 — 수정. 이 경로는 종류별 상태 행을 쓰지 않으므로 `company_status` 가 회사 단위 원인을 따로 읽는다. 클로브 연결 상태(`clobe.get_status()["reauth_required"]`, 3초 제한·실패 시 False)와 연결 회사의 `permission_ok=FALSE`(`_preflight` 가 거부 시 기록)를 보고, 있으면 이전 수집 성공 여부와 무관하게 모든 종류 카드의 `next_action` 을 재연결/권한 요청으로 덮는다. 첫 수집이어도 "아직 수집 전"이 아니라 실제 원인이 나온다. 기존 `status`·`last_error_code` 등 필드는 그대로다.
3. [P1] 캡차·CSV 경로 — 구현. 코드가 없다는 가정이 틀렸다: 클로브가 알려주는 원천 기관 실패 분류(`failureCategory`)가 실행 기록 `counts.scrape.failure_categories` 에 저장되어 있다. `company_status` 가 `source_scrape_error` 상태의 마지막 실행 기록에서 이를 읽어(`_scrape_failure_categories`, 쿼리 1회) `next_action` 에 넘긴다. 분류에 CAPTCHA/OTP 가 있으면 `solve_captcha`, 캡차가 아닌데 2회 연속 막히면 `upload_file`(CSV 직접 올리기 + 다시 시도). 저장 `error_code` 는 바꾸지 않았다(기존 문구·통합 테스트 유지).

## 리뷰 지적 처리 (복구 라운드: 업로드 대상 회사 고정)

[P1] 수집 화면에서 회사 B 를 보는데 설정에 A 가 선택돼 있으면 B 용 CSV 가 A 원장에 들어가던 문제 — 수정.

- `clobe-collection.js`: `upload_file` 버튼이 `selectedCompany()` 의 `business_id`·회사명을 `data-business-id`·`data-company-name` 으로 싣고 새 액션 `go-upload` 를 보낸다. 핸들러가 `pinUploadTarget(view, businessId, 회사명)` 으로 대상을 기억한 뒤 화면을 이동한다(탭이 없으면 즉시 해제). `window.obysClobe.uploadTargetFor(view)`·`releaseUploadTarget(currentView)` 를 노출한다.
- `index.html`: 업로드 패널은 `ledgerUploadScope(panel)` 로 대상을 정한다. 넘겨받은 값이 있으면 그 `business_id` 만 쓰고(설정 선택값 무시), 없으면 기존 `selectedSettingsBusinessId()` 그대로다. 고정된 패널에는 `대상 회사: <회사명>` 을 표시하고, 목록 조회(`/uploads`·`/uploaded-ledger`)와 전송(`business_id`)이 모두 같은 값을 쓴다. `setView` 가 매번 `syncLedgerUploadTargets()` 로 다른 화면으로 이동하면 고정을 해제하고 패널을 원상태(설정 선택값 기준)로 되돌린다.
- 대상 미확정(`business_id` 비어 있음): 파일 입력·업로드 버튼을 비활성화하고 `대상 회사를 먼저 선택하세요` 를 표시하며, 강제로 호출돼도 전송하지 않고 같은 안내 토스트를 띄운다.
- 고정은 해당 화면(accounts → 거래내역 패널, sales → 매출 패널)에만 적용되고 다른 패널·일반 업로드 경로는 바뀌지 않는다.

테스트(`test_obys_clobe_ui_static.py`): 실제 `clobe-collection.js` 와 `index.html` 의 업로드 함수를 node 로 실행한다. 설정 A·수집 B 에서 렌더된 버튼 클릭 → 업로드 요청 `business_id` 가 B, 목록 조회도 B, 화면 이탈 뒤에는 A(일반 경로), 대상 미확정이면 요청 0건·안내 표시를 확인한다. 전송 쪽 코드를 설정 선택값으로 되돌리는 변형을 넣으면 이 테스트가 실패함을 확인했다.
