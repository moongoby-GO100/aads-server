## 4. 설계 결정과 한계

- change set 은 목표 단위 1건(90건 개별 승인 방지). 승인 경로는 `ceo` 하나로 줄였다 — 이 목표에 독립 검수 역할 보유자가 없고, CEO 결정이 범위를 명시하기 때문이다(기본 A3 경로의 `independent_reviewer` 는 이 경로에서 사용하지 않음).
- 롤백은 version 을 1로 되감지 않고 단조 증가시킨다(ABA 방지). 90개 ID, draft 상태, `created_by` 는 복원되고 version 은 +2 가 된다. 이 경로가 만든 배정만 종료하며, 기존 보유 배정은 종료하지 않는다.
- 롤백 기록은 별도 change set 행(state=executed)으로 남고 원 change set 은 `revoked` 가 된다.
- **한계 1** — 변조 차단 이벤트(`patch_tamper_blocked`)는 오류 응답과 같은 트랜잭션에서 롤백되어 남지 않는다. 기존 M14 실행 경로도 같은 구조이며 이번에 바꾸지 않았다. 차단 자체(409, 부작용 0)는 테스트로 확인했다.
- **한계 2** — 격리 Postgres 는 superuser 로 접속하므로 RLS 정책은 이 시험이 검증하지 못한다. tenant 격리는 쿼리 조건과 FK 로 확인했다.
- **한계 3** — 운영 API 엔드포인트 호출 경로(JWT 인증·`member_dependency`)는 격리 환경에서 실행하지 않았다. 서비스 함수와 엔드포인트 존재는 시험했고 HTTP 계층 통합은 미실행이다.
