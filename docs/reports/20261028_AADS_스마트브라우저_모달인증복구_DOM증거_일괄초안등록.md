## 2. DOM 증거 artifact 의 묶음과 차단

artifact 는 `browser_artifacts` 행(`artifact_type='dom_evidence'`)이며 다음을 해시로 묶는다: tenant, chat session, agent, 대상 호스트, url(마스킹), captured_at, expires_at(기본 15분·최대 60분), run id, browser session id, work key, route, 검증 assertion, 스크린샷 sha256.

| 시도 | 결과 코드 |
|---|---|
| 서버가 발급하지 않은 id | `dom_evidence_not_found` |
| 다른 테넌트 | `dom_evidence_not_found` (조회가 테넌트로 걸러진다) |
| 다른 세션 | `dom_evidence_session_mismatch` |
| 만료 | `dom_evidence_expired` |
| 다른 대상 호스트 | `dom_evidence_target_mismatch` |
| 행 변조(세션·만료 연장 등) | `dom_evidence_hash_mismatch` |
| 호출자가 주장한 url/스크린샷/시각이 저장값과 다름 | `dom_evidence_claim_mismatch` |
| 등록 verify 가 관찰된 assertion 과 다름 | `dom_evidence_assertion_mismatch` |

- `artifact_id` 를 낸 호출은 검증에 실패해도 자기신고(`screen_verified=true`)로 내려가지 않는다.
- `artifact_id` 없이 `screen_verified=true` 만 낸 호출은 기존처럼 승인 대기 초안으로만 등록되고, 증거에 `trust="self_reported"` 가 붙는다. 서버 발급분은 `trust="server_issued"`. 조회 요약의 `evidence_trust` 로 승인자가 구분할 수 있다. 승인·자동승인 정책은 건드리지 않았다.
- 원본 DOM·쿠키·입력값은 저장하지 않는다. 자기신고 증거는 허용 필드만 남기고 url 은 마스킹한다.
- 서버 헤드리스 경로는 `browser_session_id`/`work_key` 가 없어도 사내 호스트에서 발급된다. 외부 도메인은 PC 레인(브라우저 세션 지정)이 필요하다.

## 3. M13(runner-3b7c1ef4) 반려 결함 재발 방지

1. 실행 원천은 요약·절단된 `input_params` 가 아니라 호출 원본 `inp` 이다. 1,500자 url 과 다중 파일 upload 가 원문 그대로 저장되는 테스트를 넣었다.
2. upload 의 `file_path`/`file_paths` 는 `value` 로 변환하고 `extra` 에서 제거한다. `value` 와 충돌하면 거부한다.
3. 서버 헤드리스 경로를 `browser_session_id`/`work_key` 부재만으로 일괄 거부하지 않는다.
