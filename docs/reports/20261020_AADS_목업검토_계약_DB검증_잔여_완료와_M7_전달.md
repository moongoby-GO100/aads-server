## 3. 이번에 추가한 검증 (`tests/integration/test_mockup_reviews_postgres.py`)

1. `test_approval_and_revoke_retries_are_idempotent_and_old_versions_cannot_approve`
   - 같은 idempotency_key로 승인 2회 → 두 번째는 200·`idempotent:true`, 같은 `approval_id`, `approved` 이벤트 1건, generation 3 유지.
   - 같은 키로 다른 본문 → 409 `idempotency_key_conflict`.
   - 같은 키로 회수 2회 → 두 번째 멱등, `revoked` 이벤트 1건, generation 4.
   - AC-M17: v1 카드를 열어 둔 채 v2 제출 후 v1 승인 → 409 `stale_revision`, 응답에 최신 revision id, `approved` 이벤트 0건. v2 승인 후 v1 재승인도 409, 승인 이벤트 총 1건, 승인본은 v2.
2. `test_mockup_create_change_revise_approve_and_reread` (생성 → 수정요청 → 수정 → 승인 → 재조회)
   - 수정요청 접수는 `approved:false`이고, 접수 뒤 v1 승인 시도는 409이며 승인 이벤트 0건이다.
   - v2는 `approval_inherited:false`, draft 상태에서 승인 시도 409, 제출 후 승인 200.
   - 재조회: 승인본 revision·manifest_hash·approval_id가 v2와 일치. v1은 manifest_hash 불변이고 `is_approved:false`. v2의 parent는 v1.
   - 수정요청 원문(앞뒤 공백·개행 포함) 보존, 기준 r1·신규 r2 링크, 결과 `applied`와 사유 저장.
   - 이벤트 순서: created, revision_created, submitted, changes_requested, revising_started, revision_created, submitted, approved.

두 테스트 모두 `AADS_MOCKUP_TEST_DATABASE_URL`(이름에 `test`가 없으면 거부)로 연결하며 테스트가 만든 행만 정리한다.

## 7. M7에 전달하는 API 계약·테스트 근거

기준 경로 `/api/v1/projects/{project}/mockup-reviews`. 권한: read(조회), write(생성·판본·제출·수정요청·검증), approve(`/approve`, `/revoke`).

| 호출 | 핵심 계약 |
|---|---|
| `POST ""` | 생성. idempotency_key 재전송 시 200·`idempotent:true`, 다른 본문이면 409 |
| `POST /{id}/revisions` | expected_generation 필수. 불일치 409 `generation_conflict`, `archive_if_stale`이면 202로 보관만(포인터 불변). 새 판본은 `approval_inherited:false` |
| `POST /{id}/submit` | latest revision만 제출. 증거 누락 422 `missing_artifacts`, 변조 409 |
| `POST /{id}/changes` | change_request_id + source_message_id + base_revision_id. 원문 보존, `approved:false`, `implementation_command:false` |
| `POST /{id}/revising` | changes_requested일 때만. 이후 판본의 `resolves`로 요청별 `applied`/`not_applied`+사유 필수(누락 422) |
| `POST /{id}/approve` | `confirm:true`, revision_id·manifest_hash·expected_generation 일치 필요. 오래된 판본 409 `stale_revision`(최신 revision id 포함) |
| `POST /{id}/revoke` | approval_id 일치 필요. 불일치 409 `stale_approval` |
| `POST /{id}/verify` | 실행 직전 번들 재검증. 거부 시 409와 사유 목록, 거부 이벤트는 감사에 남음 |
| `GET /{id}`, `/revisions/{rid}`, `/change-report` | 재조회. 승인본은 `approved_revision{revision_id,manifest_hash,approval_id}` |

테스트 근거 위치: `tests/integration/test_mockup_reviews_postgres.py`(17건), `test_mockup_chat_flow.py`(5건), `test_mockup_gate_decisions_postgres.py`(4건). 재현은 §5의 방식(운영 스키마 덤프 → 일회용 DB → `AADS_MOCKUP_TEST_DATABASE_URL`)이다.
