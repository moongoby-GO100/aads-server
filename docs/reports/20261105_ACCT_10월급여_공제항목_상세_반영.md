1. **[P1] "5행 모두 합계 조건을 만족시킬 수 없었다" 단정** — 타당. 결론을 "항목별 금액 검증 불가"로 고쳤다. 앞 4명은 "남는 금액(소득세+지방세)"이 존재할 뿐 그 타당성을 판단할 표가 없다는 것까지만 주장한다.

## 3. 확정 행(홍석빈) 규칙

`save_payroll` docstring: "확정(confirmed)·지급(paid) 명세는 덮어쓰지 않고 새 버전(draft)으로만 고친다." payload 에는 `version: 1`, `root_id`, `confirmed_at`(2026-11-05T12:06:58+09:00), `confirmed_by` 가 있다. SQL 로 payload 만 바꾸면 이력·확정 시점 내용이 어긋나므로 쓰지 않았다. 올바른 경로는 새 버전 draft 로 항목을 채운 뒤 재확정이다(관리자 승인 필요).

## 4. 백업과 되돌리기 SQL

쓰기 0건이므로 되돌릴 대상이 없다. 전체 `statement_payload` 는 DB 원본 그대로이고(변경 전·후 동일) 이름·이메일 등 개인정보가 있어 이 보고서에 옮기지 않았다. 향후 쓰기 시 사용할 형식:

```sql
BEGIN;
-- 쓰기 전 백업: SELECT id, updated_at, statement_payload FROM yeoljeong_payroll_statements WHERE id IN (...);
UPDATE yeoljeong_payroll_statements SET statement_payload = <새 payload>
 WHERE id = '<id>' AND updated_at = '<백업 updated_at>';   -- 각 UPDATE 가 정확히 1행이어야 COMMIT
-- 되돌리기: 같은 형식으로 백업 payload 를 id + (새 updated_at) 조건으로 복원
COMMIT;
```
