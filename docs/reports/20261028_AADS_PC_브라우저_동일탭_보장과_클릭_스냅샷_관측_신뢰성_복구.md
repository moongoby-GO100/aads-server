## 3. 동일 탭 보장

- 응답에 target 이 실려 오면 서버 페이지가 그것을 고정한다. 이후 명령은 같은 `target_id` 를 보내고, 다른 탭의 응답은 `TARGET_MISMATCH`(`retry_safe=False`) 로 거절한다. 고정된 target 은 조용히 바뀌지 않는다.
- PC 쪽은 명시 target 이 없거나 URL 호스트가 다르면 명령을 보내지 않고 거절한다.
- 두 페이지(두 work_key)는 서로 다른 target 을 유지한다.

## 4. 클릭 신뢰성과 엄격 셀렉터

- `dispatched`(입력 전달) 와 `verified`(기대 후조건 확인) 를 분리했다. `expect` 키: `url_contains`, `url_changed`, `text_present`, `text_absent`, `selector_visible`, `selector_absent`, `checked{selector,value}`.
- `verification_state`: `verified` / `failed` / `observed_change` / `no_observed_effect` / `unknown`. `observed_change`(변화는 있었으나 기대와 무관) 도 verified 로 치지 않는다.
- 기대 후조건이 틀리면 `CLICK_NOT_VERIFIED`(dispatched=true). 사용자에게 "[클릭 완료]" 는 verified 일 때만 쓴다.
- 클릭·다운로드·키 입력은 복구 재전송 대상에서 제외했다. 불확실한 외부 쓰기를 자동으로 다시 누르지 않는다(`dispatch_state=uncertain`).
- 셀렉터 오류 코드: 래퍼 DIV(`text=`) → `ELEMENT_NOT_ACTIONABLE`, 0건 → not found, 여러 건 → ambiguous(`nth` 로 지정), disabled, 숨김, 가려짐(obscured).

## 5. 스냅샷 관측

- PC·서버 모두 실제 target + `location.href` + DOM 상태를 합쳐 읽는다. 비밀번호류 입력은 `[filled]` 로만 표시한다.
- 문서 교체(`Execution context was destroyed`) 시 최대 3회 제한 재시도, 실패하면 `SNAPSHOT_UNSTABLE`. 로딩 중이면 마지막 읽기에 `stable=false` 를 붙인다. target 불일치는 재시도하지 않는다.
- 세션 상태 `last_url` 은 http(s) 실제 URL 로만 갱신한다. `about:blank` 등은 덮어쓰지 않는다.
- 본문 텍스트는 "ARIA 접근성 트리가 아닙니다" 로 명시한다.

## 6. CDP 재사용과 진단 예산

- 시간을 handshake / attach / command / queue / diagnostics 로 분리해 응답에 싣는다.
- 실패 진단은 성공 경로에서 반복하지 않는다.
- **CDP 연결 재사용은 구현하지 않았다.** RAM·지연의 인과는 측정하지 않았으므로 주장하지 않는다. 분리된 시간 값으로 다음 측정이 가능하다는 것까지만 확인했다.

## 7. 스크린샷 참조

- 같은 target 을 촬영해 저장소에 PNG 를 쓰고 참조(artifact id) 만 돌려준다. base64 본문과 새 이동은 없다.
- 읽기: tenant 불일치·없음·만료·변조·경로 이탈·tenant 누락은 모두 `not_found`. 저장 시 session_id/work_key 가 있고 호출자가 같은 값을 보낸 경우에만 추가 대조한다(하드 경계는 tenant).
- 저장 URL 은 query/fragment 를 제거한다. 화면 픽셀 자체의 비밀 마스킹은 불가능하다(비밀번호 입력란은 브라우저가 마스킹해 그림).

## 9. 알려진 한계

- 스크린샷 저장소는 API 슬롯(blue/green)별이다. 슬롯이 바뀌면 이전 참조는 `not_found` 가 된다.
- 세션/work_key 대조는 호출자가 값을 보낸 경우에만 적용된다.
- `page.click`(레시피 경로)은 non-strict 로 남겼다.
- 스크린샷이 DATA 본문을 갖지 않아 레시피의 스크린샷 증거 자동 기록은 더 이상 적용되지 않는다.
- 의미 검색(semantic)은 날짜 필터를 적용하지 않는다(응답에 안내 문구를 추가).
