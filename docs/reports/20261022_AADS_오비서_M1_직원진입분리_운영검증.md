## 1. skip 1건의 정체

tests/unit/test_obys_employee_skip_v41.py 에서 skip 되는 것은 test_shouldOpenV41App_return_values_in_node 하나다.
조건은 skipif(NODE is None, reason="node 미설치 런타임") 이다.

- 운영 런타임 이미지(aads-server)에는 node 가 없다. docker exec 로 확인: node 없음.
- scripts/run_unit_tests.sh 는 이 이미지로 돌므로 항상 이 테스트를 건너뛴다. 이 러너 호스트에는 node 가 있어 host pytest 로 7 passed, skip 0.
- 영향: 나머지 6건은 index.html 문자열 검사다. 계정 유형별 반환값(관리자/직원/미리보기/초대 링크 등)을 실제로 실행해 보는 유일한 테스트가 게이트에서 빠져 있다.
- 다만 이 테스트가 통과해도 이번 FAIL 은 잡지 못한다. 이 테스트는 permissions.role 이 employee 로 들어온다고 가정하고 함수를 돌리는데, 실제 서버가 그 값을 주지 않는 것이 문제다.

운영 판정에는 영향이 없다(skip 이 PASS 를 만들어 주지 않았다). 게이트 관점에서는 node 를 이미지나 테스트 마운트에 넣어야 행동 검증이 돈다.

### 2-1. 판정 기준 (스크립트 judge)

PASS 는 화면 URL·제목만으로 내지 않는다. 아래를 모두 만족해야 한다.

- 공통: POST /auth/login 200, PC·모바일 양쪽에서 GET /session 200 응답이 있고 비정상(401 등) 응답이 없음, 로그인 게이트(authGate)와 세션 복구 화면(loginRecoveryBtn, "로그인이 필요합니다")이 없음, 모바일 캡처 존재.
- 관리자: /session 에 owner/admin 권한(또는 is_admin·can_manage_settings) 응답이 있고 PC·모바일 모두 admin.html + 제목 V4.1.
- 직원: /session 에서 role=employee 또는 employee_request_status=approved 가 확인되고, owner/admin/can_manage_settings 응답이 섞이지 않으며, PC·모바일 모두 admin.html·V4.1 이 아니고 onboarding 또는 직원 서류 제목이 보임.
- 로그인 전 자격증명 조회 실패는 그 계정만 '미실행'으로 기록하고 fallback·관리자·JSON 리포트는 계속 진행한다.

## 3. 원인 (실측)

### 3-1. m1-staff1 은 직원이 아니다 (테스트 계정 문제)
읽기 전용 SELECT(acct-pg, obys_auth DB)로 확인했다.

- m1-staff1: 자기 테넌트 cf4d829b 의 owner, active. 직원 가입 요청 행 없음. 이 계정이 V4.1 로 가는 것은 정상이다.
- 이름과 달리 "직원 계정"이 아니므로 직원 검증용으로 쓸 수 없다.

### 3-2. m1-staff2 는 승인된 직원인데도 V4.1 로 간다 (제품 결함 후보)
- obys DB 의 yeoljeong_employee_join_requests 에 테넌트 1bbc4f60 · 상태 approved · role employee 인 행이 있다. tenant_memberships 에도 1bbc4f60 member/active 가 있다.
- 그런데 운영 GET /session 응답은 다음과 같다(권한 요약만 기록, 토큰·이메일 제외).

| 계정 | role | employee_request_status | can_manage_settings | tenant |
|---|---|---|---|---|
| m1-staff2 | member | 없음 | false | 1bbc4f60 |
| m1-owner-a | owner | 없음 | true | 1bbc4f60 |

- index.html 의 isEmployeeAccount() 는 role 이 employee·employee_pending·employee_rejected 이거나 employee_request_status 가 있을 때만 직원으로 본다. 서버가 member 를 주므로 false 가 되고, shouldOpenV41App() 이 true 가 되어 admin.html 로 이동한다.
- app/api/obys_finance.py 의 get_session 은 is_legacy_obys_tenant 가 아니면 tenant_session_for_user 를 부른다. 이 함수는 멤버십 역할(owner/admin/member/viewer)을 그대로 돌려줄 뿐 employee_join_requests 를 보지 않는다. 직원 역할(employee)을 만드는 session_for_user(yeoljeong_finance_service)는 레거시 테넌트에서만 호출된다.
- 따라서 M1 의 "직원은 V4.1 로 가지 않는다"는 레거시 테넌트에서만 성립하고, 신규(SaaS) 테넌트의 직원에는 적용되지 않는다.

### 3-3. 후속 과제 (이번 작업에서 하지 않음 — 앱 코드 수정 금지)
- 비레거시 테넌트 /session 이 직원 가입 요청(approved)이 있는 member 에게 permissions.role=employee 와 employee_request_status 를 주도록 하는 서버 수정이 필요하다.
- 수정 후 이 스크립트를 다시 돌려 m1-staff2 가 PASS 로 바뀌는지 확인한다.
- 단위 테스트 게이트에 node 를 포함시켜 1절의 skip 을 없앤다.
- m1-staff1 을 직원 fixture 로 쓰려면 owner 멤버십을 직원 가입 승인 형태로 바꿔야 한다(쓰기 작업, 별도 승인).

- 빌드·배포·재시작·Apache 라우팅은 건드리지 않았다.
- DB 조회는 모두 READ ONLY 세션이었다.
- 직원 로그인 후 "계약서·서류" 화면 자체의 렌더링(onboarding)은 직원 계정이 V4.1 로 가는 탓에 운영에서 확인하지 못했다.

## 6. 자동 재작업(AI 리뷰 반려) 처리

1. [P1] 관리자 PASS 가 인증 성공을 보장하지 않음 — 수정. 로그인 HTTP 200, PC·모바일 /session 200 + owner/admin 권한 응답, 게이트·세션 복구 화면 부재를 모두 요구한다. 세션 401 + 같은 URL·제목은 FAIL 로 확인.
2. [P1] 직원 판정이 신원·권한을 확인하지 않음 — 수정. session_responses 로 role=employee/approved 를 요구하고 owner 세션이면 FAIL, 모바일 authGate 노출도 FAIL. 일반 제목('계약서'·'서류')만으로는 통과하지 못한다. owner 세션 + '계약서 관리' 제목은 FAIL 로 확인.
3. [P2] 자격증명 조회 실패가 전체 실행을 중단 — 수정. 계정별 '미실행'으로 기록하고 fallback·관리자 검증·JSON 저장을 계속한다. 직원 종합 판정은 PASS > FAIL > 미실행 순이다.
