## 근본 원인

GO100 갱신 스크립트가 "이미 실행 중"이면 exit 0 으로 끝났다. 상위 스크립트는 이를 성공으로 읽고 로그에 success 를 적었으며, 같은 공유 산출물을 KIS 에 재발행했다. skip 이 성공·신선도 증거로 둔갑한 것이다. 또 적재(ingest) 실패도 exit 0 이었다.

## 범위 1 — 스케줄러

- 종료코드: 0 성공 / 1 실패 / **7 skip(성공 아님)** / 8 적재 실패. 장중(평일 08:00~15:40 KST) 회피는 우회 옵션이 없다.
- 상태: `<STATE_DIR>/scheduler/<PROJECT>.json`, 저장소 안이면 거부(exit 2). 비밀값 미저장. 원자적 쓰기. 손상 파일은 `corrupt` 로 분류.
- 중복 실행: flock + owner/pid/heartbeat. 죽은 pid 의 owner 는 인수, 살아 있으면 skip. owner 를 잃으면 exit 3.
- freshness 증거는 `last_success_at` 뿐이다. skip·실패는 덮어쓰지 않는다(테스트로 고정).
- catch-up: 마지막 성공이 기준 시간을 넘으면 due 로 표시. 장중이면 대기.
- 게이트 모듈이 깨지면 스캔하지 않고 실패(fail-closed).
- 다른 프로젝트: 전체 스크립트에서 GO100 skip 시 GO100·KIS 만 skipped, 나머지 동작 유지.
- 확인된 한계: 테스트 주입용 `AAG_SCHEDULER_STATE_PY` env 로 스케줄러 스크립트 경로를 바꿀 수 있다. 운영에서 환경변수 설정 권한이 있으면 게이트를 대체할 수 있으므로 운영 unit/cron 환경에 이 변수를 두지 않아야 한다.

## 범위 2 — `GET /api/v1/aag/v2/operations`

- 인증·권한: 사용자 JWT, 프로젝트 RBAC(viewer/proposer/approver/admin), v2 flag. 권한 없음은 타입드 403 `insufficient_permission`, 스냅샷 조회 이전에 거부.
- 응답: `schema_version=aag-operations-v1`, `axes{freshness,last_run,debt,coverage}`, `recovery_actions`, `limitations`(공유 계약 그대로).
- 계산 규칙: 실제 포인터 스냅샷(ready·authoritative·verified·커밋 일치)에서 계산. 미측정은 unknown. 0/0 은 100% 가 아니라 null. 재적재된 낡은 artifact 는 `verified_at` 이 최신이어도 `generated_at` 으로 stale 판정.
- last_run: `aag_scan_runs` 최신 행. succeeded/no_change_success→success, scan_failed/ingest_failed→failed, skipped_locked→skipped, 60분 초과 running→running_stale, 수집 불가→unknown.
- recovery_actions: `request_rescan` 은 항상 `enabled=false`, "승인 필요" + 근거만 표시. **실행 엔드포인트 없음**(테스트로 고정).
- 타입드 오류: 400 `invalid_query`, 404 `snapshot_not_found`, 503 `schema_unavailable`, 503 `operations_unavailable`(DB 내부 메시지 비노출).
- 한계: API 는 호스트 상태 파일을 읽지 못하므로 last_run 은 DB 기록 기준이다(응답 `limitations` 에 항상 명시). `aag_finding_exceptions` 는 부채에서 차감하지 않는다(명시).

## 교훈

- "skip" 을 종료코드 0 으로 표현하면 상위 합성 로직이 반드시 성공으로 읽는다. 세 번째 상태를 별도 코드로 두고 상위가 해석하게 해야 한다.
- 재적재는 `verified_at` 을 갱신하므로 `verified_at` 만으로 freshness 를 판단하면 낡은 산출물이 신선해 보인다.
- 테스트가 운영과 같은 고정 경로(락·임시 파일)를 쓰면 호스트에서 운영과 경합한다. 경로는 env 로 주입 가능해야 하되, 주입 수단 자체가 우회 수단이 되지 않도록 운영 환경에 두지 않는다.
