| 경로 | owner | admin | member | viewer |

| 급여·직원·인사문서·변경이력·접근기록·연동·은행/매출/세무 연결 | 허용 | 허용 | 403, 메뉴 숨김 | 403, 메뉴 숨김 |

- `gross_pay` 는 "총지급액"으로만 표시. 기본급·수당은 원천이 없으면 "미산출", 공제는 세 원천 키가 모두 있을 때만 값 표시, 아니면 "미산출". 이미 구현·운영 중이라 재구현하지 않았다.
- 비라일론 승인 3행의 화면·API·SELECT 대조: **미수행**(자격 없음·운영 읽기 권한 없음). 개인 급여 원문은 이 보고서·로그에 싣지 않았다. 후보 E2E 는 합성 값만 사용.
- 잔여 위험: 레거시 `index.html` 급여 표는 과세 대상 금액이 없을 때 0원으로 보일 수 있다. U1 범위에서는 재현·수정하지 않고 U2 입력으로 남긴다.

## 6. 재현된 결함과 최소 보완

- **증상**: 레거시 오늘 홈의 5지표(매출·입출금·검토·급여·승인)가 응답이 200 이어도 "불러오는 중"에 머묾.
- **원인**: `init()` 이 저장된 화면 상태가 없을 때 `setView`(홈 집계의 유일한 트리거)를 호출하지 않았다. 또 실패·렌더 예외 시 카드를 종결하지 않았고 복구 행동이 없었다.
- **보완**:
  1. `init()` 에서 저장 화면이 복원되지 않았고 현재 화면이 오늘 홈이며 서버 로그인 상태면 `loadTodayHome()` 호출.
  2. 카드별 실패를 오류 상태로 종결하고 `다시 시도`, 404·403 계열은 `관리자 화면 열기` 행동 제공. 미종결 카드는 `.catch`/미로그인 분기에서 일괄 종결. 직원 체험 모드에서는 호출하지 않음.
  3. 404 는 "찾을 수 없습니다", 403 은 권한 안내, 401 은 로그인 안내 문구.
- **재현하지 못한 것**: 운영 owner 세션에서 보고된 "서버응답오류 404"·"레거시접근권한없음" 의 실제 원인 경로는 운영 로그인 없이 재현할 수 없었다. 후보 모킹은 404/403 을 흉내낸 것이며 운영 원인 확정이 아니다.
