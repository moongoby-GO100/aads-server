**필요한 최소 조치: 아래 중 하나를 CEO 가 승인.**

- **A (자격증명 1쌍, 변경 없음)** — 비내부 tenant 의 member(역할 무관)로 현재 로그인 가능한 이메일+비밀번호 1쌍을 Vault(`e2e_credentials` 해당 행)에 갱신. 이후 `/auth/login` → `GET /api/v1/project-docs/search?q=<파일럿 제목>` 와 `GET /api/v1/projects/AADS/documents` 를 1회씩 호출해 **정본 0건·403** 을 확인한다. 쓰기 없음.
- **B (임시 grant 1행)** — 위 계정(또는 같은 tenant 의 비관리자 member) 한 명에 `project_document_grants` 한 행(예: `<TENANT_ID>`/`ACCT`/`<USER_ID>`/`read`)을 승인받아 만든다. 허용 확인 → 삭제 → 차단 재확인 순서.

재현 순서(승인 후):
1. 사전: `select count(*) from project_document_grants` = 0 기록, 대상 `user_id`·`tenant_id` 기록.
2. grant 전: 대상 신원으로 로그인 → 정본 목록 403 `project_access_denied` 또는 검색 결과에 `canonical://` 0건.
3. 허용: 아래 INSERT → 같은 호출에서 200·정본 노출.
4. 복구: 아래 DELETE → 같은 호출에서 다시 차단, `count(*)` = 0 으로 원복 확인.

```sql
-- 승인된 값으로만 채운다. 이 보고서는 실행하지 않았다.
BEGIN;
INSERT INTO project_document_grants(tenant_id, project_key, user_id, access)
VALUES ('<APPROVED_TENANT_ID>'::uuid, '<APPROVED_PROJECT>', '<APPROVED_USER_ID>', 'read');
COMMIT;

-- 복구(롤백 스크립트): 같은 PK 한 행만 지운다.
BEGIN;
DELETE FROM project_document_grants
 WHERE tenant_id='<APPROVED_TENANT_ID>'::uuid AND project_key='<APPROVED_PROJECT>'
   AND user_id='<APPROVED_USER_ID>' AND access='read';
-- 기대: DELETE 1, 이후 select count(*) from project_document_grants = 0
COMMIT;
```

복구 보증: grant 행은 PK `(tenant_id, project_key, user_id, access)` 로 유일하고 다른 데이터에 연쇄 영향이 없다. 복구 실패 시 위 DELETE 를 반복해도 안전하다(멱등).
