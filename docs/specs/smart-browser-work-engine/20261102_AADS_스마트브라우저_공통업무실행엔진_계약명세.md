## 2. 계약 구조와 검증 범위

contract-v1.json은 JSON Schema draft 2020-12다. 루트는 Request이며 $defs에 Request/Ticket/Error/Checkpoint/Observation/ActionPlan 및 하위 객체를 둔다. DTO의 additionalProperties=false, required, recipe_ref/task_intent 배타 oneOf, ActionPlan의 action/plan 배타 oneOf를 validator로 검사한다. inputs/safe_values만 레시피 선언에 따른 동적 맵이므로 SafeValue 재귀를 허용한다. 임의 추가 DTO 필드를 허용하는 우회로 쓰면 안 된다.

Request의 contract_version은 정수 1이다. recipe_ref는 UUID id·semver version·64자리 소문자 SHA256 hash를 요구한다. 요청은 inputs/location 필수, recipe_ref 또는 task_intent 정확히 하나다. Idempotency-Key는 HTTP 헤더 또는 MCP/SDK 인자로 분리한다. collection rev4의 1~128자 규칙 재사용은 초안이며 일반 실행의 길이 정책은 B1/B3 확인 대상이다. 본문 tenant/project/principal/session_id·평문 secret 필드는 거부한다. user project selector는 인증된 별도 문맥에서 grant에 재검증한다. credential_refs는 vault: 참조만 받으며 실제 Vault 해석·권한을 schema가 보증하지 않는다.

location은 server+device_id=null 또는 pc+비어 있지 않은 device_id다. limits의 시험 기본 상한은 50 action/600초/LLM8회/100페이지/depth3/1000URL/10000행/20MiB이며 관리자 축소만 허용한다. READ 일시오류 재시도2회, selector 복구 후보2회, 쓰기·인증 불명 결과 재시도0회는 런타임 gate다. allow_partial 기본 false의 적용은 서비스 책임이며 JSON Schema default는 값을 삽입하지 않는다. payload의 hash는 semantic inputs+version+location+limits를 canonicalize해 계산한다. inputs는 선언 레시피 schema에 대해 추가 필드 거부·타입 검증 후 해시하고 selector/domain/credential/risk 덮어쓰기를 차단한다.

Ticket은 설계 §7 최소 예시 필드를 required로 삼고 PRD의 phase/current_step/reason_code/result_ref/evidence_refs/retry_after는 선택 확장한다. 실제 허용 status는 queued/running/waiting_auth/waiting_approval/waiting_device/paused/needs_reconciliation/succeeded/partial/failed/cancelled다. terminal resume 금지, 단조 event_seq, reconciliation 후에만 queued 재진입은 DB·서비스 시험 대상이다. schema의 enum 검사만으로 상태 전이를 입증하지 않는다.

Error는 성공 Ticket과 별도 envelope다. PRD 오류 목록과 설계 §6의 cursor_expired를 허용한다. HTTP 상태·권한 우선순위·retry 결정은 서비스 책임이다. Checkpoint는 검증 단계·recipe hash·context fingerprint·비민감 값/artifact·후조건·증거·시각을 요구한다. raw secret, 인증 원문, 임의 scope 추가는 허용하지 않는다.

Observation은 설계 §8의 origin/url/document_revision/tab/frame/DOM·AX/screenshot/visible controls/page_state/timestamp/redaction manifest를 고정 필드로 표현한다. ActionPlan은 action 하나 또는 최대50개의 plan이며 안정 target_ref·evidence·postcondition·risk·confidence를 요구한다. action/risk 허용값은 현재 WorkRecipe schema의 12종/RISK_LEVELS를 재사용한다. URI format은 SSRF 검사가 아니다. 관측 target 일치·origin/IP 검사·revision 변경 시 재관측·승인 범위·foreground·fence는 별도 dispatch 전 검증이다.

미확정 wire 결정: DOM/AX 요약의 상세 구조, redaction manifest 항목 형식, phase vocabulary, recipe별 입력 schema, plan별 action payload 해석은 rev1에 완전한 wire 정의가 없다. 본 문서의 최소 DTO는 검토 초안이다. B1/B3/B4가 실제 adapter와 상호 검증하고 새 계약 판본을 등록하기 전 외부 공개/실계정 dispatch를 차단한다. Observation·ActionPlan을 임의 raw selector/action payload로 자동 실행하지 않는다. model fallback도 동일 validator·permission gate를 거친다. 중앙 call_llm_with_fallback()·Auth Token 우선 정책을 유지한다.

## 3. 추가 권한 경계 — PM-C1

## 5. 보존기간 종료와 재실행 차단 — PM-C3

collection의 기존 24시간 응답 cache와 외부 effect 중복방지 원장을 구분한다. cache/receipt/응답 본문이 만료됐다는 이유만으로 과거 key/command를 새 dispatch로 취급하면 안 된다. 원래 승인도 새 동작 승인으로 재활용하지 않는다. 과거 외부쓰기의 수행 여부가 불명하면 needs_reconciliation과 읽기 대사/기존 사람 확인 경로로 전환하고 자동 재클릭·새 key 발급은 0회다.

필수 최소 비민감 식별 근거는 scope/principal/key digest, request hash, command/execution 안전 참조와 effect state다. 원문 입력/secret을 넣지 않는다. 보존기간·tombstone 삭제 조건·정확한 만료 HTTP code는 rev1에 확정되지 않았으므로 임의 TTL 또는 새로운 오류 enum을 확정하지 않는다. 안전한 중복 식별 근거가 없으면 실행을 거부/차단하고 정책 추가결정 및 대사를 요구한다. unknown은 needs_reconciliation, payload 충돌은 409 idempotency_conflict, 권한 취소는 원래 403/404를 먼저 적용한다. 확정 결과의 본문만 소실된 경우에도 새로운 execution/outbox/command를 생성하지 않는 만료 응답 정책을 B1/B3의 새 판본에서 확정해야 한다.

PM-C3-T1: 24h 직전/직후·receipt/artifact GC 전후·동일 key 동시 재전송·payload 변경을 시험해 신규 execution/outbox/command/외부 dispatch 증가0을 확인한다.
PM-C3-T2: succeeded/failed/cancelled/unknown, ACK 소실·worker 재시작·revoke 조합에서 권한 우선·unknown 대사·최소 digest 유지·민감 원문0을 확인한다. B1/B3 담당, V1 전체 GC 회귀; not_run이다. 보존기간·GC 안전기준이 결정되지 않으면 해당 정리 기능과 외부쓰기 재개를 활성화하지 않는다.

참고로 같은 호스트의 별도 PM rev2 자료는 무기한 digest tombstone 및 idempotency_result_expired 제안을 포함한다. 이것은 고정 rev1 번들의 일부가 아니며 이번 미러·오류 enum에 자동 반영하지 않았다. B1 runner-2c77a119의 PM_REV2_BINDING_cd38d591 배정에서 최신 정본 ID/hash·검토 결과·PM-C1~C3를 대조하고 동일 계약 key의 새 초안으로 갱신 후 인수한다. rev1 D0 산출물과 rev2의 자동 일치를 주장하지 않는다.
