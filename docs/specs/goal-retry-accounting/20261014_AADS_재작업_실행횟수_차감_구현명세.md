## 1. 결정

재작업 한도 2회는 **제안/승인/시작이 아니라 실제 모델 호출 직전**에 차감한다.

| 단계 | 차감 | 비고 |
|---|---|---|
| 후보 제안(proposal) | 아니오 | 10분 백오프·failed_task_id 당 3회 제한은 그대로 |
| 승인 | 아니오 | 승인만으로는 소모 없음 |
| 러너 start (`started_at`) | 아니오 | 관찰값일 뿐 |
| 대기·스캔·claim·relay 슬롯·의존성 대기·시작 전 reject/cancel·만료·중복 카드/큐 | 아니오 | |
| codex / litellm / claude 호출 직전 | **예** | job_id 기준 원자·멱등 |

대안 A(`started_at` 에서 차감)는 모델을 부르기 전에 취소되어도 한도가 소모되므로 채택하지 않았다.

## 2. 장부

`goal_retry_executions` (additive 마이그레이션 `20261014_goal_retry_execution_ledger.sql`)

- `UNIQUE(tenant_id, job_id)` — 같은 job 은 두 번 차감되지 않는다(멱등).
- `UNIQUE(tenant_id, milestone_id, lineage, slot)`, `slot CHECK 1..2` — 동시 실행 경합에서도 3번째 행은 DB 가 거부한다.
- `lineage` = RETRY 사슬의 루트 failed_task_id. `RETRY_OF_LINK:` 줄을 최대 5단계, 같은 tenant 안에서만 따라간다. 재작업의 재작업이 새 예산을 만들 수 없다.

`charge_goal_retry_execution(job_id, cap)` → jsonb `outcome`:
`not_retry | job_not_found | tenant_missing | milestone_missing | scope_mismatch | charged | already_charged | cap_exceeded`

- 줄 머리에 있는 `RETRY_OF_LINK:` 만 재작업으로 센다. `SUPERSEDES` / `AUTO_REWORK_OF` 는 차감하지 않는다.
- tenant 가 맞지 않거나 장부를 쓸 수 없으면 fail closed.

## 3. 러너 훅

`scripts/pipeline-runner.sh` 의 `retry_execution_charge_or_abort` 를 세 모델 실행 지점 직전에 호출한다. 지시문에 `RETRY_OF_LINK` 줄이 없으면 DB 를 건드리지 않는다. `cap_exceeded` 이거나 장부가 불가하면 모델을 부르지 않고 중단한다.

## 4. 제안·후보·큐

- `ensure_retry_candidate`: 유효한 active/completed 후속을 먼저 확인하고, 소진 판정은 lineage 기준 실제 실행 수로 한다.
- `enqueue_next_step_reaction`: `skipped_stale / failed / cancelled` 큐는 재사용하지 않는다(T12: 죽은 큐는 재사용 제외, 새 큐 생성. 고유 후보는 distinct card_id 로 세므로 교체 큐는 새 id, 죽은 큐는 이력으로 남는다).
- `deferred_reaction_freshness.annotate_or_skip`: 재작업 본문 안의 실패 job id(`retry_target_ids`)는 stale 대상에서 제외한다. 일반 stale 가드는 약화하지 않는다.
- 릴리스 게이트 AADS 의 `release_certified` 단계 없는 `done` 은 활성 후속으로 센다.

## 5. 읽기 모델

`attach_retry_accounting`, `split_dispatch_note`, `archive_exhaustion_note` (DB 변경 없음, 완료 마일스톤의 소진 문구는 이력으로 분리하여 현재 블로커에서 제외).

표시 문구: `고유 후보 N · 실제 실행 M/2 · 남은 한도 K · 다음 행동 …` (0회는 `실행 없음 0/2`).

## 6. 하지 않은 것

- 전역 한도 상향, 완료 상태/실패 증거 삭제 없음.
- 과거 52 마일스톤 / 14 목표 일괄 정리 없음(범위 밖). 백필이 필요하면 실제 모델 호출 증거 + 좁은 트랜잭션 + before/after SELECT + 롤백 메모가 있어야 한다.
