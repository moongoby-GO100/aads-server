# 오비서 V4.1 잔여 결함 보완 · 검증 계약

대상: 대표님 계정의 열정국밥·라일론 조회 및 기존 로그인 URL 사용자를 위한 운영 화면.
범위: 로그인 진입/조직 전환, 라일론 매입 집계와 오래된 건별 상세. 기존 원본 데이터 수정·자동 수집 신규 구현은 포함하지 않는다.

## 동작 계약

- 기본 진입 및 과거 `index.html?legacy=1#auth-login` 북마크는 인증 후 V4.1로 이동한다. 명시적인 `legacy=1&view=legacy` 경로는 기존 화면을 유지한다. 계약서·초대·검증된 업무 redirect를 보존한다.
- V4.1 조직 선택은 `/auth/tenants`의 실제 유효 소속만 보여 준다. 전환은 기존 `/auth/tenants/{id}/switch`의 권한 검증과 token 발급을 사용한다. 사업자 선택을 초기화하고 새 조직의 자료만 다시 조회한다. 오류 시 기존 조직을 유지한다.
- ACCT 매입 집계는 중복 제거 후 전체 기간의 건수/금액을 SQL window로 계산한다. 2,000건 조회 상한을 전체 건수로 오인하지 않는다. 오비서 수기·업로드 자료는 별도 원천으로 더한다. 표는 최대 500건 표시이고 전체 집계와 구분한다.
- 건별 원문은 현재 사업자 소유권 확인 후 식별자로 직접 조회한다. 최근 2,000건 밖의 이전 날짜 자료도 열려야 한다. 타 사업자·잘못된 식별자는 404, 원천 장애는 오류로 표시한다.
- 매출 원천이 없는 것을 전체 실적 0원으로 해석하지 않는다. 원천 미적재 표시와 로컬 등록 건을 분리한다. 원천 미적재 해소는 별도의 실제 자료 적재가 필요하다.
- 사용되지 않는 데모 처리 함수의 거짓 저장 완료 문구를 제거한다. 전표 수정/승인/역분개가 구현됐다는 뜻이 아니다.

## 근거 및 검증

- `query_project_database(ACCT)`로 실제 신규 집계 SQL 실행: 라일론 회사 11 매입 4,210건 / 5,390,990,031원. 이 금액은 중복 제거된 위하고 원천 합계이며 오비서 수기분 제외.
- 원천 `ty_mth` 값 2/3만 확인, 매출 분류 1 없음. `ty_mth2`도 매입 분류만 확인했다.
- 관련 단위테스트 24개 통과. 전체 합계+로컬 합산, 이전 자료 단건조회, 타 사업자 거부, 식별자 SQL 주입 차단을 포함한다.
- `node --check`: 두 HTML의 모든 인라인 스크립트 문법 검사 통과. `git diff --check` 통과.
- 화면 검증은 운영본과 로컬 수정 HTML을 구분해서 기록한다. 운영에 배포되지 않은 화면을 배포 완료 근거로 사용하지 않는다.

## 현재 운영 차단 및 배포 조건

- 열정국밥·라일론 조직은 `tenants.deleted_at`이 설정되어 소속 조회에서 제외된다. 기본 조직은 열정국밥으로 저장돼도 내부 조직으로 돌아간다. 삭제가 별도 사용자 지시인지 확인 전 임의 복구하지 않는다.
- 기존 배포 5095는 `7b2c75e3bde1`의 `success_partial`이다. P0/P1 300초 관제는 통과했지만 green에 현재 채팅 실행이 남아 같은 이미지 동기화가 지연된다. 기존 systemd 재시도 작업이 실행 중이다.
- 새 코드 완료 조건: 정확한 SHA 원격 반영 → clean worktree bluegreen → 후보 health → routed health → 양 슬롯 같은 digest → 5분 관제 → 실제 화면 확인. 게이트를 우회하거나 진행 중 채팅을 종료하지 않는다.
- DB 핸드오버 정본 키: `obys-completion-reconcile-20260922`. 최종 커밋·배포·조직 복구 상태는 해당 정본의 검증 결과를 따른다.

## 롤백

코드 문제는 직전 인증 이미지로 bluegreen 라우팅 복구한다. 신규 DB 스키마 변경은 없다. 조직 복구가 승인되면 두 ID만 조건부 트랜잭션으로 처리하고 기존 deleted_at 값을 보존하여 되돌릴 수 있게 한다.
