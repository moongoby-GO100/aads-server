# AADS 실행 슬롯 반영 판정 설계

| document_key | `aads-live-slot-verification-20261006` |
- 오류 사전: `runner.live_gate.accepts_stopped_container`
- 범위: AADS API의 Runner 소스 판정. GO100 systemd 서비스의 반영 판정은 포함하지 않는다.
- 상태: 구현·검수용 저장소 문서. 소스 전달과 운영 설치·인수는 별도이며 정본 문서 등록은 이 변경에서 수행하지 않는다.

## 확인된 결함

기존 `aads_release_live_verdict`는 두 컨테이너의 `Config.Image` 태그가 요청 SHA를 포함하면 `live`를 반환했다. 만들어 놓고 시작하지 않은 실제 Docker 컨테이너도 같은 태그이면 성공했다. 이 기록은 시험용 컨테이너에서 확인한 소스 반례이며 운영 장애 발생 증거가 아니다.

컨테이너 실행·health·실제 활성 슬롯을 확인하지 않아, 정지된 슬롯이나 아직 트래픽이 향하지 않는 후보도 완료로 기록할 수 있었다. `aads_finalize_deploy_queued_jobs`도 같은 함수를 호출하므로 최초 완료와 후속 완료 양쪽에 영향을 준다.

## 변경된 판정

세 읽기 함수가 판정 자료를 모은다.

1. `aads_live_route_snapshot`: AADS nginx 설정에서 `aads_api`의 단일 활성 `127.0.0.1:8100` 또는 `8102`를 구하고 `.active_port`·`.active_container`와 비교한다. 없거나 모호하거나 지원하지 않는 주소이면 거부한다. 설정·마커의 원문 해시를 함께 반환한다. FIFO 등 일반 파일이 아닌 입력과 크기 제한 초과 입력은 거부하고 읽기 프로세스를 5초로 제한한다.
2. `aads_live_container_snapshot`: Docker를 한 번 inspect하여 ID, Running, Status, Paused, Restarting, Health, 실제 이미지 ID, 이미지 태그, StartedAt, 재시작 횟수와 PID를 얻는다. 실행 중이고 정상 health이며 멈춤·재시작 상태가 아니어야 한다. 실제 이미지 ID와 해당 태그의 로컬 image-inspect ID가 같아야 한다. digest나 health가 없으면 허용하지 않는다. 각 Docker 호출은 5초로 제한한다.
3. `aads_live_slot_snapshot`: 활성 슬롯의 직접 health와 기존 `AADS_API_URL`의 라우팅 health를 읽는다. HTTP 성공뿐 아니라 `status=ok`·`graph_ready=true`를 요구한다. 각 요청의 연결 제한은 2초, 전체 제한은 4초다. health 전후의 라우팅·마커 해시와 컨테이너 ID·시작 시각·PID·이미지·상태가 모두 같아야 한다. 달라지면 재확인이 필요한 상태로 거부한다.

라우팅 파일의 일치가 nginx 메모리에 로드된 설정의 원자적 증명은 아니다. 이 검사는 기존 배포 제어 계약 아래 설정·마커와 현재 health를 함께 관측하고 변경 중인 자료를 거부한다. API health 응답 자체에 릴리스 SHA 증명이 없으므로, HTTP 응답만으로 이미지의 출처를 주장하지 않는다. 태그가 가리키는 image ID와 컨테이너 image ID의 일치는 로컬 Docker 태그 결합 검증이며 빌드 공급망 증명은 아니다.

## 두 호출 경로의 서로 다른 계약

`aads_release_live_verdict`는 위 조건을 통과한 **활성 슬롯 한 개**의 태그만 SHA 포함 여부를 검사한다. 기존 정확 태그 또는 Git 조상 관계를 유지한다. 활성 슬롯이 새 릴리스를 제공하면 standby가 옛 릴리스인 동기화 대기 상황도 인정한다. 반대로 standby만 요청 SHA를 포함하면 완료하지 않는다.

`approved_sha_is_live`는 같은 관측 검사를 추가로 사용하면서 기존의 더 강한 조건을 유지한다. 성공·completed인 AADS production API 배포 기록, 유효한 릴리스 SHA, 요청 SHA의 조상 관계, 인증된 image digest, `standby_digest=image_digest`, 기록된 슬롯과 현재 활성 슬롯의 일치를 모두 요구한다. standby 동기화가 미완인 릴리스를 이 인증 경로로 통과시키지 않는다.

## 실패와 호출자 호환성

- stdout의 `live:<container>`, `queued:<run_id>:<status>`, `not_live:<run_id>:<status>` 형식을 유지한다.
- 실행·라우팅·health 정보가 없거나 일치하지 않으면 `live`를 반환하지 않는다. 진단은 stderr의 `AADS_LIVE_UNKNOWN`으로 표시한다.
- 기존 배포 기록이 queued/running/verifying/syncing_standby이면 기존대로 `queued`를 반환한다. 그 밖에는 `not_live`가 된다.
- 최종 처리 함수의 상태 조건·원자 UPDATE·중복 알림 방지·대기 만료 정책은 변경하지 않는다.
- `instruction_forbids_deploy`, maintenance/drain, HOLD controller, GO100/KIS 등 다른 프로젝트의 배포 분기는 변경하지 않는다.

## 검증과 운영 경계

정식 회귀 시험은 실제 Bash 함수와 임시 Git 저장소·라우팅 파일을 사용한다. Docker/HTTP probe 스키마 fixture로 정지·불건강·미기동·health 없음·digest 불일치·미라우팅 후보·잘못된 SHA·모호한 라우팅·health 실패 및 전후 변경을 검증한다. 기존 완료/대기/인증 시험은 관측 입력을 제공하도록 조정하며 성공·실패 기대값은 약화하지 않는다.

별도 실제 Docker 시험은 소유 임시 컨테이너만 생성·제거하여 never-started, unhealthy, healthy/wrong-SHA, healthy/correct-SHA를 비교한다. 운영 컨테이너·서비스·라우팅 변경은 수행하지 않는다. 원래 반례와 고친 소스의 결과를 각각의 SHA에 연결한 영수증으로 보존한다.

전체 attempt fencing, legacy Runner bootstrap, 운영 런타임 설치 및 배포 인증 완료는 이 소스 수정의 완료 조건과 구분한다.
