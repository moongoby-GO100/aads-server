## 1. 배경과 문제

현재 기능은 오비서 운영 화면, ACCT 매입 화면, 업로드 API, 은행 API, 직원/급여 API와 개별 PRD에 분산되어 있다. 목표에는 문서가 연결되지 않았고, 매출·매입·은행·카드가 동일한 상세/등록 경험을 갖지 못한다. 직원계약·근태·급여도 같은 직원 정본과 상태 흐름으로 연결되어야 한다.

## 2. 제품 목표

1. 사업자별 핵심 업무를 한 로그인과 한 내비게이션에서 수행한다.
2. 모든 재무 건은 파일이 아니라 건별 원장으로 조회·등록·정정할 수 있다.
3. 직원 가입부터 급여 지급/분개까지 상태와 근거가 연결된다.
4. 사용자에게 현재 상태, 오류, 승인 필요, 재시도를 같은 맥락에서 보여준다.
5. tenant/company 격리를 화면·API·DB에서 중복 강제한다.

### 비목표

- 본 버전에서 외부 은행 이체를 자동 실행하지 않는다.
- 법률·세무 판단을 모델이 자동 확정하지 않는다.
- 운영 데이터를 목업 샘플 데이터로 대체하지 않는다.
- 기존 ACCT 원장을 오비서 DB로 합치지 않는다.

## 7. 완료 수용 시나리오

1. owner가 4개 사업자를 전환해 같은 메뉴를 유지하고 각 사업자 데이터만 본다.
2. 재무 담당이 4종 원장을 각각 1건 등록하고 상세에서 수정/정정 이력을 확인한다.
3. 같은 파일/요청을 재전송해도 원장·분개 중복이 생기지 않는다.
4. 다른 사업자의 목록, 단건 ID, 파일 URL을 호출하면 모두 403이다.
5. 직원 1명이 가입→서류→계약 검토→서명을 완료하고 새로고침 후 상태가 유지된다.
6. 직원 2명의 근태를 마감해 급여를 계산하고 명세서·지급자료·ACCT 분개 합계가 일치한다.
7. 각 흐름을 1440px와 390px에서 캡처하고 console/page error 0을 확인한다.
