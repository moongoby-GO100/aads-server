## 1. 한 문장 목표

대표자가 한 번 로그인해 사업자를 전환하면서 매출·매입·은행·카드·직원계약·근태·급여를 조회·등록·승인하고, 모든 확정 결과가 같은 `tenant/company` 축의 ACCT 원장으로 이어지는 경영관리 서비스를 만든다.

## 2. 대상 사용자와 핵심 업무

| 사용자 | 첫 진입에서 해야 할 일 | 반복 업무 | 실패 시 복구 |
|---|---|---|---|
| 대표자(owner) | 사업자 선택 후 오늘의 미처리 확인 | 손익·자금·승인·급여 확정 | 오류 항목에서 원인·재시도·담당 확인 |
| 재무/회계 담당 | 미분류 거래와 증빙 확인 | 매출·매입·은행·카드 등록·대사 | 임시저장 복구, 중복 경고, 원본 재열람 |
| 점장(manager) | 자기 사업장 현황 확인 | 발주·입고·근태 승인 | 권한 요청 또는 대표자 이관 |
| 직원(employee) | 초대 가입 후 입사서류 제출 | 출퇴근·휴가·계약서/명세서 열람 | 세션 복구 후 중단 단계에서 재개 |
| 외부 회계 담당 | 허용 사업자 선택 | 전표 검토·마감 지원 | 타 사업자 접근 403과 요청 경로 제공 |

## 3. 사용자 중심 정보 구조

로그인 후 첫 화면은 설정이 아니라 업무 홈이다. 사업자 선택기는 모든 업무 화면 상단에 고정하고, 일반 사용자가 쓰지 않는 연동·권한·정책은 설정으로 분리한다.

1. **통합 홈**: 오늘의 미처리, 자금, 매출/매입, 승인, 마지막 오류.
2. **재무 원장**: 매출, 매입, 은행 거래, 카드 사용을 동일한 목록→상세→등록 구조로 제공.
3. **사람 관리**: 직원계약, 근태, 급여를 직원 정본 하나로 연결.
4. **회계 원장**: 전표, 계정별 원장, 시산표, 월마감.
5. **설정**: 사업자·지점, 멤버·권한, 외부 연동, 감사로그.

## 4. 우선순위와 릴리스 흐름

| 우선순위 | 목표 마일스톤 | 사용자 가치 | 완료 게이트 |
|---|---|---|---|
| P0 | O11 사업자별 4종 원장 | 매출·매입·은행·카드를 건별 조회·등록·수정 | 타 사업자 0건, API 403, 목록/상세/등록 E2E |
| P0 | O2 직원계약 기반 | 가입→서류→작성·수정→서명→보관 | 상태·버전·감사 이력, 모바일 복구 |
| P1 | O12 근태 | 계획→출퇴근→승인→마감 | 원시 기록과 집계 0분 차이 |
| P1 | O13 급여 | 근태→산정→승인→명세서→지급 | 급여대장·지급자료·분개 0원 차이 |
| P1 | M0~M6 ACCT 원장 | 운영 자료를 차대균형 전표와 손익으로 연결 | 차대균형, 마감잠금, 화면/API 합계 일치 |
| P2 | O8/O9 모바일·감사 | 현장 반복 사용과 보안 증적 완결 | 한 손 동선, 세션 복구, 감사로그 |

의존 순서는 `tenant/company 식별자 → 4종 원장/O2 → O12 → O13 → ACCT 분개·마감`이다. 화면은 병렬 구현할 수 있지만 확정 데이터의 후속 단계는 이 순서를 건너뛰지 않는다.

## 5. 상세 페이지 구성 원칙

4종 원장은 모두 아래 공통 골격을 사용한다.

- 목록: 기간·사업자·상태·금액·거래처·검색, 저장된 필터, 합계.
- 상세: 원본값, 분류값, 증빙, 연결 거래, 수정 이력, 감사로그.
- 등록: 수기 입력과 파일 업로드를 분리하고 임시저장·중복검사를 제공.
- 수정: 확정 전 직접 수정, 확정 후에는 취소/정정 버전 생성.
- 실패 복구: 입력값 보존, 오류 원인, 재시도, 원본 다운로드, 담당 이관.

추가로 필요한 페이지는 다음과 같다.

| 영역 | 필수 페이지 | 현재 기준선에서 특히 필요한 보강 |
|---|---|---|
| 매출 | 목록, 건별 상세, 수기등록, 정산대사, 반품/취소 | 파일 목록과 거래 상세를 분리하고 원장 연결 표시 |
| 매입 | 목록, 건별 상세, 전표등록, 증빙검수, 입고/재고 연결 | 계정과목·적요·카드·세금계산서 필드를 같은 상세에 배치 |
| 은행 | 계좌목록, 거래목록, 건별 상세, 수기등록/업로드, 대사 | 입금/출금·잔액·원문적요·매칭 근거와 재수집 상태 |
| 카드 | 카드목록, 사용내역, 건별 상세, 수기등록/업로드, 취소/대사 | 은행 거래와 분리된 전용 원장·마스킹·사용자/부서 귀속 |

## 6. 운영·버전관리 원칙

- 본 패키지는 SemVer를 사용한다. 문구/오탈자는 patch, 요구사항 추가는 minor, 데이터·API 계약 파괴는 major를 올린다.
- `docs/goals/acct-unified/manifest.json`이 현재 문서 버전과 관련 세부 PRD를 가리키는 인덱스다.
- 요구사항 ID는 PRD 버전이 바뀌어도 재사용하지 않는다. 폐기 시 `deprecated`로 남긴다.
- 목표 화면의 문서 링크는 사본이 아니라 Git 경로를 가리킨다.
- 구현 변경은 PRD 요구사항 ID와 테스트/커밋 근거를 함께 남긴다.
- 목업의 숫자와 행은 명시적으로 샘플이며 운영 실적을 뜻하지 않는다.
