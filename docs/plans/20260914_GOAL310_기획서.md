# #310 전략카드 일일 누적수익 3% — 기획서

- 작성 2026-09-14 KST
- 대표님 지시: "#310전략카드로 일일 누적수익이 3%이상 확보가 목표이다.
  이걸 기준으로 주도담당이 세부목표를 세우고 작업을 기획하고 진행하게
  조치하는거지"
- 설계·규격은 [PRD](../prd/20260914_GOAL310_PRD.md)

## 1. 목표를 숫자로 못 박는다

**#310 전략카드로 일일 누적수익 3% 이상.** 슬리피지와 수수료를 뺀
**실현 손익** 기준이다.

이 단서가 중요하다. 승률만 올리고 손익비가 무너지는 개선은 달성이 아니다.
평가손익으로 3% 를 찍어도 체결에서 깎이면 의미가 없다.

## 2. 지금 측정할 수가 없다

기준선부터 막혀 있다. 2026-09-14 실측:

    go100-daily-results-snapshot   17:23 실패   전략카드 일별 결과 스냅샷
    go100-ws-krx                   죽음        KRX 실시간 시세
    kis-v41-minute-collector       죽음        분봉 수집기

**일별 결과를 스냅샷하는 서비스가 죽어 있으면 3% 달성 여부를 알 수 없다.**
그리고 시세·분봉이 안 들어오면 후보가 만들어지지 않는다 — 같은 날
종목발굴담당이 "후보가 3,310종목 → 20종목" 이라고 보고했다.

그래서 이 목표의 첫 마일스톤은 전략 개선이 아니라 **측정 복구**다.
기준선이 없으면 무엇을 고쳐도 좋아졌는지 알 수 없다.

## 3. 혼자 못 고친다 — 그래서 담당 8명

수익은 한 군데서 나오지 않는다. 진입 시점, 체결 품질, 후보 품질, 데이터
정합성이 곱해진 결과다. 한 담당의 개선이 다른 담당의 지표를 깎는 것이
이 작업의 기본 위험이다.

| 담당 | 맡은 것 | 키 |
|---|---|---|
| 전략카드담당 (주도) | 취합·조정·판단 | `StrategyCardLead` |
| 파동엔진담당 | 진입 시그널 정확도 | `WaveEngineOwner` |
| 실매매엔진담당 | 체결·슬리피지 손실 | `LiveTradingOwner` |
| 데이터엔진담당 | 데이터 결손·정합성 | `DataEngineOwner` |
| 종목발굴담당 | 후보 품질·유니버스 | `StockDiscoveryOwner` |
| 백테스트엔진담당 | 개선안 검증·기준선 | `BacktestEngineOwner` |
| 학습모델담당 | 모델 예측력·라벨 | `MLModelOwner` |
| 운영인프라담당 | 서비스 생존·복구 | `OpsInfraOwner` |

주도는 **혼자 고치지 않는다. 배정하고 취합한다.**

## 4. 왜 이 순서인가

측정 → 진단 → 개선 → 검증 → 반영이다. 순서를 건너뛰면 되돌릴 수 없다.

특히 **검증 없이 실매매에 반영하지 않는다.** 백테스트로 기준선 대비
개선을 확인하고, 대표님 승인을 받은 뒤에 반영한다. 이 경계는 프롬프트가
아니라 **코드가 막는다**(`live_trading_guard`).

## 5. 하지 않는 것

- **파라미터 난사.** 무엇을 왜 바꿨는지 남기지 않는 변경은 다음 사람이
  되돌릴 수 없다.
- **승률 최적화.** 목표는 누적수익이지 승률이 아니다.
- **주도의 독단.** 방향을 바꾸려면 대표님 승인을 받는다(`direction_guard`).

## 6. 달성했다고 말할 수 있는 조건

하루 반짝 3% 가 아니다. **연속 5거래일 중 3일 이상**에서 실현 손익 기준
일일 누적수익 3% 이상, 그리고 그 기간 최대 낙폭이 기준선보다 나쁘지 않을 것.
