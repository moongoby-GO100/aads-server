## 1. 배경과 문제

기준 코드: 대시보드 origin/main `35fe03f`, 서버 origin/main `3095cc45`.

| # | 문제 | 근거 | 사용자에게 보이는 영향 |
|---|---|---|---|
| 1 | 목표가 칩으로 가로로 늘어난다. 접어도 앞 4개에 더해 주도·막힘·작업중 목표는 강제로 보인다 | `src/components/chat/GoalStrip.tsx` `VISIBLE_CHIPS = 4`, `keepVisible` | 이 대화(목표 6, 주도 2)는 접힌 상태에서 요약 칩 + 목표 칩 4개 + `목표 +2` + 정리 칩이 한 줄에 놓인다. 주도·막힘·작업중 목표가 많으면 칩이 그만큼 더 늘어난다 |
| 2 | 펼치면 칩이 줄바꿈되어 최대 290px까지 대화를 밀어낸다 | `GoalStrip.tsx` `maxHeight: open ? 290` | 대화 영역이 줄어들고 메시지가 가려진다 |
| 3 | 멈춘 목표가 우선순위 그룹에 그대로 섞인다 | `app/services/goal_activity.py` `strip_rank()` 가 `goal_paused` 를 보지 않는다 | 멈춘 P0 가 진행 중인 P0 사이에 보인다 |
| 4 | 막힌 목표(status=blocked, 마일스톤 배정 막힘)에 별도 그룹이 없다 | `strip_rank` 5단(🔄 ⏳ P0 P1·P2 💤) | 대표님 조치가 필요한 목표가 P1 사이에 묻힌다 |
| 5 | 같은 그룹 안 순서가 제목 가나다순이다 | `strip_sort_key = (strip_rank, priority_rank, title)` | 최근에 움직인 목표를 찾으려면 전부 읽어야 한다 |

**직전 검토 답변 정정.** "API 가 priority·paused 를 내려주지 않고 goal_id 순으로 반환한다"는 설명은 틀렸다. `GET /goals/for-session/{sid}` 는 이미 `priority`·`priority_rank`·`goal_paused`·`activity`·`dormant`·`strip_rank` 를 내려주고 `sort_for_strip()` 로 정렬한다(origin/main `app/routers/goals.py` 997행). 이번 변경은 이 계약을 **확장**한다.

실측(2026-10-22 13:55 KST, DB 조회): 열린 목표 58건(active 33·blocked 24·draft 1), P0 계열 30건, 멈춤 1건. 세션당 연결된 열린 목표는 최대 9건, 이 대화는 6건(주도 2).

## 2. 목표

1. 채팅 상단 목표 영역을 목표 수와 관계없이 **한 줄**(데스크톱 32px, 모바일 36px)로 고정한다.
2. 목표 목록은 버튼을 눌렀을 때만 **드롭다운**(모바일은 하단 시트)으로 연다.
3. 목록은 **진행 우선순**으로 묶는다: 🔄 작업중 → ⏳ 대표님 대기 → ⛔ 막힘 → P0 → P1·P2 → ⏸ 멈춤 → 💤 휴면·초안.
4. 각 줄에서 상태·우선순위·진행률·막힘 사유를 한 번에 읽고, 누르면 오른쪽 목표 패널이 열린다.

| 구분 | 내용 |

| 첫 진입 | 채팅 창을 열면 상단 한 줄에 `🎯 목표 6 · ⛔1` 과 정렬 1순위 목표 1개가 보인다. 대화는 가려지지 않는다 |

## 5. 대안 비교

권장: **A안**.

| 안 | 내용 | 장점 | 리스크 | 판정 |
|---|---|---|---|---|
| A | 드롭다운 + 서버 `strip_group` 추가(기존 `strip_rank` 유지) | 정렬 판정이 서버 한 곳. 배포된 구버전 화면과도 호환 | 서버·대시보드 릴리스 2건 | 권장 |
| B | 대시보드만 바꾸고 화면에서 그룹 계산 | 릴리스 1건 | `goalStrip.ts` 의 "서버 판정을 다시 계산하지 않는다" 원칙과 충돌, 판정이 두 벌이 된다 | 대안 |
| C | 칩 유지, 접힘 개수만 줄임 | 변경 최소 | 대표님 요청(드롭박스)과 다르고 멈춤·막힘 정렬이 해결되지 않는다 | 비권장 |

B 를 택하지 않는 이유: 판정 규칙이 서버(`goal_activity.py`)와 화면 두 곳에 생기면 한쪽만 고쳐지는 순간 화면 순서와 서버 순서가 어긋난다. 다만 화면에는 서버 값이 없을 때만 쓰는 폴백을 둬서 릴리스 순서와 무관하게 동작하게 한다.
