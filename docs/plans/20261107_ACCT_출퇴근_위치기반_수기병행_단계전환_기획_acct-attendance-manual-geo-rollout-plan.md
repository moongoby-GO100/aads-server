| freelancer | requested | 1 | 1 | 1 |

```sql

-- 근로 합계

-- 근로·용역 겹침 인원
SELECT count(*) FROM (SELECT lower(employee_email) FROM yeoljeong_contracts WHERE deleted_at IS NULL AND status='signed' GROUP BY 1 HAVING bool_or(contract_type IN ('regular','part_time')) AND bool_or(contract_type='freelancer')) x;

-- 종류별 계약 현황
SELECT
  contract_type,
  COUNT(*) as contract_count,
  COUNT(DISTINCT LOWER(employee_email)) as unique_people
FROM yeoljeong_contracts
WHERE deleted_at IS NULL AND status = 'signed'
GROUP BY contract_type
ORDER BY contract_type;

-- 사업자별 계약 현황
SELECT
  business_id,
  contract_type,
  COUNT(*) as contract_count,
  COUNT(DISTINCT LOWER(employee_email)) as unique_people
FROM yeoljeong_contracts

ORDER BY business_id, contract_type;
```

## 4. 처리 원칙
1. 근무표는 '예정', 출근 기록은 '확인'이다. 결근은 대표·관리자가 확정할 때만 결근이다. 근로계약·용역계약 모두 같다.
2. 확인필요가 0건이어야 월 급여 마감을 할 수 있다. 확인필요에는 **기록이 없는 지난 예정 근무 구간**과 **퇴근 누락**도 포함한다(DB 행이 없어도 센다).
3. 같은 근무 구간에 기록이 여럿이면 급여에는 대표 기록 1건만 쓴다(짝 문서 8장).

## 5-1. 단계별 처리 규칙 (구현 기준)
대상은 근로계약 직원과 용역계약자 모두다.

| 입력 | 0 수기 병행 | 1 위치 시험 | 2 위치 본적용 |
|---|---|---|---|
| 버튼 + 반경 안(출근·퇴근 합산) | 확인필요 | 확인필요(배지: 반경 안) | 자동 승인 |
| 버튼 + 반경 밖·판정 불가·미동의 | 확인필요 | 확인필요(배지) | 확인필요 |
| 버튼 미입력(근무표 있음) | 근무표 기준 생성(확인필요) | 같음 | 생성하지 않음 → '미기록(확인필요)', 마감 게이트가 셈 |
| 출근만 있고 퇴근 없음 | 퇴근 누락(확인필요) | 같음 | 같음 |
| 결근 확정 | 대표·관리자 수기만 | 같음 | 같음 |

- **승인 차단은 출근·퇴근 API 둘 다에 적용한다.** 현재 퇴근 API는 `combined_geofence` 결과로 status 를 다시 계산하므로 `judge_geofence`만 고치면 0·1단계에서도 퇴근 때 자동 승인된다. 최종 status 를 정하는 한 곳(공통 함수)에서 지점 방식을 보고 결정한다.
- **단계 효력 시점**: 지점 방식 변경은 저장 시각 이후 **새로 시작하는 근무 구간**부터 적용한다. 출근 시 그 구간의 방식을 기록에 `clock_mode` 로 저장하고, 퇴근·자동 생성·재판정은 저장된 값을 쓴다. 근무 중 단계가 바뀌어도 그 구간은 출근 때 값을 유지한다.

## 5-2. 자동 생성 작업의 날짜 규칙
- 실행: 매시 정각(KST). 05:00 1회가 아니다.
- 대상: 예정 종료 시각 + **유예 6시간**이 지난 근무 구간 중 버튼 출근이 없는 것. 자정을 넘는 근무(예: 22:00~익일 06:00)는 구간 시작일의 근무로 보고, 예정 종료(익일 06:00) + 6시간이 지나야 대상이 된다.
- 출근만 있는 구간은 생성하지 않고 '퇴근 누락(확인필요)'으로 둔다.
- 멱등: (사업자, 대상자, 근무 구간 시작 시각) 고유키로 `source=schedule_auto` 1건만 만든다. 재실행·서버 복구 후 재실행에도 중복 0건.
- 생성 뒤 늦게 버튼 기록이 들어오면 자동 생성 건은 `payroll_excluded`(사유: 실제 기록 도착)로 바꾸고 대표 기록을 다시 정한다(짝 문서 8장).

## 6. 용역계약자 (rev5, 대표님 지시 2026-11-06)
- 용역계약자도 근로계약 직원과 **같은 출근 버튼과 근무표 기준 자동 생성 대상**이다. rev4 의 "용역계약자 제외"는 철회한다.
- 이유: 시급·일급으로 용역비를 산정하는 계약(예: 3.3% 시급 12,500원)은 승인된 근무 시간이 곧 용역비 산정 근거다. 기록이 없으면 용역비를 계산할 수 없다.
- 확인필요·대표 기록·월 마감 게이트도 같은 규칙을 쓴다. 결근은 모두 수기 확정이다.
- 남은 리스크(미검증): 출퇴근 통제·지각 판정은 근로자성 판단에 불리할 수 있다. 그래서 용역계약자 화면·명세에는 '지각·조퇴' 표시를 붙이지 않고 근무 시각과 승인 시간만 보여 준다. 노무 전문가 확인 결과에 따라 바꾼다(9장 대표 결정).

### 자동 생성 롤백 절차 (`clock_schedule_auto_enabled` off 시)
생성분은 `source=schedule_auto` 로 식별한다. 이 절차가 보는 **대상 source 집합을 S 로 부른다. 기본값은 S={schedule_auto}** 이고, 11장 (나)를 채택해 `default_present_enabled` 를 켠 사업자는 S={schedule_auto, schedule_default} 로 확장한다. 아래 (a)·(b)·검증 (a)~(d) 의 '생성분'은 모두 S 에 속한 source 전체를 뜻한다. 상태별로 다르게 처리한다.
0. **먼저 마감·지급을 차단하고, 재집계가 끝날 때까지 유지한다(롤백 off 와 같은 시점).** 롤백 off 시 해당 사업자에 '롤백 검토' 표시(롤백 시각 기록)를 남긴다. 표시가 남아 있는 동안 월 마감·지급 API 는 거절한다. 표시는 아래 두 조건이 **모두** 참이 될 때만 해제한다.
   - (a) `source ∈ S` 이면서 `payroll_excluded` 가 아니고 대표 확인 기록이 없는 건(미승인·이미 승인 모두)이 0건.
   - (b) 롤백 시각 이후 S 의 생성분이 하나라도 들어 있던 급여 초안이 모두, (a) 가 참이 된 시각(마지막 대표 확인 시각) **이후에** 재집계됨. 재집계 시각이 마지막 대표 확인보다 앞선 초안이 1건이라도 있으면 해제하지 않는다.
   - 해제는 서버가 (a)·(b) 를 다시 계산해 판정한다. 수동 해제는 대표 승인으로만 한다. 이 조건은 7장 마감 게이트(작업 2)의 '롤백 검토 미완료' 사유다.
1. **미승인(확인필요) 생성분**: 그대로 두고 급여 집계에서 제외한다. 대표·관리자가 건별로 승인 또는 반려한다. 새 생성은 중단된다.
2. **이미 승인된 생성분**: 승인 기록은 지우지 않는다. 대표가 실제 출근 여부를 건별 확인해 맞으면 유지, 틀리면 `payroll_excluded`(사유: 롤백 검토)로 표시한다.
3. **급여 초안에 반영된 분**: 월 마감 전이면 위 1·2 의 대표 확인이 끝난 뒤 초안을 재집계하고, 재집계 전후 근무시간 합계 차이를 대상자별로 보고한다. 재집계가 끝나야 절차 0 의 차단이 풀린다.
4. **마감·지급이 끝난 달**: 기존 명세는 수정하지 않고 차액 정산 항목을 새로 만든다(작업 6 과 같은 방식).
5. 검증:
   - (a) 롤백 직후 확인 미완료 건이 있는 상태에서 마감·지급 API 가 거절된다(통합 테스트).
   - (b) 마지막 오승인 생성분을 `payroll_excluded` 로 바꾼 직후, 재집계 전 상태에서 마감·지급 API 가 여전히 거절된다(통합 테스트 — 확인 완료와 재집계 사이 공백 차단).
   - (c) 영향받은 초안을 모두 재집계한 뒤에만 차단이 풀리고, 재집계된 초안에 `payroll_excluded` 생성분이 합산되지 않는다(테스트).
   - (d) 롤백 후 `source ∈ S` 이면서 `payroll_excluded` 가 아닌 승인 건 중 대표 확인이 없는 건 0건(SELECT).

| 급여 반영 전 확인 | '출근(기본)'은 대표·관리자 승인 전에는 **급여 초안·용역비 입력에 합산하지 않는다**(표시만 한다. '합산 후 미확인 표시' 방식은 쓰지 않는다). 승인된 건만 합산한다. 월 마감 게이트(작업 2)가 미승인 '출근(기본)' 건을 센다 |
| 플래그 | 사업자 단위 `default_present_enabled`(기본 off). off 면 본문 규칙 |
| 테스트 | 근무표만 있는 구간이 승인 전 급여에 합산되지 않음, 대표 결근 수정 후 제외됨, 용역계약자 동일 동작, 마감 API 거절, `schedule_default` 롤백 시 7장 검증 (a)~(d) 가 `schedule_default` 건에 대해 통과(차단 해제 조건 계산이 `schedule_default` 를 포함함) |
| 롤백 | 플래그 `default_present_enabled` off 시 7장 '자동 생성 롤백 절차'를 **S={schedule_auto, schedule_default}** 로 적용한다(7장 절차 0 의 차단 해제 조건 (a)·(b) 와 검증 (a)~(d) 가 `schedule_default` 를 포함해 계산됨). 처리 순서는 7장과 같다: 절차 0 차단 → 미승인 건은 건드리지 않고 급여 집계 제외 유지(이 방식에서는 애초에 합산되지 않음) → 이미 승인된 건은 대표가 건별로 실제 출근을 확인해 맞으면 유지, 틀리면 `payroll_excluded`(사유: 롤백 검토) → 영향받은 초안 재집계 → (a)·(b) 충족 후 차단 해제. 모든 기본 생성분을 먼저 일괄 제외하지 않는다(승인된 건까지 제외하면 맞는 근무가 급여에서 빠지고 7장 절차 2 와 충돌) |
