# 승인 게이트 재설계 기획서

- 작성: 2026-09-15
- 지시: 대표님 — "승인게이트 일단 모두 승인으로 풀어주고 완전 진짜 내 승인을
  받아야하는것만 승인 받게 조치하자"
- 상태: 대기분 6건 일괄 승인 완료(미션 범위·12시간·20회). 재설계는 이 문서로 제안.

## 1. 지금 무엇이 잘못됐나

게이트는 두 곳에서 올라온다. 그런데 **기록되는 모습은 한 가지**다.

| 올리는 곳 | 실제 성격 | 기록되는 모습 |
|---|---|---|
| `live_trading_guard` | 실매매 경로 변경 | `[실매매]` · risk=high |
| `direction_guard` | 목표·마일스톤·프롬프트 변경 | **`[실매매]` · risk=high** |

`direction_guard` 가 `live_trading_guard.request_approval()` 을 그대로 부르는데,
그 함수가 프리픽스 `[실매매]` 와 `risk_level='high'` 를 **박아 넣는다**. 그래서
목표 중복 정리(`UPDATE goals SET status='archived'`)가 실매매 고위험 요청으로
대표님 화면에 올라온다.

### 실측 — 대기 6건의 정체

일괄 승인 직전 대기 목록이다. 전부 `[실매매] high` 였다.

| 요청 | 실제 내용 | 진짜 승인 대상인가 |
|---|---|---|
| `run_remote_command` | `grep -n "async def" … live_engine.py \| awk \| tail` | **아니다** — 읽기다 |
| `run_remote_command` | `psql … ` 조회 | **아니다** — 조회다 |
| `db_safe_write` ×4 | `UPDATE goals SET title='[중복-보관]'`, `INSERT goal_task_links` | **아니다** — 목표 정리다 |
| `patch_remote_file` | `live_engine.py` | 그렇다 |
| `patch_remote_file` | `live_trading_guard.py` | 그렇다(게이트 자신) |

**여덟 중 둘만 진짜였다.** 나머지는 대표님 시간을 쓰게 하고, 담당은 읽기 한 번
하려고 승인을 기다렸다.

### 재현한 오탐

실제 `classify()` 에 넣어 확인했다.

    막음  grep … live_engine.py 2>/dev/null        ← 읽기인데 막힘
    막음  docs/risk_report.md                      ← 문서인데 막힘
    막음  reports/scalping_backtest_result.md      ← 보고서인데 막힘
    막음  systemctl restart go100-kiwoom-scalping  ← 맞음
    막음  patch live_engine.py                     ← 맞음
    통과  cat /srv/live_trading/config.yaml        ← 맞음

원인 셋.

1. **`2>/dev/null` 을 쓰기로 본다.** 리다이렉트 판정이 `>` 뒤에 글자가 오면
   무조건 쓰기로 친다. `2>/dev/null` 은 거의 모든 조회 명령에 붙는다.
2. **파일명 단어만 보고 판단한다.** 경로 정규식에 `risk`, `scalping`, `kiwoom`
   이 들어 있어 `docs/risk_report.md`, `reports/scalping_*.md` 가 걸린다.
   문서·보고서는 실매매를 바꾸지 않는다.
3. **위험도가 전부 `high` 고정이다.** INSERT 문에 `'high'` 가 상수로 박혀 있어
   대표님이 급한 것과 아닌 것을 구분할 수 없다.

## 2. 무엇을 승인 대상으로 둘 것인가

기준 한 줄로 정한다.

> **되돌릴 수 없고 돈이 걸린 것만 대표님 승인을 받는다.**

되돌릴 수 있는 것(코드 수정, 문서, 목표 정리)은 승인이 아니라 **알림**이다.
알림은 막지 않는다. 대표님이 보고 아니다 싶으면 그때 되돌리면 된다.

### 3단계

| 등급 | 뜻 | 동작 | 예 |
|---|---|---|---|
| **T1 승인필수** | 돈·주문·되돌리기 불가 | **막고** 승인 대기 | 주문 실행 경로 변경, `is_live` 켜기, 배정금액·계좌 변경, 실매매 서비스 재기동, 진입·청산·손절 파라미터 |
| **T2 알림** | 실매매 주변이지만 되돌릴 수 있음 | **막지 않음** + 오비스 알림 + 기록 | 로깅·모니터링 코드, 목표·마일스톤·프롬프트 변경, 실매매 코드의 주석·리팩터 |
| **T3 통과** | 아무 영향 없음 | 아무것도 안 함 | 모든 읽기, 백테스트, 분석, 문서·보고서 |

### T1 의 구체 목록 (이것만 막는다)

    주문:     order_executor · 주문 전송/취소 함수 · 체결 처리
    스위치:   go100_strategy_cards.is_live · dedicated_account
    자금:     allocated_amount · account_no · 한도 설정
    파라미터: 진입/청산 조건 · 손절 · 포지션 크기 · 유니버스 선정 기준
    운영:     실매매 서비스 systemctl restart/stop · 실매매 배포

이 다섯 줄에 안 걸리면 T1 이 아니다.

## 3. 판정 규칙 수정

| # | 지금 | 바꿀 것 |
|---|---|---|
| R1 | `>` 뒤 글자 = 쓰기 | `2>/dev/null`, `2>&1`, `1>/dev/null`, `>/dev/null` 은 쓰기가 아니다 |
| R2 | 경로 단어 매칭 | `.md`·`.txt`·`.html`·`.json` 및 `docs/`·`reports/`·`tests/` 는 제외 |
| R3 | `risk[_-]` 단독 매칭 | 코드 심볼(`risk_limit`, `risk_manager`)만. 파일명 `risk_report` 제외 |
| R4 | `risk_level='high'` 고정 | 등급을 계산해 넣는다 (`critical`/`high`/`medium`) |
| R5 | `direction_guard` 가 `[실매매]` 로 기록 | `[방향]` · `risk=medium` · T2(알림)로 분리 |
| R6 | T2 도 막는다 | T2 는 막지 않고 알림만 |

## 5. 왜 이렇게 하나

**오탐은 규칙을 죽인다.** 여덟 중 여섯이 헛것이면, 다음번엔 내용을 안 보고
누르게 된다. 그러면 진짜 하나가 섞여 들어와도 같이 통과한다. 오늘 아침
와치독이 10만 건의 거짓 경보로 진짜 고장 4건을 가린 것과 같은 구조다.

**막는 것과 알리는 것을 나눈다.** 되돌릴 수 있는 일까지 막으면 담당이 멈춘다.
멈춘 담당은 게이트를 우회할 길을 찾고, 그때부터 게이트는 없는 것과 같다.

## 6. 하지 않을 것

- **게이트를 끄지 않는다.** 대표님 지시는 "진짜만 받게 하라" 이지 "받지 말라"
  가 아니다. T1 은 그대로 막는다.
- **자동 승인을 넣지 않는다.** 에이전트가 자기 요청을 스스로 승인할 수 있으면
  게이트가 없는 것과 같다. 승인은 사람만 한다.

## 7. 남은 판단

미션 승인의 기본값을 얼마로 둘지는 대표님 판단이 필요하다. 지금 일괄 승인은
**12시간·20회**로 넣었다. 하루 한 번 승인으로 끝내려면 24시간이 맞고, 매번
확인하시려면 2시간이 맞다.
