# 채팅 반응성 — 왜 즉시 답하지 못하나

- 작성 2026-09-14 KST
- 대표님 질문: "너처럼 즉시 응답이 왜 안되는지", "중간 추가지시에 대한
  너 정도 반응이면 좋겠는데"
- 설계·규격은 [PRD](../prd/20260914_CHAT_RESPONSIVENESS_PRD.md)

## 1. 첫 토큰까지 — 실측

첫 글자가 나오기 전에 하는 일이 있다.

    질문 임베딩 1회        2,558 ms   ← CPU Ollama
    Auto-RAG 전체          2,168 ms
    프롬프트 컴파일            51 ms
    컨텍스트 조립 전체      2,234 ms   → 시스템 프롬프트 33,347자

**임베딩이 가장 큰 단일 항목이다.** 질문을 벡터로 바꿔야 Auto-RAG 가
근거를 찾는데 CPU Ollama 라 2.5초가 걸린다. 그동안 화면은 비어 있다.

그런데 **근거가 첫 문장에 필요한 경우는 드물다.** 대개는 답을 시작한 뒤
중간에 쓰인다. 지금은 근거를 다 모을 때까지 첫 글자도 못 낸다.

## 2. 중간 추가지시 — 이쪽이 더 심각하다

    model_selector (LiteLLM 경로)    도구 호출 경계에서만 집어감
    agent_sdk_service (릴레이 경로)   인터럽트 처리 **0줄**

최근 12시간 응답 258건이 `claude-opus-5` — **전부 릴레이 경로**다.

즉 응답 중에 보내신 지시는 **그 턴이 완전히 끝날 때까지 반영되지 않는다.**
큐에 쌓였다가 다음 턴 앞에 붙는다. 턴이 2~61분 걸리니 최악의 경우 한
시간 뒤다.

원인은 SDK 호출 방식이다.

    sdk_query(prompt=..., options=...)   일회성. 시작하면 넣을 수 없다.

## 3. 넣을 수 있는 길이 있다

SDK 0.2.152 의 `ClaudeSDKClient` 에 `query` 와 `interrupt` 가 있다.
**연결을 열어 두고 도는 중에 메시지를 보낼 수 있다.** 지금 쓰는
일회성 `query()` 와 다르다.

## 4. 고치는 순서

**① 첫 토큰을 먼저 낸다.** Auto-RAG 를 기다리지 않고 시작하고, 근거는
준비되는 대로 뒤에 붙인다. 체감 2.5초가 줄어든다.

**② 중간 지시를 돌고 있는 턴에 넣는다.** `ClaudeSDKClient` 로 바꾼다.

①이 먼저인 이유 — 모든 턴에 효과가 있고 위험이 작다. ②는 SDK 호출
구조를 바꾸므로 더 조심해야 한다.

## 5. 하지 않는 것

- **Auto-RAG 를 끄는 것.** 근거가 붙는 것이 이 채팅의 값어치다.
  늦게 붙이는 것과 안 붙이는 것은 다르다.
- **인터럽트를 받으면 턴을 죽이고 다시 시작.** 20분치 작업이 사라진다.
  오늘 배포로 두 번 그런 일이 있었고 그때마다 조사가 날아갔다.
- **임베딩을 GPU 로.** 이 서버에 GPU 가 없다. 원격 두 대에 Ollama 를
  올려 뒀지만 그건 백필용이고, 대화 경로에 네트워크 왕복을 더하면
  지금보다 나아진다는 보장이 없다 — 재 보고 정할 일이다.
