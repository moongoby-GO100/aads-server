# OHVIS Chrome 사이드패널 디자인 개선 기획서

- 작성: 2026-10-03 13:10 KST, CTO 세션 `7fb5f50a`
- 대상: `aads-dashboard/extensions/ohvis-sidepanel` (origin/main `9d5dc4c`, v0.1.1) + 대시보드 `/chat` 화면
- 계기: CEO 지시 "열리는데 디자인수정이 필요할듯하긴하다 검토하고 개선 기획서 상세하게 보고서로 저장" (12:47 KST, 첨부 화면 `c4f23d18`)
- 근거의 한계: 첨부 화면은 서버에 저장돼 있다(1024×550 축소본). 다만 이번 턴의 도구로는 이미지의 픽셀을 다시 볼 수 없다. 그래서 아래 진단은 **코드와 앞선 CEO 지적("채팅창이 떠야 하는데 승인창이 떠 있다", "브라우저 옆에 떠야 한다")을 근거로** 한다. 화면으로 확인한 사실은 아니다. 구현 단계에서 실제 Chrome 캡처로 다시 검증한다.

## 1. 대상 사용자와 사용 장면

| 항목 | 내용 |
|---|---|
| 사용자 | CEO 1인. Windows PC에서 Chrome으로 업무 사이트(쇼핑몰 관리자, 금융, 대시보드)를 보면서 동시에 OHVIS에 지시한다 |
| 첫 실행 경로 | Chrome 툴바 OHVIS 아이콘 → 오른쪽 사이드패널 열림 → **바로 채팅 입력** |
| 반복 사용 경로 | 보고 있는 웹페이지에 대해 묻기·지시 → 답변 확인 → 승인이 필요하면 패널 안에서 승인 |
| 실패 복구 경로 | 로그인 만료·연결 끊김 → 패널 안에서 한 번 눌러 복구. 새 탭으로 튕겨 나가지 않음 |
| 패널 폭 | Chrome 사이드패널 기본 약 320~400px. 사용자가 끌어서 넓힐 수 있다 |

## 4. 개선안

원칙은 하나다. **패널을 열면 바로 채팅이 보이고, 나머지는 필요할 때만 보인다.**

### 4-1. 레이아웃 (목표 와이어프레임, 폭 360px 기준)

```
┌────────────────────────────────┐
│ ● OHVIS   승인 2 · 작업 1   ⋮  │  ← 높이 36px 한 줄. 숫자는 누르면 아래 시트로 펼침
├────────────────────────────────┤
│                                │
│   (대화 — /chat?surface=panel) │  ← 남은 높이 전부. iframe 테두리 없음
│                                │
│                                │
├────────────────────────────────┤
│ [📎] 이 페이지에 대해 묻기…  [▶] │  ← 입력창은 /chat 쪽에서 하단 고정
│  ☐ 현재 탭 포함: naver.com/…    │  ← 체크하면 URL·제목·선택 텍스트를 첨부
└────────────────────────────────┘
```

### 4-2. 개선 항목

| 순위 | 개선 | 해결하는 문제 | 변경 위치 | 검증기준 |
|---|---|---|---|---|
| P0 | `/chat?surface=panel` 축소 모드 신설: 세션 목록·워크스페이스·모델 선택 숨김, 머리글 없음, 입력창 하단 고정, 본문 글자 13px, 좌우 여백 8px | D1, D2, D7 | 대시보드 `src/app/chat/page.tsx`(쿼리 분기), 관련 레이아웃 컴포넌트 | 폭 360px 캡처에서 대화 영역 높이가 패널 높이의 80% 이상. 세션 목록이 보이지 않음 |
| P0 | 확장 상단을 한 줄로 통합: 상태 점 + "OHVIS" + `승인 N · 작업 N` 칩 + ⋮ 메뉴(새로고침·새 탭에서 열기·로그아웃). "OHVIS 채팅" 제목줄 삭제 | D1, D3 | `sidepanel.html/css/js` | 채팅 위 머리 영역이 1줄(≤40px) |
| P0 | 승인·작업은 칩을 눌렀을 때 **아래에서 올라오는 시트**로 표시(최대 60%, 바깥을 누르면 닫힘). 기본은 닫힘. 승인 대기가 있으면 칩만 주황색 | D3, D5 | `sidepanel.js/css` (`details.fold` 대체) | 승인 대기 4건 상태에서도 첫 화면에 채팅이 보임. 시트를 열고 닫는 동작 캡처 |
| P1 | 안내 문구는 iframe 로딩 실패·인증 실패일 때만 표시. 정상일 때는 숨김 | D4 | `sidepanel.js` `renderChat`, `deliverAuth` | 정상 상태 캡처에 안내 문구 0건. 강제로 토큰을 실패시키면 안내와 "다시 연결" 버튼이 보임 |
| P1 | "패널에서 숨기기" 삭제. 채팅은 항상 보이고, 숨기는 기능이 필요하면 ⋮ 메뉴에 "승인·작업만 보기"로 둠 | D5 | `sidepanel.js` `setChatMode` | 버튼을 잘못 눌러 채팅이 사라지는 경로 0개 |
| P1 | 현재 탭 맥락 첨부: `chrome.tabs.query({active:true})` 로 URL·제목을 얻어 postMessage 로 `/chat` 에 전달하고, 입력창 아래 체크박스로 포함 여부를 선택 | D6 | 확장 `sidepanel.js`, `manifest.json`(`tabs` 권한 — 이미 있는지 확인), `/chat` 수신부 | 체크하고 "요약해"를 보내면 서버 메시지에 URL이 포함됨(DB 조회) |
| P2 | 테마 통일: 확장의 `:root` 변수를 대시보드 토큰 값으로 맞추고, iframe 테두리·이중 카드 배경 제거 | D7 | `sidepanel.css` | 라이트·다크 캡처 2장에서 경계선 1겹 |
| P2 | 단축키: `Alt+O` 로 패널 열기(`commands`) | 반복 사용 | `manifest.json` | Chrome 단축키 설정 화면에 표시됨 |

### 4-3. 실패 복구 흐름

| 상황 | 지금 | 개선 후 |
|---|---|---|
| 로그인 만료 | 배너 + "OHVIS 에 로그인" (새 탭) | 상단 점이 주황색 + 채팅 자리에 "다시 로그인" 한 버튼. 로그인 후 패널이 자동으로 다시 연결 |

## 6. 완료 판정 기준

1. 실제 Chrome 사이드패널 캡처에서 첫 화면에 채팅 입력창과 최근 대화가 보이고, 승인·작업은 칩 한 줄로만 보인다.
2. 채팅 위 머리 영역이 40px 이하이고 "OHVIS" 표시는 1번만 나온다.
3. 정상 상태에 안내·경고 문구가 0건이다.
4. 로그인 만료와 연결 끊김을 각각 재현했을 때 패널 안에서 한 번 눌러 복구된다.
5. `extensions/ohvis-sidepanel/tests/*.test.mjs` 와 대시보드 빌드를 통과하고, 배포 run 이 success 다.
