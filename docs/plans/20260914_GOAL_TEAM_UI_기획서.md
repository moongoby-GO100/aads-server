# 목표 팀 화면 — 주도를 드러내고, 담당을 버튼으로 붙인다

- 작성 2026-09-14 KST
- 대표님 지시: "목표카드에 담당 8명이 표시되는데 목표책임담당을 표시하면
  좋을듯해 시각화 기획하고 보고해 그리고 내가 수동으로 세션과 담당을
  추가할수 있는 버튼이 있었으면하는데"

## 1. 지금 화면의 문제 — 주도가 안 보인다

현황판은 담당 8명을 **같은 크기 카드로 나열**한다. 정렬에서 주도가 맨
앞에 올 뿐이다.

    ┃전략카드 관리자   작업 중 │ ┃파동엔진 관리자   응답대기
    ┃데이터관리자      진행 중 │ ┃고백운영인프라    막힘

목표를 책임지는 사람과 한 조각을 맡은 사람이 **똑같이 보인다.** 대표님이
"이 목표는 지금 누가 끌고 있나" 를 물으실 때 답이 화면에 없다.

그리고 **주도가 없는 목표도 그냥 보인다.** 담당만 넷 붙어 있고 취합할
사람이 없는 상태가 정상처럼 보인다.

## 2. 주도는 역할이 다르다

| | 주도 | 담당 |
|---|---|---|
| 맡은 것 | **목표 전체** | 마일스톤 하나 |
| 하는 일 | 배정·취합·조정·판단 | 자기 영역 실행 |
| 막히면 | **목표가 선다** | 그 마일스톤만 선다 |
| 완료 판정 | 담당 신고를 **확인한다** | 근거와 함께 **신고한다** |

마지막 줄이 특히 중요하다. 주도는 판정자다. 판정자가 다른 담당과 같은
줄에 있으면 그 관계가 안 보인다.

그래서 **위아래로 나눈다.** 나란히 두면 동급으로 읽힌다.

## 3. 담당 추가 버튼 — 그런데 함정이 있다

오늘 운영인프라담당을 추가할 때 실제로 한 일은 이것이다.

    1. prompt_assets 에 역할 프롬프트 INSERT
    2. chat_sessions.role_key UPDATE
    3. goal_task_links INSERT
    4. **기존 담당 7명의 프롬프트에 든 명단을 전부 수정**

4번이 문제다. 실측하면 명단이 **8개 프롬프트에 각각 박혀 있다.**

    go100-310-wave-engine          Owner 언급 8회
    go100-310-data-engine          Owner 언급 8회
    ... 8개 전부

버튼으로 1~3번만 하면 **새 담당이 외톨이가 된다.** 자기는 남을 부를 수
있는데 남들은 그를 모른다.

### 손으로 적힌 목록은 반드시 갈라진다

오늘 같은 문제를 다섯 번 고쳤다 — 통합지시 목록 네 벌, 감시기 서버 지도,
골 스케줄러 프로젝트, `/goals` 필터, Layer 1 의 "3개 서버".

**이것이 여섯 번째다.** 버튼을 만들면서 4번을 자동화하면 여섯 번째를
더 정교하게 만드는 것일 뿐이다.

### 근본 해결 — 명단을 프롬프트에서 뺀다

서버 목록을 Layer 1 에서 빼고 Layer 2 에 실측으로 넣은 것과 같다.
담당 명단도 `goal_task_links` 에서 읽어 넣는다.

    프롬프트   "부를 수 있는 담당" 자리를 비워 둔다
    Layer 2    목표에 묶인 담당을 매 요청마다 넣는다

그러면 버튼으로 담당을 붙이는 순간 **다음 턴부터 전원이 안다.**
프롬프트를 8개 고칠 일이 없어진다.

## 4. 세션은 만들지 않는다

버튼은 **이미 있는 세션을 담당으로 붙이는 것**이다. 새 채팅창은 대표님이
만드신다.

채팅창이 늘어나는 것을 대표님이 모르시는 상태가 되면 안 된다. 그리고
세션은 대화 이력을 갖는데, 기계가 만든 빈 세션은 맥락이 없다.

## 5. 역할 프롬프트가 없는 담당

세션을 붙였는데 그 `role_key` 에 맞는 프롬프트가 없으면 **그 담당은 자기가
누구인지 모른다.** 오늘 실측한 것과 같은 상태다(`role=""` 로 자산이
하나도 안 걸리던 건).

붙일 때 확인하고, 없으면 화면에 경고를 띄운다. 막지는 않는다 — 프롬프트를
나중에 쓸 수도 있다. 다만 **모르는 채로 지나가면 안 된다.**
