## 1. 한 줄 요약

처음 쓰는 사람도 **"쿠팡이츠에서 어제 매출 받아줘"라고 말하기만 하면**, 오비스가 대신 사이트에 들어가 한 번 해 보고, 사용자는 **확인 카드 3장(사이트 → 로그인 → 결과)** 만 눌러 자동화를 만든다. 내부 용어(work_key·레인·credential_scope·레시피 조각)는 화면에서 사라진다.

## 2. 왜 하는가 — 현재 상태 (실측)

| 지표 | 현재 값 | 출처 |
|---|---|---|
| 자동화 등록 요청 | 16건 (승인 10 · 반려 2 · 대기 4) | [DB 조회 `work_recipe_registration_requests`, 2026-10-14 12:4x KST] |
| 대표님 외 사용자가 직접 등록 | **0건** (16건 중 15건이 대표님 채팅 세션·에이전트, 1건이 대표님 계정) | [DB 조회 `requested_by`] |
| 승인 대기 최장 체류 | **22일** (2026-09-22 요청 2건) | [DB 조회] |
| 등록 후 실행 | 34회 (성공 27 · 실패 6 · 차단 1, 성공률 79.4%), 마지막 실행 2026-09-30 | [DB 조회 `recipe_runs`] |
| 레시피 저장소 | 3갈래 — `work_recipes` 13 · `ovis_recipes` 11 · `browser_recipes` 2(초안) | [DB 조회] |
| 작업 화면 입력값 | `/browser-tasks` 가 work_key · target_url · chat session_id 를 직접 입력받음 | [코드 확인 `aads-dashboard/src/app/browser-tasks/page.tsx:326-331`] |
| 등록 조건 | `smart_browser register_e2e` 는 단계 배열 + `screen_verified=true` 화면 증거 필수 | [코드 확인 `app/services/tool_registry.py:2198-2226`] |

**해석.** 기능은 동작한다(성공률 79.4%). 그러나 등록 경로가 "개발자가 채팅으로 도구를 부르는 것"을 전제로 만들어져 있어, 도구를 모르는 사람은 들어올 입구가 없다. 등록이 끝나도 승인이 묻혀 쓰이지 않고, 만든 자동화를 한곳에서 볼 수도 없다.

## 3. 목표와 비목표

### 목표
1. 처음 쓰는 사람이 **설명서 없이 10분 안에** 첫 자동화를 만든다.
2. 화면에 내부 용어가 **0개** 보인다(관리자 '자세히' 펼침 제외).
3. 승인 대기가 **48시간 안에** 처리된다.
4. 만든 자동화를 **한 목록**에서 보고, 다시 실행하고, 고장 나면 고친다.

### 비목표 (이번 범위 밖)
- 새 브라우저 실행 엔진 개발 — 기존 서버 Playwright / PC Agent 레인을 그대로 쓴다.
- 레시피 저장소 3갈래의 물리적 통합(마이그레이션) — 이번에는 **조회만 통합**한다. 물리 통합은 별도 과제.
- 결제·주문·발송 같은 외부 쓰기 자동화의 무승인 실행 — 기존 승인 게이트를 유지한다.
- CAPTCHA 자동 풀이.

## 4. 대상 사용자

| 구분 | 누구 | 하고 싶은 것 | 지금 막히는 지점 |
|---|---|---|---|
| U1 처음 쓰는 직원 (주 대상) | 매장·운영 담당, 비개발자. 사이트 로그인은 할 줄 앎 | "매일 아침 배달앱 매출을 받아 보고 싶다" | 어디서 시작하는지 모름. work_key·도메인·단계 같은 말을 모름 |
| U2 대표님 (파워 사용자) | 지금 채팅으로 등록 중 | 더 빨리 등록하고 직원에게 넘기기 | 등록 후 승인·예약을 따로 챙겨야 함 |
| U3 승인자 | 대표님 또는 지정 관리자 | 위험한 자동화만 걸러 승인 | 승인 대기가 어디 있는지 모름 → 22일 방치 |

## 5. 핵심 아이디어 — "말하기 → 지켜보기 → 확인하기"

```
[사용자] "쿠팡이츠에서 어제 매출 받아줘, 매일 아침에"
   │
   ▼ 카드 1 「이렇게 이해했어요」  — 사이트 / 할 일 / 받을 결과 / 주기   [맞아요] [고칠게요]
   ▼ 카드 2 「로그인 연결」        — 저장된 계정 있음 → [이 계정으로] / 없음 → 안전 입력칸
   ▼ (오비스가 대신 해 보는 중)    — 라이브 화면 + "로그인 중 → 매출 메뉴 → 어제 날짜 선택"
   ▼ 카드 3 「이 결과가 맞나요?」   — 마지막 화면 캡처 + 결과 미리보기 5줄   [맞아요] [아니에요]
   ▼ 「자동화 만들었어요」          — 매일 09:00 예약 · 승인 필요 여부 · [지금 한 번 더 실행]
```

- 사용자가 직접 화면을 조작해 "녹화"하지 않아도 된다. 필요하면 "제가 직접 보여줄게요" 버튼으로 기존 녹화(오비스 '레시피 학습')로 넘어간다(보조 경로).
- 내부적으로는 기존 규칙대로 **로그인 / 이동 / 조회** 조각으로 나눠 저장하고, 같은 사이트의 승인된 로그인 조각이 있으면 재사용한다. 사용자는 조각을 모른다.

## 6. 사용자 흐름

### 6.1 첫 사용 (U1)
1. 채팅창 또는 홈의 **[자동화 만들기]** 버튼 → 빈 입력칸과 예시 문장 3개("배달앱 어제 매출 받기", "스마트스토어 새 주문 확인", "세금계산서 목록 내려받기").
2. 한 문장 입력 → 카드 1. 사이트 주소를 모르면 사이트 이름으로 후보를 보여 주고 고르게 한다.
3. 카드 2. Vault 에 같은 사이트 계정이 있으면 "○○ 계정으로 진행" 한 번. 없으면 채팅 안 **안전 입력칸**(기존 `VaultCredentialCard`)에 아이디·비밀번호 입력 — 값은 채팅·레시피·로그에 남지 않는다.
4. 오비스가 대신 해 본다. 진행 단계가 문장으로 바뀌고, 라이브 화면 썸네일이 보인다.
5. 카드 3. 결과가 맞으면 [맞아요] → 주기 선택(매일/평일/매주/한 번만) → 완료.
6. 결과가 다르면 [아니에요] → "무엇이 다른가요?" 선택지(날짜가 달라요 / 다른 메뉴예요 / 다른 매장이에요 / 직접 보여줄게요).

### 6.2 반복 사용
- 채팅에서 "어제 매출 받아줘" → 등록된 자동화가 하나면 바로 실행, 여럿이면 고르기 카드.
- 예약된 자동화는 결과를 채팅과 '내 자동화' 목록에 남긴다.

### 6.3 실패 복구
| 상황 | 화면 문장 | 버튼 |
|---|---|---|
| 비밀번호 틀림 | "로그인이 안 됐어요. 비밀번호가 바뀌었나요?" | [비밀번호 다시 입력] [나중에] |
| CAPTCHA·추가 인증 | "사이트가 사람 확인을 요구해요" | [내 PC에서 계속하기] [나중에] |
| 접근 차단 | "이 사이트가 서버 접속을 막고 있어요" | [내 PC에서 계속하기] |
| 화면이 바뀜 | "사이트 화면이 바뀌어 메뉴를 못 찾았어요" | [다시 보여주기] [담당자에게 요청] |
| 일시 오류 | "잠깐 연결이 끊겼어요. 2분 뒤 다시 할게요" | (자동 재시도 1회) |

복구는 **마지막으로 성공한 조각부터** 다시 시작한다(로그인이 살아 있으면 로그인을 반복하지 않음).

### 6.4 승인 (U3)
- 읽기 전용 자동화(조회·내려받기)는 **사이트별 최초 1회만** 승인, 이후 같은 사이트 읽기 자동화는 자동 승인 범위에 들어간다(정책 결정 필요 — 11절).
- 외부 쓰기(주문·발송·저장)·되돌릴 수 없는 행위가 섞이면 **항상** 승인자가 승인한다.
- 승인 대기는 홈 상단 배지 + 인박스 + 텔레그램 알림. 48시간 미처리 시 1회 재알림, 14일 미처리 시 '만료' 표시(요청자에게 다시 요청 버튼).

## 7. 화면 용어 바꾸기

| 내부 이름 | 화면 이름 |
|---|---|
| recipe / work_recipe / 레시피 | 자동화 |
| register_e2e / registration | 자동화 만들기 |
| work_key | (숨김 — 자동 생성) |
| lane (서버 Playwright / PC Agent) | "서버에서" / "내 PC에서" (실패 복구 때만 노출) |
| credential_scope / Vault | 저장된 로그인 |
| screen_verified / e2e_evidence | 결과 확인 |
| pending / approved / rejected | 확인 기다리는 중 / 사용 가능 / 다시 만들기 필요 |
| READ / WRITE_EXTERNAL / IRREVERSIBLE | 보기만 해요 / 사이트에 저장해요 / 되돌릴 수 없어요 |

## 8. 범위와 단계

| 단계 | 내용 | 결과물 | 선행 |
|---|---|---|---|
| M0 | 승인 대기 정리 + 승인 알림(홈 배지·텔레그램·48h 재알림) | 대기 0건, 알림 동작 | 없음 |
| M1 | 대화형 등록 백엔드: 자동화 초안(draft) 상태 머신 + API + 채팅 도구 | API·단위테스트 | 없음 (M0과 병렬) |
| M2 | 채팅 카드 3종 + 완료 카드 + 홈 [자동화 만들기] 입구 | 대시보드 화면 | M1 |
| M3 | '내 자동화' 통합 목록 (3갈래 조회 통합) + 다시 실행 + 실패 복구 | 목록 화면 | M1 (M2와 병렬) |
| M4 | 처음 쓰는 계정으로 실사용 검증 (쿠팡이츠 읽기, 공개 사이트 1개) + 지표 계측 | 캡처·지표 보고서 | M2·M3 |

## 9. 성공 지표

현재 값이 없는 항목은 M1 에서 계측 이벤트를 넣고 측정을 시작한다. 목표값은 **목표**이지 측정값이 아니다.

| 지표 | 현재 | 목표 (출시 4주) | 측정 방법 |
|---|---|---|---|
| 대표님 외 사용자 등록 수 | 0건 [DB 조회] | 5건 이상 | `automation_drafts.owner` 기준 상태 `active` 수 |
| 첫 자동화까지 걸린 시간(중앙값) | 미측정 | 10분 이하 | draft 생성 → 결과 확인 완료 시각 차 |
| 시작 대비 완료율 | 미측정 | 70% 이상 | draft 생성 수 대비 `pending_approval`/`active` 도달 수 |
| 승인 대기 체류(중앙값) | 최장 22일 [DB 조회] | 48시간 이하 | `requested_at` → `decided_at` |
| 화면 내부 용어 노출 | `/browser-tasks` 입력칸 3개 [코드 확인] | 0개 | 화면 문자열 검사 테스트 |
| 등록 후 14일 내 재실행 비율 | 미측정 | 60% 이상 | 자동화별 `recipe_runs` 2회 이상 비율 |

## 10. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 오비스의 대신 시연이 엉뚱한 메뉴를 누름 | 잘못된 자동화 등록 | 카드 3(결과 확인)을 통과해야만 등록. 외부 쓰기 단계는 시연 중 실행하지 않고 멈춤 |
| 비밀번호 노출 | 보안 사고 | 기존 Vault 안전 입력만 사용. 채팅·레시피·로그·캡처에 값 금지, 입력칸은 filled/empty 만 기록 |
| 서버 접속 차단 사이트 | 시연 실패 | "내 PC에서 계속하기"로 PC 레인 전환. 단 PC 성공을 서버 성공으로 보고하지 않음 |
| 자동 승인 범위가 넓어짐 | 위험 자동화 통과 | 읽기 전용만 사이트별 자동 승인 후보. 외부 쓰기는 항상 승인 |
| 3갈래 저장소 | 목록 누락 | M3 에서 조회 통합 뷰, 출처 표시. 물리 통합은 별도 과제 |
| 스마트브라우저 담당 작업(M1~M13)과 중복 | 같은 파일 충돌 | 착수 전 담당 확인(2026-10-14 문의 시 `target_not_found`로 미전달 — 재시도 필요), 러너 `depends_on` 로 순서 고정 |
