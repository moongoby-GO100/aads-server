1. 정본 후보 문서(plan·prd·spec·design·architecture·contract·tasks·report·reference)가 만들어지면 정본 head 에 초안으로 등록된다.

#### "최신 트렌드와 디자인을 반영하려면" — 제안한 답

최신성은 사람 취향이 아니라 **기록된 조사 → 승인된 revision → 같은 기준으로 하는 QA** 순서로 들어온다.

1. 착수 때 공식 디자인 시스템과 동종 실제 서비스를 조사하고, 참조마다 원 URL·발행일·확인일·버전·적용/제외 이유·라이선스를 남긴다(spec 9항).
2. 기존 브랜드·사용자 업무·접근성·성능에 맞는 것만 고른다. 큰 신규 화면은 기존 체계 유지안과 선별 트렌드 적용안을 비교해 권장안을 적는다.
3. 고른 결과는 승인 revision 으로 고정한다. 이후 조사 갱신은 새 revision 제안일 뿐이어서 승인된 기준을 자동으로 바꾸지 않는다. 자동 스케줄은 만들지 않는다.
4. QA 는 승인 시안과 같은 viewport·fixture 로 비교하고, 접근성은 WCAG 2.2 AA 로 본다(spec 11항).

OHVIS 권장 방향(제안): 정보 가독성·작업 상태·핵심 행동이 뚜렷한 업무 화면을 우선하고, 장식·투명 효과는 검증 뒤 제한해서 적용한다. 외부 근거는 Google Expressive Material Design(핵심 행동 강조, 익숙한 패턴 보존), Apple HIG Materials(투명도·대비 접근성 고려), WCAG 2.2 목표 크기·포커스 가림 없음이며, 2026-10-03(KST) 확인분이다 [지시서 인용]. Google 자료의 수치는 당사 성과로 인용하지 않고, Apple 가이드를 웹 필수 효과로 삼지 않으며, 업계 전체 최신 순위를 주장하지 않는다.
