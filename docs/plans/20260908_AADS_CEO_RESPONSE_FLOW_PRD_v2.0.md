## 1. 배경

CEO 지시(2026-09-07):

> "현재 응답출력이 응답과정을 형식없이 쭉 나열식으로 채팅창에 응답하는데 이를
> 질문 및 지시 파악 내용 정리 / 목표 / 계획 / 실행순서 / 결과 / 검증 / 리스크 / 다음
> 순으로 보고되게 하려면 어떻게 해야해?"

기존 v1.0은 "응답 개요 7칩(목표·계획·진행·결과·검증·리스크·다음)"까지 진행됐다.
그러나 7칩은 **본문을 사후 분석해 표시하는 품질 체크 카드**였을 뿐, 본문 자체의 서술 순서를
강제하지 않았다. 그 결과 CEO가 체감한 문제는 그대로 남았다.

| v1.0 한계 | 실측 근거 |
|---|---|
| 본문 순서 미강제 | `output_validator._REPORT_REQUIRED_GROUPS`에 순서 개념 없음 [코드 확인] |
| "지시 파악", "실행순서" 항목 부재 | 칩 7종에 해당 항목 없음 [코드 확인] |
| 진행 문구가 본문 서두에 잔존 | `_PROGRESS_LEAD_PATTERN`은 800자 이상에서만 검사 [코드 확인] |

## 2. 목표 (v2.0)

1. 보고형·실행형 응답 본문이 **CEO 8섹션 순서**로 서술된다.
2. 응답 버블 상단 개요 칩이 8섹션과 **1:1로 일치**한다.
3. 8섹션 미충족 응답은 저장 전에 **재작성 신호**를 받는다. 단, 재시도 폭증으로 인한 응답 끊김을 유발하지 않는다.
4. 간단 조회·인사 응답에는 8섹션을 **강제하지 않는다**.

### 완료 기준 (측정 가능)

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 8섹션 커버리지 (900자 이상 보고형) | 평균 7/8 이상 | `evaluate_ceo_flow_coverage()` 배치 측정 |
| REPORT_STRUCTURE_WEAK 재시도율 | 기존 대비 +3%p 이내 | `chat_executions` 재시도 분류 집계 |
| 응답 중단율 | 악화 없음 | `chat_executions.interrupt_category` 24h 비교 |

## 3. 8섹션 정의

| # | 섹션 | 필수 내용 | 미해당 시 |
|---|---|---|---|
| 1 | 지시 파악 | 요청을 어떻게 이해했는지, 범위 포함/제외 | 생략 불가 |
| 2 | 목표 | 이번 응답의 완료 기준 | 생략 불가 |
| 3 | 계획 | 처리 방식(직접/러너/조회)과 선택 이유 | "단일 조회" 등 1줄 |
| 4 | 실행순서 | 실제 수행 단계 + 대상 파일·명령·도구 | "실행 없음(조회 전용)" |
| 5 | 결과 | 완료/미완료 분리, 커밋·푸시·배포·문서 상태 | 생략 불가 |
| 6 | 검증 | 실행 명령/도구와 ✅❌ 결과, 미실행은 "미실행" | 생략 불가 |
| 7 | 리스크 | 남은 위험·영향 범위 | "없음" 명시 |
| 8 | 다음 | 즉시 실행 가능한 액션 1~3개 | 생략 불가 |

### 축약 규칙
- 900자 미만: `지시 파악 / 결과 / 검증 / 다음` 4섹션으로 축약 허용.
- 900자 이상: 8섹션 전부. 해당 없는 섹션은 삭제 대신 "해당 없음".
- greeting·casual·단순 확인 질문("~된 거지?"): 8섹션 미적용, 3줄 이내.

## 4. 3레이어 구현 설계

```
[L1 프롬프트]  global-ceo-8section-response-flow (priority 23)
      ↓ 생성 시점에 순서를 지시
[백엔드 검증]  output_validator.evaluate_ceo_flow_coverage()
      ↓ 커버리지 < 5/8 이면 REPORT_STRUCTURE_WEAK 재작성 신호
[프론트 렌더]  ResponseOverviewPanel 8칩 + 본문 섹션 점프
```

### 4.1 L1 프롬프트 (생성 제어)
- slug: `global-ceo-8section-response-flow`
- layer_id: 1, priority: 23 (report-depth 22 / response-structure 21 보다 상위)
- intent_scope: NULL(전역), role_scope: `{*}`
- 역할: 모델이 처음부터 8섹션 순서로 쓰게 만든다. **1차 방어선.**

### 4.2 백엔드 검증 (저장 게이트)
- `_CEO_FLOW_GROUPS`: 8개 그룹 × 키워드 사전
- 트리거 조건: 보고형 인텐트 **AND** 본문 900자 이상 **AND** 커버리지 5/8 미만
- 의도적으로 보수적: 8/8 완전 일치를 요구하면 재시도가 폭증해 응답 끊김(현재 P0)을 악화시킨다.
- 재시도 프롬프트에 8섹션 골격을 그대로 주입한다.

### 4.3 프론트 렌더 (확인 경로)
- 칩 8개: 지시파악 / 목표 / 계획 / 실행순서 / 결과 / 검증 / 리스크 / 다음
- 각 칩 클릭 → 본문 해당 섹션으로 스크롤 점프
- 미충족 칩은 `!` 아이콘 + 비활성 → CEO가 "무엇이 빠졌는지" 즉시 식별

## 5. 사용자(CEO) 관점 흐름

1. **첫 진입**: 응답 버블 상단에 8칩이 뜬다 → 3초 안에 "이 답변이 완결됐는지" 판단.
2. **반복 사용**: 칩 클릭 → 궁금한 섹션으로 바로 점프. 전체 재독 불필요.
3. **실패 복구**: `검증 !` 또는 `결과 !`가 뜨면 그 응답은 미완료 → 재지시 근거가 명확.
4. **모바일**: 칩은 wrap 배치, 터치 영역 4px 패딩 + 999px radius로 한 손 조작 대응.

## 6. 리스크와 대안

| 리스크 | 영향 | 대응 |
|---|---|---|
| 검증 강화 → 재시도 증가 → 응답 끊김 악화 | P0 | 커버리지 하한 5/8, 900자 이상에만 적용 |
| 짧은 답변까지 장황해짐 | 사용성 | 900자 미만 4섹션 축약 규칙 명문화 |
| 칩 오탐(키워드 기반) | 신뢰도 | 프론트/백엔드 키워드 사전 동일 기준 유지, 백엔드 `evaluate_ceo_flow_coverage()` 공개 함수화 |
| 프롬프트 길이 증가 | 비용 | L1 에셋 1건(약 1.3KB) 추가로 제한 |
