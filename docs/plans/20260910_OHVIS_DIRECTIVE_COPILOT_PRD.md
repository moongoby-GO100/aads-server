# OHVIS 지시 코파일럿 PRD

- 문서 상태: 구현 승인
- 작성일: 2026-09-10 KST
- 대상: AADS 채팅, 아티팩트 패널, 지시 초안 API
- 1차 범위: 확인형 MVP

## 1. 문제

개발 요청의 원문에는 작업 범위, 기존 구현의 정본, 완료 조건, 금지사항, 검증과 배포 포함 여부가 자주 생략된다. 실행 에이전트가 이를 임의 해석하면 같은 목적의 엔진을 중복 구현하거나, 부분 완료를 최종 완료로 보고하거나, 기존 경로를 남긴 채 신규 경로를 추가하는 문제가 반복된다.

현재 채팅은 응답 이후 아티팩트 추출과 완료 계약 검사를 제공하지만, 최근 문답을 실행 가능한 지시서로 바꾸어 사용자가 검토·교정하는 입력 전 단계가 없다. 기존 아티팩트의 `지시서` 동작도 클립보드 복사에 그쳐 교정 이력과 승인 데이터를 남기지 않는다.

## 2. 목표와 비목표

### 목표

1. 현재 세션의 최근 사용자 질문과 AI 응답을 근거로 지시 초안을 생성한다.
2. 초안을 세션 아티팩트에 즉시 노출하고, 저장형 편집을 지원한다.
3. 사용자가 검토한 초안을 한 번에 채팅 입력창으로 옮긴다. 자동 전송하지 않는다.
4. 생성본, 수정 revision, 입력창 반영 이벤트를 테넌트 범위로 보존한다.
5. 프로젝트·위험도·완료 계약을 초안에 명시하여 중복 엔진과 부분 완료를 예방한다.

### 비목표

- 1차 버전에서는 지시서를 Runner에 자동 제출하지 않는다.
- 코드·DB·배포 작업을 사용자 승인 없이 실행하지 않는다.
- 교정 데이터가 쌓이기 전에는 자동 전송·자동 승인 정책을 활성화하지 않는다.

## 3. 대상 사용자와 핵심 흐름

대상 사용자는 여러 프로젝트의 개발·운영 지시를 내리는 CEO와 내부 관리자다.

1. 사용자가 세션에서 AI 응답을 확인한다.
2. 입력창 옆 `지시 초안`을 누른다.
3. 서버가 최근 문답, 세션 프로젝트, 위험 키워드를 검토해 AADS 지시서 v2.0 초안을 만든다.
4. 초안은 `보고서` 아티팩트로 열리고 DB에 revision 1이 저장된다.
5. 사용자는 아티팩트 편집으로 범위·완료 기준을 수정한다.
6. `입력창에 넣기`를 누르면 현재 입력창에 반영된다.
7. 사용자가 최종 확인 후 기존 전송 버튼으로 보낸다.

실패 시에는 생성 실패 이유와 재시도 행동을 같은 위치에 표시한다. 기존 입력 내용은 자동으로 덮어쓰지 않고, 내용이 있으면 교체 확인을 받는다.

## 4. 지시서 계약

생성 초안은 다음 필드를 반드시 포함한다.

```text
>>>DIRECTIVE_START
TASK_ID: {PROJECT}-DRAFT
TITLE: {작업명}
PRIORITY: P0-CRITICAL|P1-HIGH|P2-MEDIUM|P3-LOW
SIZE: XS|S|M|L|XL
MODEL: AUTO
DESCRIPTION: |
  목표:
  현재 근거:
  허용 범위:
  금지 범위:
  구현 요구사항:
  검증 기준:
  완료 보고:
>>>DIRECTIVE_END
```

`TASK_ID`는 제출 전 초안임을 명시한다. 실제 Runner 작업 ID는 제출 시스템만 발급한다.

## 5. 기능 요구사항

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| F-01 | 최근 문답 검토 | 테넌트·세션 범위의 최근 메시지만 사용 |
| F-02 | 프로젝트 판정 | workspace `project_key` 우선, 미지원 값은 `AADS`로 임의 전환하지 않고 `CUSTOM` |
| F-03 | 위험도 판정 | 조회/코드/DB/배포를 `low/medium/high`로 저장 |
| F-04 | 초안 생성 | 필수 6개 헤더와 DESCRIPTION 계약 검증 |
| F-05 | 실패 폴백 | LLM 실패 시 근거가 표시된 결정론적 초안 생성 |
| F-06 | 아티팩트 노출 | 생성 응답에 artifact를 포함하고 보고서 탭을 연다 |
| F-07 | revision | 생성·수정 내용을 순번과 변경 주체로 보존 |
| F-08 | 입력창 반영 | 자동 전송 없이 편집 가능한 입력값으로 이동 |
| F-09 | 피드백 이벤트 | created/edited/inserted/approved/rejected/sent 이벤트 보존 |
| F-10 | 충돌 방지 | 다른 세션·테넌트의 초안 조회/수정 차단 |

## 6. 데이터 모델

### `directive_drafts`

초안 정본, 상태, project/risk/classification, 원본 source message ID, 현재 revision, 연결 artifact ID를 저장한다.

### `directive_draft_revisions`

생성본과 CEO 수정본 전체를 immutable revision으로 저장한다. 이후 자동화 품질 평가는 revision 1과 최종 사용 revision의 diff를 학습 데이터로 사용한다.

### `directive_draft_events`

초안 생성, 편집, 입력창 반영, 승인, 반려, 전송 이벤트를 저장한다. 단순 대화량이 아니라 실제 채택·교정 행동을 자동화 승격 근거로 사용한다.

## 7. API

| Method | Route | 역할 |
|---|---|---|
| POST | `/api/v1/chat/sessions/{session_id}/directive-drafts` | 최근 문답 기반 초안 생성 |
| GET | `/api/v1/chat/sessions/{session_id}/directive-drafts` | 세션 초안 목록 |
| PATCH | `/api/v1/chat/directive-drafts/{draft_id}` | 낙관적 revision 기반 수정 |
| POST | `/api/v1/chat/directive-drafts/{draft_id}/events` | inserted/approved/rejected/sent 기록 |

기존 `/api/v1/chat/artifacts/{artifact_id}` 편집도 directive draft subtype이면 같은 revision 저장 경로로 연결한다.

## 8. 권한·보안

- 모든 SELECT/UPDATE/INSERT에 `tenant_id`를 강제한다.
- 생성과 수정은 MEMBER 이상, 조회는 VIEWER 이상이다.
- LLM 입력은 선택된 최근 메시지만 포함하고 최대 문자 수를 제한한다.
- 자동 제출과 자동 배포는 1차 버전에서 금지한다.
- 원문에 없는 파일·수치·완료 사실을 초안이 확정하지 않도록 프롬프트와 검증기에 명시한다.

## 9. 자동화 승격 기준

1차는 확인형만 제공한다. 최소 100개 사용 초안과 프로젝트별 20개 이상의 교정쌍이 쌓인 뒤 다음 지표를 평가한다.

| 지표 | L2 추천형 기준 | L3 자동형 기준 |
|---|---:|---:|
| 입력창 반영률 | 80% 이상 | 95% 이상 |
| 핵심 필드 무수정률 | 70% 이상 | 90% 이상 |
| 프로젝트 오분류율 | 3% 이하 | 1% 이하 |
| 금지 범위 누락률 | 2% 이하 | 0.5% 이하 |

L3 자동형은 조회·보고 같은 low risk에만 허용한다. 코드 수정, DB 변경, Git push, 배포는 계속 사용자 확인을 요구한다.

## 10. 검증 기준

- 서비스 단위 테스트: 필드 검증, 프로젝트/risk 판정, LLM 실패 폴백.
- API 계약 테스트: 인증, 세션/테넌트 격리, revision 충돌 409.
- 대시보드: lint/build, 데스크톱·모바일 버튼, 기존 입력 보호, 아티팩트 편집·입력 반영.
- 운영 검증: migration 적용 후 DB row/revision/event 생성, API 헬스, 로그인 화면 E2E.

## 11. 출시 계획

1. Phase 1: 확인형 MVP와 revision/event 수집.
2. Phase 2: 지시 품질 점수, 수정 diff 대시보드, 자주 쓰는 정책 추천.
3. Phase 3: 기준을 통과한 low-risk 요청만 자동 초안 생성. 자동 전송은 별도 정책 승인 후 검토한다.
