## 1. 지금 상태 (실측)

문서가 네 군데에 흩어져 있고 서로를 모른다.

| 보관소 | 규모 | 상태 |

| 파일 `.md` | 13,219개 | **고유는 2,604개** |

### 1-1. 80%가 중복 사본

12,616개 중 고유 2,604개. 한 문서가 **33벌** 있고 한글·영문 두 이름으로 갈린다.

    /root/aads/aads-server/reports/20260615_e_contract_templates_draft.md
    /root/aads/aads-docs/reports/20260615_전자계약서_3종_템플릿_초안.md
    ... 31곳 더

원인은 릴리스 사본과 워크트리가 `docs/` 트리를 통째로 들고 다니는 것이다.
상위 20개 문서가 전체 용량의 40%(28.8MB)를 차지하는데, 그중 5개가
`HANDOVER.md` 1.67MB 의 워크트리 사본이다.

### 1-2. 문서함에 문서가 아닌 것이 더 많다

`/docs` 4,876건의 구성: `.md` 1,674 / png 1,104 / jpg 733 / **py 372** /
html 301 / json 270. 스크린샷과 파이썬 소스가 "문서"로 섞여 있다.

### 1-3. 위키가 위키가 아니다

`ohvis_wiki_pages` 의 `slug` 는 전부 `memory-fact-<uuid>` 다. 프로젝트당
정확히 300건씩 `memory_facts` 를 퍼온 일회성 덤프이고, 출처추적
(`ohvis_wiki_sources`)과 링크그래프(`ohvis_wiki_links`)는 **둘 다 0행** —
설계만 있고 비어 있다.

### 1-4. 교훈 체계가 두 벌

`docs/shared-lessons/INDEX.md` 는 8건에서 2026-03-06 이후 멈췄다. 그런데
`.claude/rules/flow-rules.md` 는 지금도 "작업 전 INDEX.md 확인"을 규칙으로
지시한다. **죽은 색인을 가리키는 규칙이다.** 실제로 채워지는 것은
`ohvis_wiki_error_book`(12건, 이번 주)이다.

### 1-5. 문서가 코드를 못 따라간다

`docs/chat/*` 는 2026-07-15 고정. 이후 채팅 코드 커밋 서버 175 / 대시보드 160건.

## 2. 진단

**생성은 자동인데 정리는 수동이다.** 리포트는 작업마다 쏟아지고 통합·폐기·
색인은 아무도 하지 않는다. 그리고 **문서에 손으로 적은 숫자는 반드시 틀어진다.**

## 3. 목표

### 3-1. 즉시성

1. **사실과 판단을 분리한다.** 줄 수·엔드포인트 수·타임아웃 상수·스키마는
   코드에서 뽑아 넣는다. 손으로 적는 것은 "왜 이렇게 했나" 뿐이고 그건 안 변한다.
   지금은 둘이 섞여 있어서 사실이 틀어지면 판단까지 못 믿게 된다.
2. **표류를 커밋에서 막는다.** 생성값과 문서값이 다르면 커밋이 막힌다.
3. **문서를 한 곳에만 둔다.** 나머지는 링크다.

### 3-2. 비전문가 가독성

4,876건 파일 탐색기는 답이 아니다. 필요한 것은 문서 목록이 아니라 세 질문의 답이다.

| 질문 | 지금 | 목표 |
|---|---|---|
| 지금 뭐가 돌고 있나 | 6개월 전 손그림 ASCII | 실제 컨테이너·라우트에서 자동 생성 |
| 오늘 뭐가 바뀌었나 | 커밋과 리포트 4,876건에 흩어짐 | 하루치 한 문단 |
| 이건 왜 이렇게 돼 있지 | 검색 불가 | **채팅에 물어보면 문서 근거로 답함** |

세 번째가 핵심이다. 대표님은 이미 물을 창구(채팅)를 갖고 있는데, **문서 1,185건이
검색 대상이 아니다.** Auto-RAG 는 `memory_facts` 와 채팅 기록만 본다.

문서를 읽기 좋게 고치는 것보다 **물어볼 수 있게 만드는 것이** 비전문가에게 낫다.

## 4. 실행 순서

원래 제안은 임베딩이 1순위였으나 실측 후 순서를 바꾼다. **제외를 먼저 한다** —
안 그러면 워크트리 `HANDOVER.md` 사본 5벌(각 1.67MB)을 임베딩하게 된다.

| 단계 | 내용 | 근거 |
|---|---|---|
| **S1** | 중복·비문서 제외 | 2,604건 72.3MB → **1,185건 24.0MB** (실측) |
| **S2** | 문서 임베딩 + Auto-RAG 연결 | 물어볼 수 있게 됨 |
| **S3** | "지금 상태" 한 장 자동 생성 | 매번 맞는 아키텍처 |
| **S4** | 문서 표류 게이트 | 재발 방지 |
| **S5** | 교훈 체계 일원화 | 규칙이 죽은 색인을 안 가리킴 |

## 5. 하지 않는 것

- 문서를 사람이 다시 정리해 쓰는 일. 160커밋 뒤에 또 벌어진다.
- 기존 `/docs` 문서함 폐기. 필요한 사람이 있다 — 색인을 더할 뿐 빼지 않는다.
- 워크트리·릴리스 사본 **삭제**. 제외 목록에서 빼는 것이지 파일을 지우지 않는다.
  지우는 것은 되돌릴 수 없고, 지금 문제는 용량이 아니라 색인이다.
