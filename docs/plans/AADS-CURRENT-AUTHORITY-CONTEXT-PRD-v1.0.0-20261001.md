# AADS 현재 정본·운영 근거 제공 PRD v1.0.0

- 프로젝트: AADS
- 문서 키: `aads-current-authority-context`
- 작성일: 2026-10-01
- 요청: 과거 자료를 현재 기준으로 오인하는 현상을 공통 경로에서 예방하고, AADS 담당자가 구현·검증·배포한다.
- 상태: 구현 지시안. API의 승인 상태·배포 상태는 별도 영수증과 증거로 확인한다.

## 1. 문제와 확인 근거

GO100 자원 분석 중 2026-06-23 3서버 토폴로지와 2026-06-19 이전 기록을 현재 운영 원장과 대조하지 않은 오류가 발생했다. 다른 모든 세션이 같은 오류를 냈다고 확인한 것은 아니다. 공통 조회 경로에는 같은 실수를 유발할 조건이 확인됐다.

1. `context_builder.py`의 서버 문맥은 DB `server_registry`와 60초 캐시를 사용한다. `/ops/status`의 원장은 `app.services.server_registry`의 `LEDGER_SERVER_IDS` 네 서버를 사용한다. 소스가 다르고 DB가 없는 진입점·조회 실패에서 문맥이 빠질 수 있다.
2. `doc_index.py`의 파일 검색 결과가 유사도 순서로 제공되고, 보유한 `mtime`, `doc_sha256`, `label`이 조회 결과에 충분히 전달되지 않는다.
3. `auto_rag.py`의 timestamp에 날짜 대신 경로가 전달되는 경로가 있다. 인덱스 문서에서 노후 자료라고 분류해도 개별 결과에 분류가 강제되지 않는다.
4. 승인 문서 포인터·세대 관리·테넌트 권한 API는 이미 존재하며, 두 문맥 builder의 승인 brief는 ACL을 확인해 주입한다. 이 보호를 유지하고, 파일 검색 결과의 최신성 표시와 실행 경로별 provenance 누락을 보완한다.
5. `SYSTEM_PROMPT_ARCHITECTURE.md`는 오래된 서버68/211/114 주소를 담고 있다. 날짜가 있는 과거 기록과 현재 운영 가이드를 구분해야 한다.

근거 파일: `app/services/context_builder.py:117,632,803,961`, `app/services/server_registry.py:89,194`, `app/api/canonical_documents.py:232,330`, `app/core/document_context.py`, `doc_index.py:160,286`, `auto_rag.py:282`, `docs/ARCHITECTURE-INDEX.md:85`, `chat_service.py:14315,14395`. 위치는 조사 시점이며 활성 릴리스 SHA는 담당자가 구현 결과에 기록한다.

## 2. 목적

모든 공통 문맥 진입점과 문서 검색에서 현재의 승인 정본, 최신 초안, 과거 자료, 실측 운영 상태를 구별해 제공한다. 서버 구성·현재 배포·서비스 상태 등 변하는 사실을 과거 문서만으로 현재 사실이라고 확정하지 않도록 근거를 연결한다.

## 3. 권위와 최신성 계약

- 설계·요구사항: 같은 문서 키의 현재 `approved_revision_id`가 승인 기준이다. 최신 초안은 수정안으로 별도 표시한다. 더 최근이라는 이유만으로 초안을 승인본보다 우선하지 않는다.
- 운영 상태: 관측시각을 가진 운영 API·실행 릴리스·실제 ControlGroup·서비스 상태가 현재 상태의 근거다. 문서가 이를 대신하지 않는다.
- 서버 구성: `/ops/status`와 같은 `list_ledger_servers()` 원장을 재사용한다. 총 원장 서버 4개와 건강 감시 서버 3개, 러너 호스트 수를 별개 값으로 제공한다.
- 과거 문서: 당시 사건·설계의 증거로 보존하고 `historical` 또는 `superseded`와 후속 문서 링크를 표시한다. 파일 변경시각과 운영 검증시각을 구별한다.
- 권한: 테넌트·프로젝트·문서 읽기 권한을 유지한다. 권한 없는 승인 문서나 타 프로젝트 문서를 검색 결과로 유출하지 않는다.
- 근거 부족: 자동으로 옛 문서를 현재 정본으로 승격하지 않는다. 조회 실패·승인본 없음·현재 상태 미검증을 명시한다.

## 4. P0: 공통 현재 서버 원장 주입

두 문맥 생성 진입점을 조사하고 공통 함수로 동일한 현재 원장을 제공한다. 정적 L1에 서버 복사본을 추가하지 않는다. 요청마다 갱신하는 동적 구역에 다음을 전달한다.

`source`, `observed_at`, `snapshot_hash`, `ledger_count`, `health_monitored_count`, 각 서버의 `server_id`, 표시명, 주소, 프로젝트, `health_monitored`.

구성 조회시각을 건강 상태 실측시각으로 표현하지 않는다. 건강·CPU·메모리가 필요하면 해당 운영 API의 별도 관측시각을 연결한다. DB 없는 진입점에서도 원장 구성을 얻는다. 실패 시 다른 소스를 권위 있게 보이는 방식으로 조용히 대체하지 않는다.

현재 원장: 콘타보116/AADS, 카페24-114/SF·NTV2·NAS, 진아서버/ACCT, 콘타보14/GO100·KIS. 진아서버는 감시 대상이 아니므로 `unknown`을 장애라고 해석하지 않는다.

## 5. P1: 문서 검색·자동 문맥 제공

- 승인본을 프로젝트와 문서 키로 해석하고 승인 포인터·버전·해시·상태를 함께 반환한다.
- 기존 파일 검색은 `source_path`, 파일 해시, 파일 변경시각, 색인시각, 자료 분류를 보존한다. 확인하지 못한 필드는 `unknown`이며 임의 날짜를 생성하지 않는다.
- 파일 검색 자료에는 승인 정본 여부와 운영 실측 근거 여부를 별도로 표시한다.
- 공통 RAG 병합에서 관련 승인본을 먼저 제시한다. 관련도가 없는 승인 문서가 관련 과거 자료를 무조건 밀어내지는 않는다. 과거 자료에는 현재 후속 문서가 있으면 링크를 제공한다.
- path를 timestamp에 넣는 오류를 수정한다. context 압축·중복 제거 후에도 상태·버전·출처·시각·해시를 유지한다.
- 같은 질의에 승인본·새 초안·옛 문서가 동시에 발견되면 관계와 충돌을 표시한다.

## 6. P1: 문서 정리

문서관리 담당자는 실제 사용된 6월 파일과 노후 시스템 프롬프트 아키텍처에 현재 안내 링크와 과거 자료 표시를 추가한다. 날짜가 있는 이전 기록·변경 로그의 사실을 일괄 치환하지 않는다. 현재 가이드는 4서버 원장과 승인 문서 위치를 설명한다. 로컬 파일·Git 정본·AADS 프로젝트 문서가 서로 다른 상태이면 배포/등록 상태를 각각 기록한다.

## 7. P2: 공통 세션과 관측

신규 세션·기존 세션 다음 턴·DB 없는 호출·장기 세션 압축 후에 동일 계약을 검증한다. 외부 Codex 등 AADS 밖의 세션은 자동 적용 대상이라고 보고하지 않는다. 원장 hash, 문서 revision/hash, provenance 누락·fallback을 진단 로그로 제공하되 문서 본문이나 비밀값은 로그에 넣지 않는다.

## 9. 완료 기준

1. 두 문맥 경로·DB 없는 경로·기존 세션 다음 턴에서 원장 4개, 감시 3개가 구분되고 출처/시각/hash가 있다.
2. 6월3서버 문서가 검색 상위에 있어도 현재 서버 구성 근거로 제시되지 않는다.
3. 승인 v1 + 최신 초안 v2 + 옛 문서 사례에서 승인 포인터를 기준으로 사용하고 초안·과거 상태를 구별한다.
4. 검색 응답과 Auto-RAG에 경로·실제 날짜·해시·상태가 전달된다. mtime이 운영 실측시각이 되지 않는다.
5. 권한 차단·없음·조회 실패·캐시·압축 회귀를 검증한다.
6. 관련 테스트, 커밋/푸시 SHA, 활성 릴리스, 후보 건강·외부 건강·동일 이미지 standby·최소5분 P0/P1 관측을 첨부해야 운영 완료다.

## 10. 일정·우선순위

오늘 P0 구현을 최우선으로 진행하고, P1 메타데이터 보존과 문서 표식을 순서대로 처리한다. 담당자는 지시 수신 후 첫 응답에 파일 책임·예상 완료시각·진행 중 작업과 충돌 여부를 보고한다. 고정 완료시각은 검증 전 단정하지 않는다. 자원 경합을 줄이기 위해 동일 변경의 병렬 러너·중복 빌드를 생성하지 않는다.

## 11. 운영 적용과 롤백

다른 세션의 dirty 변경은 포함하지 않고 clean worktree에서 scoped commit/push한다. AADS `/root/aads/AGENTS.md`의 blue/green·실행 lease·짧은 nginx lock·같은 digest·관측 기준을 지킨다. 조회 API 호환성을 유지하고 추가 메타데이터는 기존 소비자를 깨뜨리지 않는다. 후보 검증 실패 시 이전 routing/image로 복귀한다. 문서 승인·본문은 담당자 검증과 기존 API CAS로 변경하고 DB를 직접 덮어쓰지 않는다.

## 12. 현 단계에서 보고할 수 없는 것

원인 분석·PRD 등록·지시 발송은 공통 보호장치의 운영 적용과 다르다. 전 세션 오류 발생 또는 전 세션 자동 교정 완료는 증거 없이 주장하지 않는다. GO100 신호·실거래 복구는 별도 운영 경로와 커버리지로 검증한다.
