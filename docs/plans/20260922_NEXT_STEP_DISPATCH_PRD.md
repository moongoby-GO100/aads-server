# 다음 단계 승인·자동 실행 신뢰성 PRD

- 작성일: 2026-09-22
- 범위: AADS 채팅 다음 단계 제안, 승인 결정, 자동 반응 전달
- 사례: 세션 `765160d6-facb-4de4-8b36-8591b9466d68`, `d19a0e9e-f96f-4c83-8367-20de50762364`

## 문제와 실측

1. 08:16 KST에 한 응답에 붙은 P0·P1·P2 세 카드를 모두 승인했지만, `project_docs._notify_chat_of_approval_decision`은 세션의 대기 카드가 0개가 된 마지막 승인 건(P0)만 `trigger_ai_reaction`에 넘겼다. P1·P2는 승인 DB 행은 있으나 해당 세션의 Runner 제출이 없다.
2. `propose_next_steps`의 `auto`는 기존 승인으로 분류될 때 프로세스 메모리 `_AUTO_FIRED`로 15분 중복을 막고 반응을 호출한다. 프로세스/슬롯 간 중복 방어 및 항목별 영속 상태가 없다.
3. 채팅 답변의 `🟢자동` 문구 자체는 작업 등록이 아니다. 09:00 KST의 standby 동기화 항목은 `propose_next_steps` 호출도 큐 행도 없었다. 화면 표기만으로 예약·완료를 보장할 수 없다.
4. `review_hold`는 CEO 승인 대기가 아닌 AI 리뷰 인프라 보류다. 해당 세션의 승인 대기 요청은 0건이었으므로 버튼을 그리지 않는 것이 맞지만, 이유가 충분히 명확하지 않다.

## 목표와 비목표

- 묶음 승인에서 승인된 모든 제안을 원래 순서로, 정확히 한 번 영속 실행 큐에 넣는다. 거절·만료 항목은 실행하지 않는다.
- 자동 제안은 항목마다 큐 ID와 상태를 반환한다. 큐 저장에 실패한 항목을 자동 실행 예정으로 보고하지 않는다.
- 재시작·블루그린 전환·동시 승인 호출에서도 실행 지시를 잃거나 중복하지 않는다.
- `review_hold`를 승인 대기로 표시하거나 CEO 승인 버튼으로 우회하지 않는다.
- 이 변경은 제안한 작업(P1/P2 등)을 자동으로 소급 제출하지 않는다. 소급 복구는 현재 상태·중복·승인 유효성을 별도 확인한 후 수행한다.

## 설계

### 승인 묶음

동일 `source_message_id`의 `next_step` 카드를 하나의 결정 묶음으로 본다. 원본 버블 ID가 없으면 해당 요청 하나만 묶는다. 묶음 내 유효한 `pending` 카드가 남아 있으면 기다리고, 마지막 결정 시 승인 항목 전부를 `created_at` 순서로 담은 단일 시스템 지시를 만든다. 거절·만료 항목은 명시적으로 제외한다. 다른 버블의 대기 카드는 이 묶음을 막지 않는다.

### 영속 전달과 중복 방어

기존 `chat_deferred_reactions`를 실행 큐로 사용한다. `dedupe_key`를 추가하고 PostgreSQL 트랜잭션 자문 잠금으로 동일 키의 동시 등록을 직렬화한다. 승인 묶음 키는 버블/요청 ID에 고정해 한 번만 등록한다. 자동 제안 키는 세션+작업 제목으로 만들고 최근 15분 등록 이력을 재사용한다. 큐의 기존 `pending/claimed/completed/failed` 상태와 재시도·활성 슬롯 소비기를 그대로 사용한다. 큐 ID 및 신규/재사용 여부를 도구 결과에 포함한다.

### 표시 계약

`propose_next_steps`의 `auto` 결과는 `queue_id`, `queue_status`, `queued`를 가진다. `auto_fired`는 신규 큐 등록 건수이고, 큐 저장 실패 건수는 별도 필드다. 에이전트에는 큐 ID가 없는 항목을 `🟢자동`이라고 보고하지 말도록 지시한다. `review_hold`는 “리뷰 인프라 재검수 대기 — CEO 승인 버튼은 검수 통과 후 생성”으로 안내한다. 상태를 실제 화면 배지로 제공하는 작업은 대시보드 별도 릴리스 범위다.

## 수용 기준

1. 동일 버블 3건을 P2→P1→P0 순서로 승인해도 P0·P1·P2가 한 반응에 모두 들어간다. 다른 버블의 pending은 차단하지 않는다.
2. 동시 마지막 승인·재호출에도 승인 묶음 큐 행은 1개다.
3. 자동 제안 반복은 15분 내 동일 큐 ID를 재사용하고, 15분 후 새 큐를 허용한다.
4. 큐 등록 실패 시 `auto_fired=0`이며 실패 사유가 반환된다. 실행된 것처럼 보고하지 않는다.
5. 거절·만료 카드는 실행 프롬프트에서 제외된다. `review_hold`에는 CEO 승인 버튼을 만들지 않는다.
6. 기존 승인 결정·채팅 자동 반응 회귀 테스트와 마이그레이션 재실행이 통과한다.

## 배포·복구·롤백

DB 마이그레이션은 `ADD COLUMN IF NOT EXISTS`와 인덱스만 사용해 구버전 슬롯과 호환한다. 이후 단일 SHA 이미지로 블루그린 배포하며 양 슬롯 digest, 외부 health, 5분 P0/P1 오류를 확인한다. 코드 롤백 시 새 nullable 컬럼은 남겨도 안전하다. 과거 누락 P1·P2는 작업 중복과 승인 만료를 재확인한 뒤 별도 명시적 복구한다.
