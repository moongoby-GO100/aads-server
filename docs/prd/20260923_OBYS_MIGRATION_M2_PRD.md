## 1. 목적과 범위
M1에서 분리한 실행 기반 위에서 로그인·조직·권한 데이터와 흐름을 진아서버로 이전·검증한다. 이 단계에서 인증 의존성 차단 시험까지 수행하되, 전체 메뉴 통합 차단 검증은 M4 범위다.

## 2. M0에서 물려받은 차단 요인
| # | 차단 요인 | 근거 |
|---|---|---|
| 1 | 공유 인증 DB(`aads`)가 반일 만에 14행 증가(`saas_users` +2, `tenants` +2, `tenant_memberships` +4, `saas_user_consents` +6) — 단순 덤프 방식 전환 시 그 사이 가입·동의·멤버십이 유실됨 | M0 2.3절 |
| 2 | `aads` DB 전체 13GB 중 인증 7테이블만 선별 추출 대상 — 전량 복원 금지 | M0 2.3절 |
| 3 | `JWT_SECRET_KEY`·`VAULT_ENCRYPTION_KEY` 등 비밀 키 참조는 확인됐으나 값 미기재 — 안전 전달 경로 미확정 | M0 2.5절 |

## 3. 완료 기준 (DB 정본)
기존 로그인·신규가입·초대·전환·만료/권한철회 성공, 구 토큰 거부, 타 조직 접근 거부, 인증 의존성 차단 시험. 비밀 원문 기록 금지.

## 4. 작업 항목
1. 인증 7테이블 선별 추출·복원 스크립트 작성(전량 복원 금지 가드 포함)
2. 컷오버 시점 쓰기 장벽(공통 쓰기 차단 또는 이중 기록) 설계 — 반일 14행 증가율 기준 허용 유실치 산정
3. 비밀 값 안전 전달 경로 확정(Vault 등), 원문은 어떤 문서·로그에도 기록하지 않음
4. 구 토큰 거부·타 조직 접근 거부 회귀 테스트 작성

## 5. 완료 판정 방법
격리 클러스터에서 선별 복원 후 로그인/가입/초대/전환/철회 E2E 성공, 구 토큰 요청 401, 타 조직 리소스 요청 403.

## 6. 리스크
컷오버 시점 쓰기 장벽 없이 실행하면 실측된 반일 14행 규모의 유실이 재현된다.
