## 3. 요구사항

### 3-1. 서버 — 정리 일괄 반영 (TR)

| ID | 요구사항 | 완료기준 |
|---|---|---|
| TR-1 | `POST /api/v1/goals/triage/apply` 신설. 입력: `keep_p0: [goal_id ≤3]`, `actions: [{goal_id, action: resume|pause|close|merge|unblock, merge_into?, reason?}]`, `candidates_version`(카드 생성 시점 해시), `Idempotency-Key` | 라우트 존재·OpenAPI 노출 |
| TR-2 | 대표님(CEO 권한)만 호출 가능. AI·러너 세션은 403 + `priority_proposal` 기록(PR-2 재사용) | 비CEO 403 테스트 |
| TR-3 | 한 트랜잭션: ① keep_p0 외 active P0(P0-CRITICAL 포함) → P1 하향 ② actions 반영 ③ 반영 후 active P0 >3 이면 전체 롤백 + 409 `p0_cap_exceeded` | 트랜잭션 롤백 테스트 |
| TR-4 | 카드 생성 후 후보가 바뀌었으면(`candidates_version` 불일치) 409 `stale_candidates` + 최신 후보 반환. 같은 Idempotency-Key 재전송은 같은 결과 | 동시성·멱등 테스트 |
| TR-5 | 자동 종료·삭제 없음(DO-5 유지). `close` 는 status=`cancelled`(행 보존), `merge` 는 원 목표 `archived` + `merged_into` 기록, 마일스톤·work_item 이동 없음 | 행 수 불변 테스트 |
| TR-6 | 모든 변경을 `goal_status_audit` 에 actor·이전값·새값·triage_run_id 로 기록 | 감사 행 = 변경 수 |

### 3-2. 서버 — 보류 목표 자동승인 정지 정합 (AS)

| ID | 요구사항 | 완료기준 |
|---|---|---|
| AS-1 | 목표 status 가 active → blocked/draft/paused/cancelled/archived 로 바뀌는 **모든 경로**(PUT /goals, pause, triage apply, 자동 차단)에서 그 목표의 active grant 를 `status='suspended'`(없으면 기존 `stale`) + `revoked_at`·`revocation_reason='goal_not_active'` 로 바꾼다 | 단위 테스트: blocked 전환 시 grant 비활성 |
| AS-2 | 재개(resume/unblock)로 active 복귀 시, 만료 전이고 suspended 사유가 `goal_not_active` 인 grant 만 다시 active. 사람이 회수(revoked)한 grant 는 복원하지 않음 | 복원/비복원 테스트 |
| AS-3 | 1회성 정합 스크립트 `scripts/goal_grant_suspend_reconcile.py --dry-run|--apply`: 현재 비활성 목표의 active grant 를 AS-1 과 같은 방식으로 정지. dry-run 은 목표별 전후 표 출력 | dry-run 5건 → apply 후 0건 |
| AS-4 | 정지·복원은 `goal_policy_decisions` 또는 `goal_auto_approval_usage_events` 에 기록 | 이벤트 행 존재 |
