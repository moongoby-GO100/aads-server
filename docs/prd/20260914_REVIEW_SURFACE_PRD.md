# 확인·검토 화면 — PRD·설계

- 작성 2026-09-14 KST · 배경은 [기획서](../plans/20260914_REVIEW_SURFACE_기획서.md)
- 범위: 채팅창 띠 보강 + `/goals` 근거 표시 + **검토함** 신설

## 1. 채팅창 띠 — 접힘/펼침

### 접힘 (기본)

대화가 주인공이다. 한 줄을 넘지 않는다.

    🎯 #310 일일 누적수익 3%   4/7   ● 손실원 진단   ▾

    ● 진행 중   ◐ 확인 대기   ■ 막힘   ⏸ 멈춤

`4/7` 은 마일스톤 진행이다. 퍼센트보다 몇 번째인지가 담당에게 쓸모 있다.

### 펼침

    ┌──────────────────────────────────────────────────────┐
    │ 🎯 #310 전략카드 일일 누적수익 3% 확보         ▴     │
    │ 마일스톤 4/7 · 3 손실원 진단 · 진행 중 2시간          │
    │                                                       │
    │ 완료 기준                                             │
    │ 손실이 진입·체결·후보 중 어디서 나는지 기여도가       │
    │ 숫자로 갈린다                                         │
    │                                                       │
    │ ✏ 대표님 수정 요청 1건 — 아직 답하지 않음            │
    │   "낙폭이 늘면 3%를 지켜도 못 쓴다"                  │
    │                                                       │
    │ 같이 일하는 담당  👑전략카드 · 파동엔진 · 데이터 …   │
    │                                    [ 목표 화면 열기 ] │
    └──────────────────────────────────────────────────────┘

**완료 기준을 띄우는 이유** — 담당이 무엇을 만족시켜야 하는지 대화에서
보이지 않으면, 신고 시점에 기준을 다시 찾아야 한다. 오늘 근거 없는
신고를 막는 규칙을 넣었는데, 기준이 안 보이면 그 규칙이 방해가 된다.

**미답 의견을 띄우는 이유** — 대표님이 남기신 것이 처리됐는지 담당도
대표님도 알 수 있어야 한다.

상태별로 색이 바뀐다. `확인 대기` 면 보라, `막힘` 이면 빨강.

## 2. `/goals` 담당 카드 — 근거를 보여 준다

    │ ─────────────────────────────────────────────────── │

`review` 상태일 때만 근거 블록이 나온다. 대표님이 창을 열지 않고도
**무엇을 근거로 완료라 하는지** 보실 수 있다.

## 2-2. 우측 패널 — 창을 떠나지 않고 검토한다

대표님 제안: "각 채팅창에 골 진행사항을 띠로 보이게하고 우측 아티팩트를
활용하면 어때?"

**이쪽이 낫다.** 원래 설계는 검토하려면 `/goals` 나 `/review` 로 **화면을
옮겨야** 했다. 담당과 대화하다가 "이 근거가 맞나" 를 보려면 창을 떠나고,
돌아오면 대화 맥락이 끊긴다.

다행히 슬라이드인 패널이 이미 있다 — `CodePanel`(diff 미리보기).
같은 자리를 목표에도 쓴다.

### 띠를 누르면 열린다

    [ 대화 ]                          │ 🎯 #310 일일 누적수익 3%    ✕ │
                                      │ 마일스톤 4/7 · 비용 3.4/20   │
    ...                               │ ───────────────────────────── │
    ┌────────────────────────────┐    │ 1 측정 복구      ✓ 완료       │
    │🎯 #310  4/7  ● 손실원 진단▾│    │ 2 기준선 확정    ✓ 완료       │
    └────────────────────────────┘    │ 3 손실원 진단    ● 진행 중 ←  │
    [ 메시지 입력 ]                    │ 4A 진입 당기기   ◐ 확인 대기  │
                                      │ 4B 분할 체결     ● 진행 중    │
                                      │ 5 A/B 비교       ○ 대기       │
                                      │ ───────────────────────────── │
                                      │ ◐ 4A 신고한 근거              │
                                      │ 진입을 15초 당겨 20거래일     │
                                      │ 재계산. 0.4% → 2.2%          │
                                      │ report/card310_...md          │
                                      │   [ 승인 ] [ 반려 ]           │
                                      │ ───────────────────────────── │
                                      │ 담당 8명                      │
                                      │ 👑전략카드   ● 작업 중        │
                                      │  파동엔진   ◐ 확인 대기       │
                                      │  운영인프라 ■ 막힘 3회        │
                                      │    [↻ 재시작] [창 열기]       │
                                      └───────────────────────────────┘

**대화는 그대로 있다.** 패널을 닫으면 원래대로다.

### 왜 이게 나은가

| | 화면 이동 | 우측 패널 |
|---|---|---|
| 대화 맥락 | 끊긴다 | 유지된다 |
| 근거 확인 | 창 옮겨 찾는다 | 옆에 나온다 |
| 판정 | 옮겨서 누른다 | 그 자리에서 |
| 담당에게 바로 말하기 | 다시 돌아와야 | 왼쪽이 그 창이다 |

마지막이 크다. 근거를 보고 "이거 낙폭은 어떻게 되나" 를 **그 자리에서
바로 물을 수 있다.**

### 그래도 검토함은 따로 필요하다

우측 패널은 **그 창의 목표**만 본다. 대표님이 어느 창에도 안 계실 때,
또는 목표 셋 중 어디가 막혔는지 모르실 때는 쓸 수 없다.

    우측 패널   맥락 안 — 이 담당과 얘기하다가 그 목표를 본다
    검토함      맥락 밖 — 어디를 봐야 할지 모를 때 들어간다

둘 다 만들되 **우측 패널이 먼저다.** 대표님이 시간을 가장 많이 쓰시는
곳이 채팅창이기 때문이다.

### 창구는 이미 있다

    GET /goals/{id}/board          담당 상태 + 근거 + 문서
    GET /goals/for-session/{sid}   이 창이 참여 중인 목표

마일스톤 목록만 추가하면 된다. 새 창구를 거의 안 만든다.

## 3. 검토함 — `/review`

목표를 가로질러 **지금 손이 필요한 것만** 모은다.

    ┌─ 검토함 ──────────────────────────── 5건 ─┐
    │                                            │
    │ 승인 대기 2                                │
    │ ┃ 🔴 실매매 파라미터 변경    실매매엔진 3분 │
    │ ┃    #310 · patch_remote_file              │
    │ ┃                        [ 보기 ]           │
    │ ┃ 🟠 마일스톤 6건 제안       전략카드  12분 │
    │ ┃    #310 · 측정 복구부터                   │
    │                                            │
    │ 완료 확인 1                                │
    │ ┃ 🟣 3 손실원 진단          전략카드  8분   │
    │ ┃    #310 · 주도 자신의 마일스톤이라        │
    │ ┃    대표님 확인이 필요합니다               │
    │ ┃              [ 근거 보기 ] [ 승인 ] [ 반려 ]│
    │                                            │
    │ 막힘 1                                     │
    │ ┃ 🔴 1 측정 복구           운영인프라 2시간 │
    │ ┃    3회 보냈으나 답이 확인되지 않음        │
    │ ┃              [ 재시작 ] [ 창 열기 ]       │
    │                                            │
    │ 기한 초과 1                                │
    │ ┃ 🟠 2 기준선 확정         백테스트  1일    │
    │ ┃    기한 09-13 · 멈추지 않았습니다         │
    └────────────────────────────────────────────┘

### 비어 있을 때

    ┌─ 검토함 ──────────────────────────────────┐
    │                                            │
    │        지금 보실 것이 없습니다             │
    │                                            │
    │   목표 3개 · 담당 12명이 돌고 있습니다     │
    │   막힌 것도, 기다리는 승인도 없습니다.     │
    │                        [ 목표 화면 ]       │
    └────────────────────────────────────────────┘

**빈 화면에 그 말을 적는 것이 핵심이다.** "없음" 만 있으면 고장인지
정상인지 모른다. 몇 개가 돌고 있는지 같이 적어야 "정상적으로 조용하다"
가 된다.

### 종류와 색

| 종류 | 색 | 누가 |
|---|---|---|
| 승인 대기 — 실매매 | 빨강 | 대표님 |
| 승인 대기 — 방향 | 주황 | 대표님 |
| 완료 확인 — 주도 자신의 것 | 보라 | 대표님 |
| 막힘 | 빨강 | 대표님 |
| 기한 초과 | 주황 | 대표님 |
| 답 없는 의견 | 회색 | 담당 (대표님은 알기만) |

**주도가 판정할 완료 확인은 검토함에 넣지 않는다.** 대표님 일이 아니다.
`/goals` 에서 보이면 충분하다. 넣으면 검토함이 금방 쓸모없어진다.

## 4. 창구

    GET /review/inbox?limit=50
      → {"items":[{kind, severity, goal_id, goal_title, subject_id,
                   title, owner, detail, since, actions}],
         "empty_note": {"goals": 3, "owners": 12}}

한 번에 모아 준다. 화면이 다섯 군데를 따로 부르면 느리고, 비었을 때
"몇 개가 돌고 있는지" 를 합칠 수가 없다.

`actions` 는 그 항목에서 할 수 있는 것의 이름만 준다(`approve`,
`reject`, `restart`, `open`). 화면이 버튼을 그린다.

## 5. 합격 기준

1. 채팅창 띠가 접힘 한 줄, 누르면 **우측 패널**이 열린다.
1-2. 패널에서 마일스톤 목록·근거·담당 상태가 보이고, **대화는 그대로다.**
1-3. 패널에서 바로 승인·반려·재시작이 된다.
2. `review` 상태면 `/goals` 담당 카드에 **신고한 근거**가 보인다.
3. `/review` 가 목표를 가로질러 손이 필요한 것만 모은다.
4. 주도가 판정할 완료 확인은 검토함에 **안 나온다.**
5. 비어 있으면 "목표 N개 · 담당 M명이 돌고 있습니다" 가 같이 나온다.
6. 검토함에서 바로 승인·반려·재시작이 된다.

## 6. 하지 않는 것

- 모든 변화에 배지 — 막히거나 손이 필요한 것에만
- 검토함에 완료된 것 쌓기 — 끝난 것은 목표 화면에서
- 띠를 두껍게 — 대화가 주인공이다
