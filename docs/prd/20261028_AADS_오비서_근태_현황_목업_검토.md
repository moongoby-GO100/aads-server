# 오비서 근태 현황 승인 검토 설계

document_key: obys-attendance-mockup-review
상태: 미승인 초안. 목업 승인 전이며, 승인 전에는 근태 화면의 추가 변경·운영 배포를 하지 않는다.

## 목적과 범위
관리자 근태 현황의 승인 검토용 독립 HTML v1이다. 가상 직원 A~D와 샘플 지점만 사용한다. 실제 개인정보, 토큰, 업무 쓰기 API, 외부 스크립트, 지도, 위치 수집, 운영 변경은 없다. 다른 프로젝트 관련 기능과 자료를 포함하지 않는다.
기존 admin.html의 어두운 사이드바·파란 강조색·회색 배경·요약 카드·흰 패널을 따른다. 모바일은 메뉴를 축약하고 기록을 두 열 카드로 바꾼다.

## 기존 계약과 유지 대상
mockup-v4-1.html은 admin.html로 이동하는 호환 파일이다. 활성 관리자 route는 admin.html#attendance다. index.html에도 기존 호환 근태 화면이 있으나 수정 대상이 아니다.
app/api/obys_workspaces.py list_attendance_records는 GET /api/v1/workspaces/{business_id}/attendance/records, from/to, limit 최대 500 계약이다. 직원·지점·상태 필터는 이번 목업에서 로컬 필터로만 동작하며 서버 지원으로 주장하지 않는다.
근무시간은 attendance_worked_minutes와 동일하게 자정 넘김 후 휴게 분을 차감한다. 시작=종료, 휴게 초과는 유효하지 않다. 퇴근 누락은 미산출이고 합계에서 제외한다. 화면 합계는 조회 샘플의 산출 가능한 분 합계다.
pending=확인필요, approved=승인, rejected=반려는 admin.html attendanceStatusV41와 같다. 확인필요 건수와 퇴근 누락 건수는 중복될 수 있다.
위치 요약은 별도 관리자 GET /attendance/locations의 inside/outside/unknown 계약이다. 일반 기록 응답과의 실제 통합은 이번 작업에서 하지 않는다. 좌표 미설정은 unknown이며 위치 동의 없음·측정 실패·정확도 부족도 unknown 가능하다. outside는 반경 밖이고 자동 확정 반려가 아니다. 승인 상태와 위치판정은 분리한다. 반려 샘플은 수동 검토 후의 가상 상태다.
clock.html은 직원 출퇴근 화면, attendance-admin.html은 관리자 좌표·반경 보조 화면이다. 실제 보조 경로를 텍스트로 설명하고 데모 버튼만 제공한다.

## 화면과 동작
첫 화면은 시작/종료일·지점·직원·상태 필터, 근태 요약, 출퇴근·휴게·근무시간·위치판정·사유 목록과 직원 상세를 보여준다. 날짜 역전은 별도 오류다.
목록 상세, 승인 데모 안내, 수정 대화상자 입력·검증·취소·데모 저장을 제공한다. 업무 데이터나 목업 승인 상태를 바꾸지 않는다.
검토 시나리오에서 조회 중, 기록 없음, 검색결과 없음, 조회 실패/재시도, 세션 만료/로그인 복구, 권한 부족/권한 확인, 오프라인을 구분한다. 복구는 필터를 유지한 샘플 복귀이며 실제 인증이 아니다.
지각·초과근무·주휴·자동 승인 등 미정 정책은 결정하지 않는다.

## 문서 역할 (plan·spec 겸용)
이 문서는 근태 현황 목업 검토의 PRD 정본이다. 단일 화면 목업 검토라 별도 구현 계획(plan)과 상세 명세(spec) 문서를 두지 않는다.
- plan 역할: 아래 "진행 순서" 절이 대신한다.
- spec 역할: 위 "기존 계약과 유지 대상"·"화면과 동작" 절과 아래 "검증 기준" 절이 대신한다.

## 진행 순서
1. 목업 검토대기 등록 → 2. 대표님 목업 승인 → 3. 승인된 리비전 기준으로 운영 admin.html#attendance 반영 → 4. 운영 화면 PC·모바일 재검증.
승인 전에는 3·4를 진행하지 않는다. 이미 푸시된 runner-e38acacb 변경(API 연결·근무시간·상태·빈 화면 문구)은 "변경 전" 캡처에 그대로 담겨 있으며, 승인 결과에 따라 유지하거나 목업 기준으로 재작업한다.

## 검증 기준
- 목업: assets/verify.cjs 를 실제 Chromium 으로 실행해 PC 1440x1000·모바일 390x844 모두 통과. console/pageerror 0, 외부 요청 0, 가로 넘침 0.
- 변경 전: assets/before-reconstruct.cjs 로 origin/main 의 admin.html#attendance 를 같은 가상 샘플 4건으로 렌더링(실 API 접속 없음).
- 상태 7종(기본·조회 중·기록 없음·조회 실패·권한 부족·세션 만료·오프라인) 캡처가 PC·모바일 모두 있다.

## 등록 경계
가상 직원 A~D 샘플만 사용한다. 목업 승인은 기존 승인 경로로만 하며 이 문서나 등록 도구로 승인하지 않는다. 다른 프로젝트 관련 기능·자료는 포함하지 않는다.
