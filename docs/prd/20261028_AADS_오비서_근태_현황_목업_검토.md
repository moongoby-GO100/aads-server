# 오비서 근태 현황 승인 검토 설계

document_key: obys-attendance-mockup-review
상태: 미승인 초안. 목업 승인 전이며, 승인 전에는 근태 화면의 추가 변경·운영 배포를 하지 않는다.

## 목적과 범위
관리자 근태 현황의 승인 검토용 독립 HTML v1이다. 가상 직원 A~D와 샘플 지점만 사용한다. 실제 개인정보, 토큰, 업무 쓰기 API, 외부 스크립트, 지도, 위치 수집, 운영 변경은 없다. 다른 프로젝트 관련 기능과 자료를 포함하지 않는다.
기존 admin.html의 어두운 사이드바·파란 강조색·회색 배경·요약 카드·흰 패널을 따른다. 모바일은 메뉴를 축약하고 기록을 두 열 카드로 바꾼다.

## 기존 계약과 유지 대상
mockup-v4-1.html은 admin.html로 이동하는 호환 파일이다. 활성 관리자 route는 admin.html#attendance다. index.html에도 기존 호환 근태 화면이 있으나 수정 대상이 아니다.
app/api/obys_workspaces.py list_attendance_records는 GET /api/v1/workspaces/{business_id}/attendance/records, from/to, limit 최대 500 계약이다. 직원·지점·상태 필터는 이번 목업에서 로컬 필터로만 동작하며 서버 지원으로 주장하지 않는다.
근무시간은 attendance_worked_minutes와 동일하게 자정 넘김 후 휴게 분을 차감한다. 시작=종료, 휴게 초과는 유효하지 않다. 퇴근 누락은 미산출이고 합계에서 제외한다. 화면 합계는 조회 샘플의 산출 가능한 분 합계다.
pending=확인필요, approved=승인, rejected=반려는 admin.html attendanceStatusV41와 같다. 확인필요 건수와 퇴근 누락 건수는 중복될 수 있다.
위치 요약은 별도 관리자 GET /attendance/locations의 inside/outside/unknown 계약이다. 일반 기록 응답과의 실제 통합은 이번 작업에서 하지 않는다. 좌표 미설정은 unknown이며 위치 동의 없음·측정 실패·정확도 부족도 unknown 가능하다. outside는 반경 밖이고 자동 확정 반려가 아니다. 승인 상태와 위치판정은 분리한다. 반려 샘플은 수동 검토 후의 가상 상태다.
clock.html은 직원 출퇴근 화면, attendance-admin.html은 관리자 좌표·반경 보조 화면이다. 실제 보조 경로를 텍스트로 설명하고 데모 버튼만 제공한다.

## 화면과 동작
첫 화면은 시작/종료일·지점·직원·상태 필터, 근태 요약, 출퇴근·휴게·근무시간·위치판정·사유 목록과 직원 상세를 보여준다. 날짜 역전은 별도 오류다.
목록 상세, 승인 데모 안내, 수정 대화상자 입력·검증·취소·데모 저장을 제공한다. 업무 데이터나 목업 승인 상태를 바꾸지 않는다.
검토 시나리오에서 조회 중, 기록 없음, 검색결과 없음, 조회 실패/재시도, 세션 만료/로그인 복구, 권한 부족/권한 확인, 오프라인을 구분한다. 복구는 필터를 유지한 샘플 복귀이며 실제 인증이 아니다.
지각·초과근무·주휴·자동 승인 등 미정 정책은 결정하지 않는다.

- plan 역할: 아래 "진행 순서" 절이 대신한다.
- spec 역할: 위 "기존 계약과 유지 대상"·"화면과 동작" 절과 아래 "검증 기준" 절이 대신한다.

### 화면 간 접점 4개(같은 가상 직원 A)
1. C 위치 거부 출근 → B 확인필요 대기함에 "위치 미확인" 으로 나타난다.
2. D 정정 요청 제출 → B 정정 요청 큐에 나타난다.
3. B 반려(사유 필수) → D 에 반려 사유와 "다시 요청" 이 보인다.
4. B 승인 → D 에 승인 결과가 보인다.
접점 값은 목업 localStorage 로만 전달되며 실제 서버 연동 증거가 아니다.

### 신규 API 후보(승인 후 설계, 이번 작업에서 만들지 않음)
- 휴게 시작/종료: `POST /attendance/break/start`, `POST /attendance/break/stop`

- 정정 요청: `POST /attendance/correction-requests`(제출), `POST .../{id}/approve`, `POST .../{id}/reject`(사유 필수)

### v2 검증 기준
- `v2/assets/verify.cjs` 를 실제 Chromium 으로 실행해 PC·모바일 모두 통과, 화면별 상태 수 A 8 · B 12 · C 14 · D 11 = 45, 캡처 PC 45 + 모바일 45 = 90장. console/pageerror 0, http(s) 요청 0, 가로 넘침 0, 44px 미만 터치 대상 0, 접점 4개 통과.
- 변경 전: `v2/assets/before-reconstruct.cjs` 로 origin/main(1f9f8971) 의 admin.html#attendance·clock.html 을 목업과 같은 가상 데이터셋(virtual-7)으로 렌더링한다(실 API 미사용). 4화면 × PC·모바일 = 8장이 role=primary·state=default 이고(A 기록 0건 첫 진입, B 오늘·이전 기록 14건, C 동의 전 첫 화면, D 는 신규 화면이라 진입점 clock.html 첫 화면 — "내 기록 화면은 현재 없음"), C 근무 중 2장은 child 로 유지한다. A 의 "좌표 0/7" 은 admin.html 에 표시 항목이 없어 기록 0건 응답으로 재현한다. v1 `before/` 참조는 v2 manifest 에서 뺐다.
- 등록 게이트: `ManifestInput` 검증 통과, `completeness()`(change_type=modify) 결과 [] — 상태 누락 0, 변경 전 누락 0.
- `v2/manifest.json` 의 sha256·byte_size 가 실제 파일과 일치한다(`sha256sum` 대조).
- B 화면은 좌표를 일부(강남점)만 설정한 뒤의 예시 상태이며 실제 회사 상태가 아니다.
- 이 목업은 미승인 초안이다. 승인은 기존 승인 경로로만 하며 이 문서가 승인을 대신하지 않는다.

### 세션 만료 정책
- 세션 만료 안내 화면을 두지 않는다. 만료를 감지하면 **로그인 화면으로 즉시 이동**하고, 로그인 후 `return` 에 담긴 **원래 화면(쿼리 포함)으로 복귀**한다. 복귀 대상은 같은 묶음의 허용 화면 목록으로 제한해 외부 주소로 보내지 않는다.
- 그래서 모든 screen 의 `states_not_applicable` 에 `session-expired: "세션 만료 시 로그인 화면으로 즉시 이동 — 별도 안내 화면 없음"` 을 넣었다. 검증 스크립트는 화면마다 "세션 만료 → login.html?return=… → 로그인 → 원래 화면" 을 실제로 확인한다.
- 입력 중이던 정정 요청 초안 보존(v2 D)은 이번 정책 범위가 아니며 승인 후 별도로 정한다.

### 주소→좌표 흐름과 실패 복구(F)
1. 주소가 있는 지점: 주소가 채워진 채 열림 → **주소 검색** → 후보 목록(도로명·지번·우편번호) → 같은 건물 선택 → 위도·경도 자동 채움(읽기 전용, 출처 "주소 검색으로 자동 채움").
2. 주소가 없는 지점: "주소 입력부터" 안내, 4자 미만이면 검색하지 않음.
3. 후보 여러 개: 관리자가 직접 고른다(자동 선택하지 않음). 후보 1개도 선택은 사람이 한다.
4. 결과 없음: 건물 번호·지번 검색을 권하고 **좌표 직접 입력**으로 넘어간다.
5. API 실패: 입력한 주소는 유지, **다시 검색** 또는 **좌표 직접 입력**.
6. 저장 검증: 주소 필수, 위도 33~39·경도 124~132(국내 범위), 반경 30~50m(상한 50m 초과 거부). 저장 후 목록·지표(좌표 n/5) 갱신.
7. 지도 타일은 쓰지 않는다 — 텍스트 + 인라인 SVG 반경 도식(상한 50m 점선 포함)만 쓴다.

### 신규 API 후보(승인 후 설계, 이번 작업에서 만들지 않음)
- 주소→좌표: `GET /workspaces/{business_id}/geocode?query=` — 서버가 외부 주소검색(후보: 카카오 로컬 주소검색)을 호출하고 후보 목록(도로명·지번·우편번호·위도·경도)을 돌려준다. 키는 서버 `.env` 에만 두고 브라우저·저장소에 두지 않는다. 시간초과·결과 없음·한도 초과를 구분한 오류 코드가 필요하다.
- 지점 주소 저장: 기존 `PATCH /branches/{id}/geofence` 에 주소 필드를 더할지, 지점 정보 API 로 분리할지 결정 필요.
- 직원별 집계: `GET /attendance/summary/employees?from&to&branch_id`.
- 직원 월 달력: `GET /attendance/employees/{id}/calendar?month=` (날짜별 상태·정정 이력).
- 통계: `GET /attendance/stats?from&to&branch_id` (비율·요일·시간대 분포·급여 전 확인 건수).
- v2 후보 유지: 휴게 시작/종료, 내 기록 `GET /attendance/me`, 정정 요청 제출·승인·반려, 기간 마감.
- 지각·조퇴 기준, 출근율 분모(예정 근무일) 정의, 근무 일정 등록은 **정책 미정 — 설정 필요** 로 남긴다. 목업의 지각·조퇴 수는 화면 배치 확인용 가상 예시이며 기준을 정한 것이 아니다.

### v3 검증 기준
- `v3/admin/assets/verify.cjs`·`v3/employee/assets/verify.cjs` 를 실제 Chromium(headless shell 1234)으로 실행해 PC·모바일 모두 통과. 캡처 수: admin 49 × 2 = 98장, employee 31 × 2 = 62장. console/pageerror 0, http(s) 요청 0, 가로 넘침 0, 44px 미만 터치 대상 0. 결과는 각 묶음 `evidence/playwright-results.json`.
- 화면 간 검사: A ①→F 링크, G 행→H(`?emp=`), B 대기함→H(`?emp=&date=`), I 요약→B·G·F, E 알림→D 정정 작성, B 승인 시 대기함에서 해당 기록 제거, D 승인 시 달력의 누락 1건 감소.
- 변경 전: 각 묶음 `assets/before-reconstruct.cjs` 로 origin/main 의 화면을 가상 API 응답으로 렌더(실 API 미사용) — F=attendance-admin.html(virtual-v3-branches), A=admin.html#attendance(virtual-v3-empty), B·G·H·I=admin.html#attendance(virtual-v3-sample; G·H·I 는 "신규 화면 — 현재 없음, 진입점 화면"), C·D·E=clock.html(virtual-v3-employee-a). 9화면 × PC·모바일 = 18장, role=primary·phase=before·state=default.
- 등록 게이트: 두 묶음 manifest 모두 `ManifestInput` 통과, `completeness()`(change_type=modify) 결과 []. 자산 URI 는 `internal://mockup_assets/AADS/obys-attendance-v3-admin/...`, `.../obys-attendance-v3-employee/...`.
- 각 manifest 의 sha256·byte_size 가 실제 파일과 일치한다(`sha256sum -c` 대조).
- 이 목업은 미승인 초안이다. 정본 등록·목업 검토 등록은 채팅 세션이 하며, 이 문서가 승인을 대신하지 않는다.

### 신규 화면 요소
- **J 직원 목록**: 재직·가입대기·퇴사 명부, 지점·직무, 계약 상태(서명 완료/미서명/없음), 근무 일정 등록 여부, 앱 연결·위치 동의, 오늘 상태. 검색·지점·상태(재직/가입대기/퇴사/일정 미등록/계약 미서명) 필터, 정렬(이름·지점·입사일·준비 미완). 가입대기 행은 링크 없이 "관리자 › 직원·급여 › 직원 현황·초대·가입승인"(현재 코드 있음) 안내 문구만. "일정 미등록 직원 모두 선택" → L(`?emp=E,F,G,H`).
- **K 직원 상세** 탭 4개: ① 이번 달 근무일·근무시간·지각·조퇴·결근·퇴근 누락·확인필요(일정이 없으면 결근 "판정 불가") ② 계약서 근무요일·근무시간·휴게·휴일·주 소정시간을 원문 문자열 그대로 읽기 전용 표시 + 해석 결과, '이 값으로 일정 만들기' → L(`&src=contract`) ③ 요일별 출근·퇴근·휴게·지점, 적용 시작일, 예외일, 변경 이력 ④ 날짜별 상태·처리자·사유·원래 값, 정정 요청 이력. '달력 보기' → H(`?emp=`).
- **L 근무 일정 설정**: 1명/여러 명 선택 → 요일 × 출근·퇴근·휴게·지점 편집, 계약서 값 불러오기, 적용 시작일(마감 기간이면 거부, 지난 날짜면 재계산 경고), 예외일(휴무 추가·대체 근무·근무 시간 변경), 지점 공휴일·휴무일. 계약서 주 소정시간·근무요일과 다르면 직원별 경고(저장은 막지 않음). 저장 확인 대화상자.
- **M 출근·결근 처리**: 직원·날짜 → 그날 일정 vs 실제 기록(분 차이 표시만) → 상태 9종(정상·지각·조퇴·결근·휴무·연차·병가·무급휴가·대체근무) + 사유 5자 이상 필수 → 저장. 관리자 수동 출퇴근 등록·시각 수정(원래 값 보존, 변경 이력). 여러 직원·날짜 일괄 결근 확정/해제(출근 기록 있음·근무일 아님·일정 미등록·마감 기간 자동 제외, 미리보기 후 적용). 마감 기간(~2026-09-30)은 입력 잠금.

### 계약서 근무조건과 근무 일정의 관계
- 계약서는 **법적 약속(원본)**, 근무 일정은 **판정 기준(운영값)** 이다. 일정은 계약서를 바꾸지 않으며, 계약서 값은 L 에서 "불러오기"로 채워 넣는 초기값일 뿐이다.
- 계약서 문자열은 형식이 제각각이다(`월~금`·`월,화,수,목,금`·`화~토` / `60분`·`1시간`·`12:00~13:00(60분)` / `40`·`40시간`·`주 40시간`). 목업의 해석 규칙은 예시이고, 해석 실패 항목은 직접 입력으로 넘긴다.
- 미서명 계약서 값은 "미서명 계약서 값" 표시와 함께만 불러온다. 계약서가 없는 직원도 일정은 직접 입력할 수 있다.
- 일정과 계약서가 다르면(주 소정시간·근무요일·시각) 경고만 하고 저장은 허용한다. 어느 쪽을 기준으로 할지는 정책 미정이다.

### 신규 API 후보(승인 후 설계, 이번 작업에서 만들지 않음)
- 직원 명부 집계: `GET /attendance/roster?branch_id&state` — 가입요청·계약·근무 일정·앱 연결·위치 동의·오늘 상태를 직원 단위로 합친다.
- 계약서 근무조건 읽기: `GET /attendance/employees/{id}/contract-terms` — `contract_payload` 원문 + 해석 결과(실패 항목 표시).
- 근무 일정 CRUD: `GET/PUT /attendance/employees/{id}/schedule`(요일별 출근·퇴근·휴게·지점, `effective_from`), 일괄 `PUT /attendance/schedules:bulk`, 변경 이력 `GET .../schedule/history`. 신규 테이블 후보(근무 일정·예외일·지점 휴무일) — 현재 없음.
- 예외일: `POST/DELETE /attendance/employees/{id}/schedule-exceptions`(off·swap·time), 지점 휴무일 `POST /branches/{id}/holidays`.
- 일별 상태 지정: `PUT /attendance/employees/{id}/days/{date}`(status 9종·reason 5자 이상), 일괄 `POST /attendance/days:bulk`(absent/undo, 제외 사유별 건수 응답).
- 수동 출퇴근 등록 이력: `POST /attendance/records/{id}/adjustments` — 원래 값을 덮어쓰지 않고 조정 행을 남긴다(처리자·시각·사유).
- 모든 쓰기 API 는 마감된 기간이면 거부(잠금 코드)한다.
