## 1. 제품 정의

**자동화 만들기**: 사용자가 하고 싶은 반복 업무를 한 문장으로 말하면, 오비스가 대상 사이트에서 대신 한 번 수행해 보이고, 사용자가 결과를 확인하면 그 경로를 승인 가능한 자동화로 저장하는 기능.

- 진입점: ① 채팅 입력 ② 홈 [자동화 만들기] 버튼 ③ 오비스 화면 [자동화 만들기]
- 보조 경로: 오비스 '레시피 학습'(사용자 직접 시연 녹화) — 대신 시연이 실패할 때 [직접 보여줄게요]로 연결

## 2. 용어

## 4. 기능 요구사항

### 4.1 시작과 이해 (카드 1)
- **FR-01 (P0)** 채팅에서 "자동화/매일/자동으로/받아줘/정리해줘" 등 반복 업무 의도를 인식하면 "자동화로 만들까요?" 제안 버튼을 띄운다. 사용자가 누르면 초안을 만든다. 홈·오비스의 [자동화 만들기] 버튼도 같은 초안 흐름을 시작한다.
- **FR-02 (P0)** 카드 1 「이렇게 이해했어요」는 4칸을 보여 준다: **사이트**(이름 + 주소), **할 일**(한 문장), **받을 결과**(표/파일/화면), **주기**(한 번만/매일/평일/매주 + 시각).
- **FR-03 (P0)** 각 칸은 눌러서 고칠 수 있다. 사이트 주소를 모르면 사이트 이름으로 후보 최대 3개를 보여 준다(기존 등록 도메인 우선).
- **FR-04 (P1)** 입력이 빈 상태에서는 예시 문장 3개를 버튼으로 제공한다.

### 4.2 로그인 연결 (카드 2)
- **FR-05 (P0)** 같은 도메인의 저장된 로그인이 있으면 "○○(계정 표시명)으로 진행" 버튼 하나만 보인다. 여러 개면 고르기.
- **FR-06 (P0)** 없으면 기존 채팅 안전 입력 카드(`VaultCredentialCard`)를 띄운다. 입력값은 채팅 메시지·레시피·로그·캡처 어디에도 남지 않는다.
- **FR-07 (P1)** 로그인이 필요 없는 사이트면 카드 2를 건너뛴다("로그인 없이 볼 수 있는 사이트예요").

### 4.3 대신 해 보기 (진행 화면)
- **FR-08 (P0)** 기본은 서버 레인으로 실행한다. 진행 단계는 사용자 말로 바꿔 보여 준다("로그인하는 중", "매출 메뉴로 가는 중", "어제 날짜를 고르는 중").
- **FR-09 (P0)** 라이브 화면 썸네일을 2초 이하 주기로 갱신한다(기존 `browser_task_live_frames`). 비밀번호 칸은 가린다.
- **FR-10 (P0)** 시연 중 **외부 쓰기·되돌릴 수 없는 행위**(저장·주문·발송·결제·삭제 신호어, `guard.py` 판정)가 다음 단계로 감지되면 실행하지 않고 멈춘 뒤 "여기서부터는 사이트에 저장하는 동작이에요. 확인 후 진행할까요?"를 묻는다. 등록 시 그 단계는 승인 필수로 표시한다.
- **FR-11 (P0)** 시연 시간 상한 5분. 넘으면 중단하고 실패 복구 카드를 띄운다.
- **FR-12 (P1)** 서버 접속 차단·CAPTCHA 감지 시 "내 PC에서 계속하기" 제안(사용자 확인 후 PC 레인). PC 레인이 없으면 설치 안내 링크.

### 4.4 결과 확인 (카드 3)
- **FR-13 (P0)** 마지막 화면 캡처 + 결과 미리보기(표면 5행, 파일이면 파일명·크기)를 보여 주고 [맞아요] [아니에요] 버튼을 둔다.
- **FR-14 (P0)** [아니에요]면 이유 선택지(날짜가 달라요 / 다른 메뉴예요 / 다른 매장·계정이에요 / 직접 보여줄게요 / 기타 입력)를 받고, 이유에 따라 단계를 고쳐 1회 재시연한다. [직접 보여줄게요]는 녹화 경로로 연결한다.
- **FR-15 (P0)** [맞아요]일 때만 등록한다. 결과 확인 없이 등록되는 경로를 만들지 않는다(기존 `screen_verified` 계약 유지).

### 4.5 저장과 승인
- **FR-16 (P0)** 등록 시 단계들을 **로그인 / 이동 / 조회** 조각으로 자동 분할한다. 같은 도메인·같은 저장된 로그인의 승인된 로그인 조각이 있으면 새로 만들지 않고 재사용한다.
- **FR-17 (P0)** 자동화의 위험 등급은 단계 중 최고 등급으로 정한다(`READ < WRITE_INTERNAL < WRITE_EXTERNAL < IRREVERSIBLE`). 화면에는 "보기만 해요 / 사내에 저장해요 / 사이트에 저장해요 / 되돌릴 수 없어요"로 표시한다.
- **FR-18 (P0)** 승인 대기가 생기면 승인자에게 홈 배지 + 인박스 + 텔레그램으로 알린다. 48시간 미처리 시 1회 재알림. 14일 미처리 시 '만료'로 표시하고 요청자에게 [다시 요청] 버튼을 준다.
- **FR-19 (P1, 정책 D1 결정 후)** 읽기 전용(`READ`) 자동화는 같은 도메인에서 승인 이력이 있으면 자동 승인한다. 그 외 등급은 항상 사람 승인.
- **FR-20 (P1)** 완료 카드에서 주기를 확정하면 기존 오비스 자동실행(`loop_controller`)에 등록한다. 승인 전이면 "승인되면 매일 09:00 부터 실행돼요"로 표시.

### 4.6 반복 사용과 목록
- **FR-21 (P0)** 채팅에서 "어제 매출 받아줘"처럼 말하면 승인된 자동화와 매칭(`work_recipe/orchestrator.resolve_recipe`)해 실행한다. 후보가 2개 이상이면 고르기 카드.
- **FR-22 (P0)** '내 자동화' 화면: 이름, 사이트, 상태(사용 가능/확인 기다리는 중/고장/만료), 마지막 실행 결과·시각, 다음 실행 시각, [지금 실행] [멈추기] [고치기].
- **FR-23 (P1)** 목록은 `work_recipes`·`ovis_recipes`·`browser_recipes` 를 조회 통합하고 출처를 관리자 '자세히'에만 표시한다.

### 4.7 실패 복구
- **FR-24 (P0)** 실패를 6종으로 분류해 사용자 문장과 버튼을 준다: 비밀번호 틀림 · 추가 인증/CAPTCHA · 접근 차단 · 화면 바뀜 · 결과 없음 · 일시 오류.
- **FR-25 (P0)** 일시 오류만 자동 재시도 1회. 비밀번호 틀림·CAPTCHA·차단은 재시도하지 않고 사용자 행동을 기다린다(로그인 반복 제출 금지).
- **FR-26 (P1)** 재시작은 마지막으로 성공한 조각부터. 로그인 세션이 살아 있으면 로그인 조각을 건너뛴다.

### 4.8 용어 숨김과 관리자 보기
- **FR-27 (P0)** 일반 화면에 `work_key`, `lane`, `credential_scope`, `session_id`, `recipe`, `registration`, `e2e` 문자열을 노출하지 않는다.
- **FR-28 (P2)** 관리자는 각 자동화의 [자세히]에서 내부 식별자·버전·조각 구성·레인을 볼 수 있다.

## 8. 계측 이벤트

`automation_draft_events.event_type`:
`draft_created`, `intent_confirmed`, `intent_edited`, `credential_linked`, `credential_requested`, `demo_started`, `demo_step`, `demo_paused_risk`, `demo_failed`, `result_confirmed`, `result_rejected`, `registered`, `approval_notified`, `approval_reminded`, `approved`, `rejected`, `expired`, `schedule_set`, `run_from_chat`.
각 이벤트는 `draft_id`, 시각, 단계, 실패 분류만 담는다(비밀값 금지). 9절 지표는 이 이벤트로 계산한다.
