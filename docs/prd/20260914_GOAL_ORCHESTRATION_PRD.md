# 골 오케스트레이션 — PRD·설계

- 작성 2026-09-14 KST · 배경은 [기획서](../plans/20260914_GOAL_ORCHESTRATION_기획서.md)
- 범위: 스케줄러 주기 안의 지시·보고·승인·개입 + `/goals` 현황판

## 0. 구동 지점

`app/main.py` 의 골 제어 사이클(2~3분). 한 사이클에서 순서대로 돈다.

    reconcile(None)              링크 재조정
    reconcile_release_links(None) 릴리스 근거로 완료 승격
    advance_active_goals(None)   마일스톤 전진
    dispatch_pending_milestones  ← 새로 추가: 담당에게 지시
    report_goal_events           ← 새로 추가: 대표님께 보고

**프로젝트를 넘기지 않는다(`None`).** 셋 다 `"AADS"` 로 박혀 있어서
GO100·NAS·NTV2·SF 목표가 전부 방치되고 있었다.

## 1. 지시 — `app/services/goal_dispatch.py`

### 대상

    status = 'in_progress'  이고  목표가 active  이고
    (한 번도 안 보냈거나  OR  마지막 발송이 RETRY_AFTER 분 전)

담당은 `milestones.owner_session_id`, 없으면 `owner_role_key` 로 세션을
찾는다. 둘 다 없으면 말을 걸 곳이 없으므로 건너뛴다.

### 끊김·오류 처리 — 네 겹

**보낸 것과 답이 온 것은 다르다.** 이것이 이 모듈의 핵심이다.

| 겹 | 규칙 |
|---|---|
| 1 | 보낸 시각 이후 그 세션에 **진짜 답**이 쌓였는지 본다 |
| 2 | 없으면 `RETRY_AFTER_MIN`(기본 30분) 뒤 재시도 |
| 3 | `MAX_RETRY`(기본 3회)를 넘으면 멈추고 `dispatch_note` 에 사유 |
| 4 | 한도 초과 건은 보고 경로로 대표님께 — **조용히 포기하지 않는다** |

"진짜 답" 판정에서 아래는 답으로 세지 않는다. 이것들이 바로 끊긴 경우다.

    content LIKE '⏳%'                    진행중 표시
    content LIKE '⚠️ _응답 생성이%'        중단 표시
    length(content) <= 40                 빈 껍데기

**발송 자체가 예외로 실패해도 횟수를 올린다.** 올리지 않으면 같은 오류로
매 사이클마다 재시도하며 폭주한다.

### 폭주 방지

    GOAL_DISPATCH_MAX_PER_CYCLE   기본 2   한 사이클 발송 상한
    GOAL_DISPATCH_MAX_RETRY       기본 3   마일스톤당 재시도 한도
    GOAL_DISPATCH_RETRY_AFTER_MIN 기본 30  재시도 간격
    GOAL_DISPATCH_ENABLED         기본 true

### 스키마

    milestones.dispatched_at         timestamptz
    milestones.dispatched_session_id uuid
    milestones.dispatch_count        integer NOT NULL DEFAULT 0
    milestones.dispatch_note         text

## 2. 보고 — `app/services/goal_report.py`

### 언제 — 시각이 아니라 사건

| 사건 | 주도 채팅창 | 텔레그램 |
|---|:---:|:---:|
| 마일스톤 완료 | ○ | — |
| 마일스톤 막힘(재시도 한도 초과) | ○ | ○ |
| 목표 달성·실패 | ○ | ○ |

정해진 시각에 요약을 보내면 아무 일 없는 날에도 알림이 온다. 그러면
알림을 안 보게 되고, 정작 중요한 것도 묻힌다.

### 어디로

**주도 채팅창** — 대표님 지시: "해당 목표는 주도책임 채팅창과 수시로
보고받고 나의 의견과 방향 설정 승인결정등을 할 수 있게". 목표에 묶인
`role_key LIKE '%Lead'` 세션에 남긴다. `assistant` 역할로 넣는다 —
보고지 질문이 아니므로 답을 요구하지 않는다.

**텔레그램** — 대표님이 지금 보셔야 하는 것만.

### 중복 방지

`goal_report_log(goal_id, subject_id, event)` UNIQUE. 스케줄러가 2~3분마다
도는데 기록이 없으면 같은 완료 소식을 하루 종일 보낸다.

## 3. 방향 승인 — `app/services/direction_guard.py`

### 지금 게이트가 못 잡는 것

`live_trading_guard` 는 **파일 쓰기·명령 실행**만 본다. 그래서 이것들이
승인 없이 지나간다.

- 마일스톤 생성·변경·삭제
- 목표 기준·해석 변경 (예: 3% 를 실현손익 대신 평가손익으로)
- 담당 추가·교체
- 여러 담당에게 동시 지시

**방향은 자유롭게 바뀌고, 그 방향대로 파일을 고치려는 순간에야 멈춘다.**
이미 담당 셋이 몇 시간 일한 뒤다.

### 잡는 규칙

| 도구 | 조건 | 판정 |
|---|---|---|
| `db_safe_write` | `milestones` / `goals` / `goal_task_links` / `prompt_assets` / `chat_sessions.role_key` 에 쓰기 | 승인 |
| `ask_session` | 같은 줄기에서 N명 이상에게 동시 지시 | 승인 |
| 모든 도구 | 대표님이 `전체 정지` 를 걸어 둔 상태 | 차단 |

**실매매 게이트와 같은 구조**를 쓴다. 확실할 때만 막고, 애매하면 통과시킨다 —
정상 작업을 막으면 담당들이 게이트를 우회할 길을 찾는다.

승인 요청은 기존 `/approvals` 화면에 같이 뜬다. 새 화면을 만들지 않는다.

## 4. 개입 — 대표님이 전체에 닿는 길

| 명령 | 효과 |
|---|---|
| 전체 정지 | 도는 작업을 멈추고 지시 대기로. 게이트가 모든 쓰기를 차단 |
| 방향 지시 | 주도 + 담당 전원에게 동시 전달. 기존 지시보다 **우선** |
| 되돌리기 | 마일스톤을 `pending` 으로 되돌리고 발송 기록 초기화 → 재지시 |

### 우선순위 규칙

**대표님 지시가 주도 지시를 이긴다.** 지금은 이 규칙이 없어서 담당이
**나중에 온 것**을 따른다. 모든 담당 프롬프트에 못 박는다.

    지시가 충돌하면 대표님 지시를 따른다. 주도 지시와 어긋나면
    주도에게 알리되, 멈추지 말고 대표님 지시를 수행한다.

## 5. 현황판 — `/goals`

목표마다 담당별 현재 상태를 붙인다. 창 8개를 열지 않아도 되게.

    목표 #310  일일 누적수익 3%                진행률 ■■□□□
    ────────────────────────────────────────────────
    주도  전략카드담당   기준선 측정 중     2분 전 · 도구 12회
          파동엔진담당   응답 대기          18분째  ⚠
          데이터엔진담당 유실 구간 조사 중  1분 전 · 도구 4회

출처: `chat_sessions` 최근 활동 + `milestones.dispatched_at` +
진행 중 실행 여부. **새 수집기를 만들지 않는다** — 이미 있는 것을 모은다.

## 6. 합격 기준

1. 마일스톤이 `in_progress` 가 되면 담당 세션에 지시가 들어간다.
2. 응답이 끊기면 30분 뒤 재시도하고, 3회 뒤 텔레그램이 울린다.
3. 완료가 주도 채팅창에 남는다. 같은 사건이 두 번 오지 않는다.
4. 주도가 마일스톤을 바꾸려 하면 `/approvals` 에 뜨고 실행되지 않는다.
5. 대표님이 `전체 정지` 를 걸면 모든 담당의 쓰기가 막힌다.
6. `/goals` 에서 담당별 현재 상태가 보인다.
7. GO100·NAS·NTV2·SF 목표가 AADS 와 똑같이 처리된다.

## 7. 안 하는 것

- 시각 기반 정기 보고
- 담당 세션 자동 생성 — 채팅창이 느는 것을 대표님이 모르면 안 된다
- 주도의 자율 방향 전환
