## 4. 요구사항 — 휴면·정리

활동 기준: `goals.updated_at` 이 아니라 **마일스톤 상태 변경, 연결 러너 작업 생성·종료, 담당 세션의 목표 연결 작업** 중 최신 시각(`last_activity_at`)을 쓴다.
러너 작업의 목표 귀속은 `pipeline_jobs.goal_id` **또는 지시문의 `GOAL_ID:` 줄** 둘 다 본다(rev2). 2026-10-15 목표관리자 실측: 최근 14일 러너 작업 322건이 지시문에만 목표를 적고 연결 칸은 비어 있었고, a4d50919 는 연결 칸만 보면 휴면으로 오판된다.

| ID | 요구사항 | 완료기준 |
|---|---|---|
| DO-1 | 14일 활동 없음 → `dormant` 파생 상태(저장 상태는 바꾸지 않음), 칩 💤, 맨 뒤 정렬 | API 응답 `dormant=true` |
| DO-2 | `blocked` 목표는 휴면 카드에 넣지 않고 **'차단 해소 또는 종료' 카드로 따로** 올린다(rev2: 휴면 처리하면 차단 원인이 가려짐). 차단 사유·해제 조건이 비어 있으면 `dormant_reason=blocked_without_reason` 로 표시 | API 응답 필드 + 카드 분리 |
| DO-3 | 휴면 7일 경과 → 주 1회 정리 카드. 선택지: 재개 / 일시정지(`paused_at`·`paused_reason` 재사용) / 종료 / 다른 목표에 병합 | 카드 생성 + 선택 반영 |
| DO-4 | 첫 정리는 카드 1장에 휴면 후보 일괄, 목표별 선택 | 카드 1장 |
| DO-5 | 자동 종료·자동 삭제 금지. 대표님 선택 전에는 표시만 | 코드에 자동 close 경로 없음 |
| DO-6 | 첫 정리 순서: **① P0 3개 선택 → ② 선택된 P0 를 뺀 휴면 카드 → ③ 차단 해소·종료 카드**(rev2). 선택되지 않은 P0는 P1 하향 | 정리 후 active P0 ≤ 3, 선택 P0 가 휴면 카드에 없음 |

## 5. 요구사항 — 자동승인 표시와 실제 동작 일치

| 상태 | 판정 | 칩 |

| 만료 | 만료 시각 경과 | `⌛ 만료` |
