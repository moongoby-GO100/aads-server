# [AADS/오비서] 현재 관리자 직원 계약 통합 — PRD v1.0.1 (검토 초안)

버전: 1.0.1 / 검토용 초안 / 승인·구현·운영 검증 미완료

## 제품 목표

가입 승인 다음에 관리자가 현재 화면을 떠나지 않고 계약을 작성하며, 요청 결과와 직원 서명·PDF 상태를 같은 직원 문맥에서 확인한다. 메뉴를 찾기 위해 기존/현재 관리화면을 왕복하는 흐름을 없앤다.

대상: 대표·권한 있는 인사/점포 담당, 본인 계약에 접근하는 직원.
범위: 직원 계약 진입점·조건 입력·미리보기·저장·서명요청·재알림·서명본 상태/다운로드·실패 복구.
제외: 전체 관리자 화면 재설계, 자동 법률 판정, 실제 직원 조건 임의 확정, 계약 일괄 생성, 공제·급여 전면 개편, 외부 유료 발송 구매.

## 사용자 시나리오

대표: 가입 승인을 완료했다 → 승인 직원 행에 계약 작성이 보인다 → 회사·점포가 고정된 입력 패널에서 조건을 확정한다 → 미리보기 후 저장한다 → 서명을 요청하고 발송 결과를 확인한다.

인사 담당: 계약 목록에서 요청 대기와 알림 실패를 구분한다 → 실패한 알림을 재전송하거나 실제 링크를 공유한다 → 직원 서명 완료 후 서명본 PDF를 확인한다.

직원: 자신에게 발급된 링크로 로그인한다 → 자기 계약과 조건을 확인한다 → 동의 및 자필서명을 제출한다 → 완료 상태와 서명본을 확인한다. 링크 만료나 권한 문제면 요청 관리자와 복구 행동을 안내한다.

## 입력 항목과 데이터 출처

| 그룹 | 항목 | 출처·판정 |
|---|---|---|
| 계약 대상 | employee_request_id, 직원명/이메일/생년월일/연락처/주소, business_id, branch | 승인된 입사요청·권한 있는 마스터, 누락은 보완 안내 |
| 사용자 | 상호·사업자번호·대표자·주소·연락처 | 사업자 마스터 대조, 다른 회사 자료 혼합 금지 |
| 계약 기본 | 유형·작성일·입사일·종료일·직무·장소 | 관리자 입력, 현재 지원 유형 사용 |
| 임금 | 시급/월급/용역비·금액·지급일·산식·수당 | 관리자 확정; 실제 금액 기본값 추정 금지 |
| 근무 | 요일별 근무지·시작/종료/휴게·주간시간 | 직원/점포 문맥; 익일 종료 가능 여부는 서비스 지원 확인 |
| 추가 | 수습·보험 구분·식사·휴일·특약·동의·외국인/미성년 관련 조건 | 현재 validator의 유형별 필수항목에 맞춰 노출 |

계약조건 및 법적 요건의 신규 판단은 이 PRD에서 확정하지 않는다. 화면의 필수 필드와 현 서버 validator가 일치하는지 개발·노무 검수에서 확인한다. 목업은 주요 동선 시연용이며 전체 유형별 조건을 구현했다고 볼 수 없다.

## 검증 계획

| 검증 | 대상·방법 | 완료 기준 |
|---|---|---|
| 단위/통합 | 기존 계약·membership·signing 테스트와 변경 영향 테스트 | 필수/권한/알림 실패/동시 요청/서명 snapshot 통과 |
| 관리자 E2E | 승인된 시험 직원, 현재 V4.1 직원 화면 | 목록→조건→미리보기→저장→요청 화면 캡처와 API 대조 |
| 직원 E2E | 동일 계약 본인 계정 | 열람→동의→자필서명→PDF 실파일 확인 |
| 실패 회귀 | 400/401/403/409/5xx·알림 실패·PDF 실패 | 허위 성공 없음, 재시도·문맥 복구 성공 |
| 다점포/다회사 | 같은 직원의 서로 다른 승인 연결 | 계약 당사자·권한·점포 혼합 없음 |
| 모바일 | 390×844 및 1440×1000, 키보드 | 주요 입력·CTA·상태가 보이고 겹침/가로 넘침 없음 |
| 배포 | 카페24 origin release SHA·digest·health·롤백·5분 감시 | 현재 관리자에서 실제 배포본 실행, P0/P1 신규 오류 없음 |

브라우저 불가 시 HTTP→API health→프로세스 순으로 폴백하고 운영 화면 검증과 별도 보고한다. 현재 기획 목업 검증은 운영 E2E를 대체하지 않는다.

## 작업과 게이트

G0: 기획·설계·PRD·목업 저장 및 보고(이번 요청).
G1: CEO 기획 확인 후 구현 작업 범위/충돌 프리플라이트.
G2: 구현·회귀·현재 화면 증거·검수.
G3: 기존 승인 범위와 변경 SHA를 대조하여 카페24 릴리스.
G4: 시험 계정으로 운영 관리자·직원 E2E 및 5분 감시.

G0를 G2/G4 완료로 표시하지 않는다. 기획 검토 전에 중단된 `runner-6ed52003`은 자동 승인·재실행하지 않는다. 산출물 잔존 여부는 별도 diff로 확인하여 보존한다.

## 미확정과 담당 확인

- Developer: 공용 editor의 기존 폼 재사용 경계, 실제 router/query 파라미터, 수정 payload, 다중 worker 요청 보호, 세션 초안 복구 방식.
- HRPayrollLead: 기존에 전달받은 시험 직원·회사, 다점포 근무와 계약 당사자, 실제 조건/템플릿 검토. CEO에게 같은 정보를 재요청하지 않는다.
- Ops: 카페24 앱 릴리스 경로의 준비·승인·현재 배포 상태와 롤백 가능한 digest.

성공률·처리시간 목표는 운영 데이터가 없어 수치로 추정하지 않는다. 최초 검증 후 측정한 값을 근거로 개선한다.
