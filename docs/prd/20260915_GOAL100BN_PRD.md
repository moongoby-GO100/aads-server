**해석.** 현재 운영 임계값 0.25는 **F1 최적값**이다. F1은 정밀도와 재현율의 균형점일 뿐

이 임계값이 실전에 그대로 반영되고 있음을 보여준다. 임계값을 올리면 정밀도는 오르지만
진입 건수가 급감한다 — 그 교환비의 최적점은 **EV(기대값) 곡선으로만** 정할 수 있다(FR-4).

증권사에는 없는 포지션이 내부 원장에는 OPEN으로 살아 있다. 이 상태에서 청산 로직이
돌면 **보유하지 않은 종목에 매도 주문**을 내거나, 반대로 실제 보유분을 놓친다.
CEO가 지적한 *"매수 취소·거절이 실제 증권사에 매매가 되었다"* 와 같은 계열의 결함이다.

### D-2. 계좌 안전장치가 코드에서 집행되지 않음 (P0)

`v4_account_config.single_stock_max_pct = 10.00`(종목당 10% 상한)이 DB에 있으나,

실매매 엔진 경로에는 없다.** [출처: `grep -rn single_stock_max_pct backend/ scripts/`]

실제로 오늘 삼성전자 1주를 249,500원에 매수했다 — 예수금 458,798원의 **54.4%**,
일일 주문한도 400,000원의 62.4%다. [DB `go100_trades` 09-15 09:03]

LIVE 카드 2개 배분액 합계 1,264,345원 vs 실제 예수금 458,798원 = **2.76배**.
[출처: `go100_strategy_cards`, `v4_account_holdings`]

§3.1 참조. 현재 F1 최적값 0.25 = precision 29.63% 구간에서 진입 중.

## 5. 기능 요구사항

### FR-1. 원장 정합 엔진 (D-1 해소) — P0

| 항목 | 내용 |
|---|---|
| 요구 | 증권사 잔고를 **단일 진실 원천(SSOT)** 으로 삼아 `go100_positions` / `go100_live_orders` / `go100_trades` 를 주기 대사(reconcile)한다 |
| 규칙 | 증권사에 없는 OPEN 포지션 → 자동 CLOSE + `exit_reason='reconcile_phantom'` 기록. 반대 방향(증권사에 있는데 내부에 없음) → 알림 후 CEO 확인 |
| 주기 | 장중 5분, 장 마감 후 1회 |
| 가드 | 대사는 **기록 정정만** 한다. 주문을 내지 않는다 |
| 수용기준 | AC-1.1 유령 포지션 주입 테스트에서 5분 내 자동 정정 · AC-1.2 정정 건수/사유가 로그·DB에 남음 · AC-1.3 SUBMITTED 상태로 N분 초과 잔류한 주문은 증권사 조회로 상태 확정 |

### FR-2. 리스크 게이트 실집행 (D-2 해소) — P0

| 항목 | 내용 |
|---|---|
| 요구 | 주문 직전 단계에서 `single_stock_max_pct`, `daily_order_limit`, `consecutive_loss_halt`를 DB에서 읽어 **차단**한다 |
| 규칙 | 위반 주문은 전송하지 않고 `go100_live_orders.safety_check_passed=false` + 사유 기록 |
| 수용기준 | AC-2.1 한도 초과 주문이 실제로 거부됨(테스트) · AC-2.2 거부 사유가 조회 가능 · AC-2.3 기존 정상 주문 흐름 회귀 없음 |

### FR-3. 자본 정합 (D-3 해소) — P0

| 항목 | 내용 |
|---|---|
| 요구 | `sum(allocated_amount of LIVE cards) ≤ 가용예수금 × 안전계수(기본 0.9)` 를 상시 만족 |
| 규칙 | 초과 시 카드별 비율 축소 또는 카드 LIVE 해제. 축소는 CapitalArbiterV2 경유 |
| 수용기준 | AC-3.1 위반 시 알림 + 자동 축소 · AC-3.2 축소 전후 배분액 로그 · AC-3.3 예수금 스냅샷 기준 시각 명시 |

### FR-4. EV 기반 진입 임계값 (D-4 해소) — P0

| 항목 | 내용 |
|---|---|
| 요구 | 임계값 0.10~0.90을 0.05 간격으로 스캔해 **비용(수수료 0.21% + 시총별 슬리피지) 반영 후 순기대값 곡선**을 산출한다 |
| 산출물 | `reports/20260915_GO100_M2_EV_threshold_curve.md` + JSON |
| 채택 규칙 | 순기대값 최대 임계값을 후보로 하되, 해당 임계값의 **월 진입 건수 하한**(미정 — CEO 승인 필요)을 함께 만족해야 채택 |
| 적용 | 분석 → SHADOW 비교 → CEO 승인 → LIVE 반영 순서. 분석 단계에서 운영값 변경 금지 |
| 현재 | 산출 작업 진행 중(`runner-f188843f`, 2026-09-15 11:12 기준 미완) |
| 수용기준 | AC-4.1 곡선 표 존재 · AC-4.2 비용 상수 출처가 코드 경로로 표기 · AC-4.3 권고 임계값 1개 제시 · AC-4.4 운영 설정 변경 0건 |
