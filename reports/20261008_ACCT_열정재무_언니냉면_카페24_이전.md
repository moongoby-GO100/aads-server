# 열정 재무·언니냉면 화면 카페24 이전 — 조사와 구현

2026-10-08 KST. 조사(A)와 구현(B) 완료. 반영(C)은 CEO 승인 후 진행한다.

## 1. 결론

- **열정 재무는 이미 카페24에서 돌고 있다.** 카페24 ACCT 앱(`app/obys_standalone.py`)은
  `app.yeoljeong_main.app` 을 감싼 것이라 코드가 같다. 2026-09-18 이름 변경으로 화면은
  `/static/apps/obys/` 로 옮겨졌고, 옛 주소 `/static/apps/yeoljeong-finance/index.html` 은 카페24 apache 가
  301 로 보낸다. 지시서의 "카페24 ACCT 앱에는 yeoljeong 코드가 없다"는 사실과 다르다.
  contabo116 `yeoljeong-finance` 컨테이너는 응답만 하고 쓰이지 않는다
  (`/static/apps/obys/`·`/static/apps/yeoljeong-finance/index.html` 모두 404).
- **이전할 것은 언니냉면이다.** 카페24 apache 는 `/unni-naengmyeon/` 을 ACCT 앱으로 넘기고, 앱의 JWT
  미들웨어가 401 JSON 을 낸다. 이것이 401 의 원인이다.
- **contabo116 obys DB 에는 10-08 이후 새로 쌓인 행이 없다.** 카페24에도 없다.

## 4. 언니냉면

| 항목 | 내용 |
|---|---|
| 정본 | `/root/aads/aads-dashboard`(src/app/unni-naengmyeon, 최근 d4f62c6 10-06). `aads-dashboard-unni` 는 07-24 에 멈춘 대시보드 전체 사본이고 조리법이 없다. 다만 contabo116 nginx `/brands/` 는 아직 그 사본의 public 을 가리킨다 |
| 화면 | `/unni-naengmyeon`(공개), `brand/logo`(공개), `brand/banners`(공개), `recipes`(직원용 — 로그인 필요) |
| API | `POST /api/v1/unni-naengmyeon/inquiries`(공개 문의, 테이블 `unni_naengmyeon_inquiries`, contabo116 aads DB 3건 / 최근 07-22) |
| 인증 | 조리법만. 원래는 Next 서버가 `fb_access_token` 쿠키로 `aads.newtalk.kr/api/v1/auth/me` 를 불러 확인 — 즉 contabo116 AADS 에 묶여 있었다 |
| 자산 | `/_next/static`(8.2MB), `/brands/unni-naengmyeon`(222.5MB, 300dpi 인쇄본 포함). 화면이 참조하는 자산 64개 |
| 401 원인 | 카페24 apache 가 `/unni-naengmyeon/` 을 ACCT 앱으로 넘기고 앱 JWT 미들웨어가 401 |

**방식: 정적 스냅샷 + ACCT 앱(Next 컨테이너를 두지 않음).** 공개 화면 3개는 요청마다 바뀌는
데이터가 없다. 카페24에 Next 컨테이너를 두면 대시보드 전체 이미지를 빌드·운영해야 한다. 그래서
공개 화면·자산은 apache 가 `/srv/unni-naengmyeon/current` 에서 직접 내고, 동적인 두 가지만 이미 떠 있는
ACCT 앱이 받는다.

- 문의 POST → ACCT 앱(인증 예외, 기존 IP 빈도 제한·허니팟 유지). 테이블은 앱 공용 풀의 DB(`obys_auth`)에
  `CREATE TABLE IF NOT EXISTS` 하고, 앱 DB 역할에 INSERT 만 준다(obys_auth 에는 default privileges 가 없다).
- 조리법 → ACCT 앱이 오비서 로그인(aads_token 쿠키/Bearer JWT)을 확인하고 `app/sites/unni_naengmyeon/recipes.html`
  을 낸다. 미로그인은 `/static/apps/obys/index.html?redirect=/unni-naengmyeon/recipes` 로 302 — 오비서
  index 의 기존 로그인 후 이동 처리를 그대로 탄다. 원래 판정(`hasFoodBizRecipeAccess`)도 사실상
  "유효한 로그인"이었다. 조리법 HTML 은 Next 페이지(page.tsx·CSS)에서 생성해 옮겼고, fb 경로의 정본은 이제 이 파일이다.
