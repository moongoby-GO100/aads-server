## 2. 공통 전자계약 적용 원칙

1. 서명 완료와 교부 완료를 분리한다.
2. 완료본 PDF, 원본문서, 변수 JSON, 감사증적 JSON을 함께 보존한다.
3. 모든 문서는 템플릿 버전과 정책 버전을 가진다.
4. 기존 완료 계약은 수정하지 않고 변경계약 또는 supersede 버전을 만든다.
5. 본인확인, 서명 시각, IP, User-Agent, 문서 SHA-256 해시를 계약 이벤트로 저장한다.

## 3. 법무/노무 검토 체크리스트

| 구분 | 검토 항목 |
|---|---|
| 근로계약 | 임금, 소정근로시간, 휴일, 연차, 업무장소, 업무내용, 교부 방식 |
| 프리랜서 | 근로자성 오인 조항, SOW, 검수, IP 귀속, 개인정보 처리위탁 |
| 입점계약 | 수수료, 정산보류, 반품/CS, 금지상품, 개인정보, 정책 변경 재동의 |

## 4. 시스템 등록 순서

1. `/docs`에서 템플릿 파일을 확인한 뒤 본문을 `contract_templates.body_markdown`에 등록한다.
2. 각 파일의 변수 스키마를 `contract_templates.variable_schema`에 등록한다.
3. 관리자 UI에서 필수 변수 누락 시 발송을 막는다.
4. 테스트 계약 1건씩 발송해 `SIGNED_ALL -> DELIVERED -> ACTIVE` 상태 전이를 확인한다.
5. 완료본과 감사증적 해시를 DB에 저장한다.
