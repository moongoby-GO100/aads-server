NTV1 / Sabangnet Automation Plan

뉴톡 V1 사방넷 로그인 기반 상품대량등록 RPA 자동화 기획서 v1.0

현재 V1에서 운영 중인 A안(사방넷 엑셀 자동생성)을 유지하고, B안(로그인 기반 자동 업로드/전송)을 단계적으로 붙이는 실행 기획서입니다.

대상 시스템NewTalk V1 / CodeIgniter
대상 경로/home/danharoo/www
권장 방식반자동 검수 + RPA 자동 업로드

1. 결론

V1에 우선 적용 가능합니다. 현재 V1에는 이미 사방넷 엑셀 생성 로직이 있으므로, 상품 매핑을 새로 만들지 않고 기존 엑셀 생성 결과를 Playwright 작업자가 사방넷에 로그인해 업로드하는 방식이 가장 안전합니다.

초기 버전은 완전 무인 자동화가 아니라 관리자 사전검수 → 실행 승인 → 사방넷 로그인 업로드 자동화 → 결과 캡처/로그 보고 구조로 시작해야 합니다. 사방넷 UI 변경, 로그인 보안절차, 필수값 누락, 중복 등록을 방지하기 위해 승인 단계를 남기는 것이 운영 리스크를 줄입니다.

2. 현재 V1 A안 확인 결과

구분 확인 내용 근거
상품 선택 화면 상품 목록에서 선택 상품을 사방넷 엑셀로 생성하는 UI가 존재합니다. /seller/views/products/goods_list.php의 getSelectedDown('E')
엑셀 생성 컨트롤러 선택 상품 ID를 받아 상품/상세/이미지/회원 정보를 조회하고 사방넷 엑셀을 생성합니다. /seller/controllers/products.php의 goods_select_sabangnet_make()
다운로드 컨트롤러 생성된 파일을 사방넷등록엑셀파일(YYYYMMDDHHIISS).xls로 다운로드합니다. goods_select_zip_down('E')
컬럼 매핑 A~CC 사방넷 대량등록 컬럼 정의가 설정 파일에 존재합니다. /seller/config/autoscrap.php의 sabangnet_excel_data
매입처 ID V1 회원의 users.sabangnet_id를 엑셀 J열 매입처ID에 반영합니다. goods_excel_sabangnet_data()
이미지 URL 상품코드 기반 이미지 URL을 https://newtalk.kr/data/files/goods/goodscode/img/...로 자동 생성합니다. goods_excel_sabangnet_data()
핵심은 현재 A안이 "상품 데이터 정제와 사방넷 양식 변환"을 이미 담당한다는 점입니다. B안은 이 로직을 건드리지 않고 업로드만 자동화해야 실패 범위가 작습니다.

3. 목표 범위

이번 V1 적용 목표

  • 관리자가 선택한 상품을 기존 방식으로 사방넷 엑셀 생성
  • 생성된 엑셀을 서버 작업 큐에 등록
  • 사방넷 계정으로 로그인
  • 사방넷 상품 대량등록 화면으로 이동
  • 엑셀 업로드 및 검증 결과 수집
  • 사방넷에서 각 마켓 전송 실행 또는 전송 대기 상태까지 자동화
  • 성공/실패/보류 결과를 V1 관리자 화면에 기록

이번 범위에서 제외

  • 사방넷 공식 API 연동
  • 사방넷 약관 우회 또는 보안장치 우회
  • 캡차/OTP 자동 해제
  • 상품 데이터 매핑 전면 재작성
  • 도매회원에게 무제한 직접 실행 권한 부여
  • 실패 상품 자동 재등록 무한 반복

4. 권장 사용자 흐름

1. 상품 선택V1 상품 목록에서 사방넷에 보낼 상품 선택
2. 사전검사필수 컬럼, 이미지 URL, 매입처ID, 가격, 옵션 검사
3. 엑셀 생성기존 goods_select_sabangnet_make() 재사용

5. RPA 실행Playwright가 사방넷 로그인 후 엑셀 업로드
6. 결과 보고업로드 결과, 실패 사유, 스크린샷 저장

5. 시스템 구조

NewTalk V1 관리자
  └─ 상품 선택 / 사방넷 자동등록 요청
      └─ CodeIgniter Controller
          ├─ 기존 엑셀 생성: goods_select_sabangnet_make()
          ├─ 신규 사전검사: SabangnetPrecheck
          └─ 신규 작업 등록: sabangnet_rpa_jobs
              └─ RPA Worker
                  ├─ Playwright Chromium
                  ├─ 사방넷 로그인
                  ├─ 대량등록 엑셀 업로드
                  ├─ 결과 텍스트/스크린샷 수집
                  └─ V1 관리자 결과 화면 업데이트

구현 원칙

원칙 내용 이유
기존 엑셀 생성 유지 사방넷 컬럼 매핑은 autoscrap.php와 goods_excel_sabangnet_data()를 그대로 사용 현재 운영 검증된 A안 자산을 보존
RPA는 별도 작업자 웹 요청 안에서 브라우저 자동화를 직접 실행하지 않음 타임아웃, PHP 프로세스 점유, 장애 전파 방지
승인 후 실행 자동등록 전 필수값과 대상 건수를 관리자에게 보여준 뒤 실행 잘못된 상품 대량 전송 방지
계정정보 암호화 사방넷 ID/PW는 DB 평문 저장 금지, 서버 키로 암호화 도매회원 로그인정보 보호
스크린샷/로그 보존 로그인, 업로드, 결과 화면을 단계별로 저장 실패 원인 분석과 고객 응대 근거 확보

7. 신규 DB 설계안

테이블 주요 컬럼 설명

sabangnet_rpa_logs id, job_id, level, step, message, payload_json, screenshot_path, created_at 단계별 실행 로그와 증빙 스크린샷 연결.
V1은 오래된 CodeIgniter/PHP 구조이므로 마이그레이션 도구가 없을 수 있습니다. 적용 시에는 SQL 파일을 버전 관리하고, 운영 DB에는 트랜잭션 가능한 DDL 전략 또는 사전 백업 후 적용해야 합니다.

8. 사전검사 규칙

자동등록은 "업로드 전에 막는 것"이 핵심입니다. 아래 항목 중 필수값이 비어 있으면 작업을 held로 두고, 관리자에게 수정 목록을 보여줘야 합니다.

검사 항목 대상 컬럼/데이터 실패 처리
상품명 A열 상품명[필수] 상품 제외 또는 보류
판매가/TAG가 Y열, Z열 0원/공란 차단
대표이미지 AE열 URL HTTP 200 확인 실패 시 보류

9. RPA Worker 세부 설계

실행 단계

  1. 작업 큐에서 approved 상태 작업 1건을 가져옵니다.
  2. 사방넷 계정 정보를 복호화하고 Playwright 브라우저를 실행합니다.
  3. 사방넷 로그인 페이지로 이동해 로그인합니다.
  4. 로그인 성공 여부를 URL, 메뉴 노출, 세션 쿠키로 확인합니다.
  5. 상품 대량등록 메뉴로 이동합니다.
  6. 기존 V1에서 생성한 danharoo_goods_sabangnet_data.xls 또는 작업별 복사본을 업로드합니다.
  7. 사방넷 검증 결과 화면을 읽고 성공/실패 메시지를 저장합니다.
  8. 필요 시 지정 마켓 전송 버튼을 순서대로 클릭합니다.
  9. 최종 결과 화면을 캡처하고 작업 상태를 갱신합니다.

Worker 실행 방식

항목 권장안
언어/런타임 Node.js + Playwright. V1 PHP와 분리 실행.
실행 주기 초기에는 수동 실행 버튼 + 1분 cron. 안정화 후 상시 worker.
동시성 초기 1개 계정당 1개 작업만 실행. 사방넷 세션 충돌 방지.
브라우저 모드 초기 검증 기간에는 headful 또는 screenshot-heavy 모드, 안정화 후 headless.
실패 재시도 로그인/네트워크 실패만 최대 1회 자동 재시도. 데이터 오류는 자동 재시도 금지.

10. 보안/운영 리스크

리스크 영향 대응
사방넷 UI 변경 자동 업로드 실패 selector를 중앙 관리하고 실패 스크린샷 저장. 월 1회 점검.
캡차/OTP/비정상 로그인 감지 자동 로그인 중단 자동 우회 금지. requires_manual_login 상태로 전환하고 관리자 처리.
로그인정보 유출 계정 보안 사고 DB 암호화, 로그 마스킹, 화면 비밀번호 재표시 금지.
오등록/중복등록 마켓 상품 품질 문제 사전검사, 승인 단계, 자체상품코드 기준 중복 검사.
대량작업 서버 부하 V1 웹 응답 지연 RPA worker 별도 프로세스, 동시성 제한, 야간 작업 옵션.
약관/운영정책 이슈 계정 제한 가능성 공식 API가 아닌 로그인 자동화임을 명시하고, 빈도 제한/승인 흐름 유지.
캡차, OTP, 보안문자, 접근제한을 우회하는 자동화는 적용하지 않습니다. 해당 상황이 발생하면 작업을 중단하고 수동 확인 상태로 보고해야 합니다.

11. 단계별 적용 계획

단계 작업 산출물 예상 기간
Phase 1 V1 사방넷 자동등록 작업 테이블/상태 화면 추가 작업 목록, 상세 로그, 계정 등록 화면 1~2일
Phase 2 기존 엑셀 생성 결과를 작업별 파일로 저장하고 사전검사 추가 검증 리포트, 보류 사유, 승인 버튼 1~2일
Phase 3 Playwright 로그인/업로드 MVP 사방넷 로그인, 엑셀 업로드, 결과 스크린샷 2~3일
Phase 4 마켓 전송 버튼 자동화 및 결과 수집 마켓별 성공/실패 결과 2~3일
Phase 5 도매회원용 제한 공개 및 과금/권한 연동 회원별 권한, 사용량 제한, 작업 이력 추후

12. 성공 기준

검증 항목 완료 기준
기존 A안 영향 기존 사방넷 엑셀 다운로드 기능이 그대로 동작해야 합니다.
사전검사 필수값 누락 상품은 업로드 전에 차단되어야 합니다.
로그인 자동화 정상 계정으로 사방넷 로그인 성공/실패를 구분해 저장해야 합니다.
엑셀 업로드 테스트 상품 1~5건 업로드 결과가 사방넷 화면에서 확인되어야 합니다.
결과 로그 작업별 최종 상태, 실패 사유, 스크린샷 경로가 V1 관리자에서 보여야 합니다.
운영 안전 RPA 실행 중에도 V1 상품목록/다운로드 기능이 지연되거나 중단되지 않아야 합니다.

NewTalk V1(/home/danharoo/www)에 현재 운영 중인 사방넷 엑셀 생성 A안을 유지하면서,
로그인 기반 B안 자동 업로드 RPA MVP를 구현한다.

반드시 먼저 읽을 파일:
1. /home/danharoo/www/seller/controllers/products.php
   - goods_select_sabangnet_make()
   - goods_excel_sabangnet_data()
   - goods_select_zip_down()
2. /home/danharoo/www/seller/config/autoscrap.php
   - sabangnet_excel_data

구현 범위:
1. 기존 엑셀 다운로드 기능은 절대 깨지지 않게 유지한다.
2. 사방넷 자동등록 작업 테이블 SQL을 추가한다.
3. 상품 선택 후 사전검사 → 작업 생성 → 관리자 승인 → RPA 실행 상태로 흐름을 분리한다.
4. 사방넷 계정정보는 암호화 저장하고 로그에 비밀번호를 남기지 않는다.
5. Playwright worker는 PHP 웹요청과 분리된 Node.js 스크립트로 작성한다.
6. 로그인/업로드/결과 단계별 스크린샷과 로그를 저장한다.
7. 캡차/OTP/보안문자 우회는 구현하지 말고 manual_required 상태로 처리한다.
8. 테스트용 1~5건 작업으로 검증할 수 있는 dry-run 또는 staging 모드를 둔다.
