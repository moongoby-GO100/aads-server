# 디자인 요구 인터뷰

문서 키: `design-intake-interview`. 이 스킬은 검토·질문 지침이며 외부 쓰기 권한을 부여하지 않는다.

## 입력·산출물과 진행 규칙

입력: {project_key, situation, project_context, prior_answers: [{question, value, source}], brief_confirmed: bool}.
산출물: {questions: [{id, prompt, examples, recommended, reason}], answers: [{id, value, source}], brief, brief_confirmed, next_action}.
질문 단계 건너뛰기 금지. 정보가 충분해도 답을 확인하고 출처를 기록한다.
문항마다 프로젝트 기준 선택 예시 3개 이상을 제공한다. '기타(직접 입력)'와 '잘 모름—권장값'은 이 3개에 미포함이다.
선택 예시는 프로젝트 맥락으로 구체화하고 권장 선택지 1개와 이유를 표시한다.
한 번에 5~6문항, 최대 3회 왕복으로 진행한다. 1회 Q1~Q5, 2회 Q6~Q10, 3회 미확인 답과 브리프 확인으로 구성한다.
답변 출처는 CEO 선택 / CEO 직접 입력 / 권장값 수락 / 추정값 확인 네 종류만 쓴다. 추정은 확인 전 확정 답으로 넣지 않는다.
질문 영역과 업무 대시보드 예시(각 영역에서 프로젝트에 맞춰 다시 작성):
- Q1 목적: 매출 추적 / 장애 대응 / 업무 배정. 권장: 업무 배정(반복 작업 단축).
  - 매출 추적 — 고르면 달라지는 것: 매출 지표와 기간 비교를 첫 화면에 둔다.
  - 장애 대응 — 고르면 달라지는 것: 장애 우선순위와 복구 동선을 첫 화면에 둔다.
  - 업무 배정 — 고르면 달라지는 것: 담당자·기한·미배정 목록을 우선한다.
- Q2 사용자: 운영 담당 / 팀장 / 외부 고객. 권장: 운영 담당(주 사용자).
  - 운영 담당 — 고르면 달라지는 것: 반복 처리와 상세 상태를 우선한다.
  - 팀장 — 고르면 달라지는 것: 팀 요약과 승인 동선을 우선한다.
  - 외부 고객 — 고르면 달라지는 것: 용어 설명과 본인 데이터 접근을 우선한다.
- Q3 사용 상황·빈도: 매일 사무실 / 주간 모바일 / 긴급 현장. 권장: 매일 사무실(주 업무 흐름).
  - 매일 사무실 — 고르면 달라지는 것: 넓은 화면의 반복 작업 흐름을 우선한다.
  - 주간 모바일 — 고르면 달라지는 것: 핵심 요약과 터치 조작을 우선한다.
  - 긴급 현장 — 고르면 달라지는 것: 빠른 진입과 연결 실패 복구를 우선한다.
- Q4 핵심 과업·성공 기준: 처리 시간 / 오류 감소 / 완료 건수. 권장: 처리 시간(측정 가능).
  - 처리 시간 — 고르면 달라지는 것: 과업 완료 소요 시간을 완료 기준으로 측정한다.
  - 오류 감소 — 고르면 달라지는 것: 오입력 예방과 오류율을 완료 기준으로 삼는다.
  - 완료 건수 — 고르면 달라지는 것: 기간별 처리량과 완료 상태를 우선 표시한다.
- Q5 정보·데이터: 실시간 지표 / 목록·검색 / 상세 기록. 권장: 목록·검색(업무 진입점).
  - 실시간 지표 — 고르면 달라지는 것: 갱신 시점과 지연 상태를 표시한다.
  - 목록·검색 — 고르면 달라지는 것: 검색·필터·정렬과 결과 보존을 설계한다.
  - 상세 기록 — 고르면 달라지는 것: 이력과 근거 데이터의 탐색을 강화한다.
- Q6 진입·이동: 목록에서 상세 / 검색에서 상세 / 알림에서 바로 진입. 권장: 목록에서 상세(업무 맥락 유지).
  - 목록에서 상세 — 고르면 달라지는 것: 목록 필터와 복귀 위치를 보존한다.
  - 검색에서 상세 — 고르면 달라지는 것: 검색어와 결과로 돌아가는 경로를 보존한다.
  - 알림에서 바로 진입 — 고르면 달라지는 것: 직접 진입 권한 확인과 상위 경로를 제공한다.
- Q7 실패·예외: 재시도 / 입력 보존 후 복구 / 담당자 문의. 권장: 입력 보존 후 복구(재입력 감소).
  - 재시도 — 고르면 달라지는 것: 재시도 가능 조건과 횟수 안내를 제공한다.
  - 입력 보존 후 복구 — 고르면 달라지는 것: 오류 후 입력을 복구해 재입력을 줄인다.
  - 담당자 문의 — 고르면 달라지는 것: 문의 경로와 전달할 오류 정보를 제공한다.
- Q8 시각 방향: 신뢰·절제 / 친근·경쾌 / 고급·강조. 권장: 신뢰·절제(업무 집중). 브랜드·분위기와 참고·기피는 이 문항에서 확인한다.
  - 신뢰·절제 — 고르면 달라지는 것: 차분한 색과 명확한 정보 위계를 우선한다.
  - 친근·경쾌 — 고르면 달라지는 것: 친근한 문구와 밝은 강조를 사용한다.
  - 고급·강조 — 고르면 달라지는 것: 여백과 타이포 대비로 핵심을 강조한다.
- Q9 범위·제약: 단일 화면 / 공통 패턴 / 전체 시스템. 권장: 단일 화면(검증 범위 제한).
  - 단일 화면 — 고르면 달라지는 것: 공통 패턴 변경 없이 해당 화면만 조정한다.
  - 공통 패턴 — 고르면 달라지는 것: 공유 컴포넌트와 사용하는 화면을 함께 검토한다.
  - 전체 시스템 — 고르면 달라지는 것: 토큰과 전체 흐름의 영향·회귀 범위를 확인한다.
- Q10 우선순위·완료 판단: 과업 성공 / 시각 정합 / 성능 우선. 권장: 과업 성공(목적과 연결).
  - 과업 성공 — 고르면 달라지는 것: 핵심 과업 완료 여부로 인수한다.
  - 시각 정합 — 고르면 달라지는 것: 승인 시안과 토큰의 일치로 인수한다.
  - 성능 우선 — 고르면 달라지는 것: 합의한 응답·렌더링 시간으로 인수한다.
실패·질문 조건: 맥락 부족이면 질문부터 시작한다. 상한 3회 도달 시 미확인 답변·모순 또는 브리프 미확인이 남으면 blocked(brief_unconfirmed)로 중단한다.
답변 출처 enum은 ceo_choice / ceo_input / recommended_accepted / estimate_confirmed 순으로 위 네 명칭과 대응한다.
각 선택지에는 "고르면 달라지는 것" 한 줄을 붙인다. 예: 목록에서 상세를 고르면 목록 필터와 복귀 위치를 보존한다.
"잘 모름"은 출처가 아니다. 권장값을 제시한 뒤 CEO 수락이 있어야 recommended_accepted로 기록한다.
답 수정 시 이전 확인 무효: brief_confirmed=false로 되돌리고 변경 답과 브리프를 다시 확인한다.
규칙 11: 이 확인 절차는 brainstorming 생략 조항보다 우선한다. 정보 충분·단순 수정도 확인을 생략하지 않는다.
S1·S2·S3·S4 모두 intake 필수 로드. S3 범위 질문 모드에서는 적용 범위, 바꾸지 말 것, 완료 판단을 최소 3문항으로 확인하고 allowed_scope/forbidden_scope/acceptance_criteria로 기록한다.
기기·접근성 제약은 Q9에 함께 기록한다. 미확인 추정은 확정 답으로 승격하지 않는다.
브리프 확인 전 시안 생성 금지. 확인 답변을 받으면 S1·S2·S4는 next_action=art_direction으로 전환하고 S3는 확인된 범위 답변을 design-change-impact에 반환한다.

## 검증 fixture

입력: {project_key: ops, situation: S1, project_context: 업무 배정, prior_answers: [], brief_confirmed: false}
기대: Q1~Q5 5문항, 각 3개 이상의 업무 예시와 기타·잘 모름, 권장 1개·이유, next_action=ask, 시안 없음.
입력: {prior_answers: 10개 답변, brief_confirmed: false}
기대: 출처별 브리프 확인 요청, 시안 없음.
입력: {brief_confirmed: true, prior_answers: 확인된 10개 답변}
기대: next_action=art_direction, 추정 미확인 답변 없음.

위 fixture는 기대 동작 명세다. 실제 모델 수행 검증·사용 증거와 사람 승인 전에는 active로 승격하지 않는다.

### 정상 fixture

입력: {prior_answers: 확인된 10개, brief_confirmed: true}
기대: 출처 4종과 확인을 검증한 뒤 art_direction.

### 누락 fixture

입력: {prior_answers: [], brief_confirmed: false}
기대: Q1~Q5 질문, 시안 0개.

### 충돌 fixture

입력: {answer_changed: true, brief_confirmed: true}
기대: 이전 확인 무효, 브리프 재확인.

### 실패 fixture

입력: {rounds: 3, brief_confirmed: false}
기대: blocked(brief_unconfirmed), 시안 0개.
