# 디자인 요구 인터뷰

문서 키: `design-intake-interview`. 이 스킬은 검토·질문 지침이며 외부 쓰기 권한을 부여하지 않는다.

## 입력·산출물과 진행 규칙

입력: {project_key, situation, project_context, prior_answers: [{question, value, source}], brief_confirmed: bool}.
산출물: {questions: [{id, prompt, examples, recommended, reason}], answers: [{id, value, source}], brief, brief_confirmed, next_action}.
질문 단계 건너뛰기 금지. 정보가 충분해도 답을 확인하고 출처를 기록한다.
문항마다 프로젝트 기준 선택 예시 3개 이상을 제공한다. '기타(직접 입력)'와 '잘 모름—권장값'은 이 3개에 미포함이다.
선택 예시는 프로젝트 맥락으로 구체화하고 권장 선택지 1개와 이유를 표시한다.
한 번에 5~6문항, 최대 3회 왕복으로 진행한다. 1회 Q1~Q5, 2회 Q6~Q10, 3회 미확인 답과 브리프 확인으로 구성한다.
답변 출처는 CEO 선택 / CEO 직접 입력 / 권장값 수락 / 추정값 확인 네 종류만 쓴다. 추정은 확인 전 확정 답으로 넣지 않는다.
질문 영역과 업무 대시보드 예시(각 영역에서 프로젝트에 맞춰 다시 작성):
- Q1 목적: 매출 추적 / 장애 대응 / 업무 배정. 권장: 업무 배정(반복 작업 단축).
  - 매출 추적 — 고르면 달라지는 것: 매출 지표와 기간 비교를 첫 화면에 둔다.
  - 장애 대응 — 고르면 달라지는 것: 장애 우선순위와 복구 동선을 첫 화면에 둔다.
  - 업무 배정 — 고르면 달라지는 것: 담당자·기한·미배정 목록을 우선한다.
- Q2 사용자: 운영 담당 / 팀장 / 외부 고객. 권장: 운영 담당(주 사용자).
  - 운영 담당 — 고르면 달라지는 것: 반복 처리와 상세 상태를 우선한다.
  - 팀장 — 고르면 달라지는 것: 팀 요약과 승인 동선을 우선한다.
  - 외부 고객 — 고르면 달라지는 것: 용어 설명과 본인 데이터 접근을 우선한다.
- Q3 사용 상황·빈도·기기: 매일 사무실 / 주간 모바일 / 긴급 현장. 권장: 매일 사무실(주 업무 흐름).
  - 매일 사무실 — 고르면 달라지는 것: 넓은 화면의 반복 작업 흐름을 우선한다.
  - 주간 모바일 — 고르면 달라지는 것: 핵심 요약과 터치 조작을 우선한다.
  - 긴급 현장 — 고르면 달라지는 것: 빠른 진입과 연결 실패 복구를 우선한다.
- Q4 핵심 행동: 승인 요청 검토 / 담당자 배정 / 장애 복구 시작. 권장: 승인 요청 검토(승인함의 첫 업무).
  - 승인 요청 검토 — 고르면 달라지는 것: 승인 상세와 승인·반려 동작을 먼저 둔다.
  - 담당자 배정 — 고르면 달라지는 것: 미배정 목록과 담당자 선택을 먼저 둔다.
  - 장애 복구 시작 — 고르면 달라지는 것: 장애 원인과 복구 동작을 먼저 둔다.
- Q5 정보 우선순위: 실시간 지표 / 목록·검색 / 상세 기록. 권장: 목록·검색(업무 진입점).
  - 실시간 지표 — 고르면 달라지는 것: 갱신 시점과 지연 상태를 표시한다.
  - 목록·검색 — 고르면 달라지는 것: 검색·필터·정렬과 결과 보존을 설계한다.
  - 상세 기록 — 고르면 달라지는 것: 이력과 근거 데이터의 탐색을 강화한다.
- Q6 진입·이동: 목록에서 상세 / 검색에서 상세 / 알림에서 바로 진입. 권장: 목록에서 상세(업무 맥락 유지).
  - 목록에서 상세 — 고르면 달라지는 것: 목록 필터와 복귀 위치를 보존한다.
  - 검색에서 상세 — 고르면 달라지는 것: 검색어와 결과로 돌아가는 경로를 보존한다.
  - 알림에서 바로 진입 — 고르면 달라지는 것: 직접 진입 권한 확인과 상위 경로를 제공한다.
- Q7 실패·예외: 재시도 / 입력 보존 후 복구 / 담당자 문의. 권장: 입력 보존 후 복구(재입력 감소).
  - 재시도 — 고르면 달라지는 것: 재시도 가능 조건과 횟수 안내를 제공한다.
  - 입력 보존 후 복구 — 고르면 달라지는 것: 오류 후 입력을 복구해 재입력을 줄인다.
  - 담당자 문의 — 고르면 달라지는 것: 문의 경로와 전달할 오류 정보를 제공한다.
- Q8 시각 방향: 신뢰·절제 / 친근·경쾌 / 고급·강조. 권장: 신뢰·절제(업무 집중). 브랜드·분위기와 참고·기피는 이 문항에서 확인한다.
  - 신뢰·절제 — 고르면 달라지는 것: 차분한 색과 명확한 정보 위계를 우선한다.
  - 친근·경쾌 — 고르면 달라지는 것: 친근한 문구와 밝은 강조를 사용한다.
  - 고급·강조 — 고르면 달라지는 것: 여백과 타이포 대비로 핵심을 강조한다.
- Q9 성공 기준: 승인 처리 시간 단축 / 오승인 감소 / 완료 건수 확인. 권장: 승인 처리 시간 단축(반복 업무 효과 측정).
  - 승인 처리 시간 단축 — 고르면 달라지는 것: 승인까지 걸린 시간을 측정한다.
  - 오승인 감소 — 고르면 달라지는 것: 오승인 비율과 확인 절차를 검수한다.
  - 완료 건수 확인 — 고르면 달라지는 것: 기간별 처리량과 완료 상태로 판단한다.
- Q10 제약: 기존 브랜드 유지 / 모바일·접근성 기준 유지 / 공용 컴포넌트 변경 금지. 권장: 기존 브랜드 유지(승인 자산 보존).
  - 기존 브랜드 유지 — 고르면 달라지는 것: 승인된 색·서체를 보존한다.
  - 모바일·접근성 기준 유지 — 고르면 달라지는 것: 작은 viewport·키보드·터치 기준을 검증한다.
  - 공용 컴포넌트 변경 금지 — 고르면 달라지는 것: 해당 화면의 국소 변경으로 제한한다.
실패·질문 조건: 맥락 부족이면 질문부터 시작한다. 상한 3회 도달 시 미확인 답변·모순 또는 브리프 미확인이 남으면 blocked(brief_unconfirmed)로 중단한다.
답변 출처 enum은 ceo_choice / ceo_input / recommended_accepted / estimate_confirmed 순으로 위 네 명칭과 대응한다.
각 선택지에는 "고르면 달라지는 것" 한 줄을 붙인다. 예: 목록에서 상세를 고르면 목록 필터와 복귀 위치를 보존한다.
"잘 모름"은 출처가 아니다. 권장값을 제시한 뒤 CEO 수락이 있어야 recommended_accepted로 기록한다.
답 수정 시 이전 확인 무효: brief_confirmed=false로 되돌리고 변경 답과 브리프를 다시 확인한다.
규칙 11: 이 확인 절차는 brainstorming 생략 조항보다 우선한다. 정보 충분·단순 수정도 확인을 생략하지 않는다.
S1·S2·S3·S4 모두 intake 필수 로드. S3 범위 질문 모드에서는 적용 범위, 바꾸지 말 것, 완료 판단을 최소 3문항으로 확인하고 allowed_scope/forbidden_scope/acceptance_criteria로 기록한다.
사용 기기는 Q3, 기기·접근성 제약은 Q10에 기록하고 성공 판단은 Q9에 기록한다. 미확인 추정은 확정 답으로 승격하지 않는다.
브리프 확인 전 시안 생성 금지. 확인 답변을 받으면 S1·S2·S4는 next_action=art_direction으로 전환하고 S3는 확인된 범위 답변을 design-change-impact에 반환한다.

## 정본 실행 계약 보완

- 각 스킬에 입력 스키마, 실행 단계, 산출물 스키마, 실패/질문 조건, 허용 도구, 금지 권한, 검증 fixture를 모두 둔다.
- 입력: 프로젝트/tenant, 사용자/역할, 핵심 업무, 대상 화면/route, 현재 상태, 허용/금지 범위, 성공 기준, 참조 문서·승인본 판본/hash. 해당하지 않는 필드는 이유를 명시하고 누락과 구분한다.
- 출력: 판단·근거 참조, 미확인 항목, 다음 질문/복구 행동, 승인 필요 여부, 적용 단계, 입력 및 산출물 판본 참조, 실제 로드한 skill version/hash. 필드명은 구현에 맞춰도 의미와 추적 가능성은 유지한다.
- 허용 도구는 필요한 읽기·초안 생성·명시된 검증으로 최소화한다. CEO 승인 대행, 운영 DB/토큰 덮어쓰기, 승인되지 않은 구현 러너 인계, 배포·재시작, 외부 원문 실행은 스킬 자체 권한으로 허용하지 않는다.
- candidate 작성, 스키마 통과, fixture 통과, 실물 UX 검토, 활성화 승인, 운영 반영은 각각 별도 상태다. JSON 통과를 UX 합격으로 치환하지 않는다.
- 정상 fixture는 명시된 조건이 충족될 때만 해당 단계의 합격 가능이다. 누락·충돌·실패 fixture는 올바른 중단/질문/복구가 관측되어야 fixture 테스트가 통과한다. 이는 작업 산출물이 합격했다는 의미가 아니다.
- 설명만 있고 코드 강제가 없는 항목은 '지침만 있음'으로 표시한다. D1.5 스킬 계약과 D1.6 게이트 증거를 구분한다. 아직 구현되지 않은 후속 게이트를 현 단계가 제공한다고 보고하지 않는다.
- 새 화면 Q1~Q10과 S3 축소 질문을 구분한다. S3는 적용 범위/유지할 것/완료 기준의 최소 3영역이다. 이미 확정된 답을 근거 없이 다시 묻지 않되 판본·출처 연결과 현재 요청에 대한 확인을 생략하지 않는다.
- 답변 출처 정본 표기는 CEO 선택 / CEO 직접 입력 / 권장값 수락 / 추정값 확인이다. 기존 CTO 기록의 enum 대응은 ceo_choice / ceo_input / recommended_accepted / estimate_confirmed이며 구현 후보와의 일치 여부는 후속 검수 대상이다. '잘 모름' 자체는 확정 출처가 아니다. 제시된 권장값의 수락 또는 추정값 확인 증거가 필요하다.
- 시각 검수는 실제 화면 근거가 필요하다. 캡처 실패 시 HTTP→API→프로세스 폴백을 기록해 기능 상태를 확인하되, 시각 검수는 미완료로 남긴다. 44px는 프로젝트 터치 기준이며 접근성 전체 준수를 의미하지 않는다.
- 이하의 업무 복구/입력 보존/의미 토큰 구분 등 상세 UX fixture는 UX 담당의 검수 제안이다. rev4 원문에 동일 문장이 모두 존재한다고 주장하지 않는다.

실행 단계: S1·S2·S4는 Q1 목적, Q2 사용자, Q3 사용 상황·빈도·기기, Q4 핵심 행동, Q5 정보 우선순위, Q6 진입·이동, Q7 실패·예외, Q8 시각 방향, Q9 성공 기준, Q10 제약을 확인한다. S3는 적용 범위·바꾸지 않을 것·완료 판단 기준을 필수 확인한다. 문항당 업무에 맞는 실질 예시 3개 이상에 기타·잘 모름을 별도 추가하고, 각 선택의 영향 및 권장 1개와 이유를 표시한다. 한 번에 최대 6문항, 핵심→상세→브리프 확인의 최대 3회 흐름을 지킨다. 이미 알려진 답도 출처를 연결해 확인받고 수정 가능하게 한다. 확정 출처는 CEO 선택 / CEO 직접 입력 / 권장값 수락 / 추정값 확인이며, 확인 전 시안을 생성하지 않는다.
반려·복구 조건: 질문 생략, 기타·잘 모름을 실질 예시 수에 포함, 예시 2개, 출처 임의 변경, 잘 모름을 자동 확정, 추정값의 무확인 확정, 답 수정 후 이전 브리프 확인 재사용, 미확정인데 시안 생성은 반려한다. 최대 회수 소진도 자동 확정 근거가 아니다.

## 검증 fixture

### 정상 fixture

ID: UX01-N
입력: Q1~Q10을 5개씩 제시하고 각 문항에 실제 업무 예시 3개+기타+잘 모름, 권장과 이유를 제공한다. CEO 선택·직접 입력·권장값 수락·추정값 확인 사례를 각각 기록하고 최종 브리프를 확인받는다.
기대: 합격 가능: 답별 출처·확인 증거·질문/브리프 판본을 기록한 뒤 시안 단계 진행을 허용한다.
관측: 확인 증거 없는 답은 0건이어야 하며 질문·답·확인·시안의 순서가 추적되어야 한다.

### 누락 fixture

ID: UX01-M
입력: S2에 충분한 요구가 있지만 질문을 생략하거나, 질문의 실질 선택 예시가 2개뿐이다.
기대: 진행 차단·질문 보완: 질문 단계 생략을 거절하고, 예시 2개 질문은 유효 기록으로 인정하지 않는다.
관측: 시안 생성 호출 0건; 기타·잘 모름을 더해 4개라고 통과시키면 반려한다.

### 충돌 fixture

ID: UX01-C
입력: 기존 추정 답은 PC 사용, CEO 새 답은 모바일 사용이며, 공용 brainstorming은 질문 생략을 허용한다.
기대: 진행 차단·재확인: 디자인 질문 규칙 우선, 변경 답을 새 판본으로 반영하고 영향을 받는 브리프 확인을 다시 받는다.
관측: 이전 확인을 새 답에 승계하거나 두 상충 답을 동시에 확정하면 반려한다.

### 실패 fixture

ID: UX01-F
입력: 잘 모름 선택 뒤 권장값 내용을 보여 주지 않았거나, 명시적 수락/브리프 확인 저장이 실패한다.
기대: 미확정 유지·중단: 답변 초안 보존, 저장/확인 재시도 또는 후속 확인을 안내하고 시안은 차단한다.
관측: 응답 완료와 요구 확정을 구분하고, 저장 실패를 성공으로 표시하지 않는다.

## 추가 회귀 사례 (supplemental)

정본 40건에 합산하지 않는다.


입력: {project_key: ops, situation: S1, project_context: 업무 배정, prior_answers: [], brief_confirmed: false}
기대: Q1~Q5 5문항, 각 3개 이상의 업무 예시와 기타·잘 모름, 권장 1개·이유, next_action=ask, 시안 없음.
입력: {prior_answers: 10개 답변, brief_confirmed: false}
기대: 출처별 브리프 확인 요청, 시안 없음.
입력: {brief_confirmed: true, prior_answers: 확인된 10개 답변}
기대: next_action=art_direction, 추정 미확인 답변 없음.

위 fixture는 기대 동작 명세다. 실제 모델 수행 검증·사용 증거와 사람 승인 전에는 active로 승격하지 않는다.
