# 완료 보고 전 실측 확인

## 대원칙
**실측 근거 없이 완료를 주장하지 않는다.** 확인하지 않고 쓴 "완료" 는 보고가 아니라 추측이다.
이 서버에서는 문서가 "돈다" 고 적은 검사가 실제로는 건너뛰어지고 있었던 일(린터 미설치)이 사고의 원인이 된 적이 있다.
말과 실제가 다르면 실제 조회 결과가 이긴다 — 작업 완료 계약도 같은 원칙이다.

이 스킬은 확인 순서와 보고 기준만 다룬다. 명령 실행은 호출한 세션이 가진 권한 안에서 한다.
실행 권한이 없는 단계(커밋·푸시·빌드 등을 러너가 맡는 세션)는 "러너 수행 대상" 으로 적고, 하지 않은 것을 했다고 쓰지 않는다.

## 확인 절차 (주장 하나마다)
1. **식별**: 이 주장을 증명하는 명령이 무엇인가.
2. **실행**: 그 명령을 새로, 전체로 실행한다. 이전 실행 결과나 일부 실행으로 대신하지 않는다.
3. **판독**: 출력 전체와 종료코드를 읽고, 실패 개수를 센다.
4. **대조**: 출력이 주장을 정말 뒷받침하는가.
5. 그 다음에야 말한다. 근거가 없으면 "미확인" 이라고 쓴다.

## 주장별 근거표
| 주장 | 필요한 근거 | 부족한 근거 |
|---|---|---|
| 테스트 통과 | `bash scripts/run_unit_tests.sh <파일>` 종료코드 0 (1=실패, 2=실행 불가 — 2는 게이트 미작동) | 이전 실행, "고쳤으니 될 것" |
| 구문·정적 검사 통과 | 해당 검사 명령의 종료코드 0 | 다른 검사 통과 |
| 버그 수정됨 | 원래 실패하던 재현 절차/테스트가 이제 통과 | 코드 수정 사실만 |
| 커밋 완료 | `git log -1` 로 새 커밋 확인 (R-COMMIT) | 커밋 명령을 쳤다는 기억 |
| 푸시 완료 | 원격 기준 브랜치에 그 SHA 가 있음을 조회 | 로컬 커밋 |
| 서비스 정상 | health 응답(예: `/api/v1/ops/health-check`) 본문과 상태 코드 | 프로세스가 떠 있음 |
| 릴리스 완료 | 배포 실행 이력(DB)의 최종 상태, 외부 경로 health, 최소 5분 모니터링 무오류 | 전환 성공 |
| 화면 정상 | 캡처·스냅샷 또는 R-E2E 폴백 기록 (`webapp-verification`) | API 200 |
| 요구사항 충족 | 지시서 완료 기준 항목을 하나씩 대조한 표 | 테스트 통과만 |
| 하위 작업(에이전트) 성공 | 변경 내용을 직접 확인(차이, 파일) | 에이전트의 "성공" 보고 |

릴리스는 "전환 완료" 와 "릴리스 인증" 이 다른 상태다. 필수 테스트, 외부 점검, 5분 모니터링이 끝나기 전에는 후자를 쓰지 않는다 (`/root/aads/AGENTS.md` 8조).

## 작업 완료 계약과 맞추기
완료 보고에는 다음이 들어가야 한다: ① 변경 파일·대상 시스템 ② 실행한 검증 명령과 결과 ③ 커밋·푸시·문서기록·릴리스 상태 ④ 완료하지 못한 항목과 사유.
- 하지 않은 커밋·푸시·문서기록·릴리스를 "완료" 라고 쓰지 않는다.
- 상태 조회 결과와 내 서술이 다르면 조회 결과를 쓰고 미완료를 밝힌다.
- 핸드오버는 DB 에만 기록한다. `HANDOVER.md` 파일을 고치지 않는다 (R-001).

## 멈춰야 하는 신호
- "아마", "~일 것", "~로 보인다", "문제없을 듯" 이라고 쓰려 한다.
- 확인 전에 "좋다", "끝났다" 같은 만족 표현이 나온다.
- 한 가지만 확인하고 나머지는 같겠거니 한다 (린터 통과 ≠ 빌드 통과 ≠ 테스트 통과).
- 피곤하거나 서두른다는 이유로 "이번만" 건너뛰려 한다.
- 다른 에이전트의 성공 보고를 그대로 옮기려 한다.
- 표현을 바꿔도(같은 뜻의 다른 말, 암시) 규칙은 같다.

## 빠져나갈 구실에 대한 답
| 생각 | 현실 |
|---|---|
| "방금 고친 거라 당연히 된다" | 실행하면 1분이다. 틀렸을 때 비용은 훨씬 크다 |
| "린터가 통과했다" | 린터는 테스트가 아니다 |
| "에이전트가 성공이라 했다" | 보고는 의도이지 실측이 아니다 |
| "일부만 돌려도 충분하다" | 일부 통과는 전체를 증명하지 않는다 |
| "시간이 없다" | 확인하지 않은 보고는 재작업을 부른다 |

## 보고 형식
`주장 / 확인 명령 / 결과(종료코드·핵심 출력) / 미확인 항목`. 미확인이 있으면 맨 앞에 쓴다.

## 승격 조건
현재 `status: candidate`. 아래를 모두 만족해야 `active` 로 올린다.
1. 이 스킬을 따라 완료 보고를 한 **사용 증거 2건** — 세션 id 또는 러너 job_id 를 각각 기록한다.
2. 두 건 모두 근거표 형식의 보고가 남아 있고, 하지 못한 항목이 "완료" 로 둔갑하지 않았다.
3. 위험 등급이 `read` 로 유지된다 (`infer_risk_tier` 확인).
승격은 증거 확인 후 사람이 승인한다. 이 문서는 스스로 승격하지 않는다.
