# 문서 공동 작성 흐름

문서는 **한 번에 완성본을 내놓는 것이 아니라 합의한 뼈대 위에 단계적으로 쌓는 것**이다.
이 스킬은 진행 방식과 사내 저장 규칙만 안내한다. 파일 쓰기·정본 등록 권한은 주지 않으며,
호출한 세션이 가진 도구로 수행한다. 쓸 수 없으면 본문을 응답으로 낸다.

## 0. 시작 전
1. 같은 주제의 문서가 이미 있는지 `Glob docs/**/*.md` 와 `Grep` 으로 찾는다. 있으면 새 문서가 아니라 **같은 document_key 의 새 판본**으로 이어 쓴다.
2. 독자와 쓰임을 한 줄로 확정한다: 누가 읽고, 읽고 나서 무엇을 결정하거나 실행하는가. 답이 없으면 사용자에게 묻는다.
3. 문서 종류(kind)를 정한다: plan, prd, spec, design, architecture, contract, tasks, report, reference 중 하나.
4. 사용자가 가진 자료(대화, 파일, 숫자)를 먼저 받는다. 없는 사실은 만들지 않고 "미확인" 으로 표시한다.

## 1. 구조 합의
- 본문을 쓰기 전에 **절 제목 목록과 절마다 한 줄 의도**만 보여 주고 합의를 받는다. 이 단계에서 합의가 안 되면 뒤 단계는 전부 다시 쓰게 된다.
- 독자가 첫 화면에서 결론을 알 수 있도록 결론·요청 사항을 앞에 둔다.
- 절 수는 필요한 만큼만 둔다. 채울 내용이 없는 절은 빼자고 제안한다.
- 합의 결과는 `[절 제목 / 의도 / 상태]` 표로 유지한다. 상태는 대기 · 초안 · 검토됨 · 확정 네 가지다.

## 2. 초안
- 절을 **하나씩** 쓴다. 한 절을 쓰고 보여 준 뒤 다음 절로 간다. 전체를 한꺼번에 내놓으면 사용자가 훑기만 하고 지나친다.
- 각 절의 첫 문장은 그 절의 주장이다. 근거(숫자·파일·로그·커밋)는 바로 뒤에 붙인다.
- 모르는 부분은 빈칸 표시(`TODO(질문)`)로 남기고 목록으로 모아 한 번에 묻는다.
- 표현은 업무 언어로 쓴다. 내부 약어는 처음 나올 때 풀어 쓴다.

## 3. 검토
절을 마칠 때마다 아래를 스스로 점검한 뒤 사용자에게 의견을 구한다.
1. 합의한 의도와 실제 내용이 일치하는가.
2. 숫자·이름·경로가 근거와 맞는가 (`Read`/`Grep` 으로 다시 확인).
3. 앞 절과 모순되거나 같은 말을 반복하지 않는가.
4. 독자가 이 절만 읽고도 다음 행동을 알 수 있는가.
사용자 의견은 **무엇을 왜 바꾸는지** 한 줄로 기록하고 반영한다. 의견이 서로 충돌하면 임의로 고르지 말고 선택지를 보여 준다.

## 4. 개정
- 전체를 처음부터 끝까지 한 번 읽는 통독을 하고, 중복 · 빠진 연결 · 과한 수식어를 정리한다.
- 바꾼 내용은 `change_summary` 로 쓸 수 있게 한 줄 요약(왜 바꿨는지, 10자 이상)으로 남긴다.
- 사용자가 확정이라고 말하기 전에는 상태를 확정으로 올리지 않는다.

## 사내 저장 규칙 (R-DOC)
규칙의 원본은 프롬프트 자산 `l1-doc-storage-rule` 이다(마이그레이션 `migrations/20261006_l1_doc_storage_rule_activate.sql`). 여기서는 요약하지 않고 핵심만 가리킨다. 어긋나면 원본이 이긴다.
- **경로**: plan → `docs/plans`, prd → `docs/prd`, design·architecture → `docs/design`, report → `docs/reports`, spec·tasks → `docs/specs/<슬라이스>/`. 저장소 루트 `reports/` 에 신규 정본을 두지 않는다.
- **파일명**: `YYYYMMDD_{PROJECT}_{한글 제목}.md`. 화면 제목과 첫 H1 도 한글. 영문 소문자 kebab-case `document_key` 를 따로 붙인다.
- **정본 초안 등록**: 등록 도구가 있으면 도구로, 없으면 `POST /api/v1/projects/{PROJECT}/documents`. `source_task_id`(또는 세션 id)와 10자 이상 `change_summary` 가 없으면 등록이 거절된다. 승인은 별도 경로이며 이 스킬이 하지 않는다.
- **갱신**: 새 파일이 아니라 같은 key 의 새 판본. 날짜만 바꾼 사본을 만들지 않는다. 기존 문서의 key·경로는 바꾸지 않는다.
- **보고**: 파일 경로를 링크처럼 적지 않는다. 등록 결과의 열람 참조(`view`/`report_line`)를 그대로 쓴다. 받지 못했으면 "정본 미등록(미완료)" 또는 "열람 링크 미제공" 이라고 적는다.
- 핸드오버는 문서가 아니라 DB(`handover_write`)에 쓴다. `HANDOVER.md` 를 고치지 않는다.

## 자주 틀리는 것
- 구조 합의 없이 본문부터 쓴다.
- 사용자가 주지 않은 수치·일정·결정을 그럴듯하게 채운다.
- 채팅에만 남기고 "문서 저장 완료" 라고 보고한다.
- 수정이라면서 새 파일을 만든다.

## 승격 조건
현재 `status: candidate`. 아래를 모두 만족해야 `active` 로 올린다.
1. 이 스킬을 따라 문서를 함께 쓴 **사용 증거 2건** — 세션 id 또는 러너 job_id 를 각각 기록한다.
2. 두 건 모두 구조 합의 기록이 있고, R-DOC 항목(한글 제목, key, 정본 초안 등록 또는 미등록 사유)이 지켜졌다.
3. 위험 등급이 `read` 로 유지된다 (`infer_risk_tier` 확인).
승격은 증거 확인 후 사람이 승인한다. 이 문서는 스스로 승격하지 않는다.

## 출처 및 변경 고지

- 변경 사실: 원본의 문장·구조·보조 파일을 가져오지 않았으며 인용도 없다. 2026-10-28 작성.
