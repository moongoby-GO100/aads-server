# 대시보드·NTV2 화면 설계 원칙

이 스킬은 화면을 **정하는 순서와 판단 기준**만 안내한다. 코드 수정·빌드 권한은 주지 않는다.
원본은 새 브랜드를 처음부터 개성 있게 만드는 작업을 전제로 하지만, 여기서는 이미 운영 중인 제품이므로
**기존 체계 안에서 일관되게, 사용자가 길을 잃지 않게** 만드는 쪽으로 기준을 바꾸었다.

## 시작 전 — 이미 있는 것을 먼저 읽는다
1. 비슷한 화면이 있는지 `Glob`/`Grep` 으로 찾고 그 구조를 끝까지 읽는다 (페이지, 컴포넌트, 상태 처리).
2. 색·간격은 기존 CSS 변수를 쓴다: `--bg-primary`, `--bg-card`, `--bg-hover`, `--text-primary`, `--text-secondary`,
   `--accent`, `--success`, `--warning`, `--danger`, `--border` (대시보드 `globals.css`). **새 색 값을 직접 쓰기 전에**
   변수로 표현되는지 확인하고, 없으면 변수를 추가하는 안을 먼저 제안한다.
3. 대시보드의 릴리스 절차와 과거 실패 사례는 `aads-dashboard/AGENTS.md` 에 있다. 거기 적힌 내용을 이 문서에 옮기지 않는다 (R-RELEASE).

## 설계 순서
1. **대상 사용자와 주된 일**을 한 문장으로 적는다. 예: "운영 담당자가 하루 한 번 실패 건을 훑고 재시도한다."
2. **첫 진입**: 처음 열었을 때 무엇이 보이고 무엇을 하면 되는가. 핵심 업무가 먼저, 설정·권한은 보조로 둔다. 3번 이내 클릭으로 목적에 닿는다.
3. **반복 사용**: 매일 쓰는 흐름에서 클릭 수와 이동을 줄인다. 자주 쓰는 동작이 화면에서 가장 크고 눈에 띄어야 한다.
4. **실패 복구**: 오류, 권한 없음, 세션 만료에서 어디로 돌아오는가를 화면 단위로 정한다.
5. **범위/비범위**: 이번에 하지 않는 것을 적는다.

## 화면 상태 6종 — 모두 정의한다
loading(스피너·스켈레톤) / empty(데이터 0건 — 다음 행동을 안내) / error(무엇이 왜 실패했고 어떻게 고치는가) /
permission(권한 없음) / session-expired / offline. 빈 화면은 설명이 아니라 행동으로의 초대다.

## 모바일·가독성 기준
- 360px 폭에서 레이아웃이 깨지지 않고 **가로 스크롤이 없다**.
- 터치 영역은 **44px 이상** (버튼, 링크, 목록 행의 눌리는 영역).
- 글자 크기: 본문 14px 이상, 보조 12px 이상, 제목 18px 이상. 텍스트/배경 대비 4.5:1 이상.
- 모바일에서는 작은 모달보다 전체 화면 또는 하단 시트를 우선한다.
- 한국어 장문이 줄바꿈에서 깨지거나 넘치지 않는지 본다.
- 키보드 포커스가 보이고 가려지지 않는다. 사용자가 움직임 줄이기를 설정하면 따른다.

## 문구
- 사용자가 아는 **한글 업무명**으로 쓴다. 내부 식별자·영문 시스템 용어(테이블명, 상태 코드)를 화면에 그대로 노출하지 않는다.
- 버튼은 눌렀을 때 일어나는 일을 말한다: "저장" 보다 "변경 저장", "확인" 보다 "재시도 요청". 같은 동작은 흐름 내내 같은 이름으로 부른다.
- 오류 문구는 사과하지 않고 무슨 일이 있었는지와 다음 행동을 말한다. 모호하게 쓰지 않는다.
- 문구 하나는 하나의 역할만 한다. 장식용 라벨을 덧붙이지 않는다.

## 시각 판단 — 절제
- 강조는 한 곳에 쓴다. 가장 중요한 동작이 기억에 남고 나머지는 조용해야 한다. 기능 중요도에 비례해 크기를 정한다.
- 같은 모양의 카드를 기계적으로 반복하거나, 의미 없는 장식(그라데이션, 모든 카드 호버 효과)을 넣지 않는다.
- 사용자 조작에 대한 반응(열림, 펼침, 확정)에만 움직임을 쓴다. 저절로 움직이는 효과는 정말 주의를 끌어야 할 때만.
- 번호·구분선·테두리는 내용이 실제로 순서나 구분을 가질 때만 쓴다.
- 기존 화면과 달라 보이는 것이 목표가 아니다. 같은 제품 안에서 **다른 화면과 같은 규칙으로 보이는 것**이 목표다.

## 검증 연결
- 구현 후 화면 근거는 `webapp-verification` 스킬 절차로 모은다 (캡처, 스냅샷, R-E2E 폴백).
- 시각·접근성·기능을 각각 따로 판정하고, 평가불가가 있으면 전체 통과로 쓰지 않는다.
- 빌드·릴리스는 직접 하지 않고 담당 절차(러너·`AGENTS.md`)에 맡긴다.

## 승격 조건
현재 `status: candidate`. 아래를 모두 만족해야 `active` 로 올린다.
1. 이 스킬을 따라 화면 설계·검토를 수행한 **사용 증거 2건** — 세션 id 또는 러너 job_id 를 각각 기록한다.
2. 두 건 모두 첫 진입·실패 복구·상태 6종·모바일 기준이 결과에 명시되어 있다.
3. 위험 등급이 `read` 로 유지된다 (`infer_risk_tier` 확인).
승격은 증거 확인 후 사람이 승인한다. 이 문서는 스스로 승격하지 않는다.
