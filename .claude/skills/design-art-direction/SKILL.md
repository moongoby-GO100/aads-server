# 디자인 표현 방향

문서 키: `design-art-direction`. 이 스킬은 검토·질문 지침이며 외부 쓰기 권한을 부여하지 않는다.

## 입력·산출물과 진행 규칙

입력: {confirmed_brief, discovery, brand_tokens, constraints}.
산출물: {directions: [{name, typography, color_roles, spacing, rationale, risks}], recommended, confirmation}.
요구와 연결된 세 방향을 비교하고 기존 토큰으로 구현 가능한지 표시한다. 색 이름만 나열하지 말고 정보 위계·밀도·타이포 역할을 설명한다.
실패·질문 조건: 브리프 미확인이면 인터뷰로 돌린다. 브랜드 제약이 충돌하면 선택을 질문한다. 선택 전 한 방향을 확정하지 않는다.

각 방향은 사용자 과업·정보 위계·밀도·가독성·브랜드 제약과 연결하고 고르면 달라지는 것과 포기하는 것을 설명한다. 권장안도 CEO 선택 전 확정하지 않으며 브리프 확인 전 시안 생성 금지.

## 정본 실행 계약 보완

- 각 스킬에 입력 스키마, 실행 단계, 산출물 스키마, 실패/질문 조건, 허용 도구, 금지 권한, 검증 fixture를 모두 둔다.
- 입력: 프로젝트/tenant, 사용자/역할, 핵심 업무, 대상 화면/route, 현재 상태, 허용/금지 범위, 성공 기준, 참조 문서·승인본 판본/hash. 해당하지 않는 필드는 이유를 명시하고 누락과 구분한다.
- 출력: 판단·근거 참조, 미확인 항목, 다음 질문/복구 행동, 승인 필요 여부, 적용 단계, 입력 및 산출물 판본 참조, 실제 로드한 skill version/hash. 필드명은 구현에 맞춰도 의미와 추적 가능성은 유지한다.
- 허용 도구는 필요한 읽기·초안 생성·명시된 검증으로 최소화한다. CEO 승인 대행, 운영 DB/토큰 덮어쓰기, 승인되지 않은 구현 러너 인계, 배포·재시작, 외부 원문 실행은 스킬 자체 권한으로 허용하지 않는다.
- candidate 작성, 스키마 통과, fixture 통과, 실물 UX 검토, 활성화 승인, 운영 반영은 각각 별도 상태다. JSON 통과를 UX 합격으로 치환하지 않는다.
- 정상 fixture는 명시된 조건이 충족될 때만 해당 단계의 합격 가능이다. 누락·충돌·실패 fixture는 올바른 중단/질문/복구가 관측되어야 fixture 테스트가 통과한다. 이는 작업 산출물이 합격했다는 의미가 아니다.
- 설명만 있고 코드 강제가 없는 항목은 '지침만 있음'으로 표시한다. D1.5 스킬 계약과 D1.6 게이트 증거를 구분한다. 아직 구현되지 않은 후속 게이트를 현 단계가 제공한다고 보고하지 않는다.
- 새 화면 Q1~Q10과 S3 축소 질문을 구분한다. S3는 적용 범위/유지할 것/완료 기준의 최소 3영역이다. 이미 확정된 답을 근거 없이 다시 묻지 않되 판본·출처 연결과 현재 요청에 대한 확인을 생략하지 않는다.
- 답변 출처 정본 표기는 CEO 선택 / CEO 직접 입력 / 권장값 수락 / 추정값 확인이다. 기존 CTO 기록의 enum 대응은 ceo_choice / ceo_input / recommended_accepted / estimate_confirmed이며 구현 후보와의 일치 여부는 후속 검수 대상이다. '잘 모름' 자체는 확정 출처가 아니다. 제시된 권장값의 수락 또는 추정값 확인 증거가 필요하다.
- 시각 검수는 실제 화면 근거가 필요하다. 캡처 실패 시 HTTP→API→프로세스 폴백을 기록해 기능 상태를 확인하되, 시각 검수는 미완료로 남긴다. 44px는 프로젝트 터치 기준이며 접근성 전체 준수를 의미하지 않는다.
- 이하의 업무 복구/입력 보존/의미 토큰 구분 등 상세 UX fixture는 UX 담당의 검수 제안이다. rev4 원문에 동일 문장이 모두 존재한다고 주장하지 않는다.

실행 단계: 동일 업무·콘텐츠·viewport를 기준으로 시각 방향 3안을 비교하고 브랜드·정보 밀도·가독성·핵심 행동 식별을 설명한다. 권장안 하나와 이유, 다른 안의 장단점, 구현 제약을 남긴다. 무드보드뿐 아니라 대표 과제 화면 적용 예와 방향 선택 근거를 제공한다.
반려·복구 조건: 분위기 이미지만 제시, 콘텐츠/viewport 차이로 우열을 왜곡, 장식이 주요 행동을 가림, 승인된 브랜드/토큰을 근거 없이 대체, 사용자 선택 없이 방향을 확정하면 반려한다.

## 검증 fixture

출처: design-agent-d15-ux-acceptance-rev4-57980cb2 revision 2. 정적 계약이며 실제 모델·화면 실행은 미검증이다.

### 정상 fixture

ID: UX03-N
입력: 같은 승인함 과제를 같은 콘텐츠·viewport에서 방향 3안으로 만든다.
기대: 합격 가능: 핵심 행동·가독성·밀도·브랜드 적합성을 비교하고 권장 이유와 선택 근거를 남긴다.
관측: 대표 화면과 방향 선택 증거를 연결하며 생성물은 승인 전 초안이다.

### 누락 fixture

ID: UX03-M
입력: 브랜드 금지사항 또는 확정 브리프가 없다.
기대: 질문 필요·시안 확정 차단: 제약을 확인하고 미확정 브리프 단계로 돌린다.
관측: 모르는 제약을 없음으로 처리하거나 승인본을 만들면 반려한다.

### 충돌 fixture

ID: UX03-C
입력: 새 방향의 색/서체가 현재 승인 브랜드·토큰과 충돌한다.
기대: 선택·변경 승인 필요: 충돌과 영향 범위를 밝히고 유지안/변경안을 비교한다.
관측: 기존 승인 토큰을 자동 덮어쓰거나 변경 동의를 추정하면 반려한다.

### 실패 fixture

ID: UX03-F
입력: 대표 화면 렌더링 또는 글꼴 로드가 실패한다.
기대: 시각 판정 보류: 대체 렌더링을 시도하고 실패 범위를 기록한다.
관측: 무드보드나 생성 API 성공만으로 대표 화면 검수 합격을 내리면 반려한다.

## 추가 회귀 사례 (supplemental)

정본 40건에 합산하지 않는다.


입력: {confirmed_brief: 업무 집중, brand_tokens: 기존 파랑}
기대: 세 방향, 기존 파랑 역할 유지 여부와 추천 이유.
입력: {confirmed_brief: false}
기대: 인터뷰 요청, 시안 없음.

위 fixture는 기대 동작 명세다. 실제 모델 수행 검증·사용 증거와 사람 승인 전에는 active로 승격하지 않는다.

### supplemental 정상 fixture

입력: {confirmed_brief: true, constraints: 확인됨}
기대: 3방향 비교, 권장 이유와 선택 요청.

### supplemental 누락 fixture

입력: {confirmed_brief: false}
기대: intake 반환, 시안 0개.

### supplemental 충돌 fixture

입력: {brand_tokens: 파랑 유지, constraints: 파랑 금지}
기대: 충돌 질문, 확정 중단.

### supplemental 실패 fixture

입력: {brand_tokens: 읽기 실패}
기대: 근거 요청, 검증 완료 주장 금지.
