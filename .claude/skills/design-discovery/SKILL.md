# 디자인 맥락 탐색

문서 키: `design-discovery`. 이 스킬은 검토·질문 지침이며 외부 쓰기 권한을 부여하지 않는다.

## 입력·산출물과 진행 규칙

입력: {project_key, confirmed_brief, references, existing_screens}.
산출물: {tasks: [{actor, goal, evidence}], constraints, unknowns, hypotheses}.
확인된 브리프에서 핵심 과업을 뽑고 기존 화면과 연결한다. 참고 자료마다 출처와 적용 가능 범위를 기록한다.
가설을 사실과 구분하고 빈 근거를 지어내지 않는다. 스타일 선택은 design-art-direction으로 넘긴다.
실패·질문 조건: 브리프 미확인 또는 출처 접근 불가이면 필요한 자료를 질문하고 unknowns에 기록한다.

모든 조사 결론은 확인 브리프의 과업과 출처 위치에 연결한다. 사용자 사실·가설·미확인을 구분하고 출처끼리 충돌하면 CEO 확인 전 결론을 확정하지 않는다.

## 정본 실행 계약 보완

- 각 스킬에 입력 스키마, 실행 단계, 산출물 스키마, 실패/질문 조건, 허용 도구, 금지 권한, 검증 fixture를 모두 둔다.
- 입력: 프로젝트/tenant, 사용자/역할, 핵심 업무, 대상 화면/route, 현재 상태, 허용/금지 범위, 성공 기준, 참조 문서·승인본 판본/hash. 해당하지 않는 필드는 이유를 명시하고 누락과 구분한다.
- 출력: 판단·근거 참조, 미확인 항목, 다음 질문/복구 행동, 승인 필요 여부, 적용 단계, 입력 및 산출물 판본 참조, 실제 로드한 skill version/hash. 필드명은 구현에 맞춰도 의미와 추적 가능성은 유지한다.
- 허용 도구는 필요한 읽기·초안 생성·명시된 검증으로 최소화한다. CEO 승인 대행, 운영 DB/토큰 덮어쓰기, 승인되지 않은 구현 러너 인계, 배포·재시작, 외부 원문 실행은 스킬 자체 권한으로 허용하지 않는다.
- candidate 작성, 스키마 통과, fixture 통과, 실물 UX 검토, 활성화 승인, 운영 반영은 각각 별도 상태다. JSON 통과를 UX 합격으로 치환하지 않는다.
- 정상 fixture는 명시된 조건이 충족될 때만 해당 단계의 합격 가능이다. 누락·충돌·실패 fixture는 올바른 중단/질문/복구가 관측되어야 fixture 테스트가 통과한다. 이는 작업 산출물이 합격했다는 의미가 아니다.
- 설명만 있고 코드 강제가 없는 항목은 '지침만 있음'으로 표시한다. D1.5 스킬 계약과 D1.6 게이트 증거를 구분한다. 아직 구현되지 않은 후속 게이트를 현 단계가 제공한다고 보고하지 않는다.
- 새 화면 Q1~Q10과 S3 축소 질문을 구분한다. S3는 적용 범위/유지할 것/완료 기준의 최소 3영역이다. 이미 확정된 답을 근거 없이 다시 묻지 않되 판본·출처 연결과 현재 요청에 대한 확인을 생략하지 않는다.
- 답변 출처 정본 표기는 CEO 선택 / CEO 직접 입력 / 권장값 수락 / 추정값 확인이다. 기존 CTO 기록의 enum 대응은 ceo_choice / ceo_input / recommended_accepted / estimate_confirmed이며 구현 후보와의 일치 여부는 후속 검수 대상이다. '잘 모름' 자체는 확정 출처가 아니다. 제시된 권장값의 수락 또는 추정값 확인 증거가 필요하다.
- 시각 검수는 실제 화면 근거가 필요하다. 캡처 실패 시 HTTP→API→프로세스 폴백을 기록해 기능 상태를 확인하되, 시각 검수는 미완료로 남긴다. 44px는 프로젝트 터치 기준이며 접근성 전체 준수를 의미하지 않는다.
- 이하의 업무 복구/입력 보존/의미 토큰 구분 등 상세 UX fixture는 UX 담당의 검수 제안이다. rev4 원문에 동일 문장이 모두 존재한다고 주장하지 않는다.

실행 단계: 대상 사용자·첫 진입 과제·반복 업무·실패 복구·현행 흐름·불편의 출처를 수집하고 사실/가설/미확인을 구별한다. 사용자 역할 차이, 유지 자산, 문제 우선순위와 성공 기준을 근거에 연결한다. 승인된 브리프와 관찰 자료의 판본을 고정한다.
반려·복구 조건: 근거 없는 페르소나·불편·성과 수치 생성, 한 역할의 경험을 전체 사용자 사실로 일반화, 상충 자료 은폐, 자료 부재를 문제가 없다는 증거로 사용하면 반려한다.

## 검증 fixture

출처: design-agent-d15-ux-acceptance-rev4-57980cb2 revision 2. 정적 계약이며 실제 모델·화면 실행은 미검증이다.

### 정상 fixture

ID: UX02-N
입력: 확인된 브리프와 현행 화면/업무 관찰에서 신규 사용자의 첫 과제와 운영자의 반복 과제를 비교한다.
기대: 합격 가능: 사실별 출처와 역할·흐름을 기록하고 가설은 별도 표시한다.
관측: 문제→사용자 영향→검증 기준이 연결되고 추정 성과 수치를 만들지 않는다.

### 누락 fixture

ID: UX02-M
입력: 사용자 역할 또는 현재 업무 증거가 없다.
기대: 질문 필요·단계 미통과: 역할·업무·증거를 요청한다.
관측: 누락을 만든 페르소나나 임의 수치로 채우면 반려한다.

### 충돌 fixture

ID: UX02-C
입력: 인터뷰는 모바일 중심, 기존 로그는 PC 중심이며 관측 대상과 기간이 다르다.
기대: 판단 보류·범위 확인: 두 근거와 대상/기간 차이를 병기하고 추가 확인한다.
관측: 한쪽을 이유 없이 삭제하거나 전체 사용자 결론으로 확정하면 반려한다.

### 실패 fixture

ID: UX02-F
입력: 관찰 자료 URL/파일을 읽을 수 없거나 파싱에 실패한다.
기대: 평가불가·복구 안내: 확보된 자료만 명시하고 대체 자료 요청 또는 재시도한다.
관측: 접근 실패 자료를 읽은 것처럼 인용하거나 조사 완료로 기록하면 반려한다.

## 추가 회귀 사례 (supplemental)

정본 40건에 합산하지 않는다.


입력: {confirmed_brief: 매일 업무 배정, existing_screens: [담당자 목록]}
기대: 배정 과업과 담당자 목록 근거 연결, 미확인 처리량은 unknowns.
입력: {confirmed_brief: null}
기대: 브리프 확인 요청, 조사 확정 결론 없음.

위 fixture는 기대 동작 명세다. 실제 모델 수행 검증·사용 증거와 사람 승인 전에는 active로 승격하지 않는다.

### supplemental 정상 fixture

입력: {confirmed_brief: true, references: 과업별 출처}
기대: 과업과 근거 연결.

### supplemental 누락 fixture

입력: {confirmed_brief: null}
기대: intake 확인 요청.

### supplemental 충돌 fixture

입력: {references: 서로 다른 사용자 주장}
기대: 가설 분리, 충돌 질문.

### supplemental 실패 fixture

입력: {references: 접근 실패}
기대: unknowns 기록, 조사 결론 중단.
