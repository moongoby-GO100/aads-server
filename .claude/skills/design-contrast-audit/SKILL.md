# 대비와 조작 영역 점검

문서 키: `design-contrast-audit`. 이 스킬은 검토·질문 지침이며 외부 쓰기 권한을 부여하지 않는다.

## 입력·산출물과 진행 규칙

입력: {rendered_styles, bounding_boxes, viewport, scroll_dimensions, calculation_results}.
산출물: {checks: [{element, metric, value, threshold, verdict, evidence}], questions}.
대비·터치(44px)·넘침은 모델 판단이 아니라 코드 계산값으로 판정한다. 계산 못 한 항목은 '평가불가'.
sRGB 채널을 선형화(c<=0.04045이면 c/12.92, 아니면 ((c+0.055)/1.055)^2.4)하고 L=0.2126R+0.7152G+0.0722B를 구한다.
대비율은 (L밝음+0.05)/(L어두움+0.05). 일반 텍스트 4.5:1, 큰 글자(24px 또는 굵은 18.66px 이상) 3:1을 비교한다.
계산 코드·입력·출력을 증거로 남긴다. 반투명·그라디언트 배경 합성을 계산 못 하면 평가불가다.
터치는 실제 조작 영역 bounding box의 폭과 높이가 모두 44px 이상인지 계산한다.
넘침은 같은 viewport에서 scrollWidth>clientWidth 및 요소 경계를 계산하고 의도된 내부 스크롤과 문서 넘침을 구분한다.
실패·질문 조건: 스타일·치수 누락이면 평가불가와 측정 요청. 스크린샷 인상으로 통과시키지 않는다.

각 계산은 대상 요소·상태·viewport·측정 시점과 입력 및 실행 결과를 연결한다. 상태별 대비와 포커스 표시를 따로 확인한다. 측정 입력이 충돌하거나 실행 실패면 평가불가이며 통과를 선언하지 않는다.

## 정본 실행 계약 보완

- 각 스킬에 입력 스키마, 실행 단계, 산출물 스키마, 실패/질문 조건, 허용 도구, 금지 권한, 검증 fixture를 모두 둔다.
- 입력: 프로젝트/tenant, 사용자/역할, 핵심 업무, 대상 화면/route, 현재 상태, 허용/금지 범위, 성공 기준, 참조 문서·승인본 판본/hash. 해당하지 않는 필드는 이유를 명시하고 누락과 구분한다.
- 출력: 판단·근거 참조, 미확인 항목, 다음 질문/복구 행동, 승인 필요 여부, 적용 단계, 입력 및 산출물 판본 참조, 실제 로드한 skill version/hash. 필드명은 구현에 맞춰도 의미와 추적 가능성은 유지한다.
- 허용 도구는 필요한 읽기·초안 생성·명시된 검증으로 최소화한다. CEO 승인 대행, 운영 DB/토큰 덮어쓰기, 승인되지 않은 구현 러너 인계, 배포·재시작, 외부 원문 실행은 스킬 자체 권한으로 허용하지 않는다.
- candidate 작성, 스키마 통과, fixture 통과, 실물 UX 검토, 활성화 승인, 운영 반영은 각각 별도 상태다. JSON 통과를 UX 합격으로 치환하지 않는다.
- 정상 fixture는 명시된 조건이 충족될 때만 해당 단계의 합격 가능이다. 누락·충돌·실패 fixture는 올바른 중단/질문/복구가 관측되어야 fixture 테스트가 통과한다. 이는 작업 산출물이 합격했다는 의미가 아니다.
- 설명만 있고 코드 강제가 없는 항목은 '지침만 있음'으로 표시한다. D1.5 스킬 계약과 D1.6 게이트 증거를 구분한다. 아직 구현되지 않은 후속 게이트를 현 단계가 제공한다고 보고하지 않는다.
- 새 화면 Q1~Q10과 S3 축소 질문을 구분한다. S3는 적용 범위/유지할 것/완료 기준의 최소 3영역이다. 이미 확정된 답을 근거 없이 다시 묻지 않되 판본·출처 연결과 현재 요청에 대한 확인을 생략하지 않는다.
- 답변 출처 정본 표기는 CEO 선택 / CEO 직접 입력 / 권장값 수락 / 추정값 확인이다. 기존 CTO 기록의 enum 대응은 ceo_choice / ceo_input / recommended_accepted / estimate_confirmed이며 구현 후보와의 일치 여부는 후속 검수 대상이다. '잘 모름' 자체는 확정 출처가 아니다. 제시된 권장값의 수락 또는 추정값 확인 증거가 필요하다.
- 시각 검수는 실제 화면 근거가 필요하다. 캡처 실패 시 HTTP→API→프로세스 폴백을 기록해 기능 상태를 확인하되, 시각 검수는 미완료로 남긴다. 44px는 프로젝트 터치 기준이며 접근성 전체 준수를 의미하지 않는다.
- 이하의 업무 복구/입력 보존/의미 토큰 구분 등 상세 UX fixture는 UX 담당의 검수 제안이다. rev4 원문에 동일 문장이 모두 존재한다고 주장하지 않는다.

실행 단계: 실제 렌더링의 전경·합성 배경·투명도·텍스트 크기/두께·상태를 근거로 대비를 계산하고 적용 정책/임계값/계산 입력을 기록한다. 터치는 실제 클릭 가능한 영역의 폭·높이를 각각 프로젝트 기준 44px와 비교한다. 이미지·그라데이션 배경은 관련 영역을 평가하고, 미측정은 평가불가로 남긴다. 넘침은 viewport와 실제 요소 경계로 판단한다. 프로젝트 44px 통과를 접근성 전체 준수로 과장하지 않는다.
반려·복구 조건: 명목 토큰만으로 실제 대비 합격, 아이콘 크기로 터치 판정, 가로·세로 중 하나만 검사, 미측정을 0 또는 합격 처리, 평균 대비로 개별 실패를 숨김, 임계값/출처 없는 점수, 계산 실패 은폐는 반려한다.

## 검증 fixture

출처: design-agent-d15-ux-acceptance-rev4-57980cb2 revision 2. 정적 계약이며 실제 모델·화면 실행은 미검증이다.

### 정상 fixture

ID: UX08-N
입력: 실제 합성 배경/전경·텍스트 조건과 클릭영역이 제공된다. 타깃 크기 44×44, 43×44, 44×43 CSS px 및 정책 대비 임계값과 그 미만 값을 각각 입력한다.
기대: 기대: 44×44는 터치 기준 통과, 43×44·44×43은 실패; 대비는 명시 정책과 원시 계산값으로 경계 판정한다.
관측: 표시 반올림으로 실패를 통과시키지 않고 대비와 터치 판정을 각각 출력한다.

### 누락 fixture

ID: UX08-M
입력: 이미지 배경의 실제 픽셀·합성값 또는 클릭영역 측정이 없다.
기대: 평가불가·증거 요청: 해당 항목은 시각 검수 통과로 인정하지 않는다.
관측: 미측정을 정상/0% 실패/전체 합격으로 대체하면 반려한다.

### 충돌 fixture

ID: UX08-C
입력: 토큰은 기준 충족이나 실제 disabled 상태의 투명 합성 배경은 불충족이고, 아이콘은 24px·실제 버튼은 44×44px이다.
기대: 실제 렌더링 기준 판정: 상태별 대비 실패와 버튼 터치 통과를 구별한다.
관측: 토큰/아이콘 치수로 실제 상태 판정을 뒤집으면 반려한다.

### 실패 fixture

ID: UX08-F
입력: 캡처 또는 측정 엔진이 실패한다.
기대: 시각 검수 미완료: HTTP→API→프로세스 폴백 결과를 별도 기록하고 측정 재시도를 안내한다.
관측: HTTP 200을 대비/터치 합격으로 간주하거나 접근성 전체 준수를 선언하면 반려한다.

## 추가 회귀 사례 (supplemental)

정본 40건에 합산하지 않는다.


입력: {calculation_results: {contrast_black_white: 21, button_width: 44, button_height: 43, scrollWidth: 390, clientWidth: 375}}
기대: 대비 통과(일반 4.5), 터치 실패(높이 43<44), 문서 넘침 15px 실패, 계산 증거 기록.
입력: {rendered_styles: null, bounding_boxes: null}
기대: 모든 미측정 항목 '평가불가', 통과 없음.

위 fixture는 기대 동작 명세다. 실제 모델 수행 검증·사용 증거와 사람 승인 전에는 active로 승격하지 않는다.

### supplemental 정상 fixture

입력: {calculation_results: 대비 21, 폭 44, 높이 44, overflow 0, evidence: 실행기록}
기대: 측정 범위 내 통과.

### supplemental 누락 fixture

입력: {bounding_boxes: null}
기대: 터치 평가불가, 측정 요청.

### supplemental 충돌 fixture

입력: {calculation_results: 동일 요소 높이 43과 44}
기대: 측정 조건 확인, 통과 보류.

### supplemental 실패 fixture

입력: {calculation_results: 실행 실패}
기대: 평가불가, 실행 결과 요청.
