# 릴리스 변경 기록 쓰기

커밋 이력은 개발자가 개발자에게 남긴 메모다. 변경 기록은 **바뀐 결과를 쓰는 사람이 아닌 읽는 사람의 언어**로 다시 쓰는 일이다.
이 스킬은 쓰는 기준만 안내한다. git 명령 실행 권한은 주지 않는다 — 이력은 호출한 세션이 이미 가진 출력
(`git log` 결과, 커밋 목록, PR 설명)을 `Read` 로 읽어 쓴다. 이력을 얻을 수 없으면 사용자에게 구간(시작·끝 SHA 또는 날짜)을 받는다.

## 시작 전
1. **구간을 고정한다.** 시작 SHA(또는 날짜)와 끝 SHA 를 적는다. 구간이 흔들리면 기록이 누락되거나 중복된다.
2. **독자를 정한다.** 대표·운영자(결과만), 개발자(영향 범위까지) 중 누구인가. 기본은 대표·운영자.
3. 병합 커밋과 되돌림(revert)은 짝을 지어 확인한다. 되돌려진 변경은 "적용됨" 으로 쓰지 않는다.

## 사내 커밋 제목 읽는 법
이 저장소의 대부분의 커밋은 러너가 만들며 제목이 `Pipeline-Runner: runner-<8자리> — <지시서 첫머리>` 형태다.
- `runner-<8자리>` 가 **job_id** 다. 근거 표기에 그대로 쓴다.
- 제목 뒤쪽은 지시서 머리글이 잘려 들어간 것이라 **무엇이 바뀌었는지는 제목에 없는 경우가 많다.** 이때는 커밋 본문과 변경 파일 목록, 가능하면 TASK_ID·TITLE 줄을 읽어 내용을 파악한다.
- 지시서 머리글의 실행 옵션 문자열(`PUSH_ONLY` 등)은 노이즈다. 변경 기록에 옮기지 않는다.
- 사람이 직접 쓴 `fix(범위): 요약` · `feat(...)` · `docs(...)` · `test(...)` 형식도 있다. 접두어는 분류 단서로만 쓴다.
- 제목이 잘려 의미를 알 수 없고 본문·파일 목록으로도 확인되지 않으면 추측하지 말고 "내용 확인 필요(SHA …)" 로 따로 모은다.

## 분류
커밋 하나가 여러 갈래에 걸치면 가장 큰 영향 하나에 두고, 나머지는 한 줄만 덧붙인다.
| 분류 | 넣는 것 |
|---|---|
| 새 기능 | 사용자가 새로 할 수 있게 된 것 |
| 개선 | 이미 있던 것이 빨라지거나 편해진 것 |
| 오류 수정 | 잘못 동작하던 것이 바로잡힌 것 |
| 운영·안정성 | 장애 예방, 재시도, 감시, 권한 보호 |
| 문서·테스트 | 사용자에게 보이지 않는 정비 (한 줄로 묶는다) |
| 주의 | 동작이 달라져 사용자가 알아야 하는 변경, 되돌림 |

## 업무 언어로 옮기기
- 파일명·함수명·테이블명이 아니라 **사용자가 보던 화면과 행동**으로 쓴다.
  - 나쁜 예: `ceo_chat_tools.py 의 retry 분기 수정`
  - 좋은 예: 채팅에서 도구 호출이 실패하면 자동으로 한 번 더 시도합니다.
- "무엇이 달라졌나 + 그래서 무엇이 좋아졌나" 를 한 문장으로. 효과를 단정하려면 근거(테스트 결과, 측정값)가 있어야 한다. 없으면 "예상" 이라고 쓴다.
- 내부 식별자(TASK_ID, 함수명)는 본문이 아니라 근거 표기에만 둔다.
- 외부에 보이면 안 되는 것(토큰, 내부 경로, 고객 데이터)은 쓰지 않는다.

## 출력 형식
```
# <구간 또는 날짜> 변경 기록

## 한눈에 보기
- (가장 중요한 변경 2~3줄)

## 새 기능
- 문장. (근거: <SHA 앞 8자>, runner-xxxxxxxx)

## 개선 / 오류 수정 / 운영·안정성 / 주의
...

## 내용 확인 필요
- <SHA> — 제목만으로 판단 불가한 사유

## 구간
- 시작 <SHA> ~ 끝 <SHA> (총 N건, 기록 반영 M건)
```
- 모든 항목에 **커밋 SHA 앞 8자**를 달고, 러너 커밋이면 job_id 도 같이 쓴다. 근거 없는 항목은 쓰지 않는다.
- 총 건수와 반영 건수가 맞는지 마지막에 센다. 안 맞으면 빠진 커밋을 찾는다.
- 새 문서로 저장하는 경우 R-DOC 를 따른다(`document-coauthoring` 스킬 참고): 한글 제목, 영문 document_key, 정본 초안 등록.

## 자주 틀리는 것
- 커밋 제목을 그대로 복사한다 — 러너 제목은 지시서 머리글이라 의미가 없다.
- 같은 변경이 수정 커밋과 재수정 커밋으로 나뉜 것을 별개 항목으로 센다. 하나로 묶고 SHA 를 모두 단다.
- 되돌려진 변경을 새 기능으로 적는다.
- 효과를 확인하지 않고 "해결됨" 이라고 쓴다.

## 승격 조건
현재 `status: candidate`. 아래를 모두 만족해야 `active` 로 올린다.
1. 이 스킬로 변경 기록을 쓴 **사용 증거 2건** — 세션 id 또는 러너 job_id 를 각각 기록한다.
2. 두 건 모두 모든 항목에 SHA 근거가 있고, 총 건수와 반영 건수가 일치한다.
3. 위험 등급이 `read` 로 유지된다 (`infer_risk_tier` 확인).
승격은 증거 확인 후 사람이 승인한다. 이 문서는 스스로 승격하지 않는다.
