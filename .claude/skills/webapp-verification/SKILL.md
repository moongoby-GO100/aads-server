# 웹 화면 검증

화면이 정상이라는 말은 **화면 근거**가 있을 때만 쓴다. 이 스킬은 근거를 모으는 순서와 보고 방식만 안내하며,
파일 수정·셸 실행 권한은 주지 않는다. 아래 도구는 호출한 세션이 이미 가진 권한 안에서만 쓴다.
원본이 쓰던 임의 셸 실행 보조 스크립트(서버를 띄우고 자동화 스크립트를 감싸 실행하는 방식)는 사내에서 쓰지 않는다.
서버 기동·재시작이 필요하면 직접 하지 말고 담당 절차(러너·릴리스 규칙)에 요청한다.

## 언제 쓰나
- 지시서·완료 기준에 로그인, 화면 접속, 스크린샷, 캡처, visual QA 가 들어 있을 때.
- 프런트엔드(대시보드 등)를 고친 뒤 "화면이 정상" 이라고 보고하려 할 때.
- 사용자가 "여기 확인해" 라고 했을 때 (소스 분석이 먼저, 부족하면 화면).

## 1단계 — 무엇을 확인할지 먼저 적는다
확인할 화면 주소, 로그인 필요 여부, 보아야 할 요소(제목, 버튼, 목록 행 수, 오류 문구 없음)를 3줄 안으로 적는다.
정적 화면이면 소스(`Read`/`Grep`)에서 선택자와 문구를 먼저 찾는다. 소스에서 답이 나오면 화면 조회는 보조로 둔다.

## 2단계 — 브라우저 도구로 화면 근거 모으기
| 목적 | 도구 | 비고 |
|---|---|---|
| 화면 이동 | `browser_navigate` | 로그인 필요 시 `credential_test_login` |
| 구조·문구 확인 | `browser_snapshot` | 접근성 트리 텍스트. 요소 존재 여부 판정에 쓴다 |
| 내부 점검용 이미지 | `browser_screenshot` | 보고서에 첨부하지 않는다 |
| 사용자에게 보일 이미지 | `capture_screenshot` | CEO·사용자 표시용 |
| 시각 품질 판정 | `visual_qa_test` | 채점기 장애는 평가불가이지 불합격이 아니다 |
| 조작 | `browser_click`, `browser_fill` 등 | 동작 후 `browser_snapshot` 으로 결과를 다시 본다 |

- 동적 화면은 로딩이 끝난 뒤의 상태를 본다. 로딩 중 스냅샷으로 "요소 없음" 을 결론내지 않는다.
- 사전 접속이 안 되면 `browser_connect(action='ensure_work_session')` 으로 작업 세션을 확보한 뒤 한 번만 재시도한다.
- 주요 행동 한 가지와 복구 흐름(오류·권한 없음·세션 만료) 한 가지는 실제로 눌러 본다. 보기만 하고 "동작" 이라 쓰지 않는다.
- 모바일이 요구되면 360px 폭에서 가로 넘침이 없는지 별도로 본다.

## 3단계 — 브라우저가 실패하면 R-E2E 폴백
"E2E 미완" 으로 끝내지 않는다. 아래 순서로 내려가며 각 결과를 **따로** 기록한다.
1. `fetch_url` 로 HTTP 상태 코드 확인.
2. API health 호출 (`/api/v1/ops/health-check` 등 해당 서비스의 상태 경로).
3. `run_remote_command` 로 컨테이너·프로세스 상태 확인 (읽기 명령만).

폴백으로 대체했으면 보고에 **"브라우저 E2E 미실행, API 검증으로 대체"** 를 그대로 적는다.
"렌더링 미확인" 은 최종 보고가 아니다 — 폴백까지 끝낸 뒤 보고한다.

## 하지 않는 것
- API 가 200 이라는 사실로 **시각 검수 성공**을 선언하지 않는다. 시각 검수는 미완료로 둔다.
- 캡처도 폴백 결과도 없는데 완료로 쓰지 않는다.
- 로그인 정보·토큰을 보고서나 캡처에 노출하지 않는다 (R-KEY).
- 로컬 서버를 임의로 띄우거나 종료하지 않는다. 띄운 프로세스는 회수 책임이 따른다 (R-BG).

## 보고 형식
| 항목 | 결과 | 근거 |
|---|---|---|
| 접속 | 통과 / 실패 / 평가불가 | 도구 이름과 응답 요약 |
| 요소·문구 | 통과 / 실패 / 평가불가 | 스냅샷에서 확인한 텍스트 |
| 주요 행동 | 통과 / 실패 / 평가불가 | 누른 항목과 결과 |
| 복구 흐름 | 통과 / 실패 / 평가불가 | 시나리오와 결과 |
| 시각 | 통과 / 실패 / 평가불가 | 캡처 또는 미완료 사유 |
평가불가가 하나라도 있으면 전체를 통과로 쓰지 않는다. 실행하지 않은 검증을 통과로 적지 않는다.

## 승격 조건
현재 `status: candidate`. 아래를 모두 만족해야 `active` 로 올린다.
1. 이 스킬을 따라 화면 검증을 수행한 **사용 증거 2건** — 세션 id 또는 러너 job_id 를 각각 기록한다.
2. 두 건 모두 위 보고 표가 남아 있고, 브라우저 실패 시 폴백 기록이 분리되어 있다.
3. 위험 등급이 `read` 로 유지된다 (`infer_risk_tier` 확인).
승격은 증거 확인 후 사람이 승인한다. 이 문서는 스스로 승격하지 않는다.
