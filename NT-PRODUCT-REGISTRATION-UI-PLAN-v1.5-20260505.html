버전 히스토리

v1.0최초 상품등록 UI 방향 v1.1등록 목적과 역할 흐름 보강 v1.2V1 필드/DB 비교 및 흐름도 v1.3V1 상세이미지/HTML 생성 흐름 반영 v1.4등록 목적 자동 분류와 기본 목업 v1.5 현재즉시 구현용 상세 UI 디자인

최종 설계 결론

상품등록은 사용자가 목적을 고르는 UI가 아니라, 시스템이 목적을 자동 판정한 뒤 필요한 작업만 열어주는 상품 작업실이어야 합니다. 도매, 뉴톡관리자, 촬영팀, 소매, 외부몰 제공까지 모두 같은 상품 마스터를 보되, 역할과 진입 경로에 따라 보이는 섹션과 필수 검증이 달라져야 합니다.

1. 사용자 목표

상품을 등록하는 것이 아니라 판매 가능한 상품 패키지를 완성하는 것이 목표입니다. 기본정보, 가격, 이미지, 상세HTML, 외부몰 제공자료가 한 화면의 작업 상태로 연결돼야 합니다.

2. V1 대체 기준

V1의 goods_img, goods_img_sorting_test1, detail_save, 단하루 HTML/엑셀 제공 흐름을 V2 상품등록 안에 포함해야 V1을 대체할 수 있습니다.

3. 구현 단위

한 번에 거대한 폼을 만들지 말고 상품 작업실 Shell, 기본정보, 이미지 작업실, 상세빌더, 채널 제공, 검수 발행 순서로 컴포넌트를 나눠 구현합니다.

상태 설계: 사용자가 판단 가능한 화면

로딩

상품 마스터, V1 원본, 이미지 파일 수, 상세HTML을 각각 skeleton으로 나눠 표시합니다. 전체 화면을 빈 화면으로 두지 않습니다.

빈 상태

도매처 상품이 없으면 "도매처 지정 후 대행등록" 또는 "V1 상품코드 가져오기" 버튼을 바로 제공합니다.

오류

이미지 폴더 접근 실패, DB 원본 없음, HTML 생성 실패를 별도 오류로 표시하고 재시도 버튼을 제공합니다.

권한 없음

일반 도매는 가격/자기 상품만 수정, 관리자만 도매처 귀속/V1 원본 복원/강제 게시가 가능하도록 버튼을 분리합니다.

모바일/반응형 설계

모바일 우선 작업

상품 기본정보는 1열 폼, 이미지 정렬은 레인 탭 방식으로 전환합니다. 드래그가 어려운 환경에서는 선택 후 이동 버튼을 제공합니다.

고정 액션

모바일에서는 하단 고정바에 임시저장, 미리보기, 다음 작업을 배치합니다. 위험 액션인 삭제/게시 취소는 더보기 메뉴 안에서 확인을 거칩니다.

텍스트/터치

버튼 최소 높이 40px, 입력 라벨 고정, 긴 상품명 줄바꿈, 가격 단위 자동 포맷을 적용합니다.

구현 우선순위

단계 작업 완료 기준

P0-2 V1 상품 원본 읽기 API + 기본정보 diff UI V1 상품코드 기준 goods/goods_detail/goods_image 원본 표시

개발자 전달 요약

구현자는 기존 /admin/products/[id] 상세 페이지를 단순 편집 폼에서 Product Workspace로 바꿔야 합니다. 첫 화면은 상품명/가격 폼이 아니라 자동 컨텍스트, 완성도, 작업 레일, 기본정보 폼, V1 diff, 차단 체크가 동시에 보이는 작업형 화면이어야 합니다.
  • 등록 목적 선택 컴포넌트는 만들지 않습니다. 목적은 role, route, linked task, V1 goods code, channel state로 자동 계산합니다.
  • 이미지 등록은 상품등록의 부속 버튼이 아니라 필수 단계입니다. 원본 업로드, 정렬, 상세HTML 생성, 외부 제공까지 연결합니다.
  • V1 대체를 위해 V1 원본값과 V2 수정값을 같은 화면에서 diff로 보여줘야 합니다.
  • 소매/외부몰 제공은 마지막 부가 기능이 아니라 상품 완성 체크의 일부입니다.
