1 기능 개요

하나의 기획 주제에 대해 서로 다른 LLM들이 독립적으로 기획안을 작성하고, 상호 검토·비판·보완하며, CEO가 실시간으로 방향을 조정하여 양질의 최종 기획서를 도출하는 오케스트레이터 시스템.

🎯 핵심 목적
  • 단일 LLM의 편향 제거 (모델 다양성)
  • 기획 품질 향상 (경쟁적 검토)
  • CEO의 실시간 의사결정 참여
  • 검증 가능한 근거 기반 기획
⚡ 핵심 차별점
  • 기존 run_debate: 일괄 실행 → 결과만 수신
  • 이 기능: 라운드별 진행 + CEO 개입
  • 대화창에 발화자별 구분 표시
  • 토론 중 방향 전환·참가자 추가 가능
🏗️ 구현 전략
  • 기존 인프라 최대 활용 (채팅 SSE, LiteLLM)
  • CTO AI가 오케스트레이터 역할
  • 신규 서비스 1개 + API 2개 추가
  • DB 테이블 1개 추가

4 토론 플로우

라운드 기반 진행. CEO가 각 라운드 후 개입 여부를 결정.

① CEO — 주제 제시

CEO가 토론 주제와 목표를 제시합니다.
예: "AADS 과금 시스템 설계 기획해줘. 토론 모드로."
오케스트레이터가 토론 의도를 감지하고 참가자 구성을 제안합니다.

② 오케스트레이터 — 세션 초기화

참가자 구성 확인 → 토론 세션 생성 → 라운드 1 시작을 선언합니다.
각 참가자의 시스템 프롬프트에 역할·관점·톤이 주입됩니다.

③ 라운드 N — 기획 A 발언

첫 번째 기획자가 주제에 대한 기획안을 작성합니다.
라운드 2+에서는 이전 라운드의 모든 발언을 컨텍스트로 받아 반박·보완합니다.
SSE 스트리밍으로 실시간 표시됩니다.

④ 라운드 N — 기획 B 발언

두 번째 기획자가 기획 A의 발언을 참조하여 대안 또는 보완 기획을 작성합니다.
다른 모델이므로 자연스럽게 다른 관점이 나옵니다.

⑤ 라운드 N — 검증자 비판

두 기획안을 비교 분석하고 논리적 결함, 비용 비현실성, 일정 리스크를 지적합니다.
각 기획안에 점수(1~10)를 부여하고 구체적 개선점을 제안합니다.

⑥ CEO 개입 포인트 (선택)

라운드 종료 후 CEO에게 선택지를 제시합니다:

🔄 다음 라운드 💬 방향 지시 ✅ 합성 요청 ⏹️ 토론 종료

CEO가 "B안 방향으로 가되 비용은 A안 수준으로"처럼 구체적으로 지시하면
다음 라운드에 해당 지시가 모든 참가자 컨텍스트에 주입됩니다.

⑦ 합성 — 최종 기획서 생성

모든 라운드의 논의를 종합하여 최종 기획서를 생성합니다.
CEO 지시사항 반영 확인, 채택/미채택 근거, 실행 계획을 포함합니다.
Extended Thinking으로 깊이 있는 합성을 수행합니다.

# app/services/discussion_orchestrator.py

class DiscussionOrchestrator:
    """멀티-LLM 토론 오케스트레이터. CEO 실시간 개입 지원."""

    async def start_discussion(
        self,
        topic: str,
        session_id: str,
        participants: list[ParticipantConfig] | None = None,
        max_rounds: int = 3,
        budget_usd: float = 10.0,
    ) -> AsyncGenerator[DiscussionEvent, None]:
        """토론 세션 시작. SSE 이벤트를 yield."""
        ...

    async def run_round(
        self,
        discussion_id: str,
        ceo_directive: str | None = None,
    ) -> AsyncGenerator[DiscussionEvent, None]:
        """라운드 N 실행. CEO 지시사항을 컨텍스트에 주입."""
        for participant in self.participants:
            # 이전 라운드 + CEO 지시를 컨텍스트로 조합
            context = self._build_round_context(participant, ceo_directive)
            async for event in self._call_participant(participant, context):
                yield event
        yield DiscussionEvent("round_complete", round=self.current_round)

    async def synthesize(
        self,
        discussion_id: str,
        ceo_final_directive: str | None = None,
    ) -> AsyncGenerator[DiscussionEvent, None]:
        """전체 라운드 합성 → 최종 기획서 생성."""
        ...

    def _build_round_context(self, participant, ceo_directive):
        """참가자별 컨텍스트 조합: 주제 + 이전 발언 + CEO 지시 + 역할 프롬프트"""
        ...

8 데이터 모델

신규: discussion_sessions 테이블

CREATE TABLE discussion_sessions (
    id            UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id    UUID        REFERENCES chat_sessions(id),
    topic         TEXT        NOT NULL,
    status        VARCHAR(20) NOT NULL DEFAULT 'active',
                  -- 'active' | 'wait_ceo' | 'synthesizing' | 'done' | 'cancelled'

    -- 참가자 구성
    participants  JSONB       NOT NULL,
                  -- [{name, role, model, system_prompt, color, avatar}]

    -- 라운드 데이터
    max_rounds    INT         DEFAULT 3,
    current_round INT         DEFAULT 0,
    rounds        JSONB       DEFAULT '[]',
                  -- [{round, ceo_directive, responses: [{participant, content, model, cost, tokens}]}]

    -- 합성 결과
    synthesis     TEXT,
    artifact_id   UUID        REFERENCES chat_artifacts(id),

    -- 비용/시간 추적
    budget_usd    DECIMAL(10,4) DEFAULT 10.0,
    total_cost    DECIMAL(10,4) DEFAULT 0,
    duration_ms   INT,

    created_at    TIMESTAMPTZ DEFAULT now(),
    updated_at    TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_discussion_session ON discussion_sessions(session_id);
CREATE INDEX idx_discussion_status ON discussion_sessions(status);
