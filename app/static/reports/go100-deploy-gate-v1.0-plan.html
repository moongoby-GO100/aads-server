담당들은 그 시간에 메시지 157건을 쓰고 있었다. 일을 안 하는 게 아니라 릴레이가 답을 회수하지 못한다. 그리고 pending 이 남아 있으면 같은 담당에게 2시간 동안 재질문이 막힌다(already_in_flight).

2.2 설계: 릴레이에 의존하지 않는 3단 통제 루프

단계수단릴레이 의존
발신ask_session → 막히면 chat_messages 에 [추가 지시](intent=queued_interrupt) 직접 주입없음
회수chat_messages 를 role_key 로 직접 SELECT — 담당의 최신 완성 회신을 읽는다없음
검증담당 주장을 GO100 서버 실측(systemctl·git·DB)으로 교차 확인없음
검증 단계가 핵심이다. 오늘 담당 주장 3건이 교차검증에서 뒤집혔다 — go100-background 가 #310 을 매매한다는 전제, 게이트 롤백 상태, 미청산 건수. 회수만으로는 통제가 아니다.

2.3 통제 대상 범위

#310 하네스 8명 — StrategyCardLead(주도) · WaveEngineOwner · LiveTradingOwner · DataEngineOwner · StockDiscoveryOwner · BacktestEngineOwner · MLModelOwner · OpsInfraOwner. 목표 250a271f 「#310 전략카드 일일 누적수익 3% 확보」 마일스톤 16건에 담당이 붙어 있다.

2.4 개선 요청 (AADS 소관, 별건)

  • session_relay.pending 에 타임아웃이 없다 → 답이 안 오면 그 줄기가 2시간 잠긴다
  • 담당 답이 chat_messages 에 완성본으로 있는데 answered 로 전이되지 않는다
  • streaming_placeholder 로 끝난 응답이 내용이 있어도 폐기된다

3.2 설계 원칙 — "꼼꼼하되 빠르게"를 어떻게 양립시키나

원칙구현얻는 것
넓게 얕게가 아니라 좁게 깊게실매매 경로만 검사. 전체 테스트 스위트는 안 돌린다40초 vs 수 분
사후가 아니라 사전핀 전환 전에 릴리스 디렉터리를 검사엔진이 죽고 나서 알던 것을 죽기 전에 안다
고정 대기가 아니라 신호 대기기동 완료 로그를 기다린다(상한 180초)78초 기동을 오탐으로 죽이지 않는다
우회로를 만들지 않는다--force 없음. 우회는 G1 환경변수 1개, 사유 로그 필수게이트가 형식이 되지 않는다

3.3 4단 게이트 흐름

[커밋 확정]
     │
     ├─ G1 정합 (10초)  git clean? ahead/behind 0?      실패 → exit 1
     │
[릴리스 디렉터리 생성]
     │
     ├─ G2 임포트 실재 (20초)                            실패 → exit 2  ★ card119 사고 차단
     │     cd <release_dir>
     │     python -m compileall -q backend/app/services/go100
     │     python -c "import backend.app.services.go100.live_trading"
     │     python -c "import ...card310_scheduler"
     │     python -c "import ...card119_limitup_scheduler"
     │
     ├─ G3 계약 테스트 (40초)  실매매 4개 파일만          신규실패 → exit 3
     │
[핀 전환 + 재기동]
     │
     └─ G4 기동 확인 (가변, 상한 180초)                  실패 → exit 4  ★ 오탐 롤백 차단
           journalctl 에서 "Application startup complete" 대기
           → /health 200 확인

3.4 왜 G2 를 릴리스 디렉터리에서 돌려야 하나

오늘 사고의 본질이 여기 있다. exit_lock.py 는 워킹트리에 있었고 git 에도 있었다. 워킹트리에서 import 테스트를 했다면 통과했을 것이다. 없었던 곳은 릴리스 디렉터리뿐이고, 서비스가 읽는 것은 그 디렉터리다. 검사는 반드시 실행될 그 경로에서 해야 한다.

7. 목표와의 연결

이 게이트는 목표(#310 일 3%)를 직접 올리지 않는다. 목표 작업이 사고로 중단되는 것을 막는다. 2026-09-16 실적은 11왕복 3승 8패, 순손익 -1,557.57원, 건별 합산 -2.304%. 같은 날 배포 사고로 엔진이 1분 36초 죽었고, 청산가 게이트는 오탐 롤백으로 실매매에 투입되지 못했다. 개선이 실매매에 도달하지 못하면 목표는 움직이지 않는다. 이 문서는 그 도달 경로를 고치는 것이다.
