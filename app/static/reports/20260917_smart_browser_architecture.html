4. 실행 시퀀스

[학습 1회차]
지시 → 레시피 없음 → LLM 탐색 실행(브리지 도구 호출) → 성공
     → 호출 순서·선택자·검증조건을 YAML로 직렬화 → work_recipes v1 저장

[재생 2회차 이후]
지시 → 도메인+의도로 레시피 매칭 → Risk Gate 사전 스캔
     → READ/WRITE_INTERNAL 단계는 즉시 실행 (LLM 호출 0)
     → WRITE_EXTERNAL/IRREVERSIBLE 도달 시 실행 중단 + 승인 카드 발행
     → 승인 수신 후 재개 → 검증조건 확인 → recipe_runs.success

[실패 복구]
단계 실패(선택자 없음/타임아웃) → 스냅샷 1장 + 실패 단계만 LLM 전달
     → 대체 경로 성공 시 해당 단계만 교체 → version+1 저장 (전체 재학습 금지)

5. 보안 통제

위협통제구현 지점
프롬프트 인젝션(BragJack 유형)페이지 텍스트를 <untrusted_page_content>로 감싸 데이터로만 취급. 도구 인자는 레시피에 선언된 값·사용자 입력에서만 생성Executor 입력 경계 Dark Reading 2026-09-16
도메인 이탈레시피 domain 외 이동 시 즉시 중단 + 감사 1행Risk Gate
크리덴셜 남용vault 조회를 (도메인×레시피) 스코프로 제한, 사용 시 감사 필수, 값은 로그·스크린샷에서 마스킹credential_vault 래퍼
무단 위험행위등급 WRITE_EXTERNAL 이상은 승인 레코드 없으면 실행 불가(코드 차단, 문서 규칙 아님)Risk Gate + DB 제약
증거 조작recipe_run_steps append-only 트리거마이그레이션
R-ERRBOOK 원칙 적용: 위 통제는 전부 코드 차단으로 구현한다. “규칙으로만 기록”한 항목은 재발한다는 것이 사내 실측 결론이다.
