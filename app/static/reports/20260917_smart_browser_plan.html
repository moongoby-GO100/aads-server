1. 배경 — 왜 지금인가

대표님 지시는 “브라우저로 되는 모든 작업을 컨트롤부터 끝까지 진행하는 브라우저”다. 이를 구현하는 방법은 세 갈래이며, 2026년 9월 시장은 그중 하나를 이미 탈락시켰다.

  • 기존 브라우저 내장 — Gemini in Chrome이 미국 안드로이드 전체 배포. droid-life, 2026-08-18
  • 업무 앱 내장 — Claude Cowork가 Chrome 확장을 걷어내고 자체 사이드패널 브라우저를 기본 탑재. TheNextWeb, 2026-09

4. 방향 선택 — 3안 비교

안내용장점리스크판정
AChromium 포크로 자체 브라우저 개발완전한 제어엔진 유지보수·보안 패치 부담. Atlas도 접는 영역비권장
B기존 브리지 위에 레시피·권한·감사 계층 신설자산 재사용, 2주 내 체감, 우리 DB·러너와 직결사이트 UI 변경 추적 필요권장
C상용 에이전트 브라우저 도입즉시 사용 가능내부 DB·러너 연결 불가, 데이터 외부 유출대안(개인 리서치 한정)
권장: B안. 근거 — ① 실행 계층은 이미 3,182줄이 돌고 있어 새로 만들 필요가 없다. ② 시장이 증명한 실패 지점(전용 브라우저·무승인 자동화)을 우회한다. ③ WebMCP가 표준화되면 B안의 실행기만 교체하면 되지만, A안은 전체를 다시 만들어야 한다.
승인 시: PRD의 P0(작업 레시피 엔진)부터 러너로 착수. 롤백: 신규 테이블·모듈 추가형이라 revert 1회로 원복. 미승인 시: 지금처럼 같은 작업을 매번 LLM이 재탐색하는 비용 구조가 유지된다.
