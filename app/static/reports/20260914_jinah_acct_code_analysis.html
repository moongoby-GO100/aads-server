1. 저장소 목적과 도메인

이 저장소는 한 중소기업(라일론 등으로 추정되는 복수 계열사)의 회계 실무를 대행하는 AI 비서 "진아"의 서버 측 코드·규칙·상태 전체다. /srv/biseo/CLAUDE.md(상위 자료 창고 안내)와 /srv/biseo/회계비서/회계비서/CLAUDE.md(진아 본체 지침, 5,938바이트, 목차만 두고 본문은 규칙/본문/에 분리)를 읽어 확인했다.

자동화 대상 업무는 시작하기.md와 .claude/agents/ 6개 부서 정의에서 명시적으로 드러난다: 통장/카드 거래를 위하고(WEHAGO/SmartA) 업로드용 전표로 변환, 전자세금계산서 대량발행 엑셀 생성 및 발행 전 검증, 은행·카드·매출채권 대사(reconciliation), 계정별원장/재무제표 증감분석, 부가세·불공제·적격증빙 감사, 그리고 WEHAGO 화면 자체를 브라우저로 조작(입력까지만, 전송·발행·마감은 사람)하는 것이다.

이 시스템의 설계 철학은 시작하기.md 121~137행에 명시된 "일부러 안 하는 것" 3원칙으로 요약된다: ① 위하고 화면의 최종 실행 버튼(전송·발행·마감)은 절대 대신 누르지 않는다 ② 규칙에 없는 애매한 거래는 채워 넣지 않고 확인필요 시트로 분리한다 ③ 금액 계산은 사람 눈이 아니라 항상 코드로 한다. 이 세 원칙은 규칙/본문/21_...절대_규칙_어기지_말_것.md(577행, 16개 절대규칙 수록)에서 강제 규범으로 재확인된다.

또한 이 시스템은 단순한 "봇"이 아니라 사람 역할을 모사한 조직도를 코드로 구현한다 — 진아(비서실장/오케스트레이터), 서린(감사실장, 결과물 대조·반려 전담), 진식(GPT 기반 기술감사관, 코드 수정 검증), 부서장(재무부장·인사부장·교육부장), 실무팀 6개(전표팀·세금계산서팀·대사팀·분석팀·감사팀·위하고팀)로 구성된 다층 승인 구조가 .claude/agents/와 도구/_하네스.py·도구/_감찰관.py에 코드화되어 있다.

채팅앱/server.py는 Flask/FastAPI가 아니라 Python 표준 라이브러리 http.server 기반 자체 구현이다. Claude Code CLI는 API 직접 호출이 아니라 subprocess로 감싸 호출한다: claude -p <message> --output-format stream-json --permission-mode acceptEdits --settings /etc/biseo-hooks.json --allowed-tools ... --model claude-opus-5 [--resume <session_id>]. ACCESS_CODE는 BISEO_APP_PW 환경변수 또는 .앱비번(600 권한) 파일에서 읽으며 없으면 서버가 기동하지 않는다. 반면 NTFY_TOPIC(폰 알림 토픽)은 소스에 평문으로 하드코딩되어 있다(§8 리스크 참조).

6. 자동화 규칙 엔진

핵심 발견 — "규칙 엔진"은 파서가 아니라 텍스트 주입 + 별도의 하드코딩 게이트 로직 두 갈래로 나뉜다.

규칙/본문/ 29개 md 파일(00~28번 접두)은 도구/_감찰관.py의 규칙읽음() 함수(약 1164~1183행)가 sorted(os.listdir(...))로 정렬해 통째로 이어붙여 모델 컨텍스트에 주입하는 용도로만 쓰인다. 코드가 이 md의 내용을 의미적으로 파싱해 조건 분기하지 않는다 — 사람(모델)이 읽고 따르는 프롬프트일 뿐이며, 기억/규칙읽음.jsonl에는 "오늘 읽었다"는 타임스탬프만 남는다.

반면 실제로 작업을 막거나 통과시키는 "관문"은 md 해석이 아니라 _감찰관.py 안의 별도 파이썬 함수들로 코드화되어 있다: 규칙읽었나()(오늘 규칙읽음 로그 확인), 헛쓰나()(토큰 낭비 확인), 역할빠짐(), 확인없이말함(), 그리고 차례인가()(외부 LLM — Gemini 계열, --model gemini-3.8-flash-low — 를 별도로 호출해 "이 작업이 사장님이 시킨 목록·순서에 맞는가"를 판정시키고, 판정을 못 받으면 무조건 막는 구조). 끝냄 명령은 보고서 파일 존재·형식을 코드로 체크하고, 관문 종료는 그날 진식의 완료감사 파일 존재 여부를 확인한다.

11. 조사 방법과 한계

본 보고서는 직접 셸 탐색(ls/find/grep/wc/git log)과 핵심 문서(AGENTS.md, CLAUDE.md 2종, 시작하기.md, 원격접속.md, .gitignore)의 직접 읽기, 그리고 5개 영역(도구/ 코드품질, 규칙엔진/에이전트, 상태·기억·금고, 실행진입점·외부연동, 작업 데이터흐름)에 대한 독립 조사 에이전트 5개를 병렬 파견해 각 에이전트가 실제 파일을 열람하고 file:line 근거를 보고한 결과를 종합했다.

  • 민감정보 비인용 원칙: 실제 계좌번호·사업자번호·거래처명·금액·비밀번호 값은 조사 과정에서 확인했더라도 본 보고서에는 구조/스키마만 기술하고 값을 옮기지 않았다.
  • 미확인 항목: .mcp.json과 현재 세션 MCP 도구의 정확한 출처 관계, .codex/·agy CLI의 정확한 용도, 기억/_사업자/ API 호출 코드 세부, analysis-team.md/wehago-team.md/인사부장.md/재무부장.md/교육부장.md/서린.md의 상세 내용(에이전트 존재와 대략적 역할만 확인, 본문 정독은 조사 범위·시간상 생략), 작업/결과 내 실제 엑셀 시트 컬럼 스키마 등은 이번 조사에서 상세 확인하지 못했다.
  • 규모 제약: 저장소 전체 로컬 파일이 약 1.5만 개(브라우저 프로필·대화기록·작업 아카이브 포함, 5GB)에 달해 전수조사가 아닌 구조적 표본조사(대형 파일 우선, 진입점 우선)로 진행했다. 특히 작업/결과/(10,300개+ 파일)와 기억/·대화기록/ 내부는 폴더 구조와 대표 파일 형식만 확인했고 전체 파일을 열람하지는 않았다.
