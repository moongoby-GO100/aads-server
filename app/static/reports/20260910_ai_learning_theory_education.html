핵심 결론

AI 학습은 모델의 가중치가 데이터에 의해 바뀌는 과정입니다. 반면 프롬프트, RAG, 위키, 대화 메모리는 가중치를 바꾸지 않고 실행 시점에 정보를 공급합니다. AADS는 현재 후자에 강하며, 이를 “AADS가 모델을 재학습한다”고 표현하면 기술적으로 부정확합니다.

실무에서는 최신 사실은 RAG·도구로, 반복되는 행동 양식은 프롬프트·정책으로, 안정적으로 축적된 도메인 능력은 미세조정으로, 선호·안전 행동은 RLHF/DPO 계열로 해결합니다. 어느 하나가 나머지를 대체하지 않습니다.

AI 학습은 정답을 누가 제공하는지와 피드백이 언제 들어오는지에 따라 나뉩니다. 실제 제품은 한 방식만 쓰지 않고 여러 방식을 단계적으로 조합합니다.

AADS 적용 해석: 현재 관찰·메모리 축적은 온라인 데이터 수집에는 가깝지만, 그 데이터로 가중치를 자동 갱신하지 않으므로 온라인 학습은 아닙니다. 검수된 데이터를 별도 훈련 파이프라인에 투입하고 체크포인트를 만들 때 비로소 모델 학습이 됩니다.
CEO 검수 포인트: 누군가 “AI가 학습했다”고 보고하면 ① 어느 가중치가 ② 어떤 데이터셋과 손실함수로 ③ 언제 바뀌었고 ④ 전후 평가가 무엇인지 물으십시오. 답이 없다면 대부분 메모리·RAG·프롬프트 개선입니다.

2. 학습을 움직이는 핵심 수학

2.1 손실함수

손실함수는 모델이 얼마나 틀렸는지를 하나의 수로 만듭니다. 언어모델은 다음 토큰의 정답 확률을 높이는 교차엔트로피 손실을 주로 사용합니다.

L(θ) = − Σ log Pθ(정답 토큰 | 이전 토큰)

정답 토큰에 높은 확률을 주면 손실이 작아지고, 엉뚱한 토큰에 확률을 주면 손실이 커집니다. 단, 손실 감소가 사실성·안전성·업무효과를 자동으로 보장하지는 않습니다.

2.2 역전파와 경사하강법

θ ← θ − η · ∇θL

∇θL은 각 가중치가 오류에 미친 방향과 크기, η는 학습률입니다. 학습률이 너무 크면 발산하고 너무 작으면 느리거나 나쁜 해에 머뭅니다. AdamW 같은 옵티마이저는 기울기의 이동 통계를 이용해 업데이트를 안정화합니다.

2.3 배치·에폭·일반화

용어뜻실패 시 현상대응
배치한 번에 학습하는 샘플 묶음너무 작으면 불안정, 너무 크면 비용 증가gradient accumulation 포함 실험
에폭전체 데이터셋을 한 번 본 횟수과도하면 과적합검증 손실·조기 종료
과적합훈련 데이터를 외우고 새 입력에 약함훈련 점수만 높음분리된 테스트셋·정규화
데이터 누수정답 또는 미래 정보가 훈련에 섞임가짜 고성능시간·사용자·프로젝트 단위 분리
분포 이동운영 입력이 훈련 데이터와 달라짐배포 후 급격한 저하슬라이스 평가·드리프트 감시

3. Transformer가 문장을 배우는 방식

Transformer는 2017년 제안된 attention 중심 구조입니다. 문장을 토큰으로 나누고 각 토큰이 다른 토큰을 얼마나 참고해야 하는지 계산합니다. 병렬 학습에 유리해 현대 대규모 언어모델의 기반이 됐습니다.

토큰화문장 → 토큰 ID
→
임베딩ID → 벡터
→
Self-Attention문맥 관계 계산
→
MLP 층특징 변환
→
출력 확률다음 토큰 분포

3.1 Attention의 직관

“철수가 영희에게 책을 주었고, 그녀는 웃었다”에서 “그녀”가 누구인지 판단하려면 앞 토큰을 참고해야 합니다. Attention은 query·key·value 벡터를 이용해 어떤 토큰을 얼마나 참고할지 수치화합니다.

3.2 토큰 예측이 왜 지식과 능력을 만드는가

방대한 텍스트에서 다음 토큰을 맞히려면 문법뿐 아니라 개념, 관계, 문서 구조, 일부 추론 패턴을 압축해야 합니다. 그러나 목표는 “진실 판별”이 아니라 확률적 예측이므로 그럴듯한 허위 답변도 만들 수 있습니다.

4. 사전학습: 범용 능력의 형성

사전학습은 대규모 말뭉치에서 자기지도 방식으로 다음 토큰을 예측하게 합니다. 사람이 모든 문장에 정답 라벨을 붙이지 않아도 원문 자체가 다음 토큰 정답을 제공합니다.

단계입력얻는 것주요 위험
수집웹·책·코드·도메인 문서폭넓은 학습 원천저작권, 개인정보, 오염
정제중복 제거·품질 필터신호대잡음 향상편향된 필터, 희귀 지식 손실
토큰화텍스트모델 입력 단위한국어·코드 효율 차이
학습토큰 시퀀스기초 언어·지식·패턴막대한 연산, 불안정성
검증미사용 데이터일반화와 오염 여부벤치마크 과적합
Scaling law의 교훈: 모델 크기만 키우는 것이 답이 아닙니다. Chinchilla 연구는 주어진 연산 예산에서 모델 크기와 학습 토큰의 균형이 중요함을 보였습니다. AADS가 독자 모델을 만든다면 먼저 작은 도메인 모델의 데이터 품질·평가 체계를 확보해야 합니다.

5. 도메인 적응: SFT·LoRA·QLoRA

5.1 지도 미세조정(SFT)

입력과 모범답안 쌍으로 사전학습 모델을 추가 학습합니다. “AADS 장애 보고를 8개 섹션으로 작성” 같은 반복 가능하고 안정된 행동 형식을 가르치는 데 적합합니다. 최신 사실을 주입하는 용도로는 유지보수 비용이 크므로 RAG가 더 적합합니다.

{
  "instruction": "채팅 스트리밍 장애를 CEO 형식으로 보고하라",
  "input": "로그, 배포 SHA, 재현 조건, DB 상태",
  "output": "지시 파악 → 목표 → 계획 → 실행순서 → 결과 → 검증 → 리스크 → 다음 단계"
}

5.2 Full fine-tuning과 PEFT

방식변경 범위장점적합한 상황
전체 미세조정대부분/전체 가중치표현력 큼충분한 데이터·GPU·MLOps가 있을 때
LoRA저랭크 어댑터훈련 파라미터·메모리 절감여러 도메인 어댑터 운영
QLoRA양자화 기반모델 + LoRA제한된 GPU에서 큰 모델 튜닝비용 제한형 실험
프롬프트 튜닝소수의 연속 벡터매우 가벼움좁고 반복적인 태스크

5.3 미세조정이 오히려 나쁜 경우

  • 매일 바뀌는 가격·정책·운영 상태를 넣으려는 경우
  • 좋은 정답 데이터보다 오류 로그만 많은 경우
  • 기존 범용 능력 저하를 측정할 회귀 평가가 없는 경우
  • 민감 데이터의 권리·보존·삭제 정책이 정리되지 않은 경우

6. 정렬 학습: RLHF와 DPO

사전학습 모델은 “다음 토큰”을 잘 예측하지만 반드시 사용자의 의도에 맞게 답하지는 않습니다. 정렬(alignment)은 도움됨·정확성·안전·형식 준수 같은 선호를 모델 행동에 반영하는 단계입니다.

6.1 RLHF의 전형적 흐름

① SFT모범답안 학습
→
② 비교 데이터A와 B 중 선호 선택
→
③ 보상모델선호 점수 예측
→
④ RL 최적화보상 증가 + KL 제약

InstructGPT 연구는 사람의 시연과 응답 순위를 사용해 SFT 후 RLHF를 적용했습니다. 핵심 교훈은 큰 모델 자체보다 고품질 피드백과 목적 정렬이 실제 사용 만족도에 큰 영향을 줄 수 있다는 점입니다.

6.2 DPO

DPO는 선택된 응답과 거절된 응답의 쌍을 직접 비교해 정책을 학습합니다. 별도 보상모델과 복잡한 PPO 루프를 생략할 수 있어 구현이 단순하고 안정적인 장점이 있습니다. 그렇다고 데이터 편향·과최적화·안전 평가가 사라지는 것은 아닙니다.

7.1 좋은 RAG의 8단계

  1. 권한이 확인된 원문만 수집
  2. 문서 구조를 보존해 청킹
  3. 메타데이터·프로젝트·시점·보안등급 부착
  4. 임베딩과 키워드 하이브리드 검색
  5. 재순위화(reranking)
  6. 중복·모순 제거
  7. 답변에 근거와 시점 표시
  8. 검색 적중률·근거 충실도·답변 정확도 평가

8. 지속학습·모델 편집·지식증류

8.1 지속학습(Continual Learning)

운영 중 들어오는 새 데이터로 모델을 계속 갱신하는 기술입니다. 가장 큰 위험은 새 능력을 얻으면서 예전 능력을 잃는 파국적 망각입니다. 따라서 리플레이 데이터, 정규화, 어댑터 분리, 구·신 평가셋 동시 검증이 필요합니다.

8.2 모델 편집

특정 사실을 국소 수정하려는 기법입니다. 한 사실이 바뀌었어도 관련 없는 답변이 변하지 않는 locality, 표현을 바꾼 질문에도 적용되는 generalization을 함께 검증해야 합니다. 운영 최신 지식에는 아직 RAG가 더 통제하기 쉽습니다.

8.3 지식증류

큰 teacher 모델의 출력 분포나 설명을 작은 student 모델이 모방하도록 학습합니다. 비용·지연을 줄일 수 있지만 teacher의 오류와 편향도 복제됩니다. 따라서 “큰 모델 생성 → 자동 필터 → 사람 검수 → 작은 모델 학습”의 품질 게이트가 필요합니다.

8.4 추론시간 계산(Test-time compute)

답변 시 더 오래 생각하거나 여러 후보를 탐색·검증하는 방식입니다. 가중치가 바뀌지 않으므로 학습이 아니라 추론 전략입니다. 어려운 문제의 품질을 높일 수 있지만 지연·비용이 증가하며, 검증기 자체가 약하면 오래 생각해도 틀릴 수 있습니다.

8.5 연합학습·차등프라이버시

연합학습은 원본 데이터를 중앙에 모으지 않고 각 장치·조직에서 계산한 업데이트를 집계합니다. 데이터 이동을 줄이지만 업데이트 자체의 정보 노출, 악성 참여자, 장치별 데이터 편향과 통신비용이 남습니다. 차등프라이버시는 개별 샘플의 영향을 수학적으로 제한하도록 노이즈를 추가하지만, 개인정보 위험을 0으로 만들지는 않으며 정확도와 프라이버시 예산의 절충이 필요합니다.

중요: 연합학습은 “데이터가 절대 외부로 나가지 않는다”는 보증이 아닙니다. 업데이트 보안, 안전한 집계, 접근통제, 데이터 최소화, 공격·복원 테스트를 함께 적용해야 합니다.

10. 평가는 학습의 계기판이다

하나의 평균 점수로 모델을 승인하면 안 됩니다. 능력, 사실성, 안전, 지연, 비용, 회귀를 각각 측정하고 실제 업무 슬라이스별로 분리해야 합니다. HELM 계열의 핵심 교훈도 다차원·재현 가능한 평가입니다.

오프라인 평가

고정 골든셋, exact match, rubric, 코드 테스트, 도구 호출 성공률.

사람 평가

블라인드 A/B, 전문 검수, 오류 심각도, 평가자 일치도.

15. 자주 틀리는 주장 10개

1. “RAG를 붙였으니 모델이 회사 지식을 학습했다.”

아닙니다. 외부 지식을 검색해 현재 입력에 붙였을 뿐 가중치는 변하지 않았습니다.

2. “데이터가 많을수록 무조건 좋아진다.”

중복·오류·누수·낮은 대표성이 많으면 성능과 안전이 악화됩니다.

3. “훈련 손실이 낮으면 운영 품질이 높다.”

훈련 데이터 암기일 수 있습니다. 잠긴 테스트셋과 실제 업무 지표가 필요합니다.

4. “RLHF를 하면 사실성이 보장된다.”

사람이 선호하는 그럴듯함을 강화할 수도 있습니다. 사실 검증을 별도 측정해야 합니다.

5. “DPO는 RLHF의 모든 문제를 해결한다.”

훈련 루프는 단순해지지만 선호 데이터 편향과 회귀는 남습니다.

6. “모델이 크면 작은 모델보다 항상 낫다.”

업무·데이터·지연·비용 조건에 따라 다릅니다. 정렬된 작은 모델이 특정 업무에서 더 유용할 수 있습니다.

7. “한 번 파인튜닝하면 계속 최신이다.”

가중치 지식은 시점에 고정됩니다. 최신 사실은 RAG·도구가 적합합니다.

8. “AI가 스스로 오류를 반성하면 진짜로 학습한다.”

반성문을 저장·재주입하면 행동은 달라질 수 있지만 가중치 학습은 아닙니다.

9. “LLM 평가 점수 하나면 출시 가능하다.”

평가자 모델 편향이 있습니다. 사람·코드·업무 결과의 교차 검증이 필요합니다.

10. “학습된 모델에는 보안 규칙을 맡겨도 된다.”

고위험 권한은 모델 행동이 아니라 정책 엔진과 승인 게이트로 강제해야 합니다.

16. 보안·거버넌스

NIST AI RMF와 생성형 AI 프로필은 AI 수명주기 전반을 Govern · Map · Measure · Manage로 관리하도록 안내합니다. 교육·실험 단계에서도 데이터 계보와 위험 측정을 먼저 설계해야 합니다.

  • 학습 데이터 원본·정제본·평가셋의 소유자와 SHA 기록
  • 개인정보·시크릿·금융정보 탐지와 마스킹
  • 외부 모델 사업자 전송 범위와 보존·학습 정책 계약 확인
  • 모델카드에 목적, 금지용도, 알려진 실패, 평가 결과 기록
  • 고위험 도구는 최소권한·승인·멱등성·감사로그 적용
  • 삭제 요청이 있을 때 RAG 문서, 로그, 데이터셋, 어댑터까지 추적
  • 모델·프롬프트·RAG 인덱스·평가셋을 하나의 release manifest로 묶기

17. AADS 다음 단계 실행 로드맵

아래는 이 교육자료에 포함하도록 요청된 실행 가능한 다음 단계입니다. 수치 목표는 현재 베이스라인을 먼저 실측한 후 확정해야 하며, 임의 성능 향상률은 제시하지 않습니다.

Gate 0 · 용어와 현황 고정 (즉시, XS)

책임: CTO/PM · 산출물: AADS Learning Registry

  • 모델 훈련, RAG, 메모리, 프롬프트, 평가를 운영 화면에서 서로 다른 상태로 표시
  • 각 기능의 데이터 원천·보존기간·소유자·버전 기록
  • “학습 완료” 표현은 실제 training run과 checkpoint가 있을 때만 허용

완료 기준: 구성별 정의·owner·source·version·last_verified가 한 표에서 조회됨.

Gate 1 · 골든 평가셋 구축 (1~2주, M)

책임: PM/QA · 산출물: 프로젝트별 골든셋과 rubric

  • AADS, KIS, GO100, SF, NTV2, NAS의 핵심 업무·실패·안전 사례를 분리
  • 동일 문서·세션이 train/test에 겹치지 않도록 해시 기반 차단
  • 정확성, 근거성, 형식, 도구 사용, 안전, 비용·지연을 별도 채점

완료 기준: 현재 모델·프롬프트·RAG의 재현 가능한 baseline report 생성.

Gate 2 · 메모리/RAG 품질 개선 (2~4주, M)

책임: Knowledge/Ops · 산출물: 검색 평가와 기억 수명주기

  • 중복·모순·만료·프로젝트 오염 탐지
  • 하이브리드 검색과 reranking A/B
  • 주장별 근거 연결 및 잘못된 기억 비활성화/복구 경로

완료 기준: retrieval recall, citation precision, stale-memory rate를 실측하고 승인 기준 충족.

Gate 3 · LoRA/SFT 소규모 PoC (Gate 1~2 통과 후, M)

책임: ML/QA · 산출물: 어댑터·dataset card·model card

  • 최신 지식이 아닌 안정된 행동 1개만 선택
  • PII·시크릿 제거된 고품질 예제와 hard negative 사용
  • 베이스모델 대비 품질·회귀·지연·비용을 블라인드 비교

중단 기준: 핵심 회귀, 데이터 권리 불명, 안전 실패, baseline 대비 유의미한 개선 미확인.

Gate 4 · 선호 최적화 검토 (PoC 성공 후, L)

책임: ML/Safety · 산출물: DPO 실험과 독립 레드팀 보고서

  • 좋음/나쁨의 근거를 rubric으로 고정하고 평가자 일치도 측정
  • 과도한 형식 준수와 사실성 저하를 별도 검사
  • Shadow → Canary → 승격, 즉시 rollback 가능한 모델 레지스트리 적용

완료 기준: 잠긴 평가셋과 실제 업무에서 품질·안전·비용의 승인 게이트 통과.

19. 이해도 점검

Q1. AADS가 memory_facts를 10만 건 저장하면 모델이 재학습된 것인가?
정답: 아니다. 검색·주입용 외부 메모리가 늘어난 것이다.
Q2. 매일 바뀌는 주가를 LoRA로 학습하는 것이 좋은가?
정답: 아니다. 실시간 DB/도구를 사용해야 한다.
Q3. 완료 보고 형식 누락을 줄일 때 학습만 하면 되는가?
정답: 아니다. validator로 결정론적 검증하고, 필요하면 SFT를 보조로 쓴다.
Q4. DPO가 PPO형 RLHF보다 단순하면 검증도 줄여도 되는가?
정답: 아니다. 데이터 편향·회귀·안전 검증은 동일하게 필요하다.
Q5. 좋은 모델 하나를 고르면 모든 프로젝트에서 최고인가?
정답: 아니다. 업무별 품질·비용·지연·안전 평가로 라우팅해야 한다.
