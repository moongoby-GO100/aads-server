1. 결론

오비스를 "자비스보다 뛰어난 완벽한 AI 비서"에 가깝게 만들 핵심은 더 많은 외부 앱을 붙이는 것이 아니라, AADS 내부에 OHVIS Control Plane을 세우는 것이다. Control Plane은 CEO 지시를 단일 접점으로 받고, 프로젝트별 격리 컨텍스트를 유지하면서 필요한 순간에만 전 프로젝트 전략 요약을 호출하고, 러너·세션·알림·승인·비용·품질을 하나의 원장으로 통제한다.
질문판정설계 답완료 기준
모든 프로젝트를 동시에 컨트롤 가능한가? 조건부 가능 프로젝트별 worktree, runner slot, dependency graph, owner lease를 Control Plane에서 관리한다. 전 프로젝트 job board에서 queued/running/blocked/done을 5초 이내 조회하고, 같은 파일 충돌을 자동 차단한다.
프로젝트별 맥락이 유지되나? 부분 가능 일반 세션은 sealed context, CEO 통합 세션은 project briefs만 주입한다. 원문 메모리 전면 공유는 금지한다. GO100 세션에는 GO100 원문만, CEO 세션에는 전 프로젝트 요약 capsule만 노출된다.
실시간 보고는 어떻게 되나? 신규 필요 채팅 내부 Task Center, Web Push, SSE timeline, approval card로 보고한다. 텔레그램은 폴백만 남긴다. 오비스 앱을 열면 진행중/승인필요/완료/장애를 한 화면에서 본다.
응답 속도 문제는 해결되나? 체감 해결 가능 즉답과 심층작업을 분리한다. 1~3초 안에 접수·계획·진행 링크를 주고, 긴 작업은 백그라운드로 돌린다. p50 첫 응답 3초 이하, p95 첫 응답 8초 이하, 심층작업 상태는 10초마다 갱신한다.
AI 사용 제한을 효율화할 수 있나? 가능 모델 계층화, prompt cache, RAG capsule, 중복 job dedup, batch/off-peak, BYOK, quota ledger를 적용한다. 작업별 예상 비용, 실제 비용, 모델 폴백, cache hit가 task 원장에 기록된다.

정확한 목표달성 완료/미완료/리스크를 분리 보고 acceptance criteria, test evidence, deploy evidence, source provenance 검증 없이 완료라고 말하는 것
지속 진화 실패가 다음 응답·러너 정책에 반영 Reflexion memory, eval replay, prompt asset promotion, policy A/B 반성문은 저장하지만 실제 라우팅/검증에 연결하지 않는 것

6. 컨텍스트 격리와 공유: 섞이지 않게 전체를 아는 방식

CEO 통합 세션은 전 프로젝트를 알아야 한다. 하지만 일반 프로젝트 세션까지 전 프로젝트 원문을 공유하면 다음 작업 지시가 섞인다. 해결책은 "공유"가 아니라 "권한 있는 요약 접근"이다.
계층내용접근 주체주입 방식
Sealed Session Memory 해당 세션의 원문 대화, pending TODO, reply_to, 작업 흐름 해당 세션만 항상 우선. 다른 세션 원문은 기본 차단.
Project Capsule 프로젝트별 최신 변경, 운영 규칙, active incident, deploy contract 해당 프로젝트 세션 + CEO 요약 capsule만 주입. 필요 시 원문 근거를 도구로 조회.
Orchestrator Digest 전 프로젝트 상태, 우선순위, 병렬 작업, 승인 필요, 리스크 CEO 통합 세션 전 프로젝트 요약을 고르게 주입. 원문 혼입 방지.
Global Governance L1 운영 원칙, 보안, 완료 계약, 비용 정책 전 세션 항상 주입. 프로젝트별 지시보다 우선.

9. 제한된 AI 사용량을 효율적으로 쓰는 운영법

현재 비용 계측은 불완전하다. cost_tracking 9월 합계가 $0으로 나오고, task_cost_log도 9월 $0이며, 반면 chat_messages.cost는 단위 해석이 불명확한 큰 값이 누적되어 있다. 따라서 첫 개선은 비용 절감 자체가 아니라 usage ledger 신뢰성 복구다.

11. 구현 로드맵

P0 / 1~2일
Control Plane 원장 복구
  • pipeline review parser를 structured schema로 교체하고 review_hold 자동 재검수 루프를 추가한다.
  • ohvis_tasks와 pipeline_jobs를 하나의 Task Center view로 통합한다.
  • 보고 직전 DB/health/git 상태 재조회 계약을 validator로 강제한다.
  • 텔레그램 primary 경로를 중단하고, 오비스 앱 Web Push primary + 텔레그램 fallback 정책으로 바꾼다.
P1 / 3~7일
컨텍스트 격리·오케스트레이션
  • CEO 세션용 orchestrator_digest와 프로젝트별 project_capsule 생성기를 만든다.
  • auto_rag를 CEO 모드에서 capsule-first search로 확장하고, 일반 세션 raw cross-project search는 차단한다.
  • 새 프로젝트 등록 wizard를 만들고 repo/server/db/deploy/health 정보를 표준 registry에 저장한다.
  • parallel_group, depends_on_key, target_files 충돌 감지를 UI에서 보이게 한다.
P2 / 2~3주
즉답·심층작업 분리
  • Immediate Response Layer를 추가해 복잡 작업도 1~3초 안에 접수·계획을 응답한다.
  • Deep Work Layer는 artifact 생성, 코드 수정, 검증, 배포를 background task로 실행한다.
  • 질문별 turn_sequence, reply_to_id, synthesis_group로 결과 귀속 문제를 해결한다.
  • Task Center에서 오래된 질문 결과가 업데이트되면 현재 하단에는 알림 chip만 표시한다.
P3 / 1개월
자동진화·비용 최적화
  • 실패 사례를 eval replay 세트로 자동 승격하고, 프롬프트 변경 전후 품질을 비교한다.
  • 성공 절차를 skill library에 저장해 유사 작업에서 재사용한다.
  • usage ledger를 정규화해 모델/도구/러너 비용, latency, token, cache hit를 단일 집계한다.
  • P3 저위험 문서/조회 작업은 자동 승인, P2 이상 또는 배포/금융/개인정보는 승인 게이트를 유지한다.
P4 / 2개월+
자율 운영 고도화
  • 프로젝트별 목표/KPI를 오비스가 추적하고, 지연·비용·품질 저하를 사전 경고한다.
  • 일일/주간 CEO brief를 자동 생성하되, CEO가 오비스 앱 안에서 승인·재지시·보류까지 처리한다.
  • 외부 앱은 선택적 connector일 뿐, 오비스 내부 task/notification/report가 기본 운영 채널이 된다.
