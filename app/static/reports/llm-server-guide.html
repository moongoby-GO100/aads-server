• 405B 모델: FP16 기준 ~810GB → H100 80GB 10장+ 필요

2-3. VRAM 요구량 계산법

# 모델 VRAM 추정 공식
VRAM(GB) = 파라미터수(B) × 정밀도(바이트) × 1.2(오버헤드)

# 예시: Llama 3.1 70B, FP16(2바이트)
70 × 2 × 1.2 = 168GB → H100 80GB 3장 또는 A100 80GB 3장

# 양자화 적용 시 (INT4, 0.5바이트)
70 × 0.5 × 1.2 = 42GB → RTX 4090 24GB 2장 또는 A100 40GB 1장

# 양자화 정밀도별 메모리 사용량
FP32(4바이트) → FP16(2바이트) → INT8(1바이트) → INT4(0.5바이트) → GPTQ/GGUF(0.4~0.6바이트)

4-2. 서빙 아키텍처 패턴

단일 GPU

직접 서빙

1장의 GPU에 모델을 로드하고 API 엔드포인트를 노출. 가장 단순.
구성: vLLM/Ollama → :8000 → 클라이언트
적합: 7B~13B 모델, 소규모 팀

멀티 GPU

텐서 병렬 (Tensor Parallelism)

모델의 각 레이어를 여러 GPU에 분산. 1대 서버 내 GPU 간 통신.
구성: vLLM --tensor-parallel-size 4
적합: 70B+ 모델, NVLink 연결 필수

멀티 노드

파이프라인 병렬 (Pipeline Parallelism)

모델의 레이어를 여러 서버에 나누어 순차 처리. 노드 간 네트워크.
구성: Ray + vLLM 또는 Megatron-LM
적합: 405B+, 초대형 모델, InfiniBand 필수

로드밸런싱

다중 인스턴스 + 라우팅

동일 모델을 여러 GPU/서버에 복제하고 요청을 분산.
구성: Nginx/Traefik → vLLM ×N 인스턴스
적합: 고트래픽 서비스, 가용성 확보

9-2. 정렬 학습 (Alignment)

기법데이터 형태장점단점
SFT (Supervised Fine-Tuning)질문→모범답변 쌍단순, 효과 확실데이터 품질 의존
RLHF (PPO)선호도 + 보상모델인간 선호 반영 최고복잡, 불안정, 고비용
DPO (Direct Preference Optimization)선호/비선호 쌍보상모델 불필요, 안정적RLHF 대비 약간 제한적
ORPO선호/비선호 쌍SFT+DPO 동시 학습최신 기법, 검증 진행 중
KTO좋음/나쁨 이진 피드백쌍 데이터 불필요DPO 대비 데이터 효율 낮을 수 있음

9-3. 파인튜닝 실전 코드 (QLoRA 예시)

# pip install transformers peft trl bitsandbytes datasets accelerate

from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model
from trl import SFTTrainer, SFTConfig

# 4비트 양자화 로드
bnb_config = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4")
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.1-8B", quantization_config=bnb_config)
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-8B")

# LoRA 설정
lora_config = LoraConfig(r=16, lora_alpha=32, target_modules=["q_proj","v_proj"], lora_dropout=0.05)
model = get_peft_model(model, lora_config)

# 학습
trainer = SFTTrainer(model=model, train_dataset=dataset, args=SFTConfig(
  output_dir="./output", num_train_epochs=3, per_device_train_batch_size=4,
  learning_rate=2e-4, fp16=True, logging_steps=10
))
trainer.train()

12-4. MCP (Model Context Protocol)

💡 2025년 핵심 기술: MCP
Anthropic이 발표한 Model Context Protocol은 LLM이 외부 도구·데이터 소스와 표준화된 방식으로 연동하는 프로토콜입니다.

• 역할: LLM ↔ 도구(DB, 파일, API, 브라우저 등) 간 표준 인터페이스
• 장점: 한번 구현하면 모든 MCP 호환 LLM에서 사용 가능
• 생태계: Cursor, Claude Code, Zed 등 주요 IDE/에디터에서 지원
• AADS 활용: 현재 AADS가 MCP 기반으로 50+ 도구를 연동하여 운영 중

13-2. API vs 자체 서버 손익분기 분석

# 예시: 하루 10만 건 추론 (평균 1,000 토큰/건)

API 비용 (GPT-4o-mini):
  입력: 500 tok × 100,000 = 50M tok × $0.15/1M = $7.5/일
  출력: 500 tok × 100,000 = 50M tok × $0.60/1M = $30/일
  월 비용: $1,125/월 ≈ ₩155만

자체 서빙 (Llama 3.1 8B on RTX 4090):
  서버 구매: ₩700만 (36개월 감가)
  월 감가: ₩19.4만 + 전기 ₩8만 = ₩27.4만/월

→ 손익분기: 약 6개월 (이후 월 ₩127만 절감)
⚠️ 숨은 비용 체크리스트
• 전기료: GPU 서버 1대 (700W) 기준 월 ₩5~10만 (24시간 가동)
• 냉각/공조: 데이터센터 수준 필요 시 초기 ₩500만+ 추가
• 네트워크: InfiniBand (멀티노드 시) 스위치만 ₩3,000만+
• 인건비: ML Ops 엔지니어 인건비 (연봉 ₩6,000만~1.2억)
• 스토리지: 모델 파일 + 데이터셋 NVMe SSD 4~16TB (₩100~500만)
• 라이선스: NVIDIA AI Enterprise 등 상용 소프트웨어

Quick Start: 가장 빠른 첫 걸음

# 1. Ollama 설치 (Linux/macOS)
curl -fsSL https://ollama.com/install.sh | sh

# 2. 모델 다운로드 및 실행
ollama run llama3.1:8b

# 3. API 서버로 사용 (기본 포트 11434)
curl http://localhost:11434/api/generate -d '{
  "model": "llama3.1:8b",
  "prompt": "한국의 수도는?"
}'

# 4. vLLM으로 프로덕션 서빙 (GPU 서버)
pip install vllm
vllm serve meta-llama/Llama-3.1-8B-Instruct \
  --host 0.0.0.0 --port 8000 \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.9

# 5. Open WebUI (채팅 인터페이스)
docker run -d -p 3000:8080 \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  --name open-webui ghcr.io/open-webui/open-webui:main

📖 부록: 핵심 용어집

용어설명
LLMLarge Language Model. 대규모 언어 모델. 수십억~수조 파라미터의 신경망
VRAMVideo RAM. GPU 전용 메모리. LLM 로딩의 최대 병목
Transformer2017년 Google이 발표한 어텐션 기반 신경망 아키텍처. 모든 현대 LLM의 기반
파라미터 (Parameter)모델이 학습한 가중치 수. 7B = 70억 개. 클수록 일반적으로 성능 향상
양자화 (Quantization)모델 가중치를 낮은 정밀도로 변환 (FP16→INT4). 메모리/속도 최적화
MoE (Mixture of Experts)전체 파라미터 중 일부만 활성화하는 구조. 효율적 대형 모델 (예: Mixtral)
RAGRetrieval-Augmented Generation. 외부 문서 검색 + LLM 생성 결합
LoRALow-Rank Adaptation. 적은 파라미터만 학습하는 효율적 파인튜닝 기법
SFTSupervised Fine-Tuning. 지도학습 기반 파인튜닝 (질문→답변 학습)
RLHFReinforcement Learning from Human Feedback. 인간 선호도 기반 강화학습
DPODirect Preference Optimization. RLHF의 간소화 버전
GGUFGPT-Generated Unified Format. llama.cpp의 모델 파일 형식. CPU 추론 지원
토큰 (Token)LLM이 처리하는 텍스트의 최소 단위. 한국어 ~1글자, 영어 ~0.75단어
컨텍스트 길이모델이 한 번에 처리할 수 있는 최대 토큰 수 (예: 128K = ~10만 글자)
CUDANVIDIA GPU 프로그래밍 플랫폼. LLM 연산의 사실상 표준
NVLinkGPU 간 고속 직접 연결. 멀티GPU 텐서 병렬에 필수
InfiniBand서버 간 고속 네트워크. 멀티노드 학습에 사용 (200~400Gbps)
PagedAttentionvLLM의 핵심 기술. OS 페이지 관리 방식으로 KV 캐시 효율화
MCPModel Context Protocol. LLM과 외부 도구 간 표준 통신 규약
