3. 게이트 4단 규격

G1 — 정합 확인 (목표 10초)

항목규격
검사git status --porcelain 비어 있고, git rev-list --left-right --count origin/main...HEAD 가 0 0
실패 시배포 중단. 분기 상태에서 릴리스를 만들면 무엇이 올라갔는지 사후에 알 수 없다.
현재 값main...origin/main [ahead 3, behind 3] — 지금 이 게이트를 통과하지 못한다
우회GO100_GATE_ALLOW_DIVERGED=1 (사유 로그 필수). 기본 미허용.

G2 — 임포트 실재 검증 (목표 20초) 핵심

항목규격
시점릴리스 디렉터리 생성 직후, 핀 전환 전
검사 1릴리스 디렉터리에서 python -m compileall -q backend/app/services/go100
검사 2진입 모듈 import 드라이런 3종:
backend.app.services.go100.live_trading
backend.app.services.go100.live_trading.card310_scheduler
backend.app.services.go100.live_trading.card119_limitup_scheduler
실행 조건반드시 그 릴리스 디렉터리를 cwd 로 실행. 워킹트리에서 돌리면 누락을 못 잡는다(오늘 사고의 본질).
실패 시핀 전환 중단. 릴리스 디렉터리는 남겨 두고 누락 파일명을 로그에 남긴다.
오늘 사고이 검사 하나로 exit_lock.py 누락이 핀 전환 전에 잡힌다.

G3 — 계약 테스트 선별 실행 (목표 40초)

항목규격
대상실매매 경로만:
tests/unit/test_exit_price_sanity.py
tests/go100/test_scalping_monitor.py
tests/go100/test_card310_live_order_safety_p0.py
tests/go100/test_card310_entry_exit_safeguards.py
선존재 실패tests/go100/KNOWN_FAILURES.txt 에 고정. 이 목록에 있는 실패는 차단 사유가 아니다.
실패 시목록에 없는 신규 실패가 1건이라도 있으면 중단.
근거전량 실행은 608 passed / 5 failed 에 수 분이 걸린다. 실전 테스트 속도를 죽인다.

G4 — 기동 확인 (가변, 상한 180초) 핵심

항목규격
방식고정 타임아웃 금지. 재기동 후 journalctl -u <svc> -f 에서 기동 완료 신호가 나올 때까지 대기, 나오면 즉시 통과
신호API: Application startup complete / 스케줄러: 첫 루프 로그
2차 확인신호 확인 후 /health 200 (경로는 /health·/api/health. /api/v1/ops/health-check 는 GO100 에서 404 — AADS 경로다)
상한180초. 초과 시에만 롤백.
근거실측 기동 78초. 지금 윈도우는 그보다 짧아 정상 배포를 계속 되돌린다.

8. 금지 사항

  • 게이트가 손절·강제청산 경로를 막는 일이 없어야 한다. 게이트는 배포 시점에만 동작하고 런타임 판정에 개입하지 않는다.
  • 장중(08:50~15:30) go100-card310 재기동은 CEO 또는 StrategyCardLead 판정 없이 하지 않는다.
  • 게이트 실패를 --force 로 넘기는 옵션을 만들지 않는다. 우회는 G1 환경변수 1개뿐이며 사유 로그가 남는다.
