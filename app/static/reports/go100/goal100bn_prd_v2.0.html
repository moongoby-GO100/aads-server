4. 기능 요구사항

FR-W0. 저점·고점 가설의 정량 검증 P0 — 코드 변경 없음

항목내용
요구과거 데이터에서 확정 저점(trough) 진입 → 확정 고점(peak) 청산 규칙의 성과를 산출한다. 분봉·일봉 각각 독립 산출
데이터분봉 go100_kiwoom_minute_ohlcv(약 3,990만 행), 일봉 ohlcv_daily(약 311만 행, 2023-01-02~2026-09-15)
산출 지표진입 건수, 승률, 평균수익률, 평균보유기간, 비용 반영 후 EV, MDD, 피벗 strength 구간별 분해
비용수수료 0.015%×2 + 거래세 0.18% = 0.21% + 시총별 슬리피지(large 0.05~0.10 … micro 0.30~0.50, 편도) [live_engine.py:755-756, wave_event_handler.py:179-186]
대조군① 현행 ML 임계값 0.25 규칙 ② 무작위 진입 ③ 매수후보유
가드DB 읽기 전용, 운영 설정·주문 변경 0건
수용기준AC-W0.1 분봉·일봉 각각 결과표 · AC-W0.2 strength/confirmation_bars 구간별 EV 분해 · AC-W0.3 대조군 3종 비교 · AC-W0.4 비용 상수 출처를 코드 경로로 표기 · AC-W0.5 "가설 지지/불지지" 명시적 판정
이 요구사항이 전체 v2.0의 관문이다. 여기서 EV가 음수로 나오면 아래 FR-W1~W3의 파라미터를 바꿔 재측정하고, 그래도 음수면 배선하지 않는다.

FR-W1. 일봉 파동매매 축 신설 P0

항목내용
요구DailyWaveCounter를 실매매 경로에 배선한다. 진입: 확정 저점 + 일봉 추세 정렬. 청산: 확정 고점 / 파동 실패 / 손절
구현 지점신규 live_trading/daily_wave_entry_engine.py + 전략카드 1장(신규, 최초 SHADOW). 기존 분봉 경로(scalping_entry_engine.py) 수정 금지
실행 주기장 시작 전 1회(전일 확정 일봉 기준) + 장중 1회 재평가. 일봉 피벗은 종가 확정 후에만 확정 처리
리페인트 금지당일 미완성 봉으로 피벗을 확정하지 않는다. confirmation_bars 충족 전 신호는 후보로만 기록
수용기준AC-W1.1 SHADOW 로그에 진입·청산 후보가 근거(피벗 시각·가격·strength)와 함께 기록 · AC-W1.2 리페인트 0건(확정 피벗 변경 없음 검증) · AC-W1.3 LIVE 승격은 V0·V1·V2 통과 후 CEO 승인

FR-W2. 분봉 진입 기준을 파동 구조 우선으로 재정렬 P0

항목내용
요구1차 판정을 확정 저점 기반 파동 위치로, ML 확률은 보조 필터로 재배치
현행W2 반등 상한 게이트 통과 후 ML 확률 0.25(F1 최적, precision 29.63%)에서 최종 진입
변경안① 확정 저점 이후 경과봉·되돌림 비율·strength로 진입 구간 정의 ② ML은 하한 필터로만(loss_prob 상한) ③ 임계값은 EV 곡선 결과(M2) 채택값 사용
가드SHADOW 병행 비교 최소 10거래일 → 승인 → LIVE
수용기준AC-W2.1 동일 시점 신호를 현행/변경안 병렬 기록 · AC-W2.2 두 규칙의 EV 차이 실측 · AC-W2.3 운영 임계값 변경은 승인 후에만

FR-W3. 고점 기반 청산 P0

항목내용
요구청산 1차 기준을 확정 고점(peak) 형성 / 파동 실패로 둔다. 시간 기반·고정 % 청산은 보조
배경오늘(09-15) 실매매는 진입 후 수분 내 청산이 반복됐다 — 삼성전자(005930) 10:03 매수 → 10:05 매도 -1,771원, 삼화콘덴서(001820) 09:14 → 09:21 -1,997원 [go100_trades]. 고점 도달 전에 나가면 파동 수익을 구조적으로 못 먹는다
수용기준AC-W3.1 청산 사유가 exit_reason에 유형별로 남음 · AC-W3.2 사유별 평균손익 집계 가능 · AC-W3.3 손절은 항상 우선
