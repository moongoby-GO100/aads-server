STORE ASSISTANT · BANK QUICK INQUIRY · DESIGN v2.0

매장비서 은행 빠른조회·간편조회 기술 설계서

은행에 신청해 둔 빠른조회/간편조회 계좌를 국내 Windows PC Agent에서 조회하고, AADS 서버가 POST 요청·작업 큐·감사·거래 원장·통계를 담당하는 보존형 설계입니다.

기준 시각 2026-09-12 KST신한·IBK 우선기존 기능 보존비밀값 API 비노출

1. 결론

BankAPI와 같은 POST 기반 사용 경험은 가능하며, 우리 구조에서는 은행 접속 실행 위치만 국내 PC Agent로 분리합니다. 운영 서버는 계좌 비밀번호를 요청 본문이나 큐에 넣지 않고 Vault 연결 식별자만 사용합니다. 기존 동기 수집 API는 유지하고, 비동기 POST quick-inquiries와 GET job status를 추가했습니다.

6. LangGraph·LangSmith·Wiki·LLMOps 적용

거래 수집의 결정 경로에는 LLM을 넣지 않습니다. 기존 LangGraph 하네스는 상태 전이를 관리하고, OHVIS trace를 기본 감사 원장으로 사용합니다. LangSmith 환경변수가 설정된 경우 같은 run ID로 trace를 보조 전송합니다.

도구적용미적용/주의
LangGraphvalidate → preflight → collect → verify 상태머신은행 응답 해석을 LLM에게 맡기지 않음
LangChain/LangSmith오류 분류·trace·회귀 평가 메타secret·거래 전문 trace 금지
Wiki/HTML본 문서·PRD·운영 runbook 정본 링크구현 전 계획과 구현 완료를 혼합하지 않음
LLMOps단계별 성공률, action_required 비율, 수집 지연 관측미측정 성능 수치 보고 금지

8. 상태·복구·롤백

상태사용자 표시복구
queued/running수집 대기/진행, 최근 갱신 시각GET polling, 중복 POST 금지
action_required로그인·보안프로그램·추가 인증 필요같은 work key에서 조치 후 재시도
succeeded수집/신규/중복 건수, 마지막 성공거래 원장·요약 재조회
failed비밀값 없는 오류코드와 안내일시 오류만 backoff, 인증 오류 자동 반복 금지

코드 롤백: 신규 두 route와 service wrapper를 제거하면 기존 동기 /collect가 그대로 남습니다. 데이터 롤백: 신규 스키마가 없고 기존 큐/원장을 사용하므로 DB 역마이그레이션이 없습니다.
