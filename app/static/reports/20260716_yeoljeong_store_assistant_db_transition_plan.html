3. 전환 순서

  1. P0 스키마 추가: 기존 migrations/113_yeoljeong_finance_settings.sql와 충돌하지 않는 신규 migration으로 HR/계약/급여 테이블을 추가합니다.
  2. 읽기 경로 이중화: DB 테이블이 있으면 DB를 읽고, 없으면 기존 JSON을 읽습니다.
  3. 쓰기 경로 전환: 신규/수정은 DB에 쓰고, 초기 1주 동안 JSON 백업 스냅샷을 함께 남깁니다.
  4. 마이그레이션 검증: JSON row count와 DB row count, 직원 이메일 마스킹, 계약서 상태, 급여 금액 합계를 비교합니다.
  5. 폴백 유지: 운영 장애 시 DB 읽기 실패를 JSON read-only 폴백으로 전환하되, 삭제/수정은 중단합니다.
  6. JSON 쓰기 종료: 검증 완료 후 JSON은 백업 입력으로만 유지하고 API 기본 저장소는 PostgreSQL로 고정합니다.

4. 완료 기준

  • 직원가입 → 서류등록 → 승인 → 계약서 저장/서명요청 → 급여내역서 저장 E2E가 DB row로 남습니다.
  • 관리자 총괄 화면의 직원/입사서류/계약서/급여 탭이 DB 조회 기준으로 동일하게 렌더링됩니다.
  • 계정 비밀번호는 평문 컬럼에 저장하지 않고 암호화 ref 또는 Vault 참조만 남깁니다.
  • 감사로그에서 누가, 언제, 어떤 직원/계약/급여 데이터를 변경했는지 추적됩니다.
