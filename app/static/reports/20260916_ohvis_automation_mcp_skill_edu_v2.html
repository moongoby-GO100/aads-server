03MCP 도구 상세 — 원리부터 운영까지

3-1. MCP 가 무엇인가

MCP(Model Context Protocol) 는 Anthropic 이 공개한 개방 표준으로, AI 모델과 외부 시스템을 연결하는 규격입니다. 흔히 "AI 계의 USB-C" 로 설명합니다. AI 가 서버·DB·브라우저·파일에 접근하려면 그때마다 전용 연동 코드를 짜야 했는데, MCP 는 그 연결 방식을 하나로 통일합니다.

왜 필요한가 — M×N 문제

구분MCP 이전MCP 이후
연동 비용모델 M개 × 시스템 N개 = M×N 개 어댑터M+N 개 (각자 MCP 규격만 지키면 됨)
도구 추가모델별로 재작성서버에 도구 하나 추가 → 모든 MCP 클라이언트가 즉시 사용
권한 통제연동마다 제각각서버 한 곳에서 화이트리스트·승인·감사 일괄 적용
오비스 적용채팅·Pipeline Runner·서브에이전트가 같은 135개 도구를 공유합니다. 도구 하나를 고치면 세 경로 모두에 반영됩니다.

MCP 의 3대 구성요소

요소의미누가 주도오비스 사례
Tools (도구)모델이 실행하는 동작모델이 판단해 호출run_remote_command, query_database
Resources (자원)모델이 읽는 데이터클라이언트/앱이 붙임HANDOVER 문서, context_docs 캐시
Prompts (프롬프트)재사용 가능한 지시 템플릿사용자가 선택L1~L5 프롬프트 에셋, 지시서 포맷 v2.0

04스킬(Skill)이란 무엇인가

4-1. 한 문장 정의

도구는 "무엇을 할 수 있는가" 이고, 스킬은 "이 조직에서는 그 일을 이렇게 한다" 입니다.
도구는 능력, 스킬은 절차 지식입니다.

스킬은 AI 가 특정 업무를 만났을 때 자동으로 펼쳐 읽는 접힌 설명서입니다. Anthropic 의 Agent Skills 규격이며, 폴더 하나 + SKILL.md 파일 하나로 성립합니다.

4-2. 왜 프롬프트에 다 넣지 않고 스킬로 빼는가 — Progressive Disclosure

단계언제 로드컨텍스트 비용내용
1단계 메타데이터세션 시작 시 항상수십 토큰name + description 만
2단계 본문관련 작업을 만났을 때수백~수천 토큰SKILL.md 전문
3단계 참조파일본문이 지시할 때필요한 만큼references/, 스크립트, 템플릿

이 구조 덕분에 스킬을 100개 등록해도 평소 컨텍스트 비용은 거의 0 입니다. 필요한 순간에만 펼쳐집니다. 모든 절차를 시스템 프롬프트에 때려 넣는 방식과의 결정적 차이입니다.

06목표(Goal) 오케스트레이션 — 오비스 자동화의 최상층

앞의 다섯 장은 "어떻게 시키는가" 를 다뤘습니다. 크론은 언제, MCP는 무슨 손으로, 스킬은 어떤 절차로, 서브에이전트는 누가 나눠서 를 정합니다. 이 장은 그 위에 있는 층 — "무엇을 이루려고 하는가" 를 기계가 기억하고 스스로 밀고 가게 만드는 구조입니다. 오비스에서 이것을 목표(Goal) 오케스트레이션, 코드상으로는 Goal Control Loop 라고 부릅니다.

한 줄 정의. 대표님이 "이걸 이루자" 한 번 말하면, 시스템이 그것을 마일스톤으로 쪼개고 → 담당에게 말을 걸고 → 근거를 모아 완료를 판정하고 → 다음 단계를 스스로 개시하고 → 결과를 대표님께 보고하는 폐루프. 지시 한 건이 끝나면 사라지는 자동화가 아니라, 목표가 끝날 때까지 살아 있는 자동화입니다.
