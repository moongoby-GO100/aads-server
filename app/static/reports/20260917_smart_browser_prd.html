4. 행위 등급과 승인 정책

등급예시정책
READ조회, 스냅샷, 다운로드(사내 경로)자동 실행
WRITE_INTERNAL사내 시스템 등록·수정자동 실행 + 감사 기록
WRITE_EXTERNAL외부 사이트 폼 제출, 메시지 발송CEO 승인 카드 필수

5. 데이터 모델

work_recipes
  id, name, domain, version, yaml_body, created_by, created_at, updated_at
  UNIQUE(name, version)

recipe_runs
  id, recipe_id, recipe_version, status(running|success|failed|blocked)
  llm_calls INT DEFAULT 0, duration_ms, started_at, finished_at, session_id

recipe_run_steps            -- append-only (트리거로 UPDATE/DELETE 차단)
  id, run_id, seq, action, url, selector_hash, risk_level,
  approval_id NULL, screenshot_path, result, error, observed_at

recipe_approvals
  id, run_id, step_seq, risk_level, requested_at, decided_at,
  decision(approve|reject), decided_by, reason

설계 근거 감사 테이블 append-only 패턴은 ACCT(진아서버) 설계에서 이미 채택해 운영 중인 방식과 동일하게 맞춘다.

6. 레시피 예시

name: ntv2_order_intake
domain: pick.newtalk.kr
version: 3
inputs: [vendor, order_date]
steps:
  - action: navigate
    url: https://pick.newtalk.kr/root/product_order
    risk: READ
  - action: fill
    selector: "#search-date"
    value: "{{order_date}}"
    risk: READ
  - action: click
    selector: "button[data-role=search]"
    wait_for: "table.result tbody tr"
    risk: READ
  - action: download
    selector: "a.excel"
    save_as: "/tmp/{{vendor}}_{{order_date}}.xlsx"
    risk: READ
  - action: api_call            # 사내 시스템은 UI 대신 API
    endpoint: POST /api/v1/orders/import
    risk: WRITE_INTERNAL
verify:
  - expect_text: "등록 완료"
  - expect_row_count: "> 0"
