ACCT-PRD-002 · decision document

공용 회계·매장·경리·인사 비서

Hermes Agent의 메시징 게이트웨이와 스킬·메모리 기반을 채널 진입점으로 사용하고, LangGraph/LangChain/LangSmith로 정확성·승인·관측성을 통제하는 제품 설계, PRD, API 미지원 사이트 수집 전략, 재사용 가능한 동작형 목업입니다.

최종 보강 2026-09-09 21:59 KST상태: 설계·PRD·목업 완료 / 제품 구현 전대상: 소상공인·다점포·경리·인사 담당자
요약현황경쟁분석설계매출수집학습·리스크PRD업무흐름보안·운영Tool Connect동작형 목업로드맵출처

1. 경영진 요약

판정: 구현 가능합니다. 권장 제품 방향은 “회계 ERP를 하나 더 만드는 것”이 아니라, 매출·증빙·근태를 먼저 모으고 증거와 검증을 붙인 뒤 기존 ERP·세무대리 흐름까지 연결하는 실행형 업무 비서입니다.
사용자 경험오늘 할 일 1화면

첫 화면에서 누락 매출, 승인 대기, 신고·급여 마감을 즉시 확인합니다.

정확성 원칙증거 우선

LLM은 제안하고, 원장 반영은 규칙 검증·대사·승인 후 수행합니다.

연결 전략API + RPA

공식 API를 우선하고 미지원 사이트는 파일·메일·브라우저 자동화로 보완합니다.

제품 한 문장

“사장님은 오늘 처리할 예외만 확인하고, 매출 집계·증빙 연결·분개 초안·급여 준비·신고 준비는 비서가 근거와 함께 선행 처리하는 서비스.”

의도적으로 하지 않는 것

  • 학습모델이 검증 없이 전표·급여·신고를 확정하지 않습니다.
  • 사이트 약관·보안통제를 우회하거나 CAPTCHA를 무력화하지 않습니다.
  • 초기부터 모든 ERP 기능을 재구현하지 않습니다. 검증된 진아실장 자산과 외부 ERP를 연결합니다.

3. 경쟁업체 정밀 비교와 승리 전략

공개된 공식 제품 페이지를 기준으로 비교했습니다. 실제 계약별 기능, 비공개 API, 최근 가격은 도입 전 별도 확인이 필요합니다.

서비스공식적으로 확인된 강점사용자 관점의 빈틈/기회우리의 응답
캐시노트매출·비용·실적캘린더·목표 달성률을 사장님 관점에서 간단히 제공깊은 회계·인사 실행보다 경영현황 경험이 중심쉬운 첫 화면은 채택하고, 증빙→분개→급여·신고 준비까지 연결
경리나라경리 업무와 고객지원/교육에 특화공개 페이지 기준 AI 실행·API 미지원 매출처 자동수집의 차별성 확인 제한자연어 지시, 자동수집 근거, 승인 가능한 실행 이력으로 차별화
WEHAGO / ONE AI회계·급여·인사·물류·세무신고와 업무 점검·신고서 초안 등 폭넓은 통합강력하지만 소상공인에게 메뉴와 도입 범위가 크게 느껴질 수 있음역할별 “오늘 할 일”과 대화형 실행, 기존 WEHAGO 자동화 자산으로 학습비용 축소
이카운트영업·구매·재고·회계·급여·그룹웨어, 실시간 보고서, POS 연동, 월 정액 정책사용자가 업무 구조와 메뉴를 학습해야 하는 ERP형 경험ERP 대체가 아니라 예외만 보여주는 비서 UX, 이카운트와도 연결 가능한 중립 계층
flex입퇴사·근태·계약과 급여 자동 계산, 구성원 셀프서비스 경험매장 매출·증빙·회계 수집은 핵심 범위가 아님매출→인건비→손익까지 한 흐름으로 대사
시프티일정·출퇴근·휴가·전자결재·급여정산·ERP/Open API 연동회계 원장과 API 미지원 매출 수집은 별도 시스템 필요근태 데이터와 매장 매출을 같은 점포/일자 축으로 결합
샤플다점포 직원의 출퇴근·스케줄·현장업무·계약 관리재무·세무·증빙 자동화는 핵심 범위 밖현장 실행 강점을 참고하되 경리·회계 결과까지 폐루프 구성

경쟁우위 5개

1. 예외 중심전체 메뉴가 아니라 오늘 사람이 봐야 할 3~7건을 우선 제시합니다.
2. 증거 팩숫자마다 원본 파일, 화면 캡처, 수집 시각, 변환 이력, 대사 결과를 엮습니다.
3. 연결 중립성특정 ERP 종속 대신 API·파일·MCP·브라우저 어댑터를 동일 계약으로 다룹니다.
4. 회계+인사 폐루프매출, 인건비, 비용, 정산을 점포 손익으로 연결합니다.
5. 안전한 학습자동학습은 추천 개선까지만 허용하고 회계 반영 정책은 버전·승인·롤백합니다.
6. 기존 자산진아실장의 WEHAGO·카드·근태 자동화 흐름을 처음부터 다시 만들지 않습니다.

4. 기술 설계 — Hermes 기반 적용 방식

용어 정정: “Hermes Gateway”를 제품 제목으로 사용하지 않습니다. Hermes Agent의 messaging gateway는 Telegram·Slack·WhatsApp·Webhook 등 접점과 세션을 담당합니다. 별도의 Nous Tool Gateway는 웹검색·이미지·TTS·클라우드 브라우저를 Nous 구독으로 프록시하는 선택 기능입니다. 회계 원장·승인·정확성의 핵심 엔진은 아닙니다.
L1 채널/대화 — Hermes Agent
메신저·웹·이메일 진입, 사용자별 세션, 스킬·메모리, MCP 도구 탐색. 채널 장애가 회계 작업 상태를 잃지 않도록 업무 상태는 별도 저장합니다.
L2 업무 오케스트레이션 — LangGraph
접수→권한확인→수집→정규화→대사→분류/계산→정책검증→승인→반영→보고를 상태 그래프로 실행합니다. PostgreSQL checkpointer로 중단·승인·재개를 보장합니다.
L3 도구 통합 — LangChain + MCP
기존 진아실장 Python 도구, ERP/POS/카드 API, Playwright worker, OCR, 메일/드라이브를 typed tool 계약으로 노출합니다.
L4 LLMOps — LangSmith
모델·프롬프트·도구 호출 trace, 비용·지연, 오프라인 회귀평가, 온라인 이상 탐지, 실패 trace→평가셋 승격을 담당합니다.
L5 신뢰 원장 — PostgreSQL + Object Storage
멀티테넌트 RLS, 불변 이벤트, 원본 증거 hash, 중복방지 키, 승인 기록, 전표 버전을 보존합니다.

5. API 미지원 사이트의 매출 자동집계

수집 성공만으로 완료하지 않고 원본 증거→정규화→중복 제거→입금/정산 대사→예외 승인까지 닫아야 정확한 매출이 됩니다.

우선순위방식적용 예통제
1공식 API/WebhookPOS, 배달, 카드, 은행, ERPOAuth scope 최소화, cursor 재개, rate limit
2정식 파일/메일/SFTP정산 CSV/XLSX/PDF, 일일 이메일파일 hash, 포맷 버전, schema validation
3브라우저 다운로드 자동화로그인 후 기간 선택·파일 다운로드전용 계정, 2FA handoff, Playwright trace·스크린샷
4DOM/표 추출다운로드 없는 매출 화면헤더 기반 semantic selector, 행 합계 검증, layout drift 탐지

사이트별 Connector 계약

connector.yaml
site_id: delivery_partner_x

  legal_basis: customer_authorized_account

  - gross = net + commission + vat + adjustments
  - unique(order_id, settled_at, amount)

정확도 보호 장치

  1. Idempotency: 사이트+사업장+외부거래ID+금액+일자의 안정 키로 재수집 중복을 방지합니다.
  2. 3-way reconciliation: 주문/매출, 플랫폼 정산, 은행 입금을 비교합니다.
  3. Drift sentinel: DOM header·열 수·합계·샘플 분포가 기준을 벗어나면 자동 반영을 중단합니다.
  4. Evidence bundle: 다운로드 원본, screenshot, parsing map, checksum, 수집 trace를 1건으로 묶습니다.
  5. 복구 UX: “연결 끊김”만 표시하지 않고 재로그인·파일 업로드·다시 수집 버튼을 같은 화면에 둡니다.

6. 학습모델 반영과 리스크 헤지

핵심 원칙: 경험은 학습하되 돈의 기록을 스스로 바꾸게 하지 않습니다. 모델 학습 결과는 추천 정책 후보이며, 검증 데이터셋·shadow·승인·canary·rollback을 통과해야 운영 정책이 됩니다.
위험차단 설계운영 신호복구
환각 분개/잘못된 계정과목차변=대변, 세율·기간·계정 허용목록을 deterministic engine에서 검증규칙 실패율, 승인 수정률전표 제안 폐기, 기존 정책으로 재실행
잘못된 경험의 자기강화자동 skill 수정 금지, 후보 diff 생성 후 회귀평가·승인정책 버전별 정확도이전 signed version 즉시 rollback
테넌트 간 데이터 누출RLS, tenant-scoped encryption, trace redaction, cross-tenant retrieval 금지RLS deny·DLP event세션 폐기·토큰 회수·감사

  • 정합성: 모든 금액은 원 단위 Decimal/정수로 저장하고 부동소수점을 금지합니다.

7A. 사용자 경험과 업무 프로세스 상세

UX 원칙: 첫 화면은 설정 페이지가 아니라 오늘의 매출·현금·마감·급여 위험을 보여줍니다. 사용자는 전체 장부를 뒤지지 않고, 비서가 찾아낸 예외의 금액·근거·영향·다음 행동만 확인합니다.

첫 실행 여정

단계사용자 화면시스템 처리실패 복구완료 기준

5. 오늘 화면정상은 접고 예외만 우선 표시예약 수집·마감·근태 점검 시작연결별 재로그인·업로드·재시도담당자가 3분 안에 우선순위 파악

배포 토폴로지

Edge — WAF/rate limit → API Gateway → Web/BFF. Hermes channel adapter는 업무 API만 호출하며 DB에 직접 접근하지 않습니다.
Control plane — Tenant/identity, connector registry, policy release, approval, audit, LLM router. 고위험 정책 변경은 서명된 release로만 승격합니다.
Execution plane — LangGraph worker, API connector worker, browser worker, document worker, ERP worker를 큐와 별도 서비스 계정으로 분리합니다.
Data plane — PostgreSQL 원장/checkpoint/outbox, object storage 원본증거, Redis 선택 캐시. 원장과 증거는 모델 메모리와 분리합니다.
Observability — OpenTelemetry metrics/logs + LangSmith redacted traces/evals. 재무 원문과 비밀은 trace에 넣지 않습니다.

업무 상태기계와 재처리 규칙

RECEIVED → AUTHORIZED → COLLECTING → NORMALIZED → RECONCILED
    ↘ AUTH_REQUIRED       ↘ SCHEMA_DRIFT      ↘ EXCEPTION_REVIEW
PROPOSED → POLICY_CHECKED → APPROVAL_PENDING → APPROVED → EXECUTING
    ↘ REJECTED/BLOCKED                               ↘ VERIFY_FAILED
VERIFIED → COMPLETED

불변식:
1) COMPLETED는 결과 참조 + evidence_id + deterministic_checks가 모두 있어야 한다.
2) 외부반영 재시도는 동일 idempotency_key를 사용한다.
3) 실패 작업은 상태·원인·재시도 가능 여부를 보존하고 삭제하지 않는다.
4) 승인 이후 입력/evidence/policy가 바뀌면 승인을 자동 무효화한다.
