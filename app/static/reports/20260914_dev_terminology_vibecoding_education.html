① 왜 용어인가 — 용어가 지시 품질을 결정한다

바이브코딩에서 CEO는 코드를 쓰지 않습니다. 대신 말로 지시합니다. 그래서 바이브코딩에서 CEO의 생산 도구는 키보드가 아니라 어휘입니다. 같은 요구라도 어떤 단어로 말하느냐에 따라 AI가 만드는 결과물이 완전히 달라집니다.

핵심 원리 — 용어는 “검수 기준”이다

용어를 쓰면 지시가 정확해질 뿐 아니라, AI가 일을 제대로 했는지 판정할 기준이 생깁니다. “빠르게 해줘”는 검수할 수 없지만 “p95 1초 미만”은 숫자로 검수됩니다. 이 문서의 모든 용어는 사실상 검수 항목 목록이라고 생각하시면 됩니다.

용어를 몰라서 생기는 3가지 손실

1. 재작업 비용

모호한 지시 → 엉뚱한 결과 → 다시 지시. AI 호출 비용과 시간이 2~3배로 늡니다. 용어 하나가 왕복 한 번을 줄입니다.

2. 검수 불능

결과물이 좋은지 나쁜지 판단할 언어가 없으면, AI가 “완료했습니다”라고 하면 믿는 수밖에 없습니다. 이것이 가장 위험합니다.

3. 사고 유발

“다시 켜줘”, “지워줘”, “올려줘” 같은 말은 파괴적 명령으로 해석될 수 있습니다. AADS가 docker compose up -d 전체 실행을 규칙으로 금지한 이유가 이것입니다.

이 문서 사용법 3장~17장은 영역별 사전입니다. 처음부터 외우려 하지 마시고, 18장(헷갈리는 짝)과 19장(지시문 템플릿)을 먼저 읽으신 뒤 필요할 때 해당 장을 찾아보시는 것을 권합니다. 20장은 이 용어들이 AADS 실물 어디에 붙어 있는지 지도입니다.

③ 코드 구조 용어 — 변수부터 프레임워크까지

코드는 작은 단위가 모여 큰 단위를 이룹니다. 아래는 작은 것 → 큰 것 순서입니다. 이 순서를 알면 AI가 “모듈을 분리했다”고 할 때 그게 얼마나 큰 변경인지 감이 잡힙니다.

코드 단위의 크기 순서

상수constant절대 변하지 않는 값. 보통 대문자로 씀.고정 간판“이 숫자를 상수로 빼서 한 곳에서 관리해”
