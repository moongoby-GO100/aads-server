NTV2 상품등록 UI 기획 v1.8

관리자 화면은 V1을 그대로 미러링해 운영 기준선을 고정하고, 도매 화면과 소매 화면을 먼저 V2 UX로 개선한 뒤 관리자 네이티브 전환을 최종 확정하는 전환 전략 보고서입니다.

버전 히스토리

v1.2 v1.3 v1.5 v1.6 v1.7 v1.8 현재

v1.0/v1.1은 작업 보존본으로 남아 있으며, 현재 보고 링크는 루트 산출물에서 확인 가능한 버전만 연결합니다.

결론

CEO님 제안대로 가는 것이 맞습니다. 지금은 관리자까지 V2로 재설계하면 갭이 너무 커지므로, 관리자는 V1 미러링으로 안정화하고 도매·소매 화면을 먼저 V2로 개선해야 합니다.

1. 관리자 = V1 운영 미러 상품코드, 상품정보, 이미지, 상세HTML, 소매 엑셀, 외부몰 제공 상태를 V1과 동일하게 노출하고 수정 동선도 V1 기준으로 유지합니다.
2. 도매 = V2 개선 우선 도매가 직접 등록하지 않는 현실을 반영해 대행등록, 촬영요청, 이미지 업로드, 상품완성 상태를 새 UX로 제공합니다.
3. 소매 = V2 매출 UX 우선 이미지 다운로드, 편집숍 등록, 외부몰 HTML, 엑셀 제공, 판매채널 상태를 소매 작업 중심으로 재구성합니다.
관리자 네이티브 전환은 마지막 단계입니다. 도매·소매 사용 흐름이 안정된 뒤 관리자 화면을 확정해야 V1 누락과 중복 개발을 줄일 수 있습니다.

v1.8 전략 보드

V1과 V2의 역할을 분리합니다. 관리자는 운영 기준선을 보존하고, 도매·소매는 새 UX를 검증하는 구조입니다.

관리자: V1 미러링
원장 유지 목표

V1 상품운영센터를 V2에서 그대로 볼 수 있게 해서 운영자가 혼란 없이 기존 방식으로 관리합니다.

포함

상품목록, 샘플등록, 상품수정, 원본이미지, 정렬저장, 상세HTML, 엑셀, 외부몰 제공 상태

금지

초기 단계에서 관리자 필드를 V2식으로 임의 축약하거나 V2 DB에 별도 원장을 만들지 않습니다.

도매: V2 UX 우선 개선
신규 UX 목표

도매가 직접 등록하지 않는 초기 현실을 반영해, 뉴톡 대행·촬영서비스와 연결되는 쉬운 상품완성 흐름을 제공합니다.

포함

간편등록, 촬영요청 연결, 이미지 제출, 상품완성률, 관리자 검수 요청, 노출 준비 상태

판정

도매 로그인, 도매 상품 생성, 촬영 요청 연결 여부로 자동 컨텍스트를 표시합니다.

소매: V2 매출 UX 우선 개선
매출 연결 목표

소매가 실제로 돈을 버는 이미지 다운로드, 편집숍, 외부몰 등록, 엑셀 제공을 빠르게 사용할 수 있게 합니다.

포함

상품소싱, 이미지 다운로드 권한, HTML 복사, 엑셀 다운로드, 편집숍 자동등록, 마크업가 관리

판정

소매 로그인, 구독 플랜, 거래처 승인, 이미지 다운로드 한도, 편집숍 상태로 자동 제어합니다.

우선순위 로드맵

구현 순서는 관리자 재설계가 아니라 데이터 기준선 확정과 도매·소매 UX 검증부터 시작합니다.

Phase 0 V1 관리자 미러 고정 V1 상품목록·상품수정·이미지·상세HTML 상태를 V2에서 동일하게 조회합니다. 이 단계는 읽기 전용 중심입니다.
Phase 1 도매 V2 상품완성 UX 도매 간편등록, 촬영요청, 원본 이미지 제출, 관리자 검수 요청을 연결합니다.
Phase 2 소매 V2 판매활용 UX 이미지 다운로드, 편집숍 등록, 외부몰 HTML/엑셀 제공을 소매 작업 화면으로 묶습니다.
Phase 3 관리자 네이티브 확정 도매·소매 흐름이 검증된 뒤 V1 미러 기능을 V2 관리자 콘솔로 흡수합니다.

구현 전환 순서

Phase 0
관리자 V1 미러 API + 상품목록 갭 화면
V1 상품 수와 상태를 V2 관리자 목록에서 그대로 볼 수 있게 하고, 이미지/HTML/가격/채널 누락을 필터링합니다. 수정 UX는 V1 동선을 유지합니다.
관리자 미러
Phase 1
도매 V2 상품완성 화면
도매 초안등록, 촬영요청, 이미지 제출, 관리자 검수 요청, 노출 준비 상태를 한 화면 흐름으로 제공합니다.
도매 V2 UX
Phase 2
소매 V2 판매활용 화면
이미지 다운로드, 편집숍 등록, 외부몰 HTML 복사, 소매 엑셀 다운로드, 마크업가 관리를 묶습니다.
소매 V2 UX
Phase 2.5
공통 이미지/HTML 제공 레이어
V1 상세이미지 흐름을 도매 제출과 소매 제공에 연결하되, 관리자 생성/수정 권한은 V1 미러 기준으로 유지합니다.
공통 자산 레이어
Phase 3
관리자 네이티브 최종 확정
도매·소매 흐름에서 검증된 필드와 권한만 V2 관리자 콘솔로 흡수하고, V1 의존 제거 범위를 확정합니다.
관리자 확정

개발 착수 기준

API 기준 V1 상품 스냅샷, 이미지 스냅샷, 상세HTML 스냅샷, V2 저장상태, 갭 계산 API가 필요합니다.
DB 기준 V1 원본을 복사해 덮는 구조가 아니라, V1 원본 참조와 V2 검증 저장을 분리하는 스냅샷/매핑 테이블이 필요합니다.
UI 기준 먼저 관리자 V1 미러 목록/상세, 도매 상품완성, 소매 판매활용 3개 화면 축을 구현해야 전환 가능성 판단이 가능합니다. 관리자 네이티브 편집은 마지막 단계입니다.
최종 판단: 상품등록 UI 구현은 기존 V2 상세페이지를 조금씩 고치는 방식이 아니라, `관리자 V1 미러`, `도매 V2 상품완성`, `소매 V2 판매활용` 3축으로 나눠야 합니다. 관리자 네이티브 전환은 도매·소매 흐름 검증 이후 최종 단계로 확정합니다.
