NTV2 상품등록 UI 기획 v1.7

V1과 V2의 갭이 큰 상태에서 바로 구현 판단이 가능하도록, 상품등록 전환 전략과 주요 화면을 이미지형 UI 보드로 재구성한 보고서입니다. 사용자는 목적을 선택하지 않고, 시스템이 역할·진입경로·V1코드·촬영요청·판매채널 상태로 자동 분류합니다.

버전 히스토리

v1.0 v1.1 v1.1 날짜판 v1.2 v1.3 v1.4 v1.5 v1.6 v1.7 현재

결론

V2 상품등록은 새 입력폼이 아니라, V1 상품운영센터를 감싸는 전환형 관리자 콘솔로 시작해야 합니다.

1. V1 미러 우선 V1 상품코드, 상품정보, 이미지, 상세HTML, 소매 제공 상태를 V2 목록과 상세에서 먼저 읽기 전용으로 완전 노출합니다.
2. V2 편집은 단계별 전환 상품기본, 가격, 이미지, 상세HTML, 채널제공을 각각 완성률로 관리하고, 검증된 블록만 V2 저장으로 전환합니다.
3. 목적 선택 제거 도매 직접등록, 뉴톡 대행등록, 촬영서비스, 직접판매 목적은 사용자 선택값이 아니라 시스템 판정 컨텍스트로 표시합니다.
현재 필요한 산출물은 더 많은 텍스트 기획이 아니라, 개발자가 그대로 화면 컴포넌트로 쪼갤 수 있는 화면 설계입니다. 아래 UI 보드는 그 기준으로 작성했습니다.

개발 착수 기준

API 기준 V1 상품 스냅샷, 이미지 스냅샷, 상세HTML 스냅샷, V2 저장상태, 갭 계산 API가 필요합니다.
DB 기준 V1 원본을 복사해 덮는 구조가 아니라, V1 원본 참조와 V2 검증 저장을 분리하는 스냅샷/매핑 테이블이 필요합니다.
UI 기준 먼저 상품목록과 상품 작업실 2개 화면만 구현해도 V1 대체 가능성 판단이 가능합니다. 이미지 작업실은 바로 다음 P0입니다.
최종 판단: 상품등록 UI 구현은 기존 V2 상세페이지를 조금씩 고치는 방식이 아니라, `상품 운영센터 목록`과 `상품 작업실`을 새 축으로 만드는 것이 맞습니다. 그 위에 이미지 작업실과 HTML 빌더를 붙이면 V1 운영 흐름을 잃지 않고 V2로 전환할 수 있습니다.
