NTV2 상품등록 UI 수정기획 v1.1
목적 V1 검수 서비스 흐름 V2 반영 UI 설계 의존성 구현

상품등록은 상품 CRUD가 아니라 NewTalk 거래 서비스를 여는 운영 절차입니다.

V1 운영 상품등록은 도매 상품 입고, 뉴톡 대리등록, 촬영 결과물 등록, 미니몰 노출, 마켓별 송출, 이미지 다운로드, 직접판매까지 연결되어 있습니다. V2는 이 목적을 먼저 선택하고 필요한 필드와 승인 단계를 자동으로 여는 구조로 바꿔야 V1을 대체할 수 있습니다.

뉴톡 관리자 대리등록 도매 자가등록 소매 발주/편집숍 뉴톡 직접판매 V1 수익모델 계승

검수 결론

현재 V2 관리자 상품상세는 상품명, 코드, 설명, 공급가, 소비자가, 상태 중심이라 V1 등록 폼의 핵심 운영 필드 대부분을 잃습니다. 그대로는 V1 대체가 불가능합니다.
별도 파일 버전업 생성: 2026-05-05 KST 대상: NTV2

1. 상품등록 목적 정의

01
도매가 원칙적으로 자기 상품을 등록한다.
02
초기에는 도매가 등록하지 않으므로 뉴톡 관리자가 대신 등록한다.
03
촬영서비스 요청, 샘플입고, 촬영, 보정, QA 후 상품등록까지 이어진다.
04
뉴톡 자체 상품은 소비자 직접판매까지 열어야 한다.
따라서 V2 상품등록 첫 화면은 “누가 등록하나?”가 아니라 “어떤 목적으로 상품 마스터를 만들 것인가?”를 먼저 물어야 합니다. 목적에 따라 도매 소유권, 촬영 의뢰, 편집숍 자동등록, 소비자 판매 노출, 마켓 송출 필드가 달라집니다.

2. V1 상품등록 페이지 정밀 검수

검수 대상 실제 확인 내용 근거 V2 반영 판단
샘플등록 URL productSample/product_sample_mng_add는 비로그인 시 로그인으로 303 리다이렉트됩니다. curl -I 실측, V1 운영 URL V2도 권한별 접근은 유지하되, 기획 HTML에는 바로 열기 링크를 유지합니다.
상품등록 폼 V1 실제 등록 폼은 application/views/products/in_form.php이며 이미지, 코드, 도매처, 원가, 상품명, 설명, 배송, 외부 이미지 URL까지 한 화면에서 처리합니다. /home/danharoo/www/application/views/products/in_form.php V2는 한 화면에 전부 노출하지 않고 목적 기반 위저드와 탭으로 분리합니다.
저장 로직 신규 등록 시 goods, goods_detail, goods_image, goods_code, 로그 테이블이 함께 갱신됩니다. application/controllers/products.php의 create, update, update_process V2 저장은 트랜잭션 단위로 상품 마스터, 상세, 이미지, 워크플로우 로그를 동시에 처리해야 합니다.
업무상태 신규등록 시 BizProgress=A1 입고 상태와 goods_biz_logs가 자동 기록됩니다. products.php, goods_m.php V2에는 상품 상태와 별도로 “등록/촬영/검수/판매준비” 업무상태가 필요합니다.
마켓 송출 V1은 옥션/G마켓, 11번가, 쿠팡, 스토어팜, 위메프, 신상마켓 송출 함수를 보유합니다. market_update() V2는 채널별 상품명, 이미지, 가격, 상세설명 payload를 보존해야 합니다.

4. 뉴톡V2 반영 원칙

V2 상품등록의 핵심 객체

  • Product Master: 모든 역할이 공유하는 상품 원장
  • Registration Case: 도매자가등록, 관리자대리등록, 촬영후등록, 뉴톡직접판매 목적
  • Legacy Field Snapshot: V1 GoodsEtc 계열 원본 보존
  • Content Pack: 이미지, 상세 HTML, 동영상, 검색어, 모델/소재 정보
  • Price Pack: V1 원가/판매가/채널별 판매가와 V2 구독/수수료 정책
  • Channel Pack: 카페24, 신상마켓, 쿠팡 등 채널별 상품명/이미지/설명 payload
  • Workflow Log: 입고, 촬영요청, 촬영완료, 보정, QA, 승인, 노출

현재 V2와의 차이

현재 V2products는 기본 10여 필드, product_details는 HTML 중심
필요 V2V1 필드 보존 + 목적별 UI + 채널별 상품정보 + 업무상태 + 촬영 결과 연결
전환 방식단순 복사가 아니라 V1 원본 필드와 V2 정규화 필드를 병행 저장
수익모델V1 계승: 도매 등록비 0%, 촬영비/예치금, 소매 구독+거래 수수료 3%, 뉴톡 직접판매는 별도 마진
