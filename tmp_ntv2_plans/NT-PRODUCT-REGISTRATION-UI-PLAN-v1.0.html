NTV2 상품등록 UI 수정기획 v1.0
목적 현황 흐름 UI 설계 의존성 구현

상품등록은 단일 입력폼이 아니라
뉴톡 상품 마스터를 만드는 운영 허브여야 합니다.

NTV2 상품등록의 목적은 도매 자가등록, 뉴톡 관리자 대리등록, 촬영서비스 결과 등록, 뉴톡 직접판매 상품 등록을 하나의 상품 마스터 체계로 통합하고, 이후 B2B 발주, 편집숍 자동등록, 소비자 판매, 채널 연동까지 이어지게 하는 것입니다.

뉴톡 관리자 도매회원 소매회원 소비자 V1 수익모델 계승 V2 구독가격 유지

1. 상품등록의 목적 정의

01
도매 원칙 등록

도매회원이 본인 상품을 직접 등록하고, 뉴톡은 검수/노출/촬영/유통 상태를 관리합니다.

02
관리자 대리 등록

초기에는 도매가 등록하지 않으므로 뉴톡 관리자가 매입처/브랜드/사입명 기준으로 대신 등록합니다.

03
촬영서비스 후 등록

샘플 입고, 촬영, 보정, QA 이후 상품정보/이미지/상세설명을 완성해 상품으로 전환합니다.

04
뉴톡 직접판매

뉴톡 자체 판매 상품은 도매 상품과 분리해 판매자, 정산, 재고, 소비자가 정책을 별도 관리합니다.

핵심 원칙: 상품 소유자(owner), 등록 수행자(actor), 판매 주체(seller), 정산 주체(settlement owner)를 분리해야 합니다. 이 구분이 없으면 관리자 대리등록 상품, 촬영서비스 상품, 뉴톡 직접판매 상품이 모두 같은 상품처럼 섞입니다.

2. 현재 V2 상품관리의 문제

V2 관리자 상품상세는 V1 샘플등록을 대체할 수 없습니다.

현재 화면은 상품명, 상품코드, 설명, 공급가, 소비자가, 상태 중심입니다. V1의 카테고리 3단, 노출여부, 상품코드 자동생성, 매입처/모델명, 색상/사이즈/중국옵션, 소재/원단느낌, 다중 판매가, 쇼핑몰별 상품명, 상세설명 템플릿, 배송/세금/재고, 외부 이미지 경로가 빠져 있습니다.

V2 API/DB도 최소 상품 구조입니다.

products는 user_id, wholesale_profile_id, name, product_code, description, supply_price, retail_price, status, v1_goods_idx, v1_master_idx 중심입니다. 등록/수정 Request도 동일한 최소 필드와 options/channels/category/html_content만 받습니다.

6. 구현 우선순위

P0. 대체 불가 필드 보존

  • v1_product_snapshots 또는 product_v1_fields 생성
  • V1 샘플등록 필드군 전체 저장
  • 상품 소유자/등록자/판매자/정산주체 분리
  • 상품코드 자동생성 및 중복검사 API

P1. 관리자 위저드

  • 등록 목적 선택 화면 신설
  • V1 필드군을 탭/단계형 UI로 재배치
  • 가격 자동계산과 채널별 상품명 자동생성
  • 누락 검수 패널과 게시 전 체크리스트

P2. 운영 흐름 연결

  • 촬영서비스 결과에서 상품 생성
  • 사입/입고에서 뉴톡 직접판매 상품 생성
  • 도매 자가등록 권한 제한
  • 편집숍/소비자 판매 상태 자동 연동

필수 DB/API 설계 항목

영역제안 구조이유
출처/목적 product_source_type, owner_type, seller_type, settlement_owner_type 도매, 관리자 대리, 촬영, 뉴톡 직접판매 상품을 구분
V1 호환 product_v1_fields 또는 JSON snapshot + 주요 검색 컬럼 분리 V1 대체 전까지 필드 손실 없이 보존
가격 product_prices: 원가, 판매가, TAG가, 자사몰, 단하루, 입점몰, 뉴톡판매가 V1 자동계산식과 V2 판매 채널을 모두 지원
이미지 product_assets: 상품이미지, 참고이미지, 채널이미지, 촬영결과 이미지 V1 이미지 경로와 V2 업로드/촬영 결과를 통합
상세/고시 product_specs, product_detail_templates 소재, 원산지, 원단느낌, 모델사이즈, 상세설명 자동생성 보존
게시 product_publications: B2B, 편집숍, 뉴톡몰, 카페24, SNS별 상태 하나의 상품이 여러 판매면으로 나가는 구조 지원

CEO 확인 필요 항목

  • 관리자 대리등록 상품의 소비자 화면 판매자 표기는 도매명으로 할지, 뉴톡 검수/등록 상품으로 표시할지 결정이 필요합니다.
  • 뉴톡 직접판매 상품은 정산 주체를 뉴톡으로 고정하고, 도매/매입처는 공급처로만 둘지 확인이 필요합니다.
  • 도매가 나중에 직접 운영을 시작할 때, 기존 관리자 대리등록 상품의 소유권 이전 승인 절차가 필요합니다.
